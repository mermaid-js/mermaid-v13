# D651: The R-PERF-1 loaded limit rises from 150,528 B to 151,552 B gz (+1 KiB); amends D600

The `loaded` budget in `packages/mermaid/size-budget.json` (core + flowchart as a page loads them for one flowchart render, gzip level 9) rises by 1 KiB, from 150,528 B (147 KiB) to 151,552 B (148 KiB).

`mermaid-v13` went over the old limit at `95773caf2` (147.1 KB fetched). Between the last green run and that commit, eight PRs merged in about ten minutes, each passing the gate against its own base. Measured with the size report's static stand-in, reverting one PR at a time: #1010 (the Courier New measurer table for monospace text, #759, D644) costs 132 B, and #1003 (`data-ast` for a node only a block or `style` line names, #987) 98 B. Neither can shrink much: the table's widths are all the same, and gzip already leaves them almost free; the cost is code and the alias list. The other six PRs cost ±4 B. The rest of the raise leaves room for #650's fix (about +530 B, spec #995, decision 4).

As D546, D625 and D600 did, the raise is a decision, not a gate loosened to make a change pass. Rejected: reverting one of the two fixes, and leaving #650 open to stay under the old limit.
