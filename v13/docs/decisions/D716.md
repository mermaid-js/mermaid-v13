# D716: The edge-label tag centres its text's ink, not its line box

The shared `edgeLabel` helper lifts the text of a tag by 0.1 × the label's ascent, so that the ink of a typical label sits at the tag's centre. The tag's size, radius, border and fill are unchanged (D626, D629). Every line moves by the same amount, so a label of several lines moves as one block. A label with an inline box (an icon or an image) keeps its line box centred. It is one rule in `edgeLabel`, with no per-type case, so every type that draws a tag moves.

The line box was already centred exactly. But the ink of a label with capitals or ascenders and descenders sat about 1.4 px below the tag's centre, because the ascent leaves more room above the caps than the descent leaves below the descenders (#1319). The offset measured in Chromium is 0.088 × ascent for Trebuchet MS and 0.103 × ascent for Arial. After the lift it is within 0.3 px. The factor is empirical: the font table has ascent, descent and line height, but no cap height or descender depth. A rule based on half the descent overshot by 0.76 px under Trebuchet MS.

A label with no descenders now sits about 1.2 px above the centre; before, it was within 0.2 px. Centring every label exactly would need cap and descender metrics in core's font table.

Horizontal centring was measured within 0.3 px and is unchanged. It is not a v12 divergence, because v12 had no tag.

(Knut, 2026-11-26, spec #1334 decision 5, #1319.)
