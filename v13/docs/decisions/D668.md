# D668: State transitions read the canvas line colour, so `default` and `dark` keep v12's under a `lineColor` override; amends D639

v12 sets a state's `transitionColor` from `lineColor` once, before an author's overrides in `default` and `dark`, so there an author's `lineColor` never reaches the transitions: they stay `#333333` and `#d3d3d3`. In `forest` and `base` v12 sets it after the overrides, so the transitions follow `lineColor`.

v13's state transitions, and the borders of their label tags (D627), now read `canvasLineColor` instead of `lineColor`. `default` and `dark` pin it to those two values (D656), and it is `lineColor` in every other theme, so nothing changes with no override. `forest` and `base` follow an author's `lineColor`, as in v12. `neutral` follows it too: v12's `neutral` draws its transitions in its own `#000` under every override, which D639 keeps out.

The rest of D639 stands. The start dot, the fork and join bars and the end ring stay on `lineColor`: v12's `specialStateColor` follows `lineColor` in `default` too. The arrowheads stay on `arrowheadColor` for now. Reading `canvasLineColor` there would change `forest`'s arrowheads from `#008000` to `#000000` and `neutral`'s from `#333333` to `#666666` with no override, which spec #1035 rules out, so they wait for their own decision.

(Knut, 2026-11-19, spec #1035.)
