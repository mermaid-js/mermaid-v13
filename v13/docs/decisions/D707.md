# D707: a theme variable of kind `opacity` also takes a percentage

Amends D221. A theme variable of kind `opacity` (`pieOpacity`, `radarCurveOpacity`, `radarGraticuleOpacity`) still takes a number from 0 to 1, given as a number or a string. It now also takes a percentage from `0%` to `100%`, written as digits with an optional fraction and a `%` sign right after them, with no space. The percentage is kept as N/100, so `"50%"` is read as `0.5` and `Theme.number()` still returns a number from 0 to 1 for every opacity. The stored value is rounded to 6 decimals; the SVG writes an opacity with 2 decimals anyway, so `"14.3%"` is drawn as `0.14`. Anything else is dropped with `THEME_VARIABLE_DROPPED` and the theme's value is kept, as before: `"150%"`, `"-1%"`, `"50 %"`, `".5%"`.

v12 wrote `pieOpacity` into the pie's CSS as given (`opacity: ${pieOpacity}`), and CSS takes `50%` as 0.5, so `pieOpacity: "50%"` worked in v12. Under D221 alone v13 dropped it with a warning and drew the slices at the theme's 0.7 (#1203). This decision keeps what v12 drew. The change is in core's check of the `opacity` kind, so radar's opacity variables take the same forms. The `opacity` property in a `style` statement is not a theme variable and does not change.

The other option was to keep D221 as it was and say in MIGRATION.md that `50%` is dropped. It was not chosen: v12 authors who wrote a percentage would lose it, and accepting it costs a few bytes.

(Knut, 2026-11-26.)
