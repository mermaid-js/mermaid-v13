# D713: Edge-label tag ink is contrasted with the tag fill, per diagram

The text colour of an edge-label tag (D626, D628) is chosen against the tag's fill in each diagram's theme table, with the existing `contrast()` rule: `contrast(<fill>, textColor, contrast(<fill>, #000000, #ffffff))`. The shared `textColor` is kept where it meets AA on the fill, else black or white, whichever reads better, as `Theme.ink` does for nodes (R-THEME-12). Under `cssVariables` the choice follows a host's colours live, as `contrast()` does elsewhere. The variables that carry the rule are D715's.

The base ink is `textColor` for every type, so a type whose tag used another ink before (class `classText`, requirement `inline(nodeTextColor, textColor)`, block's node text, use case `primaryTextColor`, C4 `c4RelationColor`) can draw a different default ink in some built-in themes. The PR for spec #1334 lists those themes.

A colour an author sets on one edge (`linkStyle … color`, an edge `style`, C4 `UpdateRelStyle` `textColor`) wins as written, with no contrast check.

Two alternatives were not chosen. A contrast computed inside the shared `edgeLabel` helper: it only sees `var(--_x)` paint, so it cannot follow CSS variables live. And a new shared ink variable in core's theme spec: the shared `textColor` and `edgeLabelBackground` are the shared level (D715).
