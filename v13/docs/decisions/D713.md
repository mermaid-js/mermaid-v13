# D713: Edge-label tag ink is contrasted with the tag fill, per diagram

The text colour of an edge-label tag (D626, D628) is chosen against the tag's fill in each diagram's theme table, with the existing `contrast()` rule: `contrast(<fill>, <today's ink>, contrast(<fill>, #000000, #ffffff))`. Today's ink is kept where it meets AA on the fill, else black or white, whichever reads better, as `Theme.ink` does for nodes (R-THEME-12). Under `cssVariables` the choice follows a host's colours live, as `contrast()` does elsewhere. With no overrides, every built-in theme keeps the ink it drew before. An author's own label ink variable still wins.

Requirement's `relationLabelColor` is chosen against `relationLabelBackground` (#1322). Class gets `classEdgeLabelColor` (D714, #1327).

Two alternatives were not chosen. A shared edge-label ink rule in core's theme spec, and a contrast computed inside the shared `edgeLabel` helper: the helper only sees `var(--_x)` paint, so it cannot follow CSS variables live.

(Knut, 2026-11-26, spec #1334 decision 1.)
