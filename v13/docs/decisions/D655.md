# D655: Per-render state reaches the outline drawer's draw and the inline providers; amends D302 and D177

An extension keeps no state of one render in module scope (R-ARCH-6, #1027). The extension contract in `core/src/pipeline/extensions.ts` and `core/src/text/inline.ts` now hands each of the two calls that lacked it what it needs for its render.

1. `OutlineDrawer.draw(role, tag, attrs, sink, ctx)`: `draw` gets the render's hook context, the same frozen object `active` got, as a fifth argument. A drawer reads its config, or what `active` put in `ctx.state`, from it. The hand-drawn plugin reads `handDrawnSeed` from `ctx.config` on each call, so its sketch no longer takes the seed of whichever render called `active` last. Amends D302: `active` still returns a boolean, and the change is additive.
2. `InlineRequest.standIns`: what the render is drawn without, because it has not loaded, which are the resources its one `PLACEHOLDER` warning names. It is empty when nothing stands in. `mermaid` passes the list from its missing-resource policy to `inlineSpans()`. A provider whose engine is among them declines without a warning of its own. The math plugin warns `MATH_NOT_RENDERED` only when `math "tex"` is not in the list, so `resources.missing()` stays pure, as `ExtensionResources` documents. Amends D177.

The two module-level `let`s this replaces (hand-drawn `seed`, math `reported`) leave `eslint-suppressions.json`, so `mermaid/no-module-state` covers both files.

Rejected:
- For the drawer, `active(ctx)` returning a draw function bound to the render. It changes D302's shape for little gain over the extra argument.
- For math, handing the render's scratch to `missing()`, which would give `missing()` a write.
- For math, warning `MATH_NOT_RENDERED` next to `PLACEHOLDER`, which adds a warning users see.

(Knut, 2026-11-19, #1027.)
