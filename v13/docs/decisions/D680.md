# D680: Arrowheads take the line colour in `forest` and `neutral` too; replaces D575's clause for those two themes

`forest` and `neutral` no longer set `arrowheadColor`, so it takes the shared rule `lineColor` in every built-in theme. With no override, `forest`'s arrowheads change from `#008000` to its `#000000` lines and `neutral`'s from `#333333` to its `#666666` lines (#1161). An author's or host's `lineColor` recolours edges and heads together in those two themes as well, and `themeVariables.arrowheadColor` still sets the heads alone. A `linkStyle` stroke still colours its own edge's head.

This replaces the clause of D575 that kept `forest`'s and `neutral`'s own `arrowheadColor`; the rest of D575 stands. It also settles the point D668 left open: state's arrowheads stay on `arrowheadColor`, which now matches the transitions' line in every theme with no override. Flowchart (with `swimlane-beta`), state, block and agentflow follow, since all four paint heads with `arrowheadColor`.

This moves toward v12, whose `.marker { fill: lineColor }` drew black heads in `forest`. v12's `getThemeVariables()` still reports `#008000` and `#333333`, which reached only the legacy `.arrowheadPath`, so the variable differs from v12 and the render matches it. The override oracle lists that difference.

(Knut, 2026-11-23, spec #1163 decision 9.)
