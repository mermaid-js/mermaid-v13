# D698: A whole-label provider gets the label's inline spans boxed

`LabelRequest.inline(text)` boxes the inline spans of `text` with the render's inline providers (D177, D293), as label layout boxes them. It returns `{ source, boxes }`, where `source` is `text` with each boxed span replaced by a placeholder character (`PLACEHOLDER + i`, exported from `@mermaid-js/core/text`) and `boxes` holds the boxes in order, or `undefined` when no span is boxed. So a whole-label provider (D695) no longer hides a label from the math and icons extensions: it calls `inline()`, lays out what is left, and places the boxes it gets.

`inline()` warns as label layout does for a span that is not drawn (`MATH_NOT_RENDERED`, `ICON_NOT_RENDERED`, `INLINE_LIMIT`). A provider that takes a label and does not call it answers for the label's math and icons itself: core does not warn for that label. The boxes are checked against the allow-list before the provider sees them, and the provider's own box is checked again with them inside.

`@mermaid-js/plugin-html-labels` uses it. A label with math (`$$…$$`) or an icon (`fa:…`) is now an HTML label: the HTML leaves an empty inline block of each box's size on the line's baseline, and the box's SVG is drawn at that place in the label's placeholder `<g>`, after the `<foreignObject>` once mounted. Without a math or icons extension the span is shown as written in the HTML label, with core's warning. This amends D697, which left such labels as SVG and named this as a follow-up.

Core grows by about 20 B gzipped for this.
