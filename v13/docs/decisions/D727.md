# D727: GANTT_UNKNOWN_TASK says what applies to each kind of unknown id

A gantt render still produces at most one `GANTT_UNKNOWN_TASK` warning, as D276 set. What changes is its text. It used to be one fixed sentence for every unknown id: it named `after`, `until`, clicks and milestones together, so a plain `after zz` was told about things that did not happen, and `click __proto__` was told that no task has the id although the task was written (#1254, #1255).

The message now has one clause for each kind of reference that is present, in this order:

- `after`: `No task has the id "x", "y" (named by "after"): the task starts at midnight today.`
- `until`: `No task has the id "z" (named by "until"): the task ends at midnight today.`
- `click`: `No task written before the click has the id "w": the click does nothing.` A click names only a task written before it, as in v12.
- the reserved id: `The id "__proto__" is reserved and cannot be referenced: …`, followed by what happens for each statement that named it (an `after` starts at midnight today, an `until` ends at midnight today, a click does nothing). `__proto__` is never stored, as v12's plain-object task table never stored it, so no statement can reach it, and it is not listed in the other clauses.

The milestone hint (`A milestone needs an id and a duration, …`) is added only when a milestone task wrote the `after` or `until` that named the unknown id.

To tell the statements apart, the schedule records each unknown `after`/`until` id with the statement and whether the referring task is a milestone (`Schedule.unknownRefs`). `Schedule.unknownIds` stays as it was: one deduplicated list of ids, which v12-derived specs read. The code stays `GANTT_UNKNOWN_TASK`; `GANTT_BAD_DURATION`, the facet diagnostics and the editor hover are unchanged.

One warning per kind was not chosen: it would change the warning count that D276 and the fixtures fix, for a reader who has to find all of them anyway.

Amends D276's wording only; the count (one `GANTT_UNKNOWN_TASK` per render) is unchanged.

(Knut, 2026-11-26.)
