# D666: Gantt draws its tick lines in `gridColor`; v12's `currentColor` lines are a listed difference

v12's gantt draws each tick line with d3's axis, which writes `stroke="currentColor"` on the `<line>`. v12's `.grid .tick { stroke: gridColor; opacity: 0.8 }` styles only the tick's `<g>`, and the line's own attribute beats what it would inherit, so `gridColor` never reached the line: the line took the host page's text colour (black on a plain page) at the group's 0.8 opacity. That is so in every theme and look, with or without an override (#838, #1041, checked in Chromium with `mermaid@12.2.0` under `look: classic` and v12's default look).

v13 strokes the tick lines in `gridColor` (`lightgrey` in every classic theme, the value v12 resolves) at 0.8, as v12's CSS meant. This decision keeps that, so the grid follows the theme and `themeVariables.gridColor`, and a standalone SVG does not draw black lines under `dark`. MIGRATION.md's gantt SVG structure section records the difference; a host that wants v12's dark lines sets `gridColor`.

Rejected: drawing the lines in `currentColor`, as v12 did. `gridColor` would then do nothing, the lines would depend on the host page's text colour, and 95 gantt fixtures would change.

(Knut, 2026-11-19, spec #1035, #1041.)
