# D733: Edge curves: each type's own `curve` key, then a global `curve`, then the type's default

A new top-level config key, `curve`, sets the curve of every diagram type that draws edges. Each such type also has its own key, `<type>.curve`. For each type the curve is, strongest first:

1. `<type>.curve`, when the author sets it;
2. `curve`, when the author sets it;
3. the type's own default, which is the curve it draws today.

Per-edge curves (`curve:` on a flowchart edge, `linkStyle … interpolate`) stay above every config key. Self-loops keep their `rounded` path. Text output stays stepped on the grid (D78). With nothing set, every type's output is byte-identical to today. An unknown name is drawn with `DEFAULT_CURVE` and warns `CURVE_UNKNOWN` once per render (D602, D681). Every key takes `flowchart.curve`'s names.

**Defaults live in code.** None of these keys has a schema default, and `flowchart.curve` loses its default `rounded`. A diagram sees only its own section's defaults, and a key with a schema default is always set, so a type could not tell a value the author set from the default, and `curve` could never apply. Each type's default is written in its code and in the key's description, and a spec pins it. The resolved config (`getConfig()`), the config reference and the editor hover show no default for `flowchart.curve`. The rendered output is unchanged.

The order per type:

- **Flowchart:** `flowchart.curve` > `curve` > `rounded`.
- **Swimlane** (`swimlane-beta`, the flowchart plugin with the `swimlane` section on top, D534): `swimlane.curve` > `flowchart.curve` > `curve` > `rounded`.
- **State:** `state.curve` > `curve` > `curved`. State does not read `flowchart.curve`. This replaces the spec's proposal that state follow `flowchart.curve`, as v12's shared edge renderer did (#1324).
- **Class, requirement, agentflow:** `<type>.curve` > `curve` > `rounded`. They stop reading `flowchart.curve`. Agentflow's `linkStyle default interpolate` stays above both.
- **Every other type that draws edges** (usecase, ER, mindmap, block, C4, cynefin, architecture, and any other found): `<type>.curve` > `curve` > the curve it draws today.

Where a configurable curve makes no sense for a type, or where the type would need more than routing the curve name, the work stops and the case goes to Knut before it is implemented.

Divergences from v12: `flowchart.curve` no longer changes state, class, requirement or agentflow edges. Each type records this in its migration fragment, which is the record for it: the files in `packages/conformance/divergences/` hold per-fixture parse divergences only.

(Knut, 2026-11-27, spec #1338, #1324, #1325, #1377.)

Amended by D748 (which types take a key) and D749 (swimlane's curve).
