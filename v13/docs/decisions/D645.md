# D645: Integrators add font tables to the table measurer with `initialize({ fontTables })`

`initialize({ fontTables })` takes a list of font tables. Each is `{ format: 1, family, aliases?, ascent, descent, lineGap, regular, bold? }`: hhea ascent, descent and line gap in thousandths of an em, and the regular and bold advances for U+0020–U+007E and U+00A0–U+00FF, two base-36 digits each, as in `FACES` (382 digits). Without `bold`, bold text uses the regular advances. Like `measurer`, it is an integrator-only option that diagram text can never set (R-SEC-6), and a per-call `config` can set it too.

- **Lookup.** Core's `createTableMeasurer({ faces })` checks each family in the stack, in order, against the given tables (by family and aliases), then the built-in tables and their aliases (D644); a stack with neither is measured as Arial. A given table wins over a built-in of the same name, so a given `Arial` table also measures the fallback. The built-in monospace aliases keep naming the built-in Courier New table; an integrator who wants `monospace` measured with their own table lists it as an alias. When two entries name the same family, the first wins. Each measurer has its own caches, so sessions with different tables never mix. `tableMeasurer` is the measurer with no extra faces.
- **Measurer choice.** `mermaid` uses the measurer with those tables wherever it used the table measurer: under `deterministic: true` in every environment, and in Node and workers by default. In a browser without `deterministic` the canvas measurer still wins, because it measures the font actually drawn, and an integrator `measurer` still wins except under `deterministic` (R-TEXT-7).
- **Label layout.** The plain-label fast path measures slices of a label without slicing it for every table measurer, through a slice function the measurer carries under a non-enumerable symbol, bit for bit equal to its `width`. A spread copy of a table measurer with its own `width` does not carry it, so it is measured by its `width`.
- **Validation.** A malformed entry (not format 1, no single family name, aliases that are not a list of names, a negative or non-numeric ascent, descent or line gap, advances that are not 382 base-36 digits) throws `MermaidError { code: 'SEMANTIC' }` from `initialize()`, or rejects a render with it for a per-call config, with a message naming the entry by index and family. `SEMANTIC` is the code for input that is well formed but invalid; `UNSUPPORTED_FORMAT` is for output formats (the CLI exits 2 on it), `SYNTAX` points into diagram text and `INTERNAL` is for bugs.
- **Determinism key (R-ARCH-6).** The measurer's `id` is `table` without extra faces and `table:<FNV-1a of the normalised entries>` with them. Normalised means family names unquoted, trimmed and in lower case, digits in lower case and a missing `bold` equal to `regular`, in the order given; the id prefix keys on that id in place of the tables. Equal tables give the same key and the same bytes; tables that differ give different keys, even when a diagram measures the same with both. Without `fontTables`, or with an empty list, the key is as before.

The table generators are separate tickets of spec #1000: from font files in the CLI, and from a browser page with the font loaded. This amends DESIGN §5.1.
