# D673: Core exports its search heap from `@mermaid-js/core/ascii`

`@mermaid-js/core/ascii` exports `Heap`, the binary min-heap of numeric items by numeric key that core's route repair searches with, and its type `HeapTies`. It was private to `repair.ts`, and the ASCII routers of C4 and block each kept a copy of it (audit finding diagram-c4-02, spec #1075, step C-102).

The order of two items of equal key is a constructor parameter, because the searches that use it break ties differently and their output must not change: `'pushed'` (the default) takes the one pushed first, as core's route repair does; `'item'` takes the smaller item, as C4's ASCII router does; `'none'` leaves them as the heap's layout has them, as block's ASCII router does. Each is deterministic.

The export is on the ASCII subpath only, as the maintainer answered. The SVG layout of C4 (`layout/channels.ts`) keeps its own heap: only ASCII code may import `@mermaid-js/core/ascii` (DESIGN §6.3, rule `mermaid/import-boundaries`), so sharing it there needs the heap on a neutral subpath, which is a further decision.

(Knut, 2026-11-20, spec #1075.)
