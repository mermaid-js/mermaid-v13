# D702: TreeView draws v12's unknown-icon glyph for an icon that cannot be drawn

An icon in treeView that cannot be drawn is drawn as v12 drew it: v12's unknown-icon glyph, a `#087ebf` square with a white `?`, in the icon's slot. This amends D485 and D299 for treeView, under which the slot stayed empty.

v12's treeView renderer asked `getIconSVG` for every icon and drew Iconify's `unknownIcon` for one it could not resolve. v13 left the slot empty with one `ICON_NOT_RENDERED`. The slot keeps its width, as v12 kept it, so the empty slot read as a gap between the connector and the name, with nothing to show which icon was missing (#1283). Architecture already draws the same glyph for an unresolved icon (D505).

The glyph is drawn when no icons extension draws the name (no extension, or none has it), and when an extension reports the name unresolved and warns itself (D291). While the name's pack is still loading in a placeholder render (`'pending'`, D299) the slot stays empty, quietly, so the `?` never shows for an icon that will be drawn. The `ICON_NOT_RENDERED` warnings are unchanged, but for their last sentence, which now says the `?` square is drawn.

The glyph is v12's art in its 80 px square, scaled to the icon size, with v12's fixed colours in every theme (D152), as architecture draws it. It moves from architecture to `@mermaid-js/shared/svg/unknown-icon`, which both import; architecture's output is unchanged.

Rejected: collapsing the slot so the name meets the connector. The layout is done before the icons are resolved, so an icon whose pack loads later would move its row's name when it arrives, and v12 kept the slot.

(Per Brolin, 2026-11-26, #1283.)
