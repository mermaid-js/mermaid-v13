# D737: A colour function is checked argument by argument

Extends D690. Where an author gives a colour, `checkCssColor` keeps a colour function only if its arguments are what CSS takes:

- `rgb`, `rgba`, `hsl`, `hsla`, `hwb`, `lab`, `lch`, `oklab` and `oklch` take 3 or 4 numbers, percentages, angles or `none`.
- `color()` takes a CSS colour space and those channels.
- `color-mix()` and `light-dark()` take two colours that pass the same check.

Anything else is dropped with the path's warning, as D690 says.

Valid CSS that the check does not read is refused too: relative colours (`rgb(from …)`), `var()` or `calc()` inside a channel function, and exponents. It is rare, and an author can write the colour out.

The channel functions are checked since spec #1371 T1, and `color()`, `color-mix()` and `light-dark()` since T2. `var()` keeps its own check in `checkColor`.
