# D638: State text and composite titles read their own inks, `primaryTextColor` in the classic family

State gains two theme variables: `stateLabelColor` for state text (v12's name) and `compositeTitleColor` for composite titles. In the `classic` family `stateLabelColor` reads `primaryTextColor` and `compositeTitleColor` reads `stateLabelColor`, so the four named classic themes draw v12's colours (`#131300`, `#e0dfdf`, `#321b67`, `#111111`) and `base` keeps `#333333`. An author's `stateLabelColor` recolours both, as v12's one variable did. The `redux` and `neo` families read `nodeTextColor` and `titleColor` as before. Keyed by family, never by theme name (D331). Amends the colour mapping in MIGRATION "State".

An author's `primaryTextColor` recolours state text in all five classic themes. v12 did that in `dark`, `forest`, `neutral` and `base`, but `default` fixed `stateLabelColor` when the theme was built, so there the override never reached state text; v13 does not copy that. `conformance/src/state/theme-inks.spec.ts` checks every other case against v12 12.2.0.

(Knut, 2026-11-19, spec #975, decision 2, #827.)
