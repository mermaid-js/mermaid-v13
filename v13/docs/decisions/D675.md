# D675: The parser kit exports `callbackArgs`, and every diagram carries it

`@mermaid-js/core/parser-kit` exports `callbackArgs(id, args)`, next to `AstCallback` in `ast.ts`. It returns the arguments of a `call fn(…)` click callback as v12's `setClickFunc` passed them: `args` split at each comma followed by an even number of `"`, each item trimmed and stripped of one pair of surrounding quotes, and `[id]` when there are none. Class diagrams and `@mermaid-js/plugin-interactions` each had a copy, with the parameters in opposite order; both now call this one (audit finding plugin-interactions-02, ticket #1088, spec #1085).

The cost is accepted. Every diagram's parser loads the chunk of `@mermaid-js/core/parser-kit`, so each type's static closure grows by 104 to 111 B gz (about 3.4 KB over the 32 types). Class saves 150 B and the build as a whole 19 B. A file of its own inside the parser kit did not help, because whatever that entry exports lands in the chunk every parser loads. A `@mermaid-js/shared` subpath is not an option: `plugin-interactions` is published and installed on its own, and `@mermaid-js/shared` is not published, so a peer on it fails the install (`ERR_PNPM_FETCH_404` in the platform specs).

(Knut, 2026-11-20, spec #1085.)
