# D697: What the first HTML labels plugin covers

- **Browser only.** Without a DOM (Node, a worker), in a deterministic render and in text output the plugin declines and core draws SVG labels: the output is the same as without the plugin.
- **Unmounted output has placeholders, not labels.** The svg string holds, for each label, a `<g class="mermaid-html-label">` with a `<rect>` of the label's size and a `<desc>` with the label's HTML as text. `RenderResult.bindFunctions(el)` (or `run()` / `mount()`) swaps in the `<foreignObject>`. A host that exports the string or shows it through `<img>` sets `htmlLabels: false`.
- **Label text as in v12 with `htmlLabels: true`:** raw HTML is rendered after sanitizing, and a markdown string becomes HTML.
- **A label with a math span (`$$…$$`) or an icon (`fa:…`) stays SVG,** so math and icons keep working; its other HTML is dropped with `HTML_DROPPED` as without the plugin. Drawing them inside an HTML label is a follow-up.
- **Only labels on the shared label path** (`layoutLabel` and `SvgWriter.label`). Text a diagram draws itself stays SVG.
- **No style sheet.** The label's font and colour come from the resolved values core already has.
