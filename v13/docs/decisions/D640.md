# D640: The PR structural audit runs fallow without coverage; CRAP gates nightly

The structural audit on a PR (`structure` in `ci.yml`) and in the pre-push hook (`tools/pre-push/cli.ts`) runs `fallow audit` without coverage. It no longer runs the tests the change reaches with `--coverage` first. CRAP findings on a PR are warnings: `.fallowrc.pr.json` extends `.fallowrc.json` and sets the `complexity-crap` rule to `warn`. Every other audit finding fails a PR as before: dead code, import cycles, boundaries, duplication, and cyclomatic or cognitive complexity. A function that exceeds CRAP together with another complexity threshold still fails on that other threshold.

Exact CRAP gates in the nightly fallow run (`fallow-nightly.yml`), which has coverage from the full unit suite and fails on new findings against `.fallow-baseline/health.json`. A function with a high CRAP score is therefore caught the night after its merge, not on its PR. To see exact scores before merging, run `pnpm exec fallow health --coverage coverage/coverage-final.json` after a `vitest run --coverage`.

This amends #722, which pointed the PR audit's `health.coverage` at the coverage of the tests the change reaches. Coverage feeds only the CRAP metric. Without it, fallow estimates CRAP from export references, and the estimate is too high: 31 findings in `core/src/text`, pie and sankey vanish with real coverage. So an estimated CRAP score can warn but not gate. The coverage run was the slowest job of the PR check in 16 of 30 merged PRs (up to 24 minutes), and the slowest part of the pre-push hook.

Rejected: collecting coverage in the unit shards and passing it to fallow (option B). It keeps exact CRAP on PRs, but adds an estimated 1.3 to 2.7 minutes to every full run (coverage cost 15% to 50% more time in a measured sample). It also puts coverage-induced timeouts into the jobs that gate the PR.

(Knut, 2026-11-19, #977.)
