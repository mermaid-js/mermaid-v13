# D715: Edge-label tags have two levels of theme variables

Every diagram type that draws D626's edge-label tag reads its fill and ink from two levels of theme variables:

- **Shared:** `edgeLabelBackground` (default `background`, D628) for the fill and `textColor` for the ink. Overriding one recolours the tags of every type.
- **Per type:** `<type>EdgeLabelBackground` (default `edgeLabelBackground`) and `<type>EdgeLabelColor` (default `contrast(<type>EdgeLabelBackground, textColor, contrast(<type>EdgeLabelBackground, #000000, #ffffff))`, D713). Overriding one recolours only that type.

The types are class, requirement, flowchart (and swimlane), state, ER, agentflow, block, use case and C4. Flowchart gains a theme table for its two variables. ER keeps `erEdgeLabelBackground` as its fill variable. Requirement keeps v12's `relationLabelBackground` and `relationLabelColor`, which still win when an author sets them. Core's theme spec is not changed: the shared level already exists.

This amends D628, which gave the tag its fill but no per-type variable, and D572, which kept ER from adding a variable for the same case. Class reading a variable of its own replaces the earlier proposal that it read only the shared `edgeLabelBackground`.
