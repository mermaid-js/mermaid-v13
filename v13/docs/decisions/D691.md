# D691: A comment before agentflow's header is a comment whatever it holds

Before the `agentflow-beta` keyword, a `%%` comment is read as a comment whatever its text is. mermaid@12.2.0 keeps comments in the text it lexes and tries its `direction` rule (`.*direction\s+LR[^\n]*`) and its link id rule before its comment rule, so `%% direction LR` was a `direction` statement and `%%x@y` a link id. Neither may stand before the header, and v12 rejected the diagram, as v13 did. This only turns rejects into accepts, as D463 did.

After the header nothing changes: `%% direction LR` inside a flow still sets that flow's direction, because v12 accepts it with that meaning. The alternative, a `%%` line is a comment everywhere, was not chosen: it would change how a diagram that v12 accepts is drawn.

The lexer and the normative grammar both hold the rule. The generated TextMate and Monarch highlighters read a line at a time and cannot see that the header is still to come, so they colour such a line as they did. The language service reads it as a comment, and so does the Lezer grammar, unless the header is more than 4,096 characters further on or a directive stands between the two. The grammar's rule is tied to the start of a line, so that it stays linear in TextMate, which searches every offset of a line.
