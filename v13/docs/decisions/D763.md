# D763: Architecture warns once for the settings it reads nowhere, which lose their defaults

An `architecture` section that sets any of eight keys v13 reads nowhere gets one `ARCHITECTURE_SETTINGS_IGNORED` warning per render. The keys are v12's six fcose settings (`randomize`, `nodeSeparation`, `idealEdgeLengthMultiplier`, `edgeElasticity`, `numIter`, `seed`, D328), `fontSize` (D507) and `useWidth`, which v12 never read either. The warning names every key that is set, in that order, whatever order the author wrote them in, and its `path` is the first of them. It says the layout is `compass` and the fcose keys tune fcose, which v13 does not have; for `fontSize`, to use `themeVariables.fontSize`; and that `useWidth` was never read. The code is new, in `packages/diagram-architecture/src/codes.ts` and exported from the package entry. `ARCHITECTURE_CONFIG_IGNORED` keeps its meaning: a bad `iconSize` or `padding`, drawn with the default. The rendered output does not change.

A key counts as set when it is an own key of the resolved `architecture` section, at whatever value, even v12's default: from `initialize`, front matter or a directive alike.

**The eight keys have no schema default.** `mermaid` merges a plugin's generated section defaults into every render's config (`config-snapshot.ts`), so with defaults the six fcose keys and `fontSize` were own keys of every architecture render, and the warning could not tell a key the author set from one nobody set. Since nothing reads them, they lose their `default` and leave the section's `required` list, as D733 took the defaults of the curve keys into code. `getConfig()`, the config reference and the editor hover show no default for them; each key's description gives v12's. Their status stays `ignored`.

This amends D328 and D507, whose migration rows said the keys were ignored with no warning. The rows now name the code.
