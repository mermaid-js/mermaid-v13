# D769: every mindmap shape wraps at `mindmap.maxNodeWidth`, clamped to 120 to 1200

Every mindmap shape (default, circle, square, rounded, hexagon, cloud and bang) wraps its label at `mindmap.maxNodeWidth`. The default is 200. There is no case per shape, and mindmap never reads `flowchart.wrappingWidth`.

- **Clamp.** An author value outside 120 to 1200 is clamped to the nearest limit, and the render carries one warning, `MINDMAP_CONFIG_IGNORED` with path `mindmap.maxNodeWidth`, saying it was adjusted. The code is the one the key already uses for a value it cannot take; its message tells the two cases apart.
- **Unchanged.** A value that is not a number (a numeric string is a number), or is 0 or less, lays out with 200 and warns `MINDMAP_CONFIG_IGNORED`, as before.
- **Differs from v12.3 on purpose.** v12 wrapped square, rounded and hexagon nodes at 120 only because those shapes went through the shared flowchart shape code, which reads `flowchart.wrappingWidth` (120 by default). That is not a design to keep. The divergence is listed in the mindmap fragment of the migration notes.

This amends D287. The rule of D287 stays: `maxNodeWidth` wraps every shape. Its premise, that v12's `flowchart.wrappingWidth` and `mindmap.maxNodeWidth` both default to 200 so defaults do not change, was wrong: `flowchart.wrappingWidth` defaults to 120. v13 keeps the 200 for all shapes, so the output with nothing set does not change, and square, rounded and hexagon nodes stay at today's v13 width. Only an author value outside 120 to 1200 changes output.

Closes #1174. (Knut, 2026-11-27, spec #1342 T4.)
