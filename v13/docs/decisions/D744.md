# D744: Mindmap square, rounded and hexagon labels wrap at 120 px by default

With `mindmap.maxNodeWidth` unset, the labels of square `[…]`, rounded `(…)` and hexagon `{{…}}` nodes wrap at 120 px, and those of every other shape (default, circle, cloud, bang) at 200 px. The redux family draws a plain node rounded (D288), so a plain node wraps at 120 there, as v12's did. An author's `mindmap.maxNodeWidth` wraps every shape, as D287 said.

D287 rested on a wrong premise: that v12's `flowchart.wrappingWidth`, which wrapped those three shapes, defaults to 200 like `maxNodeWidth`. It defaults to 120, so D287 made those nodes wide and flat where v12 drew them compact (#1174). In the issue's sample, the square node was 238×76 against v12's 160×140 in `default`; it is now 154×113, five lines as in v12 (the height differs by v13's line height).

The 120 is a layout metric (`narrowWrap` in the mindmap's `layout/metrics.ts`). Mindmap does not read `flowchart.wrappingWidth`, so an author who set it in v12 to widen these nodes sets `mindmap.maxNodeWidth` instead.

The resolved config always carries the generated default, so the layout cannot tell an unset `maxNodeWidth` from one set to 200. As in D124, a value equal to the generated default (200) counts as unset: an author who writes exactly `maxNodeWidth: 200` still gets 120 for square, rounded and hexagon nodes, and any other value wraps every shape at it. No schema change.

Amends D287.
