# D689: The shared `lineHops` key is off by default again; replaces D672's default

The shared `lineHops` key defaults to `false`, as D537 (a row in `DECISIONS.md`) had it. D672 turned it on. A render that sets no `lineHops` in any config layer draws crossings plainly, and a document or `initialize()` that sets `lineHops: true`, `arc` or `gap` draws hops as before.

Knut filed it as mermaid-js/mermaid-v13#1191, "Line hops is slow - don't have default on": "Line hops, on by default since #1062, make flowchart rendering 13.7% slower on the 5,000-diagram sample. The other 223 commits on main cost about 0.35%, which is noise." With `lineHops: false` on the same sample the difference was −0.35%. The cost is paid by every diagram that draws edges, crossings or not: the hop step tests every straight run against every other one and parses every edge path again.

The engine defaults stay: `swimlane.lineHops` defaults to `arc` and `elk.lineHops` to `true`. They are v12 parity, since v12 hopped under swimlane and ELK, and #1191 is about the shared default. So a diagram laid out by swimlane or ELK still hops unless the author sets `lineHops: false`. D537's precedence is unchanged, with `false` as its last step: a top-level `lineHops: false` the author set, the engine's key the author set, the top-level key the author set, the engine's default, the shared default.

The rest of D672 stands. The hop step stays part of core, `mermaid` imports it statically, `renderSync` draws hops with nothing to preload, and `lineHops` is no lazy layout name. Moving the step back to a lazy chunk, now that only the swimlane and ELK engines and authors who opt in need it, is an open question for Knut and not part of this decision. D650's merged hops are unchanged.

The fixtures that D672 changed draw as they did before it, apart from those that set `lineHops` themselves. Every fixture about hops sets `lineHops: true` in its front matter. `eventmodeling/nightly-check/layout-line-hops.mmd` relied on the default and now sets it.

Not done here: the faster hop step that #1191 describes as a prototype. It is not committed anywhere, and it is not needed while hops are off by default.

(Knut, 2026-11-23, #1191.)
