# D726: The first gantt section band is derived from `mainBkg` in every classic theme

In `default`, the first section band (`sectionBkgColor`) was `#f9ffec`, the tertiary colour `default` pins, almost the page's white: contrast 1.02:1 against `background`, and 1.14:1 against the third band (#1249). v12's `default` draws `rgba(102, 102, 255, 0.49)` (a lavender, about `#b4b4ff` on white) and never recomputes it. The other classic themes had the same weakness to a lesser degree: `base` 1.04:1 against `background`, `neutral` 1.00:1 against the third band.

The gantt theme table now derives the band for the whole classic family, as the rule of each family under D152 (a diagram package never checks a theme name):

- `families.classic.rules.sectionBkgColor` is `mix(darkenHsl(mainBkg, 10%), black, 18%)`: a small HSL darkening, then 18% black.
- `families.classic.dark.rules.sectionBkgColor` is `darkenHsl(mainBkg, 15%)`, which clamps to `#000000` for `dark`'s `mainBkg` (`#1f2020`). `dark`'s `background` (`#333333`) is lighter than its `mainBkg`, and its done and active bars (`#474949`, `#595c5c`) sit between the two, so the only place a band is 1.2:1 from the page, the bars and the third band alike is below all of them.

The band is checked against what is drawn behind and on it, not only against the page: `background`, the third band (`sectionBkgColor2`, which reads `mainBkg`), `gridColor`, and the done, active and plain bar fills (`doneTaskBkgColor`, `activeTaskBkgColor`, `taskBkgColor`), each at least 1.2:1 in every classic theme. `taskTextOutsideColor` and `titleColor`, the text written on a band, must reach AA (4.5:1) on it. `packages/conformance/src/gantt/theme.spec.ts` checks all of it. An earlier step (16%, `lightenHsl` 18% under `dark`) met only the page and the third band; the grid and the done bars, both `lightgrey`, sat 1.03 to 1.15:1 from the band in `forest`, `neutral` and `base`, and `dark`'s done bar 1.10:1.

Resolved values and ratios (band against `background`, third band, `gridColor`, done, active and plain bar; then the text):

Two constraints pull against each other in the light themes. The band has to be darker than `lightgrey` (`#d3d3d3`), because nothing lighter than the page can be 1.2:1 from both the page and the grid. And `default`'s `taskTextOutsideColor` (`#333333`) needs 4.5:1 on it, which a saturated blue band darker than about `#9090ff` loses, since blue has little luminance. A plain `darkenHsl` step cannot satisfy both `default` (at most 18%) and `base` (about 40% to clear the grid, and then a saturated orange): the mix with black darkens `base` without the saturation. `default` lands at a periwinkle where v12's lavender was lighter.

An author's `sectionBkgColor` still wins in every theme. Because the band reads `mainBkg` now, an author's `mainBkg` moves it in every classic theme (as it already moved the bars and the third band, D657), and `base`'s band no longer follows an author's `tertiaryColor`. The `bandBkg` variable that D656 added for it is no longer read by gantt, so it is removed from core (its vocabulary entry and alias `bnb`, the four pins in `default`, `dark`, `forest` and `neutral`, and the `base` derivation). It is a v13-only name; v12 has none. An author's `themeVariables.bandBkg` is now ignored with no warning, as any unknown theme variable is; `sectionBkgColor` is the variable to set.

**Provisional, pending Knut:** the removal of `bandBkg` from core. It was taken by the spec's project manager overnight so that core's `usedBy` and shared-input checks stay green. The alternative is to keep `bandBkg` in core as a variable no diagram reads, and to change the `usedBy` expectations; switching back costs restoring those lines and the pins.

This amends D656's pin of gantt's `sectionBkgColor` to `bandBkg`, and D541's `DIFFERS` rows: `sectionBkgColor` of `default`, `neutral`, `dark` and `forest` changes value, and `base` gains a row (its band was v12's `#f6f9ff`); the values are those of the table above. `forest` and `base` change too, though #1249 names only `default`, because the rule belongs to the family. The other `DIFFERS` values were reviewed and are unchanged. The override matrix's lists (`theme-overrides.spec.ts`) gain the matching entries under this decision.

Not chosen: v12's literal through a value `default` pins in core (core's theme specs name no gantt variable, D331), and keeping `bandBkg` and listing the difference.
