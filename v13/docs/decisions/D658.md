# D658: From the 13.0 release, v13's own output is the reference, and v12 leaves the tests

Until 13.0 is released, `mermaid@12` is the oracle: it decides what syntax is accepted and what it means, and the theme values v13 matches (D15, D151). From the 13.0 release, v13's own output is the reference, in every area: syntax, parse results, layout values and theme values.

At that release, each spec that compares with v12 is rebased on v13's output. Its list of differences from v12 folds into the expected values and is deleted. After that a change to an expected value is reviewed like any other change to output, and needs a decision when it is on purpose. `mermaid@12` is then removed from `packages/conformance` (R-ARCH-9 already keeps v12's sources out of the tree).

Until then, specs that compare with v12 should be able to run without it installed, by keeping v12's values as literals in the spec (D654 for theme values). Moving the other conformance specs off a live v12 is planned in #1044.

Rejected: keeping v12 as the oracle after the release, which keeps a second, older Mermaid installed and consulted for years; and recording the change for theme values only, which would leave each area to decide the same question again.

(Knut, 2026-11-19, spec #1035.)
