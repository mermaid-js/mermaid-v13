# D690: A misspelt colour is ignored wherever an author gives one

A colour that CSS does not know (`redd`, `#12345`, `red blue`) is dropped with a warning, and the theme's or the default colour is drawn, where an author gives it outside a style statement too: a sequence `rect`, the journey, sankey and railroad config colours, legacy C4's `Update…Style` arguments, boundary colours and `c4` config colours, and a colour, palette entry or palette list in `themeVariables`. The warnings are those each path already had (`STYLE_VALUE_DROPPED`, `SANKEY_COLOR_INVALID`, `RAILROAD_CONFIG_INVALID`, `C4_COLOR_INVALID`, `THEME_VARIABLE_DROPPED`). #1197 did the same for `style`, `classDef`, `linkStyle` and `todayMarker`.

- Core's check of an author's colour is `checkCssColor`. `checkColor`, which takes any word, is unchanged: theme rules are told from colours with it, and a formula whose `\color` it refused would be shown as TeX.
- Legacy C4 colours change, which amends D635's "Legacy C4's `UpdateElementStyle` values are unchanged". A colour CSS knows is drawn as before.
- v12 wrote a misspelt colour of a `rect`, a journey, a sankey, or a legacy C4 boundary or relation into an SVG attribute, where a browser falls back to the inherited paint: the dark text colour for a fill, usually nothing for a stroke. v13 differs on purpose.
- A refused entry of `journey.actorColours` or `sectionColours` keeps its place: that actor is drawn in the built-in colour of its slot, that section's names in `textColor`, and the other entries stay where they were written (they moved up before). Amends D225 and D249.
- One refused entry of a palette list still drops the whole list (D545), and a refused `sankey.nodeColors` entry still counts as not listed.

(Knut, 2026-11-24, #1195.)
