# D770: The reference implementation is credited in the layered engine's header only

v13's code that was ported from, or based on, the reference implementation, Pele (https://github.com/obsidianmd/pele), no longer carries its attribution file by file. The one credit kept is the header of `packages/core/src/layout/layered/index.ts`, which names it, its repository, the MIT License and the copyright holder. This amends D12 ("porting the reference implementation's code allowed with MIT attribution (THIRD_PARTY_NOTICES + headers)") and R-REL-4, which required that attribution in every ported file's header and in each package's `THIRD_PARTY_NOTICES`.

So:

- `pnpm check:licenses` (`tools/release/src/licenses.ts`) no longer knows the reference implementation as an upstream: no header is checked for its credit, no notices file must hold its text, and `packages/core/src/svg/url.ts` must credit only `@braintree/sanitize-url`. Every other upstream (`@braintree/sanitize-url`, `@iconify/utils`, the d3 packages and the venn diagram's solver) is checked as before.
- The diagram packages' `workspace.yaml` files list no credits for it.
- Its sections of `THIRD_PARTY_NOTICES` are removed. Core and mermaid keep their notices for their other upstreams; agentflow, c4, flowchart, gantt and shared, whose notices held it only, ship none.
- Source headers drop its repository link, licence, copyright holder and pointer to the notices.

The bench keeps comparing v13 with the reference implementation's published package, which it calls the compare renderer (D205, R-PERF-10); that is a dependency of the private bench package, not ported code.

This decision was first written as D749, which mermaid-v13 gave to another decision before this one merged.
