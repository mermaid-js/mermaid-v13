# D770: Pele is credited in the layered engine's header only

v13's code that was ported from, or based on, Pele (https://github.com/obsidianmd/pele) no longer carries Pele's attribution file by file. The one credit kept is the header of `packages/core/src/layout/layered/index.ts`, which names Pele, its repository, the MIT License and the copyright holder. This amends D12 ("porting Pele code allowed with MIT attribution (THIRD_PARTY_NOTICES + headers)") and R-REL-4, which required that attribution in every ported file's header and in each package's `THIRD_PARTY_NOTICES`.

So:

- `pnpm check:licenses` (`tools/release/src/licenses.ts`) no longer knows Pele as an upstream: no header is checked for Pele's credit, no notices file must hold Pele's text, and `packages/core/src/svg/url.ts` must credit only `@braintree/sanitize-url`. Every other upstream (`@braintree/sanitize-url`, `@iconify/utils`, the d3 packages and the venn diagram's solver) is checked as before.
- The diagram packages' `workspace.yaml` files list no Pele credits.
- The Pele sections of `THIRD_PARTY_NOTICES` are removed. Core and mermaid keep their notices for their other upstreams; agentflow, c4, flowchart, gantt and shared, whose notices held Pele only, ship none.
- Source headers drop Pele's repository link, licence, copyright holder and pointer to the notices. Where a header says which Pele file a port follows, that note stays until the naming cleanup of #1372 rewords it.

The bench keeps comparing v13 with Pele's published package (D205, R-PERF-10); that is a dependency of the private bench package, not ported code.
