# D749: Xychart data labels take a dark ink inside the bars in the dark redux and neo themes, and labels outside the bars get their own colour; amends D333(b)

**Inside the bars.** In the dark redux themes (`redux-dark`, `redux-dark-color`) and in `neo-dark`, `xyChartDataLabelColor` is `contrast(slot(xyChartPlotColorPalette, 0, plotColorArray0), canvasTextColor, #131300)`. The labels keep the canvas text where it reads on the first bar colour; otherwise they take `#131300`, the dark ink v12 drew there. The first bar colour is the author's own: the first colour of their `xyChart.plotColorPalette` (or `xyChartPlotColorPalette`) when they set one, else the theme's first chart colour. So a dark custom palette gets the light canvas text inside its bars, and a light one keeps `#131300`. The rule is in the xychart theme table, under the `redux` and `neo` families' `dark` entries, so no code checks a theme name (D152). All three themes draw the shared palette `BASE_PLOT` there. `#131300` reaches AA contrast (4.5:1) on every one of its ten colours: 5.5:1 on the darkest, `#738FA7`. Before this decision the labels took the theme's `primaryTextColor` `#e0dfdf` (D333(b)), which is 1.0–1.5:1 on the light bars, so they could not be read (#1314).

**Core `slot()` takes a table's palette.** For that rule, the theme rule function `slot(<palette>, <n>, <fallback>)` (D474) accepts a diagram table's own `palette` variable as well as a shared palette. It reads the palette as `palette()` does (D545): the author's list of the table variable when set, else the shared palette its rule names. The fallback is read when that list is empty. This is in `packages/core/src/theme/theme.ts` (`paletteOf`).

**Known limit: one ink per chart.** The rule reads only the first bar colour. A chart with several bar plots draws each later plot in its own palette slot, and its labels take the same ink as the first plot's. Where the author's palette mixes dark and light colours, the labels on a later plot may not reach AA. This is Knut's choice of one ink (2026-11-27); a per-plot ink is not part of this decision.

**Outside the bars.** A new theme variable, `xyChartDataLabelOutsideColor` (nested key `xyChart.dataLabelOutsideColor`), colours the labels drawn outside the bars (`showDataLabelOutsideBar`). Those labels sit on the canvas, not on a bar. Its rule in every theme is `ifSet(xyChartDataLabelColor, canvasTextColor)`: an author's `dataLabelColor` when one is set, else the canvas text. The renderer picks the variable by placement (`XyBarPlotLayout.dataLabelsOutside`). This is one choice per chart, not one per bar. In the three dark themes the outside labels keep `#e0dfdf` on the `#333333` canvas (9.5:1).

**Author overrides.** An author's `xyChart.dataLabelColor` (or `xyChartDataLabelColor`) still wins inside the bars. It also colours the outside labels, as it did in v12. `dataLabelOutsideColor` sets only the outside labels.

**Divergence from v12.** v12 drew every data label in one colour, `dataLabelColor`, and fell back to theme-default's `#131300` in these themes. Inside the bars v13 now matches v12 again. Outside the bars v13 draws the canvas text where v12 drew `#131300` on the dark canvas (1.5:1). In the dark themes, an author's dark `primaryTextColor` that reads on the first bar is used inside the bars where v12 kept `#131300`, and so is the light canvas text on an author's dark palette. `packages/conformance/src/xychart/theme.spec.ts` lists both differences, and the XY chart section of MIGRATION.md (`v13/docs/migration/330-xy-chart.md`) describes them.

Light themes and `dark` draw exactly what they drew before. A chart with outside labels changes only the alias name of the label colour, not the colour.

Not part of this decision: the size of the labels (#1374).

(Knut, 2026-11-27, spec #1341 T5: one ink in the table, contrast(plotColorArray0, canvasTextColor, #131300); a second variable for outside labels, picked by placement in paint.ts and render.ts.)

(Knut, 2026-11-27, amended: inside ink follows the author's first palette colour; core `slot()` takes table palettes, with D545's fallback.)
