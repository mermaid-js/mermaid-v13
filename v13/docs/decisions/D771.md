# D771: Closed decisions call Pele the reference implementation; an editorial exception to D636

`DECISIONS.md` and the merged decision files no longer name Pele. Where they did, they now say "the reference implementation", and where a decision is about benchmarking v13 against it (D43, D201, D205–D209 and the note before D200), "the compare renderer", the name the bench gives it. Nothing a decision says changes: every one still decides what it decided, and every citation of it still holds. This amends D636 and the decisions README, under which a merged decision is not edited, for this rewording only.

What the term means is written once, in D770: the reference implementation is Pele (https://github.com/obsidianmd/pele), the program parts of v13 were ported from, credited in the layered engine's header. The code, the living docs, the research and the run notes use the same term (#1372).

So:

- 66 rows of `DECISIONS.md`, its notes before them and the research list in its introduction (the file `research/pele.md` is now `research/reference-implementation.md`), and D682, are reworded. Where Pele named another thing ("the Pele commit", "a Pele port"), the wording follows the sense ("the reference implementation's commit", "a port of the reference implementation").
- Identifiers, versions, paths and URLs inside code spans stay as written.
- D770, the one decision about the credit itself, names Pele once, to say what the term means.

The rule of D636 holds for everything else: a merged decision is replaced by a later one, not edited.
