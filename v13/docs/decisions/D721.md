# D721: Compass separates overlapping straight routes

`compass` routed each edge on its own, so a straight route or a route with one bend could lie on top of another edge, or run through a node it does not end on. In #1176 a junction sat in the cell between two services, and the group edge between their groups ran straight along both junction lines and through the junction. Such a route is now moved apart.

A route runs along another edge when the two lie on one line and run together for longer than a corner, which is a stub (12 px): two edges that leave one port both start with its stub. Edges that share exactly one end may run together from it, as a bundle into or out of that port. Two edges between the same two ports may not, so a repeated edge is drawn apart from the first. Only edges routed earlier count, so the later of two edges moves.

A route that crosses a node other than its ends, or runs along an earlier edge, takes the D720 detour, with those edges as walls as well as the nodes. The detour is kept only if no run of it is then blocked. Among the slides, one that clears the runs beside it as they are comes before a nearer one that has to slide a neighbour as well. Where the detour's first jog lands on the side an end meets, the end moves along that side to take it, so the route leaves the side straight. On a group's border the end may move anywhere along the side. On a node it moves only within the square about where the node's ends meet, `anchorY` above and below the anchor line and as wide (D501): for a service that is its icon, so an end never moves onto the label below it or into the air beside the icon. A straight route is only ever offset this way and stays straight; when no offset clears it, it is drawn as before. In #1176 the group edge runs straight between the two group borders, below the junction. A route with two or more bends is first detoured off nodes as in D720. If it then runs along an earlier edge, it is moved again, and that is kept only when no run of the result is blocked.

Refines D507: a route with at most one bend keeps v12's look only while it runs along no other edge and crosses no node it does not end on. A diagram with no such route is laid out as before.

A facing edge between two nodes in line stays straight (the architecture layout invariants). So when a service sits between them and no offset clears it, the edge still runs through that service.

Confirmed by Knut, 2026-11-27 (two readings taken overnight, spec #1335):

- **#1176 counts as fixed.** Every edge in the repro is visible: the group edge runs on its own, below the junction. The spec's "three visible lines" is not met literally: the junction is not drawn and stays in line between S1 and S4, so its two edges read as one S1 to S4 line. Three lines would need the junction placed off the line, as v12 did. That is a compass placement change, not a routing one, and would take its own decision and move more fixtures.
- **A bundle may run together for any length.** Edges that share exactly one port run together from it (up to 104 px in `architecture/nightly-check/layout-detour-neighbour-blocked.mmd`), read as "no shared run longer than a corner" between edges that are not a bundle. Parting them too would be a follow-up that changes the fan-in fixtures.
