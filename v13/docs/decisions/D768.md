# D768: The swimlane lane body is filled `clusterBkg` in every look

A swimlane lane (`rect.swimlane-body`) is drawn with the lane's cluster fill, `clusterBkg`, as its title band is, in every theme and every look. A palette slot still wins, so the lanes of the `*-color` themes keep their slot fill. Spec #1343 T4, resolving #1217, #1245 and #1316.

- v12 wrote `fill="none"` on the body, but its stylesheet rule `.cluster rect { fill: clusterBkg }` overrode the attribute, so the body was filled in every theme without a lane palette. v13 ported the attribute and not the rule, and drew the lane hollow, invisible on a white page in `neo`. The body fill now equals `clusterBkg` in `default`, `dark`, `forest`, `neutral`, `base`, `redux`, `redux-dark`, `neo` and `neo-dark`. The v12 values are the table in #1245.
- A lane with no palette fill takes `clusterBkg` too, in every theme. That covers the engine's default lane for loose nodes, which has no palette slot, and every lane of `redux-dark-color`, whose slots carry no fill because the theme has no background palette. That is accepted.
- The hand-drawn look hachures the filled body, as the plugin sketches every filled cluster. v12 left its hand-drawn lanes unfilled only as a side effect of the CSS, which did not reach the sketched paths. A diagram package never checks `look` (D152), so the lane code has no hand-drawn branch.
- The author's `style` and `classDef` still win.

This corrects the lane note of D536's migration row and `v13/docs/migration/flowchart-swimlane.md`, which called the body "unfilled" because they followed v12's attribute, not its drawing.
