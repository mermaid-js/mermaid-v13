# D643: `init()`, `getRegisteredDiagramsMetadata()` and the `startOnLoad` property come back as deprecated shims

This amends D32, the list of v12 API members v13 keeps. Three members it did not name are kept, deprecated, on every `mermaid` API object (`createMermaid()` ones too). `init` and `getRegisteredDiagramsMetadata` are also named exports of the module. All three live in the `mermaid` package; core is unchanged.

- `init(config?, nodes?, callback?)` is v12's: it calls `initialize(config)` when `config` is given, then `run()` over `nodes`. `nodes` is a selector (default `.mermaid`), an element, or a list of elements. `callback` is `run()`'s `postRenderCallback`. Like v12's, it returns `run()`'s promise.
- `getRegisteredDiagramsMetadata()` returns `[{ id }]`: v12's `error` and `---`, then the v12 type of every detectable diagram in detection order (first-party, discovered, then registered with `registerExternalDiagrams`). A conformance spec checks that the list is v12 12.2.0's, plus the types only v13 has (`c4beta`). It is synchronous, so a discovered type is listed only after an awaited `preload()` or render.
- `startOnLoad` is a writable property, `true` by default. `contentLoaded()`, which runs on `window` load, runs `run()` only while both the property and the `startOnLoad` config key are on, as v12's did. The CDN loader's stand-in has the property too, and a value set before the module loads is copied onto it.

Each is marked `@deprecated` in the types and points at its replacement: `initialize` and `run`, `detectType` and `supportsFormat`, `initialize({ startOnLoad })`. They do not log a warning: v13 writes nothing to the console (R-ERR-4). They exist so that a page written for v12 keeps working when it moves to v13 without changes (R-COMPAT-10); `mermaid.init()` is still common in old pages and tutorials.

Rejected: recording the removals in MIGRATION with their replacements, which would leave such a page with a `TypeError` on upgrade (#764).

(Knut, 2026-11-19, spec #988, #764.)
