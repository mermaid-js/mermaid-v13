# D712: Kanban reads Markdown only in markdown strings

Kanban labels follow the label rule of D710. This amends D372, which laid out every label with `markdown: true`.

- **The rule, for all four label kinds.** Column titles, card titles, tickets and assignees are read alike. A label wholly in backticks, with or without double quotes (`` ["`**bold** card`"] ``, `` assigned: '`**md**`' ``), is a markdown string, laid out as Markdown without its wrapper. Any other label is plain: `<br>` and raw line breaks break the line, the drawn tags (`<b>`, `<i>`, `<u>`, `<s>`, `<sub>`, `<sup>` and their aliases) draw their formatting, entities decode, and math and `fa:` icons work as before. Markdown syntax in a plain label is drawn as written.
- **The model marks a markdown string.** The parser hands a shape's markdown string on without its wrapper, as v12's grammar did, so the model's `label` keeps v12's value. A new field, `markdown: true`, says the label was one; a `label` from `@{ … }` data replaces it and the mark with it. The layout input carries such a label in backticks again, so the layout reads every label with core's `markdownString`.
- **Text output** draws the measured text, so it follows the same rule; `ASCII_DROPPED` for emphasis is given for whatever the label draws bold or italic, from a tag or a markdown string.

What v12 did: it set every label to Markdown (`labelType: 'markdown'` for titles, `createText`'s default for tickets and assignees), and its converter drew only paragraphs, `**bold**` and `*italic*`; anything else it gave back as written. So ``Use `npm ci` first``, `- not a list` and `1. not a list` drew as written in v12, and v13 under D372 drew them as inline code and list items (#1230). They draw as written again, which is parity. `**bold**` and `*italic*` without backticks drew bold and italic in v12 and now stay as written: that is the deliberate break D710 makes, listed in MIGRATION.md. Existing boards that relied on it wrap the label in `` "`…`" ``.
