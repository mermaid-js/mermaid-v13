# D767: Use case include and extend arrowheads take their line colour

An include or extend relationship's arrowhead is drawn in the colour of its line: `usecaseIncludeLine` for include, `usecaseExtendLine` for extend. An author's own stroke on the edge (`style`, `classDef`) still wins over both. Generalization and association heads do not change: they stay in the edge line colour (`lineColor`). This is a deliberate divergence from v12, which filled every `.marker` with `lineColor`, so that in `redux-color` the head and the line it ended differed (#1227).

The line already took its colour from the same variables, and the edge label's border already follows the line (D627). The head now does too.

Recorded in the migration row in `v13/docs/migration/usecase.md`. It is a rendering difference with no parse divergence, so `packages/conformance/divergences/` has no entry for it.

(Knut, 2026-11-27, spec #1343 T3, #1227.)
