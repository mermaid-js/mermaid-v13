# D742: Kanban reads `accTitle` and `accDescr`

`accTitle: …`, `accDescr: …` and the block form `accDescr { … }` are kanban statements. They set the SVG's `<title>` and `<desc>`, referenced by `aria-labelledby` and `aria-describedby` as in the other types (D29, R-A11Y-1), and draw no column or card. v12's kanban grammar had no such statements: it drew each line as an item, and rejected the `{` of the block form (#1300). This is a deliberate divergence from v12.

- A line is a statement only when, after blanks, it starts with the keyword followed by `:` (blanks allowed before it) or, for `accDescr`, by `{` on the same line. A line starts after a line break (`\n`, as the grammar file's `(?<=^|\n)`), not after U+2028 or U+2029. `accTitle[x]`, a bare `accTitle` or `accDescr`, `accTitleX: y` and a keyword after other text on its line stay items, as in v12.
- The keywords are read without regard to case, as kanban's lexer reads every keyword (jison's `case-insensitive`), and as v12's jison types read theirs.
- `accTitle: …` and `accDescr: …` take the rest of the line, whatever it holds (`[`, `(`, `@{`, `}`). The block runs to the first `}`, as in the other types; one with no `}` runs to the end of the text and is an error (`UNCLOSED_DESCRIPTION`).
- They may stand on any line before or between columns, at any indent. They are not items, so they set no column level and move no card to another column. Their statement spans are top-level ones, never inside the column span open around them (outline and folding).
- A later statement replaces an earlier one, as in the other types. An empty value sets an empty title or description, which the root does not write.
- The AST has an `AccTitle` or `AccDescr` node for each (`accTitle:1`, `accDescr:1`, …); completions offer both keywords where a statement may start, and hover shows their docs on the keyword (not on the value).
- Highlighting: TextMate and Monaco read them as the lexer does. CodeMirror's generated tokenizer runs each rule on the text from the cursor, so it cannot see the line start, and also highlights an `accTitle: …` that follows a shape on its line (`todo[x] accTitle: y`) as the keyword. That is a known limit of the generator, not of the grammar (#1409).
- Text output drops them with one `ASCII_DROPPED` warning (`accessibility`), naming the statements (D82).

The lexer is the shared indentation-tree lexer, so the statements are an opt-in of it, as shape data is: a diagram whose kind table names `AccTitle` and `AccDescr` gets them, and mindmap does not. The scans stay linear (R-PARSE-7).

Files outside the spec's list, approved for this ticket: `packages/shared/src/parser/tree-lexer.ts`, `tree-parser.ts` and `tree-facet.ts`; kanban's `facet/hover.ts` and `ascii/warnings.ts` (with `ascii.ts`), which use the shared `droppedFeatures`; the grammar file `packages/diagram-kanban/grammar/kanban.ebnf` and what `pnpm regen` builds from it (`grammar/generated/*`, `src/generated/{categories,docs}.ts`, `v13/docs/syntax/kanban.md`, the CodeMirror and Monaco copies); the kanban completion golden of `packages/language-service`; and `packages/bench/src/core-chunks.spec.ts`. Kanban reuses `@mermaid-js/shared/parser/common-values` for the values, so esbuild gives that file a chunk of its own, which kanban and the langium-ported types load (until now it was part of the rule chunk). Core and the loaded size do not change. The kanban closure grows by about 1.2 KB gzip, mindmap's by about 250 B, and each langium-ported type's by about 200 B, for the extra chunk.

Divergence entries are in `packages/conformance/divergences/kanban.json`, and the migration row in `v13/docs/migration/220-kanban.md`. The lexer and grammar gates still compare every token: v12 lexes and parses each source with its acc statements replaced by a placeholder item, which v13's acc token stands for (`packages/conformance/src/kanban/acc-divergence.ts`), and on the source as written v12 must have read an item where v13 reads the first acc statement.
