# D696: `html.labels` is the HTML labels plugin's key; v12's `htmlLabels` keys alias to it

`@mermaid-js/plugin-html-labels` owns the config key `html.labels` (boolean). Its default is `true`: registering the plugin turns HTML labels on, as v12 drew flowchart labels by default. v12's `htmlLabels`, `flowchart.htmlLabels` and `class.htmlLabels` alias to it (D153), so `htmlLabels: false` turns HTML labels off as in v12. An alias is not per diagram type: `flowchart.htmlLabels: false` turns them off whatever type is drawn. Class diagrams, which v12 drew with SVG labels by default, get HTML labels when the plugin is registered.

In core's schema those three keys stay `removed`: without the plugin they warn `CONFIG_REMOVED_KEY` and have no effect, and the warning's replacement points to the HTML labels plugin. Core's schema does not name the package, since core never names an optional package (D153). This amends D22 for these keys.

Diagram text can set the key, as in v12. An integrator who wants sole control lists `html` in `secure`: diagram text that sets `html.labels`, or one of v12's keys, then warns `CONFIG_SECURE_KEY` and changes nothing.

(Knut, 2026-11-26, spec #1278.)
