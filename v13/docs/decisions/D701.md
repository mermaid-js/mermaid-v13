# D701: Verdicts on the extension API gaps left open after #1281

Spec #1281 closed three of the eleven gaps in `v13/docs/plugin-api-gaps.md` (D699, D700 and the authoring guide). The others stay open, for these reasons. The byte counts are estimates, not measurements.

- **A plugin cannot supply a measurer: rejected.** The measurer decides every size in a diagram, so it is the integrator's (`RenderOptions.measurer`, `deterministic`), and two extensions could not both supply one. An extension sizes its own output through the label provider (D695) and inline boxes (D177).
- **Providers do not compose, and a covering span silences core's warnings: deferred.** Knut kept D697: a label with math or an icon stays an SVG label, so the HTML labels plugin declines it and nothing needs composition yet. A request method that boxes a string's inline spans for a whole-label provider was built and measured at about 20 B in core, then taken out.
- **No render-end or unmount hook: deferred** until a second extension needs one. An extension can remove what it added in a microtask, because a draw is synchronous. About 60 to 90 B in core.
- **No plugin-owned `data-*` attribute: deferred, and Knut's call.** A reserved prefix widens the allow-list of R-SEC-2. About 60 to 100 B in core.
- **A plugin's config key cannot be integrator-only by default: deferred** until a plugin has such a key. `html.labels` may be set from diagram text (D696), and `secure` works for an integrator who wants otherwise.
- **`postRender` switches the render to the tree writer: deferred.** A read-only hook over a streamed document needs a design first.
- **Label hooks do not reach every diagram: deferred to each diagram type's tickets.** It is a gap in those renderers, not in the API.
- **The hook context for inline and glyph providers: deferred** until a provider needs the config or its own state. About 100 B in core.
