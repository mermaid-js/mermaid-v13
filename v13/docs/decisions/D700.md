# D700: `mermaid` names the HTML labels package in the warning for a removed `htmlLabels` key

`CONFIG_REMOVED_KEY` for `htmlLabels`, `flowchart.htmlLabels` and `class.htmlLabels` ends with "For HTML labels, register @mermaid-js/plugin-html-labels." while no registered config fragment declares the key `html`. The `mermaid` package adds the sentence, as it does for `LOOK_REMOVED` and `ELK_NOT_INSTALLED` (D173). Core's schema still says only "the HTML labels plugin" (D696), because core never names an optional package (D153).

A config fragment cannot carry this hint: it is needed exactly when the plugin, and so its fragment, is not registered. A table in core that maps removed keys to packages would break D153. So a first-party plugin that takes over a removed core key adds its hint to `hint()` in `packages/mermaid/src/errors.ts`.

`mermaid` grows by about 50 B gzipped for this.
