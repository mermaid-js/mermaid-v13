# D717: Layered cycle breaking starts from the sources

The layered layout breaks a cycle by a depth-first search and reverses the edges that close it. The search now starts from the sources, the nodes with no incoming edge once the port pre-pass has turned edges into start ports and out of end ports. The sources are taken in the order their first edge was written. Then the search starts from every node not yet reached, in declaration order. Before, it started from every node in declaration order, so a node declared before the edges that reach it, such as `state check <<choice>>` or `state "…" as check`, became the top of its cycle and the drawing read from the bottom up (#1215).

This holds for every type that uses the layered layout, and for each level of a compound graph, since both call the same `orient`. A cycle with no source is oriented as before, from its node declared first. An acyclic graph has no edge to reverse, whatever the order of the roots, so its layout is unchanged.

The sources are taken in the order of their first edge, not of their own declaration. A state diagram often declares its composite states before any transition, so a source declared early, such as a state with one edge into the middle of a cycle, would be searched before the start state `[*]`, and the start would be drawn at the bottom. That happened to `state-diagram-v2/pr-check/should-render-edge-labels-correctly-with-multiple-transitions.mmd` when the sources were taken in declaration order.

Not chosen: a greedy feedback arc set, as ELK uses. It changes the output of more cyclic graphs. D127 is unchanged: it chooses the engine for state diagrams, not this result. v12 with `layout: dagre` flips the #1215 sample the same way v13 did; v12's default for state, ELK, draws it from the top down, as v13 now does.
