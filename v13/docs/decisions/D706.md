# D706: `checkStyle` joins a style value that the parser split at a comma

The `style`, `classDef` and `linkStyle` parsers split a statement on every comma, as v12 did, so `fill:rgb(255, 200, 200)` arrives as `fill:rgb(255`, `200` and `200)`. `checkStyle` now joins the pieces back before it checks them. A piece with no `:` is joined onto the piece before it, with `, ` between them, when that piece has a parenthesis still open (`rgb(`, `hsl(`, `var(`) or is a `font-family` declaration. So `fill:rgb(255, 200, 200)` draws that fill and `font-family:Georgia, "Times New Roman", serif` keeps the whole list, with no warning. The join is the same whether or not the parser trimmed the pieces, so the same source gives the same value in every type.

A piece that has a `:` always starts a new declaration, even after an unclosed parenthesis, so a typo such as `fill:rgb(1,2,stroke:red` drops only the bad fill. A piece with no `:` that follows neither an open parenthesis nor a font list is still dropped with `STYLE_PROPERTY_DROPPED`, as before. A single declaration passed whole (a theme or config font list) is unchanged.

This differs from v12. v12 joined the pieces with `;` into a CSS string, so `rgb(255;200;200)` was not a colour and the fill was lost, and a font list kept only its first name. Both happened without a warning (#1312). The fix is in core, so every type that splits on commas and checks with `checkStyle` gets it: state, class, flowchart, and the others that do the same. The parsers do not change, so syntax that v12 rejects is still rejected: flowchart's `style` takes no parentheses at all, so there `rgb()` is still a parse error and only the font list part applies.

The other option was to keep v12's drawing and give one warning per declaration saying that a comma ended the value. It was not chosen: authors write `rgb(…, …)` and font lists expecting them to work, and joining them fixes this without new syntax.
