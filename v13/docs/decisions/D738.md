# D738: Quadrant fills 2–4 derive from the input fill 1 derives from, not from `quadrant1Fill`; amends D232

`quadrant2Fill`, `quadrant3Fill` and `quadrant4Fill` are v12's per-channel `adjust()` offsets (+5, +10, +15) of the colour `quadrant1Fill`'s default derives from, not of `quadrant1Fill` itself (`packages/diagram-quadrant/src/theme/table.ts`):

| Themes | Input of all four fills |
| --- | --- |
| classic themes and `base` | `canvasItemBkg` |
| `redux`, `redux-color`, `neo` | `#ececfe` |
| `redux-dark`, `redux-dark-color`, `neo-dark` | `primaryColor` |

D232 derived fills 2–4 from `quadrant1Fill`, so an author who set `quadrant1Fill` alone recoloured all four quadrants into near-identical shades (#1265). v12 derived 2–4 from `primaryColor` (or `#ECECFE`), so only quadrant 1 changed. Now v13 does the same in every theme.

With no override, every resolved colour is unchanged in all eleven themes. The SVG root `style` changes text: fills 2–4 read `var(--_cvi)` (`canvasItemBkg`), the literal or `var(--_p)` instead of `var(--_q1f)`. A host that sets `--mermaid-quadrant1Fill` in CSS now moves only quadrant 1 as well. A user `primaryColor`, the `default` theme's constructor behaviour (D656) and explicit `quadrantNFill` values match v12, as before.

D232's `adjust()` in core's theme DSL stays.

(Knut, 2026-11-27, spec #1341 T7: accepted as proposed.)
