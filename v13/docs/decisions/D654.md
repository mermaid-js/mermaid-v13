# D654: Diagram variables are compared with v12 under one override at a time, against v12 values written in the specs; extends D568

D568 compares core's shared variables with v12 under overrides and leaves diagram variables to their own specs, which compare them only with no override. From now on every first-party diagram theme table is compared under the same matrix as D568: the five classic themes, no override, each of `primaryColor`, `secondaryColor`, `tertiaryColor`, `background`, `primaryTextColor`, `lineColor` and `mainBkg` set alone to a light and a dark test colour, and `darkMode`. Colours only, as exact hex (D71).

Two checks, chosen by how the variable compares with no override:

- Where v13 and v12 give the same value with no override, the values must be the same under every override.
- Where they differ with no override (a difference the type's own spec already lists), only the response is compared: the value must change under exactly the overrides that change v12's value.

v12's values are literals in the specs, not loaded from `mermaid@12` when the tests run. Each type has `packages/conformance/src/<type>/theme-overrides.spec.ts` with, per classic theme, each variable's v12 value with no override and only the overrides that change it, with the value they change it to. An override a variable does not list must leave it unchanged. The type's list of differences sits in the same file, grouped under the decision that accounts for them, as D568 requires. D568's own spec, `theme-overrides.spec.ts`, moves to the same form and stops loading v12. The matrix and the comparison are one shared module, where D568's `PROBES` becomes `TEST_COLOURS`, because "probe" is already a term of the language service. A capture tool in `packages/conformance`, run by hand and not part of `pnpm regen`, prints a type's table from v12 for pasting; at 13.0 it prints v13's values instead (D658).

Rejected: loading v12 live, as D568 does, which keeps v12 installed for as long as the spec exists; a generated file of all values, which is no easier to review than the literals and invites a quiet refresh; and the full matrix as literals (about 13,300 values for the diagram variables, against about 1,700 in this form).

(Knut, 2026-11-19, spec #1035.)
