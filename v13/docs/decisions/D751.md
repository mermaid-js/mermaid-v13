# D751: An ER entity with no attributes wraps its name at the new `er.wrappingWidth`

v12 drew an ER entity with no attributes with `drawRect`, whose HTML label wrapped at `flowchart.wrappingWidth` (120 by default). An entity with attributes (`erBox`) kept its name on one line. v13 drew every name on one line (#1226).

- **The key.** A new ER setting, `er.wrappingWidth`, a number in px, default 120. The name of an entity with no attributes wraps at it. ER does not read `flowchart.wrappingWidth`, so an author who set that key for ER sets `er.wrappingWidth` instead (MIGRATION.md).
- **Where a line breaks.** Between words and after a hyphen between letters, never inside a word (`layoutLabel`'s `keepWords`). A word wider than the width stays whole and widens the box. This is what v12's browser did for names such as `DELIVERY-ADDRESS` (`DELIVERY-` / `ADDRESS`) and a 24px bold `CUSTOMER` (one 137 px line), measured against mermaid 12.2.0 in Chromium.
- **Not covered.** The browser also breaks after some other punctuation (UAX #14), for example after `€` and `…`. Core does not, so a name with no space and no letter hyphen stays on one line. That is a core follow-up for every diagram type.
- **Entities with attributes** keep their name on one line, as in v12.
- **Text output.** In cells the default gives the cell profile's own wrap width (`builder.wrapWidth`); a value the author set converts from px, and a value equal to the default counts as not set (D124).

(Knut, 2026-11-27, spec #1342, #1226.)
