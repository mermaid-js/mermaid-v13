# D676: The core-chunks spec follows the rule-chunk layout

Ticket #1066 (spec #1065, PR #1119) moved architecture and railroad onto the shared `RuleLexer` and `RuleParser`. Every langium-family diagram now loads the same shared parser modules, so esbuild merges `@mermaid-js/shared/parser/common-values` into the lazy rule chunk, and `shared/parser/support.ts` into the lazy parser-kit chunk. The real build has one chunk fewer: loaded −180 B, core +4 B, no fixture changes. No change to the code kept the old split: architecture and railroad were the only diagrams that reached those modules without the rest of the rule family. Two expectations in `packages/bench/src/core-chunks.spec.ts` changed to match.

- **#818 (D559):** the value readers no longer sit in a chunk of their own. The test still guards what #818 is for: `common-values` is in neither core nor any eager chunk, its chunk holds only the rule family, and only the langium entries load it.
- **Stub growth:** the "parser-kit only" stub's loaded growth has its own allowance, `PARSER_KIT_LOADED_ALLOWANCE = 240` B (measured 215 B), because a stub that imports only the parser kit splits the merged chunk again. Every other stub keeps `ROW_ALLOWANCE = 64` B.

No other gate or limit changed.
