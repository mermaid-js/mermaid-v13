# D748: All bar plots of an xychart take one data-label size; extends D611

With `showDataLabel`, the fitted size of every bar's data label is computed first, over every bar of every bar plot of the chart. Then one size is used for all bar plots: the smallest fitted size among the bars that have room (D611). A bar with no room still gets no label. `XYCHART_LABEL_TOO_SMALL` is raised only when no bar of the whole chart gets a label, and it names every bar plot with bars.

Before, each bar plot was sized on its own (D611 took the minimum inside one plot), so one chart could show its first plot's numbers at about 20 px and its second plot's at 40 px (#1308 F-002, `xychart/baseline/data/many-plots.mmd`). v12 also sized each plot on its own, but it labelled every plot with plot 0's values (D382), so the change of size was less visible there. The warning was raised when any one bar plot had no label; now a chart where one plot has labels gets none.

A chart with one bar plot draws exactly what it drew before.

Not part of this decision: a cap on the label size, collisions with lines and point labels, bars drawn from zero (#1374), and bar plots that overlay one another (#1375).

The xychart layout parity spec (`packages/conformance/src/xychart/layout-parity.spec.ts`) gives v12's per-plot labels the smallest of the plots' sizes before it compares.

(Knut, 2026-11-27, spec #1341 T4: accepted as proposed, no size cap.)
