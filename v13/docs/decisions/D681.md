# D681: An unknown curve name is drawn with the default curve

A `curve` name that is none of the `flowchart.curve` values is drawn with the default curve, `rounded` today, not with S-curves. This holds for the config key (`curve: bogus`) and for a per-edge or default `linkStyle … interpolate bogus`. A per-edge name falls back to the default curve, not to the diagram's own curve. `curveKind` in `@mermaid-js/shared/svg/route` returns `DEFAULT_CURVE`, which a diagram-flowchart spec pins to the schema default of `flowchart.curve`. Class, requirement and agentflow use the same function and follow: an unknown name draws `rounded` in all four. Agentflow with no curve set is unchanged and draws S-curves, since it does not read the `flowchart.curve` default; that is ticket B9 (#1181). The `CURVE_UNKNOWN` warning stays, once per name and render, and its text names the curve drawn.

This replaces the fallback clause of D602 ("the edge is drawn `curved` as before"). The rest of D602 stands. It is a divergence from v12, which drew an unknown name as `basis`. In v12 that fallback was also the default curve, and v13 changed the default to `rounded` without changing the fallback. The divergence is recorded here and in MIGRATION.md, not in `packages/conformance/divergences/`: those lists hold parser parity only (`accept`, `reject`, `model`), and the parse of an unknown name is the same as v12's.

(Knut, 2026-11-23, spec #1163, decision 10, #1158.)
