# D667: Three gantt variables keep v13's response to an override where v12's would move a value with no override; within D656

D656 has each diagram variable respond to an override of a base colour as v12's does. Three gantt variables already differ from v12 with no override (D574), and matching v12's response would move their value with no override too, which spec #1035 rules out:

- `neutral`'s `doneTaskBorderColor`: v12 follows `lineColor` there only (`#666666`); v13 keeps `grey` in every theme, so it stays grey under a `lineColor` override.
- `dark`'s `altSectionBkgColor`: v12 follows `background` (`#333333`); v13 keeps `white`, the alternate band of every theme, under a `background` override.
- `dark`'s `doneTaskBkgColor`: v12 keeps `lightgrey`; v13 takes the dark rule, `mainBkg` lightened (v12's `secondBkg`), so it follows a `mainBkg` override.

v13 keeps its own response for these three. The gantt override spec lists them under this decision and MIGRATION.md (gantt Themes) says what an author sets for v12's colours. They are revisited with gantt's colours with no override, not under D656.

Rejected: reading `lineColor` and `background` there, or pinning a dark value for the done fill, which would change gantt's colours with no override in `neutral` and `dark`.

(Knut, 2026-11-19, spec #1035, #1041.)
