# D663: Mindmap draws the bar under a plain node in every classic theme; v12's zero width in four of them is a listed difference

v12's `mindmap/styles.ts` draws the bar under a plain node (`line.node-line-<n>`, in `cScaleInv<n>`) 3 px wide. Its `genGradient` then writes `stroke-width: 0` for the same lines whenever `useGradient` is set, and that rule is not limited to `look: neo`. v12's `base`, `dark` and `forest` set `useGradient = true` in their constructors and `neutral` resolves to true as well (`base` turns it off again when `nodeBorder` is overridden), so v12 draws the bar only in `default`. That is so with and without an override (#1042 findings, row 3).

v13's classic themes set `useGradient: false`, because in v13 it turns on gradient outlines, which v12 draws only under neo (D182). `diagram-mindmap/src/render/paint.ts` draws the bar unless there is a gradient, so v13 draws it in all five classic themes. This decision keeps that, and records the difference from v12 in MIGRATION.md's Mindmap SVG structure section. A host that wants v12's look in those four themes can set `stroke-width: 0` on the bars in its own CSS, which beats the presentation attribute.

Rejected: a new shared theme flag, pinned off in `base`, `dark`, `forest` and `neutral` as v12's `useGradient` is, with mindmap drawing the bar only when it is on. A diagram table can key only on family and the `dark` trait (D331), which cannot tell `default` from the other four; turning `useGradient` on in their specs would put gradient outlines on every diagram type; and a theme spec may not name a mindmap variable (D331). The flag would be new core vocabulary written in four theme specs, for one rule that v12 reached as a side effect of its gradient.

(Knut, 2026-11-19, spec #1035, #1042.)
