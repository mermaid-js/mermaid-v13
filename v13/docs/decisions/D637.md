# D637: A PR runs only the unit tests its change can reach

On a PR that changes only TypeScript source inside packages (`packages/*/src/**/*.ts`), with or without documentation and changesets beside it, the unit shards run the test files the change can reach, not all of them: the files vitest finds affected through the import graph (`vitest list --changed`), and every spec that reads the tree without importing it (it scans a folder or names a path into a `src` tree). The `Scope` job decides this (`tools/ci/scope.ts`) and lists the files.

Documentation and changesets are not in the import graph, so the tests that depend on them are found by name: the code that names a changed docs file, or the changesets folder, has its tests run by the `docs-tests` job, as in a docs-only run.

Any other changed file runs every test: a fixture, a JSON file, a snapshot, a manifest, a config, a workflow. Tests read those from disk, and no rule yet says which. So does a failure to list the affected tests or to search for readers.

Every push to `mermaid-v13` runs every test. That is what makes the PR rule safe: a test a PR wrongly left out fails on the push, minutes after the merge. The required check `Check and build` therefore passes on a PR without every unit test having run; this is accepted.

`pnpm exec tsx tools/ci/replay-cli.ts` reports how many merged PRs each rule would have covered. The rule is narrow on purpose and is widened from those numbers: source alone covered 10% of the PRs merged 2026-11-02 to 2026-11-19, and with documentation and changesets about 20%.

(Knut, 2026-11-19.)
