# D637: A PR runs only the unit tests its change can reach

On a PR that changes only TypeScript source inside packages (`packages/*/src/**/*.ts`), the unit shards run the test files the change can reach, not all of them: the files vitest finds affected through the import graph (`vitest list --changed`), and every spec that reads the tree without importing it (it scans a folder or names a path into a `src` tree). The `Scope` job decides this (`tools/ci/scope.ts`) and lists the files.

Any other changed file runs every test: a fixture, a JSON file, a snapshot, a manifest, a config, a workflow. Tests read those from disk, and the import graph does not see that. So does a failure to list the affected tests.

Every push to `mermaid-v13` runs every test. That is what makes the PR rule safe: a test a PR wrongly left out fails on the push, minutes after the merge. The required check `Check and build` therefore passes on a PR without every unit test having run; this is accepted.

`pnpm exec tsx tools/ci/replay-cli.ts` reports how many merged PRs each rule would have covered. The rule starts narrow on purpose and is widened from those numbers.

(Knut, 2026-11-19.)
