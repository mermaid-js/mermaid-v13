# D710: One label rule for every diagram type

A label's text means the same in every diagram type. The rule:

- **Tags.** `<br>` breaks the line. `<b>`/`<strong>` draw bold and `<i>`/`<em>` italic, as before (D566). New: `<u>` and `<ins>` underline; `<s>`, `<strike>` and `<del>` strike through; `<sub>` and `<sup>` draw sub- and superscript. Underline and strike-through together are drawn as `text-decoration="underline line-through"`, a value the SVG allow-list now takes. The drawn tags work in every mode of `layoutLabel` (D562) and give no `HTML_DROPPED`; every other HTML tag is still dropped with its text kept and the warning (D566).
- **Sub- and superscript** are drawn at the size they are measured at, the font size divided by 1.2 (`SMALLER`), and moved with `dy`: 0.3 em down for `<sub>`, 0.4 em up for `<sup>`, in the label's font size. The next run moves back. A line's height and the label's box do not change. The size and the shift are in the run's `attrs`, so a renderer with a fast path for plain runs hands such a run to the writer. Text output draws the text plainly.
- **Markdown only in a markdown string.** A whole label in backticks, with or without double quotes around them (`` "`…`" `` or `` `…` ``), is a markdown string and is laid out in the `markdown` mode without its wrapper. A label whose text inside the outer backticks holds another backtick is not a markdown string: `` `npm` or `pnpm` `` is plain and draws its backticks as written, in both forms. Confirmed by Knut, 2026-11-27. Any other label is plain: tags, `<br>` and character references (D709), no Markdown. This holds also where v12 read Markdown in a label without backticks. It is a deliberate break with v12, listed in MIGRATION.md.
- **One helper.** `markdownString(label)` of `@mermaid-js/core/text` recognises a markdown string and returns `{ text, markup }`: the text without its wrapper and `markdown`, or the label as written and `plain`. A diagram package calls it and does not keep its own copy; pie moves onto it (its regular expression was the rule).
- **Railroad** keeps terminals and rule and non-terminal names literal, as gitGraph keeps its identifiers (D268); its comments, title and `? … ?` special sequences follow the rule.

**Railroad tokens are literal** (follow-up of spec #1333, first mate, 2026-11-27). Terminals, non-terminals, rule names and PEG predicates (`&X`, `!X`, and PEG's `.`) draw exactly as written, in the SVG and in `format: 'ascii'`: no tags, no Markdown, and no decoding of a reference typed with `&` (`&lt;` stays `&lt;`), as v12's `.text()` drew them. A Mermaid code (`#lt;`, `#35;`) is the author's way to write a character, so it is still drawn as that character, as v12 drew it. The parsers read these tokens with `displayText` of `@mermaid-js/shared/parser/display-text`, which decodes only the codes (its new `convert` argument runs the string's unquoting and escapes first, so a `#bsol;` is a backslash, not an escape), and the layout no longer decodes them. PEG's predicates are specials marked `literal` in the model; every other special (EBNF `? … ?`, IR `special("…")`) follows the rule above. This amends D563 for railroad: D563 decoded every reference in railroad text, typed ones included. Gantt, gitGraph and treeView keep D563. Confirmed by Knut, 2026-11-27. The other option, to stop decoding in the layout only, was not taken: it would have drawn `#lt;` as `&lt;`, which is neither what was written nor what v12 drew, and changed the four `entity-codes` baseline fixtures.

This overrides "v12 decides syntax" for label text, and replaces the per-type proposals of spec #1333 (where markdown strings are recognised, timeline's tags, kanban's markdown, and v12 deciding railroad and swimlane). Spec #1333 builds the core part and moves journey, railroad, architecture, venn, timeline, kanban, swimlane and pie onto it; D711 and D712 are its timeline and kanban parts. The types that still read emphasis without backticks (class, state, mindmap, requirement, ER; D564, D565) and the ones that pass every label as Markdown (radar, cynefin) move in a later spec. New `Style.Strike` bit; core grows by about 250 B gzip.

(Knut, 2026-11-26, spec #1333, ticket #1352.)
