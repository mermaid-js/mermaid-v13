# D766: Timeline warns about the cScale overrides its theme does not read

Timeline does not honour a `cScale<n>`, `cScaleInv<n>` or `cScaleLabel<n>` override that the active theme's timeline paint does not read. It warns instead: one `TIMELINE_PALETTE_IGNORED` warning per render names every such key the author set and suggests `theme: default`, which reads all three palettes. The drawing does not change. This keeps D151 and D257: the redux family still paints boxes from `mainBkg`, `nodeBorder` and the border palette, and the neo themes still take their box fills and rules from `mainBkg` and `nodeBorder`.

- In the redux family (`redux`, `redux-color`, `redux-dark`, `redux-dark-color`, and `theme: 'auto'`, whose light half is `redux-color`) the paint reads none of the three palettes, so every override warns.
- In `neo` and `neo-dark` the paint reads only `cScaleLabel` (box text, and slot 11 for the axis and connectors), so `cScale` and `cScaleInv` overrides warn.
- In the classic themes the paint reads all three, and nothing warns.
- Which palettes are unread is decided from the theme variables that already pick the paint (`timelineScaleColors` and the gradient), never from the theme's name (D152).
- What the author set is read from `config.themeVariables`, as venn does: a key counts when it is a numbered palette entry core reads (slot 0 to 11, no leading zero) and holds a colour. A value core drops already has its own warning.

Honouring the overrides in the redux paint would be a design change and was not taken. Migration row: `v13/docs/migration/070-timeline-config.md`.
