# D708: `journey.sectionFills` and `timeline.sectionFills` are removed and warn

Amends D241, which made `journey.sectionFills` `ignored`. Both `journey.sectionFills` and `timeline.sectionFills` are now `status: removed` in the config schema. A value set for either, from any source, is dropped with one `CONFIG_REMOVED_KEY` warning that says what colours the boxes instead. Neither key is in the generated config types or defaults any more.

Neither key ever changed a drawing. In v12 the journey's `fillType<n>` style rules beat the `fill` attribute in every theme, so the theme's `fillType0`–`fillType7` filled the sections (D241). v12's timeline never read the key at all. As `ignored` keys they were accepted without a word, so an author who set them saw no colour and no reason (#1293). The warning names the theme variables to set instead:

- journey: `fillType0`–`fillType7`, written `fillType<n>`, n from 0 to 7, in the warning text. The text is kept in core (`KEY_NOTES`), and D331 bars core from naming a diagram's theme variable outright;
- timeline: the `cScale<n>` palette in the classic themes, otherwise `mainBkg` or the `borderColorArray` palette, as the timeline renderer paints boxes today (D227, D257).

Drawing does not change: the keys had no effect before and have none now.

The other option was to keep both keys `ignored` and close #1293 as by design. It was not chosen: a key that looks like it sets a colour should say that it does not.

(Knut, 2026-11-26.) The `fillType<n>` wording of the journey warning is provisional, pending Knut.
