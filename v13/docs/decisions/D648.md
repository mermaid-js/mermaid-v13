# D648: A PR that changes fixtures and snapshots runs only the tests that read them

This amends D637's list of files that run every test. A `.mmd` fixture under `e2e/diagrams/` and a vitest snapshot (a file in a `__snapshots__` folder under `packages/*/src/`) may now sit beside package source, documentation and changesets in a PR whose unit shards run only the related tests. Every other file still runs every test, a manifest, a JSON or text file beside a fixture included.

A changed snapshot runs the spec that owns it. `<dir>/__snapshots__/<name>.spec.ts.snap` belongs to `<dir>/<name>.spec.ts`. Any other snapshot, a file in `<dir>/__snapshots__/` or in a folder there, belongs to the specs under `<dir>` that call `toMatchFileSnapshot` and name that file or folder, found by searching.

A changed fixture runs every spec that names the corpus (`e2e/diagrams`, or `'e2e'` and `'diagrams'` as string literals), and every spec that imports a file that does, as `vitest related` selects them. It is not narrowed by diagram type: most of the code that reads the corpus walks every type's folder.

These tests run in the six unit shards, beside those the changed source reaches, not in the single `docs-tests` job. The readers of changed docs and changesets still run in `docs-tests`, as in D637.

Every doubt runs every test: a snapshot that no spec is found to own, a deleted or renamed snapshot (vitest reports an obsolete snapshot only in a full run), a failed search for the code that reads the corpus. Every push to `mermaid-v13` still runs every test.

The replay of the last 280 merged PRs (`tools/ci/replay-cli.ts`) moves from 19% to 27% `related` (53 to 76 PRs).
