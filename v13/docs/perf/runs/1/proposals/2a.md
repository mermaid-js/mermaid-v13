# 2a: deferred flowchart editor metadata

Status: experimental candidate; requirement amendment pending Knut's review. This proposal
is not an approved D-row and does not change REQUIREMENTS.md, DESIGN.md, or the frozen
performance policy. The base is `094ec5283059b7a87c2c2745ea6dffcc5a4dcee7`.

The ordinary SVG pipeline selects a model sink that keeps the model, stable rendered AST
ids and diagnostics eager. It skips editor-only node, edge, statement and symbol records.
The required `ast`, `symbols` and `statements` fields remain synchronous, enumerable getters.
Reading any one materializes all three together by replaying the same grammar with captured
source and parse options, then retains only the editor data. Repeated reads return the same
objects. The getters also work after sealing or freezing the parse result.

Direct `parseFlowchart` calls, language-service parsing, token/probe requests and pipeline
parses with registered extensions or loaded ASCII hooks use the eager sink. Arbitrary diagram
resource callbacks and layout-loader hooks can read the lazy fields normally. A cached SVG
preparation reused for ASCII materializes metadata when ASCII requests it. No production
cache policy, lexer/source-view optimization, parser grammar, diagnostics policy, AST type,
source span, rendered id or `data-ast` value changes.

The internal optional `deferMetadata` parse context permits this behavior; third-party parsers
can ignore it. The existing public `prepare` contract still requires consumers to read the
cached result without changing it. Descriptor reflection observes accessors on the deferred
fields; JSON serialization, object spread and structured cloning obtain the complete values.
Materializing editor fields after a model-only parse pays for a second parse. This is a cost
of the candidate, and the private counter evidence records that path separately.

Proposed R-PARSE-3 clarification: every parse exposes the model, diagnostics, identifier
occurrences and statement spans, plus tokens when requested. Rendering may defer editor-only
metadata until first access, provided values and original-source ranges match an eager parse
and diagnostics remain available immediately.

Proposed DESIGN §4.2 replacement for “Spans ... are always produced”: editor parses produce
all metadata eagerly. A rendering parse may select the model sink and expose complete editor
metadata through synchronous memoized getters. AST ids needed by the model and SVG remain
eager. Requesting tokens or a parser probe selects the full sink. The public result types and
R-PARSE-8 source-to-SVG mapping obligations remain unchanged.

Delivery still requires the independent review, all correctness and size gates, the unchanged
P12 threshold (7.40237% for this round), and both executed-object and separately sampled
physical-allocation reductions. No counter result approves this amendment or establishes fit.
