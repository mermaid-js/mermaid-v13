# The reference implementation: research notes for Mermaid v13

Source: `/Users/knsv/repos/pele` at commit `3a2f075` ("Release: 1.13.0"), package `pele@1.13.0`, author kepano / obsidianmd.
All paths below are relative to that checkout unless prefixed. I read the code directly. Where a statement is my inference, it is marked **(inference)**.

Benchmark context (from `/Users/knsv/repos/mermaid-v13-approches/README.md`, Chromium, M4 Max, 158 flowcharts, pele@1.12.0): the reference implementation fetches 62 KB gz JS for a flowchart against Mermaid's 213 KB (dagre) or 654 KB (default ELK). It is ready in 10 ms against about 36 ms. The summed warm median over 153 common diagrams is 0.14 s against 8.5 s (dagre) and 13.7 s (ELK), a geomean of 118 to 135 times faster, with 0 npm dependencies. Its output has no `foreignObject` and no `<style>`. The README's main conclusion is that "most of the gap to Mermaid comes from the architecture, not the language": Merman, a Rust port that keeps Mermaid's architecture, is only about 6 times faster.

## 1. Architecture overview

### Module layout (`src/`, about 53k lines of TS including diagrams)

| Path | Role |
|---|---|

| `src/core.ts` (195) | `register`, `registered`, `parse`, `render`, `mount`, `detectType`, `supports`, limits, error tagging. |
| `src/lazy.ts` (92) | `load(type)`, `renderAsync`, `mountAsync`: dynamic `import()` per diagram type. |

| `src/util/yaml.ts` (470) | Its own YAML reader, which replaces js-yaml. |

| `src/diagrams/<type>/` | Each type has `index.ts` (a `Diagram` object) and usually `lexer.ts`, `tokens.ts`, `parser.ts`, `db.ts`/`model.ts`, `graph.ts`, `layout.ts`, `render.ts`. |
| `src/diagrams/common/` | Shared Langium-style tokenizer (`tokens.ts`), fit-to-width helpers (`fit-width.ts`, `fit.ts`), `outline.ts`, `accDescr.ts`. |

### Pipeline

1. `parseSource` (`src/core.ts:83-110`) checks the length limit (`:89`) and runs `preprocess` (`src/preprocess.ts:138-183`). That function normalizes CRLF, rewrites HTML attribute quotes, reads front matter YAML, merges `%%{init}%%` JSON and strips comments.
2. `detectDiagram` (`src/detect.ts:85-88`): the first matching regex in `DETECTORS` (`:37-75`) wins.
3. `encodeEntities` (`src/preprocess.ts:237-247`), then `diagram.parse(source, config, title, lineOffset, {maxEdges})` (`src/core.ts:104-107`). This step produces a plain model object (a "db").
4. `render` (`src/core.ts:162-189`) runs `diagram.render(model, config, options)`. It sets three pieces of render-scoped state: `withPalette`, `withMath` and `withIcons` (`:172-178`).
5. Inside each renderer, for example `src/diagrams/flowchart/render.ts:66-371`:
   - build the graph (`buildFlowGraph`)
   - lay out every label (`layoutLabel`, which measures text with no DOM)
   - compute shape sizes (`shapeSize`)
   - run `compoundLayout` (`:188-190`)
   - concatenate SVG strings
   - wrap the result with `svgDocument` (`src/svg/root.ts:20-56`)
6. Check the output size limit (`src/core.ts:179-185`), then return `{svg, width, height, links, type, mermaidType}`.

The whole path is synchronous and touches no DOM. `AGENTS.md` sets this as a rule: "Rendering must be synchronous, without DOM access. Identical inputs and text measurer must produce identical SVG."

### Public API (`src/core.ts`, `src/types.ts`, `package.json` exports)

- **Functions**:
  - `render(source | model, options): RenderResult` (sync)

  - layout and sizing: `idPrefix`, `responsive`, `maxWidth`, `autoDirection`, `directionBreakpoint`, `padding`
  - limits: `limit`, `outputLimit`, `maxEdges`
  - links and images: `linkSchemes`, `imageSchemes`, `links`, `images`, `linkRel`
  - host hooks: `icons` (resolver), `math` (resolver), `config` (host-side Mermaid config), `now` (for gantt)

### Diagram registration

The `Diagram<Model>` interface (`src/types.ts:76-87`) has these members: `{type, section?, keepComments?, math?, parse(source, config, title, lineOffset, limits): Model, render(model, config, options): Rendered}`. A module-level `Map<DiagramType, Diagram>` stores the registered diagrams (`core.ts:23-29`). `src/diagrams/registry.ts` and `src/lazy.ts:8-42` are both generated by `scripts/gen-registry.mjs`. Example: `src/diagrams/flowchart/index.ts:7-18`.

### Supported types

There are 33 `DiagramType`s (`src/detect.ts:1-34`): flowchart, sequence, class, state, er, pie, gantt, gitGraph, mindmap, timeline, journey, xychart, quadrantChart, requirement, c4, sankey, block, packet, kanban, architecture, radar, treemap, info, agentflow, usecase, railroad (4 dialects), treeView, venn, cynefin, wardley, swimlane, ishikawa and eventmodeling. The README and `website/src/content/docs/compatibility.md` claim "every diagram type built into Mermaid 12.1.0". ZenUML and external plugins are not supported (`compatibility.md`).

The detector returns both the reference implementation's type and Mermaid's own id, for example `flowchart-v2` or `flowchart-elk` (`detect.ts:36-78`). `flowchart-elk` is drawn with the reference implementation's own layout.

## 2. Parsing

- **Technology.** Everything is hand-written. There is no parser generator and no runtime dependency.
  - **JISON-origin diagrams** (flowchart, class, state, er, sequence, gantt, etc.) each get a hand-written state-machine lexer that mirrors the JISON lexer's start conditions, plus a recursive-descent parser over flat token arrays.
    - Flowchart lexer: a `const enum S` holds the lexer states copied from `flow.jison` (`src/diagrams/flowchart/lexer.ts:11-30`). It uses sticky (`/y`) regexes (`:37-64`) and a `Uint8Array` ASCII class table for node characters (`:32-35`). Tokens go into parallel arrays `types[]`, `texts[]` and `starts[]` (`:5-9`, `:66-90`).
    - Flowchart parser: token-class membership is checked through `Uint8Array` lookup tables (`src/diagrams/flowchart/parser.ts:7-68`). The parser makes the same calls into `FlowDb` that the Jison grammar actions make (`parser.ts:83-623`).
  - **Langium-origin diagrams** (pie, packet, radar, treemap, info, architecture, gitGraph) share a table-driven tokenizer in `src/diagrams/common/tokens.ts:1-37`. Its doc comment says: "Token types are tried in order and the first match wins, as in Chevrotain." It has extensions for speed:
    - `first`: a first-character filter
    - `opener`: skip a pattern when no closer exists later in the text
    - `scanner`/`match`: linear matchers that replace backtracking regexes
    - `longer`: Chevrotain's LONGER_ALT

    Each diagram's parser is a small hand-written recursive descent over that table (`src/diagrams/pie/parser.ts`).
- **Fidelity strategy.** The parsers deliberately reproduce Mermaid's quirks: "Mermaid trims whitespace between a closing brace and the end of its line before parsing" (`flowchart/parser.ts:81-87`), "Callbacks are never executed..." (`flowchart/db.ts:360`), and others. Preprocessing also reproduces Mermaid's regex pipeline. For example, `dropColorSemicolons` reimplements Mermaid's backtracking `/keyword.*:\S*#.*;/` regex as a single linear pass (`src/preprocess.ts:196-234`). Entity codes are hidden behind Mermaid's own `ﬂ°°…¶ß` placeholders (`:236-247`).
- **Errors.**
  - `PeleError` carries `code` (`'unsupported-diagram' | 'syntax' | 'semantic' | 'limit'`), `type`, `mermaidType`, `line`, `column` and `snippet` (`src/errors.ts:1-25`).
  - `syntaxError` produces Jison-style messages: "Parse error on line N:\n<line>\n----^\nExpecting 'X', got 'Y'" (`errors.ts:95-108`, used at `flowchart/parser.ts:90-95`).
  - Positions are mapped back to the original source. Preprocessing records `Edit[]` steps, and `inputOffset` reverses them (`errors.ts:27-48`). This happens lazily: the edits are recomputed only when an error needs a position (`core.ts:112-126`).
  - Stack overflow (`RangeError`) is turned into a `'limit'` error, "Diagram is nested too deeply." (`core.ts:44-52`).
- **Coverage** (flowchart):
  - Front matter is read with its own YAML parser, which mirrors Mermaid's fence regex (`preprocess.ts:52-96`). `title`, `config` and `displayMode` are read (`:168-175`).
  - `%%{init}%%` / `%%{initialize}%%` JSON is merged, and `%%{wrap}%%` sets `config.wrap` (`preprocess.ts:114-135`).
  - `classDef`, `class`, `:::`, `style` and `linkStyle` are supported (`flowchart/parser.ts:367-430`; `db.ts:284-339`).
  - `click` supports href, callback and tooltip (`parser.ts:425-470`). Callbacks only add the `clickable` class (`db.ts:360-363`).
  - Subgraphs support `direction` (`parser.ts:472+`, `lexer.ts:46-52`).
  - Markdown strings `` "`...`" `` are supported (`MD_STR`, `lexer.ts:131`, `:636-653`).
  - `@{ shape: ..., label, icon, img, pos, w, h, constraint, form }` shape data is parsed as YAML (`db.ts:189-215`). The shape name is validated against Mermaid's full documented list plus internal aliases (`src/diagrams/flowchart/shapes.ts:2-108`). Unknown or uppercase names throw `'semantic'` errors that match Mermaid's messages (`db.ts:191-201`).
  - `accTitle` and `accDescr` (including the multiline form) are supported.
  - Edge ids (`e1@-->`) are supported. Edge `animate` is parsed but not drawn **(inference: the field exists in `graph.ts:44-45` but is never read in `flowchart/render.ts` or `svg/edges.ts`)**.
- **Verification.** Parsers are tested against Mermaid's own grammars, both differentially and by fuzzing (see §10). Skipped cases are recorded per type in `tests/compat/<type>/SKIPPED.md`. Flowchart skips only two (`tests/compat/flowchart/SKIPPED.md`).

## 3. Label handling and text measurement

- **The measurer interface** is a single method: `TextMeasurer { width(text, size, style): number }`, where `style` is a bitmask of Bold, Italic, Mono, Sub, Sup and Underline (`src/text/measurer.ts:3-17`). Hosts can inject their own measurer (`RenderOptions.measurer`).
- **The default measurer is canvas with a cache** (`measurer.ts:107-154`):
  - It uses `OffscreenCanvas` when available, else `document.createElement('canvas')`, and calls `ctx.measureText`.
  - Widths are cached per font string, up to 20,000 entries per font.
  - It does not cache a width when `document.fonts.check(font, text)` says the font is not loaded yet, because that width belongs to a fallback font (`:97-105`, `:134-137`).
  - It clears the caches when `document.fonts.size` changes (`:116-120`).
  - It calls `measureText` on the whole string. There is no per-glyph summation, so kerning and complex scripts come out right.
- **The fallback for Node, workers without canvas, and tests** is a metric table (`metricsMeasurer`, `measurer.ts:52-69`):
  - Arial advance widths for printable ASCII (95 glyphs, regular and bold), packed as two base-36 digits per glyph. That is 190 characters per weight, in `src/text/metrics.ts`. The table is generated from a TTF by `scripts/gen-metrics.mjs`, which parses the `cmap`/`hmtx` tables by hand.
  - Wide CJK, Hangul and fullwidth characters and surrogate pairs count as 1000/1000 em (`isWide`, `:28-39`). Combining marks, ZWSP, variation selectors and low surrogates count as zero width (`:41-50`). Every other non-ASCII character counts as 0.58 em. Mono counts as 0.6 em per character, or 1.2 em when wide.
  - Emoji are approximated: the high surrogate is "wide" and the low surrogate has zero width, so an emoji counts as one em **(inference from the ranges)**.
  - All the render tests use `metricsMeasurer` for determinism (`tests/render/flowchart.test.ts:10`).
- **Fonts.** The default family is `sans-serif`. The fonts used for measuring are also written into the SVG root as `font-family: var(--pele-font, <measured family>)` (`src/svg/theme.ts:39-47`). The page can therefore override the font, but the docs warn that measured and drawn fonts must match (`website/src/content/docs/theming.md`, "Fonts"). `mount()` reads `--pele-font` from computed CSS (`src/mount.ts:58-64`) and calls `forgetTextWidths()` and re-renders after `document.fonts.ready` (`mount.ts:72-99`). The default font size is 16, and edge labels use `round(size*0.875)` (`flowchart/render.ts:72-73`).
- **Label layout** (`src/text/label.ts`):
  - **Fast path**: a label with no markup, entities or `<` is measured once and wrapped only when it overflows (`label.ts:335-355`).
  - **Line breaks**: `<br>`, `\n` and literal newlines (`:30`).
  - **Inline HTML**: `b/strong/i/em/cite/dfn/var/code/kbd/samp/tt/sub/sup/u/ins` become style bits (`:34-50`). Other known HTML tag names are dropped and their text kept. Anything else that looks like a tag (`List<T>`) stays literal text (`:52-61`, `:196-201`). Arbitrary HTML is never emitted.
  - **Markdown**: only `*`/`_` italic and `**`/`__` bold, with flanking rules and word-internal `_` protection (`:203-219`). Markdown text is dedented (`:92-102`). Lists and headings are not handled **(inference: there is no such code in `label.ts`)**.
  - **Wrapping**: greedy and word-based. The piece regex breaks between any two CJK characters, honouring Japanese and Chinese kinsoku opening and closing punctuation; Hangul is left space-delimited (`:63-74`). It honours ZWSP and soft hyphen (`SHY`), and a soft hyphen renders as `-` at a break (`:236-309`). `flowchart.wrappingWidth` sets the width, default 200 (`flowchart/render.ts:75`).
  - **Line height**: 1.5 em for one line and 1.3 em for wrapped lines (`label.ts:26-28`).
  - **Icons and math**:
    - `fa:fa-x` icons count as 1.25 em and are drawn only when the host resolver returns markup. Otherwise the gap collapses (`:135-158`).
    - `$$tex$$` math goes to the host `math` resolver. The resolver returns SVG (or HTML, which is the only path that produces a `foreignObject`), and the result is cached per render (`src/text/math.ts`, `src/svg/builder.ts:129-137`).
  - **Entities**: a small named-entity table of about 200 names plus numeric codes (`src/text/entities.ts:1-20`).
- **Output.** `labelSvg` emits one `<text>` with `<tspan>` per line. Single-span plain labels get a plain `<text>`. Bold is `font-weight="var(--_w)"` and mono is `font-family="var(--_fm)"`. Emphasis shared by every span is hoisted onto `<text>` (`src/svg/builder.ts:50-106`, `:139-179`). Vertical centering uses a fixed `size*0.35` baseline shift (`:56`), not font ascent metrics.

## 4. Layout

- **The core is its own Sugiyama implementation** in `src/layout/layered.ts`. The file opens with a ranked list of 8 aesthetic goals, each naming the function that carries it out (`layered.ts:1-27`). This is unusually explicit design documentation.
  - **Cycle removal**: DFS in declaration order reverses back edges (`orient`, `:804-844`).
  - **Ranking**: longest path, followed by a balancing pass that "moves each node toward the side that has more edges" (`rank`, `:845-946`, comments at `:870-900`). It is not network simplex. When any edge has a label, or there are parallel edges, every edge gets a middle rank (`step = 2`, `:252-268`).
  - **Long edges** are split into dummy nodes. Past `MAX_DUMMIES = 20000`, the longest edges are drawn as one direct curve instead (`:125-127`, `:273-294`).
  - **Crossing reduction**: barycenter sweeps with a custom typed-array sort (`sortByBary`, `:207-240`), up to 24 sweeps and stopping after 4 stale ones (`:123`, `:1982`). The sweeps run twice, down-first and up-first, and the order that keeps more of the declaration order wins (`:1960-1975`). There is also group-contiguity support (`groups` option, `:86-87`).
  - **Coordinates**: Brandes-Köpf, four aligned layouts balanced (`position`, `:2031+`).
  - **Post-passes** give the "pretty" output:
    - `spread`: ports along node sides (`:983`)
    - `alignLabels` (`:1070`)
    - `settle`: slides ends to make edges straight (`:1135`)
    - `snap`: nudges nodes up to 12px to straighten (`:1243`)
    - `straighten` (`:1574`)
    - `pastLabels` (`:1633`)
    - `assignTracks`: orthogonal or curved "levels" per inter-rank gap, so parallel curves don't touch; capped at `MAX_WEIGHED = 400` edges per gap (`:1344`)
  - **Performance style**: typed arrays everywhere (`Int32Array`/`Float64Array`/`Uint8Array`), CSR adjacency (`outStart`/`inStart`), and reused sampling buffers (`:179-182`).
- **Compound graphs (subgraphs)** are handled in `src/layout/compound.ts`. "Each group is laid out on its own, in its own direction, and then placed in its parent as a single box. An edge that crosses a group's border passes through a port on the side facing its other end" (`:416-419`). It also:
  - lays out a flat version and switches to independent group ordering when crossings exceed `flat*1.5+4` (`:87-89`, `:877`)
  - counts route crossings (`routeCrossings`, `:155`)
  - matches Mermaid's rule that groups crossed by edges inherit their parent's direction (`inheritCrossedDirections`, `:373-388`)

  Flowchart, class, state, er, requirement, agentflow, usecase and swimlane use `compoundLayout` (grep of `src/diagrams`).
- **Other layouts**:
  - `src/layout/lanes.ts` for swimlanes: shared ranks across lanes.
  - `src/layout/components.ts`: packs disconnected parts into rows; used by class diagrams (`class/render.ts:477`).
  - Per-diagram layouts: `sankey/layout.ts`, `venn/layout.ts`, `treemap/layout.ts`, `c4/layout.ts` + `c4/route.ts`, `architecture/layout.ts` and `block/layout.ts`. Sequence, gantt, timeline, etc. lay themselves out inside `render.ts`.
- **Edge drawing.** `routePath` turns layout routes of `(x, y, axis)` triples into an S-curve per gap, a rounded step for `curve: step*`, or straight lines for `linear` (`src/svg/edges.ts:46-60`). `flow.curve` selects the style (`flowchart/render.ts:179-187`).
  - Markers are drawn inline as a `<path>` or `<circle>` at the tip. There are no `<marker>`/`<defs>` (`edges.ts:203-232`), so no ids are needed.
  - Self-loops make the node's box bigger so the loop fits beside it (`flowchart/render.ts:159-164`, `edges.ts` `loopPath`).
  - Ends are inset from the layout box onto the drawn shape outline (`insetRoute`, `src/svg/shapes.ts:678-689`).
  - Where edges cross other edges or fills, they get a background-coloured halo (a "casing") under the line (`edges.ts:460-495`). Over a filled subgraph, the edge takes a contrasting ink colour (`overFills`, `:453`).
- **Space-based layout (available width).** `maxWidth` is a first-class render input (`types.ts:25-31`) with three helpers in `src/diagrams/common/fit-width.ts`:
  - `tighten` (`:60-66`) renders once, and if the result is wider than `maxWidth` renders "tight": half the nodeSep, 0.75 times the rankSep, and smaller group padding (`flowchart/render.ts:67`, `:179-182`). It keeps whichever is narrower.
  - `turnToFit` (`:44-52`) applies to LR/RL diagrams. If they don't fit and the width is under `directionBreakpoint` (640 by default), it re-renders TB and keeps that if narrower. `autoDirection:false` disables this.
  - `fitWidth` / `capWidth` (`:7-38`) apply to charts with a free plot width (pie, sankey, radar, wardley, xychart, quadrant, gantt, treemap). They shrink the plot by the overflow, up to 3 rounds.
  - Titles wrap at the available width (`titleRoom`, `:27-30`). Class diagrams wrap disconnected components into rows (`class/render.ts:477`).
  - `mount()` takes the element's content width as `maxWidth` (`src/window.ts:8-11`). It renders "natural" first. Only when the container is narrower does it probe whether the diagram adapts at all, by rendering at `maxWidth:1` and comparing the SVG, and then re-render (`src/mount.ts:150-170`). A `ResizeObserver` triggers re-fits (`mount.ts:326-348`).
  - Nearly every renderer wraps its `draw` in one of these helpers (grep: flowchart, class, state, er, sequence, journey, timeline, mindmap, packet, usecase, c4, railroad, architecture, treeview, etc.).
  - Docs: `website/src/content/docs/api.md` "Narrow screens" / "Direction".

## 5. SVG creation

- **The SVG is built as strings, with no DOM**: template literals concatenated per section (`flowchart/render.ts:209-368`). The z-order is fixed: clusters, casings, edges, struck cluster titles, edge labels, nodes (`:354-368`).
- **Escaping** (`src/svg/builder.ts:8-26`):
  - `esc()` escapes `& < > "` and *removes* characters that are invalid in XML (C0 controls, DEL, lone surrogates, U+FFFE/FFFF). It has a fast path that does nothing when there is nothing to escape.
  - `escText()` first decodes entity codes, then escapes. It is used only for text-only values; values that were validated go through `esc()` so that "what was checked is what is written" (`:20-23`).
- **Numbers**: `num()` formats to 2 decimals from integer math with a precomputed fraction table, "much faster than converting a double" (`builder.ts:28-47`).
- **Styling is attributes plus CSS variables**, with no `<style>` element:
  - The root `<svg>` carries `class="pele pele-<type>"`, `viewBox`, `width`/`height` and an inline `style`. That style holds `max-width:100%;height:auto` (when responsive) and the private alias vars `--_bg --_fg --_m --_l --_s --_a --_b --_c` mapped to public `--pele-*` with fallbacks (`src/svg/theme.ts:6-9`). It also holds the font declarations and any `--pele-series-N` palette overrides (`src/svg/root.ts:20-56`).
  - Alias vars such as `--_r`, `--_w`, `--_tw` and `--_hw` are added only when the content uses them; a regex scan over the content checks this (`root.ts:13`, `:41-49`).
  - Shapes use `fill="var(--_s)" stroke="var(--_b)"` (`flowchart/render.ts:27-28`).
- **Classes** are stable and documented: `pele-node`, `pele-shape-<name>`, `pele-edge`, `pele-cluster`, `pele-label`, `pele-marker` and so on. User `classDef` names are passed through after being reduced to `[\w-]` (`src/svg/theme.ts:138-143`).
- **Ids**: elements carry `data-id` (the source id, escaped) rather than `id`. The only `id`s are `${idPrefix}-title` / `-desc` for a11y (`root.ts:29-39`) and sankey gradient ids (`sankey/render.ts:201-219`), which are emitted only when an `idPrefix` is present. `mount()` generates `pele-<random>-<n>` (`mount.ts:141`).
- **Accessibility**: `role` plus `aria-roledescription` on the root, and `<title>`/`<desc>` with `aria-labelledby` and `aria-describedby` (`root.ts:30-39`, `:51`). Tooltips become `<title>` in nodes (`flowchart/render.ts:292`).
- **Output size**: there is no measurement in the repo. **(inference)** Output is compact for three reasons: there are no defs or marker definitions, no embedded CSS, and no `foreignObject`, and coordinates have at most 2 decimals. A default output cap of 4,000,000 characters applies (`core.ts:39`).

## 6. Config handling

- **Sources.** Front matter `config:` and `%%{init}%%` are deep-merged with prototype-key protection (`preprocess.ts:20`, `:102-112`; YAML `__proto__` is handled in `util/yaml.ts:14-20`). The host's `options.config` is shallow-merged *under* the diagram's own config (`core.ts:101`). The docs warn hosts not to let authors supply `options.config` (`SECURITY.md`).
- **Honored keys.** These are per diagram and read defensively, with type checks and clamps (for example `numberOption`, which caps values at 2000, `flowchart/render.ts:30-33`). A grep of option readers finds:
  - flowchart: `nodeSpacing`, `rankSpacing`, `wrappingWidth`, `curve`, `inheritDir`
  - sequence: `wrap`, `actorMargin`, `messageMargin`, `noteMargin`, `boxMargin`, …
  - gantt: `useWidth`, `barHeight`, `barGap`, `topPadding`, `sectionFontSize`, `numberSectionStyles`, `displayMode`
  - pie: `donutHole`, `textPosition`
  - xychart and quadrant: axis positions and sizes
  - sankey: `nodeAlignment` / `linkColor`
  - and others
- **`useMaxWidth: false`** in the diagram's section turns off responsive sizing (`core.ts:165-167`).
- **Ignored**: `theme`, `themeVariables` (except palette lists, §7), `look` (handDrawn), `layout` (elk), `htmlLabels`, `securityLevel` and `fontFamily` in config. A grep for these in `src/` finds nothing. `compatibility.md` confirms: "Mermaid themes don't apply, and `themeVariables` colors apply only as series palettes."
- **Its own options** are those in `RenderOptions` (§1). Host-level policy such as fonts, limits, link schemes and the width budget lives in options, not in diagram config.

## 7. Theming

- **The model is a monochrome base with CSS custom properties**:
  - 10 public tokens: `--pele-bg/fg/muted/line/surface/surface-alt/border/accent/critical/error`
  - `--pele-fg-on-light` / `--pele-fg-on-dark`
  - fonts: `--pele-font` / `--pele-font-mono`
  - weights: `--pele-title-weight`, `--pele-heading-weight`, `--pele-bold-weight`
  - `--pele-radius`
  - `--pele-series-1..8` for charts and categories

  Defaults are in `src/svg/theme.ts:6-9`, `:27-29` and `:145-151`, documented in `website/src/content/docs/theming.md`.
- **Light/dark.** Because every colour is `var(--pele-x, fallback)` inside the SVG, a host stylesheet (for example under `@media (prefers-color-scheme: dark)`) re-themes diagrams without re-rendering (`theming.md`). This is the "host app theme matching" mechanism: Obsidian maps its own CSS vars onto `--pele-*` **(inference from the example in `theming.md`: `--pele-font: var(--font-text)`)**.
- **Private alias layer.** The root defines `--_fg: var(--pele-fg, #1f1f1f)` and similar, so each element only writes the short `var(--_fg)` (`theme.ts:3-9`). That keeps output small while the public tokens keep their fallbacks.
- **`classDef`/`style` colours** are emitted as inline `style="fill:…;stroke:…"`. They are fixed and do not follow the theme (`theming.md`, "Styles in the diagram").
  - `resolveStyle` splits declarations into shape, line and text parts using property allow-lists, and maps `color` to `fill` for text (`theme.ts:49-136`).
  - **Automatic text contrast**: `ink()` computes the WCAG relative luminance of the fill (hex, named colours, rgb/hsl with alpha, and fill-opacity), then picks `--pele-fg-on-light` or `--pele-fg-on-dark`. Fills below 50% opacity are skipped (`src/svg/ink.ts:1-131`). It needs no colour library.
- **Palettes.** The Mermaid theme variables `pie1..8`, `git0..7`, `cScale0..7`, `venn1..8` and `xyChart.plotColorPalette` are mapped to `--pele-series-N` on the root (`src/svg/palette.ts:9-17`, `:104-118`). Values are validated by `safeColor`:
  - charset allow-list
  - balanced parentheses
  - function allow-list (`rgb/hsl/lab/oklch/color-mix/light-dark/var`)
  - `var()` only of `--pele-*`

  So palette entries cannot read page variables or load resources (`palette.ts:41-61`).
- **There is no theme API** beyond CSS. Hosts can also style by class or `data-id` (`theming.md`, "Classes").

## 8. Security

- **Inert by construction.** There is no sanitizer in the library. Output contains no `<script>`, no `<style>`, no `foreignObject` (except host-supplied HTML math), no `on*` attributes and no HTML labels (`website/src/content/docs/security.md`). The test oracle `tests/support/inert.ts` enforces strict allow-lists:
  - **elements**: `svg g rect circle ellipse polygon path text tspan a title desc image` (`:8`)
  - **attributes**: a fixed list (`:9-15`)
  - **style properties**: a fixed list (`:16-20`), with numeric-attribute checks, href scheme checks and target checks (`:40-66`)

  The test runs over every corpus input and over XSS payload templates (`tests/render/security.test.ts`). Every diagram type has a `*-security.test.ts`.
- **Escaping**: §5 (`esc`/`escText`). Invalid XML characters are dropped, and the docs warn that removing them "can make validated values unsafe" (`builder.ts:12-13`).
- **CSS from `style`/`classDef`**: properties are allow-listed (`theme.ts:49-74`). Values matching `url(`, `expression(`, `javascript:`, `[<>{};\\]`, `@import`, `image-set` or `/*` are dropped (`theme.ts:76`, `:111`). Font family lists are validated by regex before they go into the root style (`theme.ts:31-37`).
- **URLs** (`src/util/url.ts`):
  - `sanitizeUrl` is a reimplementation of `@braintree/sanitize-url` (which Mermaid uses) that keeps percent escapes (`:42-72`). It repeatedly strips control characters and entities, with a 32-round cap.
  - It is followed by an *allow-list* of schemes: links `http/https/mailto/tel`, images `http/https`. Network paths `//host` are blocked, and both the raw and the decoded forms are checked (`:79-107`). Hosts can change the lists with `linkSchemes`/`imageSchemes`, or turn links and images off entirely (`types.ts:37-43`).
  - `rel="noopener"` is the default (`:127-130`).
  - Obsidian `internal-link` classes become `<a class="internal-link" data-href>` with the same URL check (`flowchart/render.ts:282-290`, `url.ts:111-118`).
- **click**: href links only. JS callbacks are never executed and only add the `clickable` class (`flowchart/db.ts:360-363`).
- **Limits**:
  - source: 50,000 characters (`core.ts:36`)
  - output: 4,000,000 characters (`:39`)
  - `maxEdges`: 5,000 (`:42`, enforced in `db.ts:253-260`; Mermaid's limit is 500)
  - layout caps: `MAX_DUMMIES`, `MAX_PORTS = 40000` (`compound.ts:82`), `MAX_WEIGHED`
  - YAML depth: 64 (`yaml.ts:12`)
  - asset sizes: at most 4000px (`flowchart/render.ts:45-47`)
  - font size: at most 200 (`theme.ts:134`)

  `RangeError` is turned into a limit error (`core.ts:44-52`).
- **ReDoS / complexity**: Mermaid regexes that backtrack are replaced by linear scans (`preprocess.ts:196-234`, `yaml.ts:134-150`, the `scanner` hooks in `common/tokens.ts:19-27`). `tests/stress.test.ts` holds adversarial inputs: 50k-character runs, 1000-deep subgraphs, unclosed directives, and others.
- **Host responsibilities** (`SECURITY.md`): show errors via `textContent`, because messages contain source text. Icon and math markup are inserted unfiltered, so they must be trusted. Use a worker for time limits. `mount({sanitize})` lets hosts run their own sanitizer.

## 9. Size and speed: design choices

1. **Zero runtime dependencies** (`package.json` has only devDependencies). The reference implementation has its own:
   - YAML parser (`util/yaml.ts`, 470 lines) instead of js-yaml
   - URL sanitizer (`util/url.ts`) instead of @braintree
   - colour luminance (`svg/ink.ts`) instead of khroma
   - layout (`layout/*`) instead of dagre, ELK or cytoscape

   It needs no DOMPurify, because the output is inert by construction, and no d3, because it builds strings.
2. **No DOM in the render path.** Text is measured with canvas `measureText` (cached) or a 190-character Arial table, never `getBBox`. That removes Mermaid's main cost: insert into the DOM, measure, lay out (`measurer.ts`).
3. **Synchronous**, with no async loading inside `render` (`core.ts:162`).
4. **Code splitting**: esbuild produces `dist/pele.js` (everything), an IIFE build, and a split ESM build with `core`, `lazy` and one entry per diagram plus shared chunks (`scripts/build.mjs:19-38`). The build script prints per-type gz cost (`:73-80`). `sideEffects` is limited to the full entry (`package.json`).
5. **Data-oriented hot loops**:
   - typed arrays and CSR adjacency in layout (`layered.ts:296-330`)
   - a custom typed-array sort that avoids comparator calls (`:207-240`)
   - `Uint8Array` char and token class tables in the lexers (`flowchart/lexer.ts:32-35`, `parser.ts:7-68`)
   - sticky regexes
   - parallel token arrays instead of token objects
6. **Fast paths**:
   - `esc()` skips work when nothing needs escaping (`builder.ts:16-18`)
   - plain labels skip markup parsing (`label.ts:335-347`)
   - single-span labels emit no `<tspan>` (`builder.ts:59-62`)
   - `num()` uses an integer table (`builder.ts:28-47`)
   - unused root CSS vars are omitted (`root.ts:41-49`)
   - error-position mapping runs only on error (`core.ts:112-126`)
   - metric tables are unpacked lazily (`measurer.ts:25-26`, `:57`)
7. **Bounded work**: caps on sweeps, dummies, ports and weighed track pairs. Repeated layouts run only on small graphs (`compound.ts:84-86`, `MAX_ORDERED_PORTS = 400`).
8. **Caching**: measurer widths per font (20k entries), `ink()` results (1000), and icon and math results per render (`text/icons.ts`, `text/math.ts`). There is no output cache. The benchmark defeats any such cache anyway by appending a unique `%%` comment.
9. **Packed data**: the Unicode identifier-letter table is base-36 run-length encoded (`src/util/unicode.ts:1-15`, generated from `flow.jison` by `scripts/gen-unicode.mjs`).

## 10. Testing

There are 175 `*.test.ts` files plus 123 ported Mermaid `*.spec.*` files (from `find tests`). Vitest runs with `pool: 'threads'` (`vitest.config.ts`). The repo has no image snapshots and no `toMatchSnapshot` calls (grep count is 0). The approaches it does use are below.

- **Ported Mermaid parser specs.** `scripts/sync-specs.mjs` copies Mermaid's spec files at a pinned tag (`mermaid@12.1.0`) into `tests/compat/<type>/` and rewrites their imports to point at the reference implementation adapters. Example: `tests/compat/flowchart/adapter.ts` exposes `FlowDB` with Mermaid's method names over the reference implementation's `FlowDb`. It also vendors the upstream grammars (`tests/compat/flowchart/upstream/flow.jison`). Skips are documented in `SKIPPED.md`.
- **Differential oracle plus fuzzing.**
  - For JISON diagrams, `tests/support/oracle.ts` and `tests/support/flow-oracle.ts` compile the upstream `.jison` with the `jison` devDependency into a reference parser that records every `yy.*` call. `tests/flowchart/oracle.test.ts:24-49` asserts that the reference implementation's tokens equal the oracle's tokens, that both accept or reject the same input, and that both make the same model calls. It runs over the corpus (more than 300 inputs) and over 5,000 mutated inputs by default; the `FUZZ` and `SEED` environment variables change this. A fragment-insertion mutator does the mutation (`tests/support/corpus.ts`).
  - For Langium diagrams, `tests/support/langium.ts` uses `@mermaid-js/parser` as the reference. It checks the reference implementation's token tables against the Chevrotain lexer definitions and the reference implementation's parse output against the Langium ASTs.
- **Corpus**: every string literal in the ported specs that looks like a diagram, plus Mermaid's docs examples (`tests/corpus/<type>-docs.json`, loaded in `tests/support/corpus.ts:4-23`).
- **Render invariants**, not pixels. For every corpus input (`tests/render/flowchart.test.ts:21-35`), the SVG must:
  - be well-formed XML
  - contain no script, style or foreignObject
  - contain no `NaN` or `undefined`
  - be deterministic (render twice and get identical output)

  There are also semantic assertions on width, height, direction, colours and so on.
- **Security tests** per diagram type check payload templates with `assertInert` (§8). `tests/stress.test.ts` tests worst-case time, with loose bounds.
- **Layout unit tests** (`tests/layout/{layered,compound,lanes}.test.ts`) check crossing counts and geometric invariants on synthetic graphs.
- **Browser compatibility test** (`tests/browsers.test.ts`): runs the IIFE bundle in a Node `vm` with built-ins newer than Safari 15 deleted, then renders every docs example at wide and narrow widths.
- **Benchmarks**: `scripts/bench.mjs` (docs corpus plus generated trees and meshes up to 500 nodes) and `scripts/bench-mermaid.mjs` (headless Chrome against Mermaid fetched from unpkg).

## 11. License, gaps and limitations

- **License**: MIT, © 2026 kepano (`LICENSE`), plus the ISC-licensed Lucide `rotate-ccw` icon in the zoom controls. The ported specs and grammars under `tests/compat` come from Mermaid, which is also MIT (`README.md`).
- **Gaps compared with Mermaid** (from `compatibility.md` plus the code):
  - Layout and appearance are deliberately different, so no pixel parity. Mermaid themes, `themeVariables` (except palettes), `look: handDrawn`, ELK and other layout choices are ignored.
  - There are no HTML labels. Only the inline subset in §3 is supported, and markdown is limited to bold and italic.
  - JS `click` callbacks are ignored. Edge `animate`/`animation` are parsed but not rendered **(inference)**.
  - ZenUML and external or registered plugins are not supported. There is no `registerExternalDiagrams`-style public plugin API, although `register()` accepts any `Diagram` object, so third parties could in principle register one **(inference)**.
  - Icons need a host resolver. The reference implementation has no built-in icon packs, except for some architecture and treeView symbols.
  - Text measurement in Node or SSR without canvas is approximate (an Arial ASCII table and fixed widths for everything else). Labels can therefore mis-fit if the drawn font differs. The docs flag the font-matching requirement.
  - Vertical text metrics are a fixed 0.35 em shift and a 1.5 or 1.3 line-height (`builder.ts:56`, `label.ts:26-28`).
  - The deliberate deviations are mostly stricter rules (`compatibility.md`): edge limit 5,000 versus 500, URL scheme allow-list versus Mermaid's deny-list, a sankey syntax error on a non-numeric value, and Unicode sankey names.
  - It targets Mermaid 12.1.0 syntax, and the ported specs are pinned to that tag (`SKIPPED.md` header).

## Steal list for Mermaid v13

1. **Make the renderer a pure, synchronous `(model, config, options) -> {svg, w, h, links}` function with no DOM.** Put mount/resize/zoom in a separate optional layer. This is the key architecture behind the roughly 100x speed-up. The reference implementation: `src/types.ts:76-87`, `src/core.ts:162-189`, with `src/mount.ts` separate.
2. **Use a pluggable `TextMeasurer` with a cached canvas default and a deterministic metric-table fallback**, and use the table in all tests. Cache per font, refuse to cache fallback-font widths, and invalidate when fonts load. The reference implementation: `src/text/measurer.ts:15-159`, `src/text/metrics.ts`, `scripts/gen-metrics.mjs`, `src/mount.ts:72-99`.
3. **Treat available width as a layout input.** Use `maxWidth` with three strategies: tighten spacing, flip LR to TB below a breakpoint, and shrink the chart plot. `mount()` should re-render on resize only when the diagram actually adapts. The reference implementation: `src/diagrams/common/fit-width.ts`, `src/mount.ts:150-170`.
4. **Theme through CSS custom properties with a private alias layer** (`--_fg: var(--pele-fg, #1f1f1f)`). Re-theme and switch dark mode with no re-render, emit no `<style>`, and include only the aliases that are used. The reference implementation: `src/svg/theme.ts:6-9`, `src/svg/root.ts:20-56`, `website/src/content/docs/theming.md`.
5. **Make the output inert by construction and enforce it with an allow-list test oracle**, instead of shipping DOMPurify. That means:
   - escape-on-write (`esc`/`escText`)
   - property and value allow-lists for `style`/`classDef`
   - a scheme allow-list for links and images
   - inline markers instead of `<marker>` defs and ids

   The reference implementation: `src/svg/builder.ts:8-26`, `src/svg/theme.ts:49-136`, `src/util/url.ts`, `src/svg/edges.ts:203-232`, `tests/support/inert.ts`.
6. **Pick text contrast automatically on user fills** using WCAG luminance, with two theme tokens (`fg-on-light`/`fg-on-dark`) and no colour library. The reference implementation: `src/svg/ink.ts`.
7. **Test the parser differentially against the legacy grammar while migrating.** Compile the old `.jison` (or use `@mermaid-js/parser`) as an oracle and compare tokens, accept/reject decisions and db calls on the spec and docs corpus plus seeded mutation fuzzing. This fits directly with our Chevrotain migration. The reference implementation: `tests/support/oracle.ts`, `tests/support/flow-oracle.ts`, `tests/flowchart/oracle.test.ts`, `tests/support/langium.ts`, `scripts/sync-specs.mjs`.
8. **Add hard, host-controlled limits and turn deep recursion into a typed `'limit'` error.** Limits should cover source, output size and edges, and be enforced in the db as well as in layout caps. Keep a stress suite of adversarial inputs, and replace backtracking regexes with linear scans. The reference implementation: `src/core.ts:35-52`, `src/diagrams/flowchart/db.ts:253-260`, `src/preprocess.ts:196-234`, `tests/stress.test.ts`.
9. **Give errors stable codes and map positions back to the original source.** Record preprocessing edits so line and column refer to the user's text (front matter and directives included), and do the mapping lazily on error. The reference implementation: `src/errors.ts:1-108`, `src/core.ts:112-126`.
10. **Use one Sugiyama core with explicit, ranked aesthetic goals plus a compound wrapper that lays out each group as a box with border ports**, and share it across flowchart, class, state, er, requirement and others. Implement it with typed arrays and bounded sweeps. The reference implementation: `src/layout/layered.ts:1-27`, `:242+`, `src/layout/compound.ts:416-419`.
11. **Split the package per diagram with a generated registry and lazy loader**, export `parse()` models that `render()` accepts, and report per-type gz cost in the build. The reference implementation: `scripts/gen-registry.mjs`, `src/lazy.ts`, `scripts/build.mjs:19-80`, `src/core.ts:152-160`.
12. **Apply micro-techniques in the SVG string builder**: a fast-path `esc`, integer-table `num()` with 2 decimals, single `<text>` without `<tspan>` for plain labels, emphasis shared by every span hoisted onto `<text>`, and `data-id` instead of `id` (avoiding id collisions across multiple diagrams on a page). The reference implementation: `src/svg/builder.ts:16-106`, `src/svg/root.ts`.
