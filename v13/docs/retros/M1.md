# M1 retrospective

Status: 2026-11-02 · Spec mermaid-js/mermaid-v13#1, tickets #2–#24, PR #25.

M1 built the v13 core pipeline with flowchart as the only diagram type. It ran as one integration branch (`feature/1_m1-core-flowchart`). An orchestrator handed out 23 tickets from the spec's task graph to implementer agents, with up to seven running in parallel, then merged each one and finished with one code-review pass. This document records what to keep and what to change for M3 (sequence, class, state, ER). The changes are already written into the port recipe, `v13/docs/agents/port-diagram/`.

## Outcome

- All 23 tickets are implemented, and `pnpm check` passes with 2155 tests.
- The flowchart lexer matches v12's jison token stream on 762/762 sources. The parsed model matches the oracle on 856/856 sources, with an empty divergence list.
- Render properties hold over the whole e2e corpus: well-formed XML, the allow-list, determinism, no NaN, and the AST round-trip.
- Open at M1 close:
  - Size: about 81.9 KB gz against the 80 KB R-PERF-1 budget. This is deferred, and the budget may be raised by 10–15%.
  - Release secrets.
  - WebKit, Argos and the nightly jobs have not run on GitHub yet.
  - The hand reviews of colours (D71) and of MIGRATION.md.

## What went well

- **The spec, the ticket graph and the frontier.** Native blocked-by links made the frontier obvious. Independent tracks (config, measurer, layout, writer, bench, conformance) ran side by side, and the renderer was the only real join point.
- **Exploration before implementation.** One agent wrote pointer notes before any ticket started. They covered how to read v12 source after it was deleted (`git show fa796a943:<path>`), the DOMPurify stub that makes `mermaid@12` parse in Node, which Pele files to port, and where the Chevrotain reference specs live. Implementers spent their time building instead of rediscovering.
- **Context pointers instead of long prompts.** Each ticket brief was a few lines pointing at the ticket, the docs and a shared implementer brief. Each finished ticket left a handoff note listing what it exported. Downstream tickets read those notes, not each other's transcripts.
- **A running gaps ledger.** Every handoff ended with the criteria it had not met. Collecting these per owning ticket meant nothing fell between tickets: the config wiring for #15, the browser tests for #18, the fuzz-only differences for #17.
- **The oracle as the arbiter.** Treating `mermaid@12` as ground truth settled syntax questions without debate.
- **Tokenizer first** (the maintainer's method from the Chevrotain migrations). The parser stalled until it was redirected to build a lexer-parity gate against v12's jison lexer before writing grammar. Once the gate was at 762/762, the grammar port converged quickly. The grammar file's lexer section, built the same way, found a real v12 quirk: blanks after `@{…}` must be followed by `&`.
- **Generated sentences and stress inputs found real bugs.** One line produced 4M edge-limit diagnostics, sibling subgraphs made parsing quadratic, and about a dozen YAML cases differed from js-yaml.
- **Cheap merges.** Implementers merged the integration tip before reporting, so most merges were fast-forwards.

## What went badly

| What happened | Cost | Change for M3 |
| --- | --- | --- |
| The worktree hook failed (`agent-browser install`: permission denied), so isolation-mode agents couldn't start. | Worktrees had to be made by hand. | Create worktrees with `git worktree add` from the start (orchestration.md). Consider making the hook tolerate a failed `agent-browser install`. |
| The parser agent started grammar-first and stalled. Tokenizer-first only arrived as a mid-ticket correction. | About an hour on the longest ticket on the critical path. | Tokenizer-first is a required step in the per-diagram recipe, with its own ticket. |
| Parallel tickets collided on shared interfaces. `LabelBox` was defined twice (#10 and #12). #15 deleted `renderForTest` while #17 and #18 depended on it. | Rework, plus orchestrator messages sent mid-ticket. | A ticket that owns a shared contract lands it first or announces it in the ledger. A helper that live tickets use is deprecated, not deleted. |
| The public API (#15) landed late, so earlier tickets tested through internal helpers and later moved to `render()`. | Duplicate test scaffolding. | The public seam now exists. M3 tickets test through `createMermaid().render()` from the first commit. |
| Agents changed defaults or semantics without asking: `layout: dagre` (against DESIGN §6.1), the changesets base branch set to `develop`, workflows left on `develop`, `securityLevel` strict semantics. | Each one was caught late. The `securityLevel` question needed the maintainer. | Escalate decisions: anything that contradicts DESIGN or a D-id, or changes a v12 default, stops and goes to the maintainer through the ledger. |
| Handoff claims were sometimes wrong. #14 said "no id collisions", but the constant default prefix collided. #16 reported duplicate node ids that didn't exist. | False confidence, and a wasted check. | Treat claims as unverified until checked. Review each ticket before merging; one end-of-milestone review over 78k lines is too shallow. |
| Per-piece size budgets were blown silently, and adding up separately measured pieces double-counted (about 87 KB estimated, about 82 KB real). | A false alarm. | Report the size of the bench bundle for the whole load path, not a sum of pieces. |
| Timing tests flaked while seven agents shared one machine. | Re-runs and noise. | Timing assertions are ratio-based (best of N). |
| Clutter in the main checkout broke merger checks: a git-ignored `.tmp/` was linted, and a stray `packages/parser/` held only CLAUDE.md. | Merger failures unrelated to the merge. | Fixed in M1: eslint ignores `.tmp/`, and workspace specs only count folders that have a `package.json`. |
| M1 was pushed straight to `mermaid-v13` with no PR, and that push started the release workflow. | Confusion about the target, and a release run (nothing published, because the secrets aren't set). | Push only to the `mermaid-js` remote and deliver through a draft PR into `mermaid-v13`, opened after the first merge. |
| Closing issues is denied in agent sessions. | The maintainer has to close the tickets by hand. | Expect this. Hand the maintainer the close commands, or allow `gh issue close`. |
| WebKit wouldn't launch locally, and Argos, nightly fuzz and the oracle bump can't run locally. | Unverified acceptance criteria. | Open the draft PR early so GitHub CI covers them, and read CI before calling a ticket done. |

## Process changes adopted for M3

See `v13/docs/agents/port-diagram/` for the recipe. In short:

1. **One spec per diagram type,** each with a small, fixed ticket graph: lexer gate, then parser and oracle, then layout, then renderer, then integration. A shared-core ticket lands first whenever a type needs new core primitives.
2. **Tokenizer first** for every parser.
3. **The public API seam from the first commit.**
4. **Escalate decisions.**
5. **Contract ownership:** the owner lands a shared contract first. Helpers are deprecated, not deleted.
6. **Review each ticket** against its acceptance criteria before merging. Claims count as unverified until checked.
7. **A draft PR into `mermaid-v13`** after the first merge, with GitHub CI read before a ticket counts as done.
8. **Durable notes in the repo.** Exploration notes and handoffs for a run live under `v13/docs/agents/runs/<spec>/`, not in a session scratchpad that disappears with the session.
