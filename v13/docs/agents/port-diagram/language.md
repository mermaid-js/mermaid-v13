# Language-service support for a ported type (R-LANG-3)

Every type ported after M2.5 ships a language facet that passes the shared golden suite (R-LANG-3, D89, D99). This is the checklist; flowchart is the worked example (`packages/diagram-flowchart/src/language.ts`, `packages/language-service/goldens/flowchart/`).

## Checklist

1. **Facet.** Export a `LanguageFacet` named `language` from the package's `./language` subpath (`src/language.ts`, helpers in `src/facet/`; the import-boundary lint keeps both off the renderer): `id`, `parse` (the parser-only entry, tokens kept on request), `isValidId(name, kind?)` per symbol kind, `categories` (generated by gen-grammar, never hand-written), `namespaces` (which symbol kinds share names: flowchart groups `node` and `subgraph`), and the **required** `completions(probe, doc)` and `hover(at, doc)`: a module without them fails `preload` with `LANGUAGE_LOAD_FAILED`. `parse` follows the contract on `LanguageFacet.parse` (whole text, never throws; preprocess diagnostics may be left to the service). The subpath loads the parser and tables only: copy the bundle check in `packages/bench/src/language-bundle.spec.ts`.
2. **Probe wiring (R-LANG-7, D95).** `parse(text, { probe })` records what the parser would accept at the offset: a parser on `TokenCursor` gets it from `at`/`eat`/`peek`; one with its own token loop (flowchart's `FlowParser`) calls `probe.tested(kinds)` in its rule methods at the same decision points where it builds `fail([...])` lists, and the lexer records its mode. Copy `packages/conformance/src/flowchart/probe.spec.ts`: a probe changes nothing but `probe` over the corpus.
3. **Generated tables.** Add the grammar file (`grammar/<type>.ebnf`) and run `pnpm gen:grammar`: it writes `src/generated/categories.ts` (kind → category) and `src/generated/docs.ts` (one-line keyword docs hover reads, from the rule docs), plus the TextMate, Monarch and Lezer highlighters. Copy the four-way agreement spec (`tools/gen-grammar/src/categories.spec.ts`: table, TextMate, Monarch and Lezer give every corpus token the same category).
4. **Registry.** The manifest's `language` entry makes `gen:registry` give the type's `firstPartyFacets` row a `load`. From then on the suite requires its goldens.
5. **Parse output.** Symbols whose range is exactly the name (the service drops any other, so a quoted id gets no definition or rename), one statement span per statement with block children (folding; a block's span runs from its keyword to its closer, so the fold starts on the keyword line), AST ranges (astAt), and N diagnostics for N errors (pitfall 8).
6. **Goldens.** Add `packages/language-service/goldens/<id>/<feature>/<case>.mmd` for every feature in `REQUIRED_FEATURES` (`src/testing/goldens.ts`): diagnostics, definition, references, rename, astAt, folding, semanticTokens, completions and hover. Mark cursors with `|` (a literal `|` is `\|`), set a rename target with `%% rename-to: X`. Cover every symbol kind and namespace, each block statement, an error-recovery case and a refused rename. Write the `.out` with `vitest run packages/language-service -u` and review every line: the first `-u` writes whatever the service says. A diagram package outside this repository runs the same suite from `@mermaid-js/language-service/testing` (`goldenCases`, `readFixture`, `renderGolden`, `missingFeatures`; usage in its module header) and writes its facet against the types `@mermaid-js/language-service` re-exports.
7. **Corpus properties.** `src/property.spec.ts` (every query at every token boundary of `e2e/diagrams/**`, no throw, in budget) and `src/rename-round-trip.spec.ts` (rename, re-parse, same model modulo the name) pick the type up from its corpus folder with no change. Add each finding to the spec's known list only with a GAPS.md entry and an owner.
8. **Oracle expectations.** Copy `packages/conformance/src/flowchart/service-symbols.spec.ts`: v12's model decides which names have one definition, which classes and groups exist, and which members sit inside which fold.
9. **Adapter highlighters (D134, D135).** Each adapter picks its first-paint highlighter per detected type from its own map: the CodeMirror adapter maps the type id to a lazily imported Lezer parser built from `grammar/generated/<type>.grammar`, and the Monaco adapter maps it to a lazily imported copy of `<type>.monarch.json`. Add your type's row to both maps (`LEZER_HIGHLIGHTERS` in `packages/language-service-codemirror/src/language.ts`; `MONARCH_HIGHLIGHTERS` in `packages/language-service-monaco/src/highlighters.ts`, whose row also carries the header pattern your `firstPartyFacets` detector tests) and your id to both adapters' `HIGHLIGHTED_TYPES` (`scripts/lezer.ts`, `scripts/monarch.ts`), run each adapter's `gen`, then extend `packages/language-service-monaco/src/adapters-agree.spec.ts` (folds and tokens agree in Monaco, LSP and CodeMirror) and both adapters' first-paint e2e specs with a document of the type. Without a row the type gets semantic tokens only, never flowchart's colours.
10. **Budget.** Report `pnpm --filter bench language`-style numbers for a 50k-character document of the type (R-LANG-4: update + every query ≤ 15 ms, D156 on the reference runner). Timing tests in PR CI assert ratios only, in CPU time (`packages/bench/src/language-budget.spec.ts`).

**Done when** `goldens.spec.ts` lists the type under "the port checklist" with no missing feature, the property and round-trip specs are green with no new known entry, and the oracle spec is green.

## Adding a feature (not a port)

A new query adds a method on the `DocumentSnapshot` interface and its implementation (`src/snapshot.ts`) and a folder `goldens/<id>/<query>/`. The runner discovers it with no code change: a feature with no renderer in `FEATURES` runs through the snapshot method of the same name (per `|` marker when the fixture has any) and prints ranges as `l:c-l:c "text"`. Add a renderer only when that output reads badly, and add the feature to `REQUIRED_FEATURES` when every facet must support it.
