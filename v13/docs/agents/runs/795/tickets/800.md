# #800 T4: block composite reads the cluster variables (done, one question)

**What:** `packages/diagram-block/src/render/paint.ts` gains `Paints.composite` (`compositePaint()`): where the theme carries no `borderColorArray` (a theme variable, D152; the same test `paletteSlots()` uses) and the model has a composite, a composite without a palette slot draws `fill` `clusterBkg` with `fill-opacity="0.5"` and `stroke` `theme.outline('clusterBorder')` with `stroke-opacity="0.2"` (v12's `.node .cluster` `fade(…)`). Under `useGradient` the stroke is the gradient, unfaded (v12 neo's rule won there). Opacities are `BLOCK_RENDER.compositeFillOpacity`/`compositeStrokeOpacity` (`render/metrics.ts`). `render.ts` `drawNode` applies it; an author's `style`/`classDef` fill or stroke drops the matching opacity (v12's inline style was opaque).

**Byte-identical where it must be:** under a palette theme, or with no composite, no cluster variable is read, so the root `style` and every attribute are unchanged. Checked by rendering every block fixture under `redux-color` and `redux-dark-color` before and after: only fixtures whose own front matter picks a palette-less theme moved.

**Fixture (#771's source):** `e2e/diagrams/block/baseline/themes/base-cluster-overrides.mmd`. `palette/off.mmd`'s description updated (redux composites now draw the cluster paint).

**Tests:** `packages/diagram-block/src/render/render.spec.ts` "a composite without a palette (#771)": the fixture (composite `clusterBkg #ffff00` @0.5, `clusterBorder #000000` @0.2, leaves `mainBkg #ff0000`), every palette-less theme, label stays `nodeTextColor`, style beats it opaque, neo gradient unfaded, nothing read without a composite or under a palette. `fixtureSource(path)` added to `layout/mmd.fixtures.ts` (reads a block fixture's raw source).

**Docs:** a row in `v13/docs/migration/block.md`'s SVG table; `pnpm regen` moved `MIGRATION.md` and `theme-variables.md` (block now listed under `clusterBkg`, `clusterBorder`).

**Core:** untouched.

**Decisions:**
- **Question (titleColor):** the ticket asks for a `titleColor` label. v12's composite label is a `g.label` sibling of `rect.cluster` (`labelHelper` in `shapes/util.ts`), so block's `.cluster text`/`.cluster span` rules never reach it, and `.label text,span` paints it `nodeTextColor`. Reading `titleColor` would change dark, forest, neutral and neo away from v12 (`#f9fffe`/`#333333`/`#000000` vs `nodeTextColor`). Not done; one line in `drawNode` if the maintainer wants it.
- **Choice:** `redux` and `redux-dark` (no palette, no gradient) now stroke composites `clusterBorder` @0.2; v12 `look: neo` drew `nodeBorder` there (neo's rule outranked `.node .cluster`). No theme variable separates the families without a core change; recorded in `migration/block.md`.
- Stroke width stays `strokeWidth` (v12's `.node .cluster` pinned 1px; out of scope, equal in the classic themes).

**Unmet:** `titleColor` (question above). Argos approves the new fixture and the moved block baselines (classic, redux, neo composites) in CI.
