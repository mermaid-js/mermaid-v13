# #800 T4: block composite reads the cluster variables (done)

**What:** block gains a theme table (`packages/diagram-block/src/theme/{vocabulary,table}.ts`, generated `theme/generated/variables.ts`, `plugin.theme`) with one flag, `blockCompositeClusterPaint` (alias `bcp`): `families.classic` true, `redux` false, `neo` falls back to redux. Where it is on and the theme carries no `borderColorArray` (variables, never a name, D152), `paint.ts` `compositePaint()` draws a composite without a palette slot with `fill` `clusterBkg` + `fill-opacity="0.5"` and `stroke` `theme.outline('clusterBorder')` + `stroke-opacity="0.2"` (v12's `.node .cluster` `fade(…)`); under `useGradient` the stroke is the gradient, unfaded. Opacities: `BLOCK_RENDER.compositeFillOpacity`/`compositeStrokeOpacity`. An author's `style`/`classDef` fill or stroke drops the matching opacity (v12's inline style was opaque). The label keeps `nodeTextColor` (v12's: its `g.label` is outside `rect.cluster`; orchestrator accepted).

**Use:** `themeVariables.blockCompositeClusterPaint: true|false` switches it in any theme (a flag, read literally, no CSS variable).

**Byte-identical:** flag off, palette on, or no composite: no cluster variable is read. Rendered all 90 block fixtures under redux, redux-dark, neo, neo-dark, redux-color, redux-dark-color and default with the pre-#800 renderer and with this one: every render whose effective theme is not classic is identical (only `default`-front-matter fixtures moved).

**Fixture (#771's source):** `e2e/diagrams/block/baseline/themes/base-cluster-overrides.mmd`. Block corpus counts 90 → 91, banded list, `yaml-tree/block.txt` digest.

**Tests:** `packages/diagram-block/src/render/render.spec.ts` "a composite without a palette (#771)": the fixture's colours and opacities, the five classic themes, redux/neo keep the leaf paint (and an author can turn the flag on), label `nodeTextColor`, style beats it opaque, gradient unfaded, nothing read without a composite or under a palette. `fixtureSource(path)` in `layout/mmd.fixtures.ts`. `blockTestTheme` now passes the table (`diagram: table`).

**Docs:** classic-only row in `v13/docs/migration/block.md`; `pnpm regen` updates `MIGRATION.md` and `theme-variables.md` (new block table; block under `clusterBkg`/`clusterBorder`).

**Core:** untouched.

**Decisions:** a flag rather than colour variables: a colour variable with a redux rule (`mainBkg`) would add an alias to the root style and break byte-identity. Stroke width stays `strokeWidth` (v12's `.node .cluster` pinned 1px; equal in the classic themes). Block is not added to conformance's `DIAGRAM_TABLES` (the flag has no v12 value to compare).

**Unmet:** none. Argos approves the new fixture and the moved classic block baselines in CI.
