# #797 T1: `base` derives by rule (done)

**What:** a `ThemeSpec.base` colour that is not a CSS colour (`checkColor` fails) is a rule in the DSL (`theme.ts` `fromSpec`, doc on `spec.ts` `base`). `specs/base.ts` writes `secondaryColor: adjustHue(primaryColor, -120)`, `tertiaryColor: lightenHsl(adjustHue(primaryColor, 180), 5%)`, `lineColor: invert(background)`, and one theme rule `arrowheadColor: invert(background)` (v12 derives it from `background`, not `lineColor`). The author's value still wins (`compute()` reads overrides first). `BASE_SECONDARY`/`TERTIARY` in base's palettes reduce to `secondaryColor`/`tertiaryColor`.

**Use:** a theme may write any base colour as a rule; it emits `var(--mermaid-x, <css of the rule>)`, so `--mermaid-primaryColor` / `--mermaid-background` on the host move the derived colours (R-THEME-4). No new API.

**Tests:** `packages/core/src/theme/theme.spec.ts` "base derives by rule" (stock values, `#3366cc` → `#66cc33`/`#d1a347`, `#222222` → `#dddddd`, author wins, CSS fallbacks). `themes.spec.ts` R-THEME-5 test now expects base's one rule and `arrowheadColor` `#000000` on a white background.
