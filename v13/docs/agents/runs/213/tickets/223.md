# #223 T0 core gradient: handoff

Branch `feature/223_core-gradient`. Core only; no renderer calls `theme.outline()` yet, so output is unchanged.

## Exports
- `Theme.outline(name): OutlinePaint`: `url(#<scope>-gradient)` (a `GradientRef`) when `useGradient` is on, else `theme.color(name)`. `Theme.gradient(): ThemeGradient | undefined` (`{ id, start, stop }`), for the pipeline.
- `@mermaid-js/core/svg`: types `GradientRef`, `OutlinePaint` (what `fill`/`stroke` take now), `StopColor`, `SvgGradient`, `GradientTag`, `GradientAttr`, `WriterOptions`; `streamWriter({ gradient })` / `treeWriter({ gradient })`; `InertOptions.gradient: string | false`.
- `ThemeOptions.idPrefix?: () => string` (lazy; read only when the gradient is on). Vocabulary: `useGradient` (new kind `flag`, a token: every spec sets `useGradient: false`), `gradientStart`/`gradientStop` (colours; LIGHT_RULES `primaryBorderColor`/`secondaryBorderColor` as v12 theme-base; redux specs `#0042eb`/`#eb0042`). `usedBy: ['core']`.

## How to use (T3–T7)
- Swap `theme.color('nodeBorder')` for `theme.outline('nodeBorder')` where v12 neo strokes with the gradient (see `v12-gradient.md`); type the paint table field `OutlinePaint`. `theme-used-by.spec.ts` sees only `outline('…')`'s argument, so `useGradient`/`gradientStart`/`gradientStop` stay `usedBy: ['core']`. Nothing else: `drawDiagram` hands `ctx.theme.gradient()` to the writer and the post-hook `assertInert`.
- Neo specs (#225/#227): `useGradient: true` in `tokens`; `gradientStart: '#0042eb'`, `gradientStop: '#eb0042'` in `values`.

## Design
- The id is `${styleScope(ctx.idPrefix)}-gradient` (`styleScope` turns `:r1:`-style prefixes into an XML name). The theme gets the prefix as a closure from `contextFor`, so the hash is computed only when the gradient is on.
- Writer: both backings note a `fill`/`stroke` equal to `url(#id)` (Stream while writing; Tree by scanning the live tree at `finish()`, so hook edits count) and splice `<defs>` after the root's start tag (the first `>`; attribute values escape `>`). No renderer root code changes. `defs`/`linearGradient`/`stop` and `offset`/`stop-color`/`stop-opacity`/`gradientUnits` are on the allow-list tables but refused by `checkTag`/`formatValue`, so only the writer emits them (renderers and `SvgTree.append`/`setAttr` throw).
- Markup: `<defs><linearGradient id="…" gradientUnits="objectBoundingBox" x1="0" y1="0" x2="1" y2="0"><stop offset="0" stop-color="var(--mermaid-gradientStart,#0042eb)"/><stop offset="1" …/></linearGradient></defs>`. **Deviation:** fractions, not the ticket's `0%`/`100%`: identical in objectBoundingBox units, and `x1`–`y2` stay in `NUMERIC_ATTRS` unchanged.
- Stops are `var(--mermaid-gradientStart,<computed literal>)`, not an alias: the defs are written after the root `style`, so an alias might be undeclared. Literal with `cssVariables: false`.
- `assertInert`: one `<defs>` as the root's first child, holding one `linearGradient` with exactly id + the fixed attributes, holding ≤ 2 `stop`s (`offset` 0–1 or %, `stop-color` a checked colour, `stop-opacity`); nothing else inside. `url(#<id>)` only on `fill`/`stroke`, only after the gradient, only that exact string. The id is `options.gradient` (the pipeline passes the render's id, or `false` = no defs at all), else the document's own, which must match `<scope>-gradient`. Another element with that id is rejected.
