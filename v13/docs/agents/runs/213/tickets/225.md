- `packages/core/src/theme/specs/neo.ts` (default export), behind `import()` (D180). `THEME_NAMES`

## What it carries

- Base `#cccccc` primary/secondary, `#ffffff` tertiary/background, `#333333` text, `#000000` lines,
  `arial, sans-serif` 14px. Tokens `strokeWidth` 2, `clusterStrokeWidth` 1, `radius` 3, `fontWeight`
  normal, spacing 4/8/16, and the redux geometry tables from `geometry.ts` (D181).
- `rules: REDUX_RULES`, chosen from the oracle. v12 neo, like v12 redux, sets `classText` from
  `textColor` and has no ER row variables, and the neo look fills the zero circle with the node fill.
- `values` pin v12 12.2.0's resolved values where the light rules (D71) miss them (borders
  `#b3b3b3`/`#e6e6e6`, `actorBorder #b3b3b3`, `noteBorderColor #e4db95`, `altBackground #f0f0f0`, …).
  `dropShadow` is `drop-shadow(0 1px 2px rgb(0 0 0 / 0.25))`, which `checkFilter` accepts. No palettes.
- Radius: v12 reads `themeVariables.radius` (`roundedRect.ts`, `state/styles.js` `rect.outer`) at fa796a943.
- Gradient: marked spot in `neo.ts` `values`; after #223, `useGradient` on, `#0042eb` → `#eb0042`.

## Tests

- `packages/conformance/src/neo-theme.spec.ts`: v12 via `loadOracle()`; compares every
  `THEME_VARIABLES` entry plus the palettes. `DIFFERENCES` gives each difference its D-id and fails on
  an unlisted or stale entry: `dropShadow` (syntax only, checked to be the same shadow),
  `cScale` (D181), the look geometry tokens (D181/D152, checked to equal redux's), the ER
  rows, `erMarkerFill` and `erEdgeLabelBackground` (D152, checked against what v12 neo draws), and
  `border1` (unset in v12, `usedBy` empty). The gradient names are listed as "added once #223 merges",
  in a test that is skipped once they are in the vocabulary. From then on the main comparison
  covers them, so it fails until neo sets them.
- AA (R-THEME-9) and inventory checks in `themes.spec.ts` loop over `THEME_NAMES`: neo is covered.
