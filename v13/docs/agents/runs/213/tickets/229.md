# #229 T3 flowchart neo gradient: handoff (branch `feature/229_flowchart-neo`)

## What changed
- `diagram-flowchart/src/render/render.ts`: node outline `theme.outline('nodeBorder')`, subgraph rect `theme.outline('clusterBorder')` (D182). Inner lines follow the outline, so cylinder rims, double-circle rings, braces, tag-doc ticks take it too, as v12's `[data-look=neo].node path/circle` rules do. Palette slots and author `style`/`classDef` strokes still win (spread order unchanged). Not on edges, edge labels, arrowheads, text, a collapsed card's separator and dots (D154).
- `shapes.ts` `usesPlain()`: `f-circ`, `fr-circ`, `lin-doc`, `browser` draw their inner lines/dots in plain `nodeBorder` when the gradient is on: v12 fills nothing with it, and a one-segment path (lin-doc's rule, browser's bar) has a zero-width/height box that an objectBoundingBox gradient doesn't paint. `f-circ` keeps the gradient stroke, filled nodeBorder (v12 `filledCircle`). No theme-name check (D152): keyed on `theme.gradient()`.
- `usedBy`: no change; `nodeBorder`/`clusterBorder` already list flowchart. `pnpm gen:theme` reran, output unchanged.
- Baselines `e2e/diagrams/flowchart/baseline/themes/{neo,neo-dark}.mmd` (the redux.mmd text); `fixtures.spec.ts` no longer pends neo/neo-dark.
