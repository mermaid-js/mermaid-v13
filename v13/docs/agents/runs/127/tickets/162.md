# #162: state T0, v12 source view in the core parser kit (D114)

Branch `feature/162_parser-kit-source-view`, cut from `mermaid-v13`. Core change (D102, D114).
Flowchart's `parser/source.ts` moved (git rename) to `packages/core/src/parser-kit/source-view.ts`.

## Exports (`@mermaid-js/core/parser-kit`, additive)

- `sourceView(src, from, directives, options?)` → `SourceView { mask, holes, text, runs, braceNewline }`.
  `from` is preprocess's `bodyStart`, `directives` its `%%{…}%%` ranges (sorted).
- `cook(src, start, end, view)`: v12's text for a source range (entities decoded, CRLF → LF, tag
  quotes as `'`, holes skipped; `}\s*\n` → `}\n` only when the view has `braceNewline`).
- `SourceOffsets` (text → source offset, O(1) near the last lookup), `localOffset`, `firstHole`,
  mask bits `QUOTE`, `DROP`; types `SourceView`, `Hole`, `SourceViewOptions`.
- `SourceViewOptions` (per type, D114): `tagQuotes` (default true), `styleSemicolons` (default
  true), `braceNewline` (default false). Comments and directives are always removed.

## Using it

- Flowchart: `flowSourceView()` in `diagram-flowchart/src/parser/lexer.ts` = `{ braceNewline: true }`.
- State (#142): call `sourceView(src, bodyStart, dirs)` with defaults. Not covered by the kit:
  state's `trimStart` after comment removal and its appended `\n`; the state lexer has to treat
  leading blanks as trivia and the end as a line break. The kit uses runs, not a per-char `at`
  array, so state's lexer reads offsets through `SourceOffsets` / `localOffset`.
- Tests: `packages/core/src/parser-kit/source-view.spec.ts` (worked examples, options, linear
  time at n vs 4n, bar 8x, as `preprocess/stress.spec.ts`).
