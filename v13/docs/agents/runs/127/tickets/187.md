# #187 handoff: layered counts a group's self-loop in the drawing size (state T0, D102)

Branch `feature/187_layered-group-selfloop`, cut from `mermaid-js/mermaid-v13`. Core change, approved
by the maintainer ("Fix in core now", D102).

## Change

- `packages/core/src/layout/layered/index.ts`: off the grid, a group's self-loop reserved no room
  (`src === dst && (src < nodeCount || grid)`), so the loop and its label ran outside the drawing
  and outside the parent group. Every self-loop now calls `reserveLoop`; a group keeps its box and
  takes the room round it (`loopW`/`loopH`), as it already did on the grid. The level layout sizes
  the group with that room, so the drawing and the parent group both hold the loop and label.
- No new exports, no API or type change.

## Tests

- `packages/core/src/layout/layered/group-loops.spec.ts`: hand-built `LayoutGraph` in the state
  fixture's shape (`Inactive --> Idle` into group `Active`, `Active --> Active`), TB and LR, with
  and without a label, top level and nested in a parent group with a sibling node.
  `validateLayout` is clean, and the loop's points and label box lie inside the drawing, inside the
  parent group, and clear of the sibling. Red before the fix (8 of 8 "runs outside the drawing").

## Flowchart

- `subgraph A … end` with `A --> A` was affected: the drawing now widens (TB) or grows (LR) to hold
  the loop. Checked by rendering the whole flowchart corpus (494 files) before and after: exactly one
  SVG changes, `e2e/diagrams/flowchart/visual-check/should-render-self-loops.mmd` (it has
  `C1 --> C1` and `D --> D` on subgraphs; viewBox 1142 → 1246 wide). Every other flowchart output,
  golden and snapshot is byte-identical; no vitest snapshot changed.

## Size
