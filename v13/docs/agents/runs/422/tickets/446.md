# Ticket 446: radar T2, grammar, parser, model, AST and ported specs

**Exports** (`@mermaid-js/diagram-radar`, runtime entry): `parseRadar(src, options?) → RadarParseResult` (`ParseResult<RadarModel, RadarDocument>`, never throws), `detectRadar(src, pre?)` (v12's `/^\s*radar-beta/` after front matter, directives, comments; `radar-betax` detects and then fails, as in v12), the codes `RADAR_UNKNOWN_AXIS`, `RADAR_TICKS_CLAMPED` (warnings), `RADAR_MISSING_ENTRY`, `RADAR_NO_AXES` (errors), types `RadarParseOptions` (`ParseOptions` + `preprocessed?`), `RadarDocument`, `RadarStatementNode`, `Radar{Header,Axis,Curve,Entry,Option,Text}Node`. Also `layoutRadar` and types `RadarLayout`, `RadarLayoutContext` from #447's `layout/` (for the conformance spec, as pie's #305 did).
- **Plugin hook for #448/#449:** `parse: (text, ctx) => parseRadar(text, { preprocessed: ctx.preprocessed })`. Without `preprocessed` the preprocess diagnostics are included.
- **Model** (`RadarModel`, **unchanged**, frozen) as v12's `db.ts` resolved it: axes and curves in source order (axes before curves whatever the text order), duplicates kept; label = converted `["…"]` else the name (`[""]` is `''`); positional entries as written, detailed ones reordered to the axes (first entry per axis wins; one naming no axis is dropped with one `RADAR_UNKNOWN_AXIS` warning per parse, the first at its range, the rest `related`); a count other than the axis count is kept (the layout skips the curve). Options: the last of each name, v12's defaults, `ticks > 32` → 32 with `RADAR_TICKS_CLAMPED` (range the value, `related` the option). `title` = last in-text title if non-empty, else `preprocessed.frontMatter.title` (D218), absent when neither; `accTitle`/`accDescr` the last value (`''` included). `warnings` = the warning diagnostics.
- **Semantic errors** (v12's messages verbatim, range = the curve, parsing goes on, the curve keeps the entries it has): `Missing entry for axis <label>` (first missing axis per curve), `Axes must be populated before curves for reference entries` (detailed entries, no axis at all).
- **AST** (`ast.children`, source order, root `doc`): `Header` `radar`; `Axis` `axis:<name>` (`@2`…, with `name`, `nameRange`, `label?`); `Curve` `curve:<name>` (`@2`…) with `children` `Entry` `<curveId>#k` (positional) or `<curveId>>axis` (detailed, `@2` for a repeat in the curve), each with `axis?`, `axisRange?`, `value`, `valueRange`; `Option` `opt:<name>` (`@2`…, `name`, `value`, `valueRange`); `Title`/`AccTitle`/`AccDescr` `title`, `title@2`, … with `text`. Ranges: Axis/Curve from the name to `]`/`}`; Option from the keyword; text from the keyword (blanks off). A failed statement has no node; finished items of a list before the error do.
- **Symbols** (D358): `axis` def for the first `axis X`, ref for a repeat and for every detailed entry name (resolved or not); `curve` def for each curve. **Statements**: `header`, `axis` / `curve` / `option` (one per list), `title`, `accTitle`, `accDescr`. **Probe**: `tested` hooks at every decision, punctuation and `String` followed (T6 tunes).
- **Diagnostics:** `UNEXPECTED` (Expected … got …, with hints: D357 "`circles` starts with the keyword `circle` …" where a name is expected or glued after one, list broken after `,`, newline before `,` in `{ }`, mixed entries, `{` on the next line), `UNEXPECTED_CHARACTER` (lexer error tokens: `;`, a `-` before a digit, bad numbers, non-ASCII), `UNCLOSED_STRING`, `UNCLOSED_ACC_DESCR` (`accDescr {` with no `}` lexes as a name then `{`). Recovery: to the next line break; inside a curve's braces to its `}` unless a line starts a statement; an error at a line end also skips the next line unless it starts a statement. Diagnostics sorted by position.
