## #486 T1 lexer
- Exploration: v12's token names are `HEXCOLOR`, `RGBCOLOR`, `RGBACOLOR`, `COMMA`, `COLON` (the spec's HEX/RGB/RGBA are short names). The registry row is at `registry.gen.ts:148`, not `:103`.
- Closed: the `yy` feedback runs both ways (the lexer calls `yy.setIndentMode(false)` itself, `text` returns no token after `INDENT_TEXT`). **Choice (done):** `loadJisonLexerOracle` extended additively: a `yy` builder's context gains `onToken(listener)` (called with each token of the run before the next lex), and the oracle gains `pulledTokens(source)`, the tokens v12's parser itself pulled during `oracle.parse` (wrapping `parser.lexer.lex` during that call only; jison's `lex` recurses after a skipped rule, so only the outer call records). `vennYy` (in `jison/types.ts`) is fresh per run: mode on from each `SET`/`UNION` token, off when the lexer says so. Other descriptors unchanged. `venn/yy-emulation.spec.ts` checks it over 2,065 sources (287 with `INDENT_TEXT`). Limit: the mode goes on at the `SET`/`UNION` token, v12's at the reduction; they differ only after a parse error, which v12's parser does not lex past.
- Oracle finding (spec text is off): `set AB%% c` lexes `IDENTIFIER:AB` and is stored as `AB`, not `A`; the glued-comment rule eats a character only when the `%%` follows the first character of a token (`set A%% c`, `:2%% c`, `[%% x]`). The gate follows v12.
- Oracle finding: "a `title` or `style` line ends the mode" is any line whose first non-blank is not `text` (an indented `  style` too, and an indented `  %%{-}`); a line glued to a comment (`x%% c`) and the comment lines v12 removed do not end it.
- Exclusion: the two `unclosed-directive-*` cases: core ends an unclosed `%%{x}` at its line end (`UNCLOSED_DIRECTIVE`), v12's directive regex took the rest of the text (as cynefin and pie exclude it).
- For T2: `INDENT_TEXT` is `T.IndentText` (the blanks) followed by `T.IndentTextKeyword` (the `text`, no jison name); a mid-line `%%` comment (with the character a glued one eats) is `Kind.Comment` trivia; skipped blanks are no token.

## #488 T2 parser
- Closed: model parity green over 2,263 sources (e2e, specs, cases and the gate variants as `venn-gate/…`), 33 listed divergences: the 2 `unclosed-directive-*` cases (core's directive reading, as quadrant and radar), 23 quoted titles (D416: `model.title` is compared with `getDiagramTitle()`, so last-wins and the quote removal are checked; `title-quoted`, `quoted-title.mmd`, the syntax page's example, and their variants) and 8 of `union-entity-sort` (below). The front-matter title is held back on both sides (the oracle never passes it on, as cynefin); D218's fallback is pinned in `parse.spec.ts`.
- **Choice (done):** one `subsets` list (v12's `getSubsetData()`: sets and overlaps in source order, a set is `sets.length === 1`), not separate `sets` and `overlaps` arrays: v12's order is one list, and slots follow it.
- **Choice (done):** D416 strips the quotes only when the trimmed title is wrapped in one pair (`title  "x" ` gives `x`); any other title is kept as v12 kept it, leading blank included (`title  Hello  ` gives ` Hello  `).
- **Choice (done, review):** a `union` failing v12's checks (`VENN_UNION_ONE_SET`, `VENN_UNKNOWN_SET`, v12's message first) is left out of the model, as v12 added nothing, and gives the indented `text` lines after it no sets: they keep their AST nodes and are not in the model (no `VENN_UNKNOWN_TARGET` for them). Cases `recovery-text-after-unknown-union`, `recovery-text-after-one-set-union`. The unknown-set hint quotes an id that is not a bare id or is a keyword (`` `set "x+y"` ``).
- **Choice (done, review):** recovery resumes at the next statement keyword (`set`, `union`, `text`, `style`, `title`) or line break, since v12 allows several statements on a line; a keyword where a statement wanted something else starts the next statement (`set A: set Ä` gives two diagnostics). What recovery skips inside a bad statement is not reported again, so each bad statement gives one diagnostic; v12's two DB checks add theirs. 27 recovery cases (65 errors), 7 lines with two to four errors. Lexer-error codes `UNCLOSED_STRING`, `UNCLOSED_LABEL` (`[` with no `]`), `UNEXPECTED_CHARACTER` (a run of adjacent bad characters is one).
- **Choice (done):** AST ids percent-encode `+` (`%2B`) too, so `union:a%2Bb+c` stays unambiguous; XML-invalid characters as cynefin.
- **Choice (done):** `VENN_UNKNOWN_TARGET` treats a pair of a three-or-more overlap as drawn (v12's `ensurePairwiseSubsets` adds it) and a one-id style naming a text node as known; `VENN_EMPTY` only when the parse has no error. `VENN_ZERO_SET` is left to T3, as the ticket allows.
- Oracle finding: a `__proto__` style key is dropped by v12's plain-object `styles`; v13's `properties` is a plain object too, so the same. Not in the corpus.
- Listed divergence (review): v12 sorts member ids in its placeholder text (`ﬂ°°35¶ßx` after `b`), v13 in the text as written (`&#35;x` before `b`), so an overlap of quoted ids holding an entity lists its ids in another order (case `union-entity-sort`). Sorting v12's way needs the placeholder text per token, which v13's text does not keep (a literal `&amp;` and `#amp;` read the same).
- For T6: the grammar's lexer modes `on` / `onBol` carry the indent mode (a zero-width `pop pop` ends it); the highlighters give both modes the same scopes, so the four-way agreement should hold, but it is T6's spec. Symbols are `set` and `text` (D418), statement spans `header`, `set`, `union` (holding their indented `text` lines), `text`, `style`, `title`.

## #491 T3 layout

- Exploration: `Upstream` takes one `holder` and one `copyright` (`licenses.ts:22–29`); venn.js has two holders (Ben Frederickson 2013, Samuel Gratzl 2021). T3 extends the shape additively (a list) rather than dropping one.
- Exploration: venn.js `wrapText` does not cap at three lines and wraps to the first set's radius; core `layoutLabel` has no max-lines option. The three-line cap (D414) is package code.
- Exploration: v12's two solves differ: `VennDiagram` (drawn circles) drops zero-size sets, `venn.layout()` (text nodes, hand-drawn) does not and rounds to 2 decimals. D412's one solve is the drawn one (unrounded, zero sets dropped); parity compares against that path.
- Exploration: venn.js 2.0.0 runs in plain Node (no DOM); the solver parity spec may import it directly. It is not yet a direct conformance dependency (`@upsetjs/venn.js@2.0.0` as a dev dependency, pinned).
- Closed: the solver is ported in `src/solver/` (`circles`, `fmin`, `solve`, `normalize`, `regions`, `index`) with venn.js's arithmetic in its order; the conformance parity spec (`venn/layout-parity.spec.ts`, venn.js 2.0.0 imported, pinned dev dependency) finds it bit-identical: 391 generated two- and three-set inputs, 144 corpus sources of up to three sets, and 60 four- to six-set inputs with venn.js's `Math.random` drawing the same fixed-seed sequence.
- **Choice (done):** attribution follows the code's origin: `fmin.ts` (bisect, Nelder–Mead, conjugate gradient, as venn.js bundles them) names fmin's BSD-3-Clause (`Copyright 2016, Ben Frederickson`) and venn.js's MIT; the other five solver files name venn.js's MIT and both holders. `THIRD_PARTY_NOTICES` has a `venn.js` and a `fmin` section. `licenses.ts` gains, additively, an optional `license` (`MIT` default, `BSD-3-Clause`) and holder/copyright lists, `venn.js` and `fmin` in `UPSTREAMS`, and the six solver files in `REQUIRED_CREDITS`. The check skips private packages, so `licenses.spec.ts` runs it on a copy of `diagram-venn` without `"private"` (T5 makes the real check bite). **For the maintainer.**
- **Choice (done):** D412's padding is `venn.padding` when given, else 15 (`VENN_METRICS.padding`). **For T5:** the schema default is 8; if `gen:config` puts `padding: 8` in `configDefaults`, every diagram solves at 8. - **Choice (done):** `VENN_ZERO_SET` is raised by the layout (`ctx.warn`), once, naming every set laid out at 0: a size of 0, a negative one (D417, also `VENN_INVALID_SIZE` from the parser) and one whose square is not finite (309 digits; v12 drew NaN). Their overlaps go too.
- **Choice (done):** `VENN_CONFIG_INVALID`, one warning naming every `venn` value the layout cannot use (`width`/`height` below 1 or not a number, `padding` below 0, `useDebugLayout` not a boolean); a padding that leaves no room (`2p ≥ min(width, chart height)`) falls back to 0 with the same code. - **Choice (done):** labels wrap at the first set's radius (venn.js's `wrapText` width; the region's radius for a set) with `keepWords`; past three lines, the narrowest wider width that gives three (24 halvings), and a label written on four or more lines keeps them. - **Choice (done):** an area venn.js marks `disjoint` (label at y −1000, `M 0 0` path) gets no label, no outline and no text nodes; v12 drew them off the canvas.

## #495 T4 renderer
- Exploration: `w.outline` takes no sketch options; settings are fixed per role in `plugin-hand-drawn/src/roles.ts` and `fillStyle` is solid or hachure only (`sketch.ts:128`). v12's venn values (fill weight 2, gap 8, angle −41 + 60i, cross-hatch for a styled overlap) are not expressible. **Choice (planned):** use the closest existing role with no hand-drawn plugin change, and list v12's parameters as a MIGRATION.md row. **For the maintainer:** an additive per-call option on `w.outline` is the alternative.
- Exploration: "palette on when `borderColorArray` is non-empty" cannot be a theme rule (slots past the end read `currentColor`; `inline()` rejects palette slots). **Choice (planned):** the renderer reads `theme.palette('borderColorArray')` (flowchart's `paletteSlots` precedent; a palette, not a theme name) and, when non-empty, slot i is `borderColorArray[i mod len]`; else `venn<i mod 8 + 1>` when written; else `primaryColor`. The table's `venn1`–`venn8` rows hold the classic formulas only.
- Exploration: v12's set-label colour uses `isDark(background)` (luminance of the resolved background, `vennRenderer.ts:120`), not a theme trait. **Choice (planned):** follow the spec and v12: luminance of the resolved `background` value, so an author's dark background in a light theme behaves as in v12.
- Exploration: core has `rgbToHsl`/`shiftHsl`/`hslToRgb` but does not export them; lightening an author's `style.fill` by 30 needs either a core subpath export (only if the CDN core closure does not grow) or package code. T4 measures and picks.
