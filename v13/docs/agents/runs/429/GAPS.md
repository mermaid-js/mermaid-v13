## #486 T1 lexer
- Exploration: v12's token names are `HEXCOLOR`, `RGBCOLOR`, `RGBACOLOR`, `COMMA`, `COLON` (the spec's HEX/RGB/RGBA are short names). The registry row is at `registry.gen.ts:148`, not `:103`.
- Closed: the `yy` feedback runs both ways (the lexer calls `yy.setIndentMode(false)` itself, `text` returns no token after `INDENT_TEXT`). **Choice (done):** `loadJisonLexerOracle` extended additively: a `yy` builder's context gains `onToken(listener)` (called with each token of the run before the next lex), and the oracle gains `pulledTokens(source)`, the tokens v12's parser itself pulled during `oracle.parse` (wrapping `parser.lexer.lex` during that call only; jison's `lex` recurses after a skipped rule, so only the outer call records). `vennYy` (in `jison/types.ts`) is fresh per run: mode on from each `SET`/`UNION` token, off when the lexer says so. Other descriptors unchanged. `venn/yy-emulation.spec.ts` checks it over 2,065 sources (287 with `INDENT_TEXT`). Limit: the mode goes on at the `SET`/`UNION` token, v12's at the reduction; they differ only after a parse error, which v12's parser does not lex past.
- Oracle finding (spec text is off): `set AB%% c` lexes `IDENTIFIER:AB` and is stored as `AB`, not `A`; the glued-comment rule eats a character only when the `%%` follows the first character of a token (`set A%% c`, `:2%% c`, `[%% x]`). The gate follows v12.
- Oracle finding: "a `title` or `style` line ends the mode" is any line whose first non-blank is not `text` (an indented `  style` too, and an indented `  %%{-}`); a line glued to a comment (`x%% c`) and the comment lines v12 removed do not end it.
- Exclusion: the two `unclosed-directive-*` cases: core ends an unclosed `%%{x}` at its line end (`UNCLOSED_DIRECTIVE`), v12's directive regex took the rest of the text (as cynefin and pie exclude it).
- For T2: `INDENT_TEXT` is `T.IndentText` (the blanks) followed by `T.IndentTextKeyword` (the `text`, no jison name); a mid-line `%%` comment (with the character a glued one eats) is `Kind.Comment` trivia; skipped blanks are no token.

## #488 T2 parser
- Closed: model parity green over 2,221 sources (e2e, specs, cases and the gate variants as `venn-gate/…`), 2 listed divergences (the `unclosed-directive-*` cases, core's directive reading, as quadrant and radar). The title is compared as v12 kept it (the AST's `text`); D416 and D218 are pinned in `parse.spec.ts`, and the front-matter title is held back on both sides (the oracle never passes it on, as cynefin).
- **Choice (done):** one `subsets` list (v12's `getSubsetData()`: sets and overlaps in source order, a set is `sets.length === 1`), not separate `sets` and `overlaps` arrays: v12's order is one list, and slots follow it.
- **Choice (done):** D416 strips the quotes only when the trimmed title is wrapped in one pair (`title  "x" ` gives `x`); any other title is kept as v12 kept it, leading blank included (`title  Hello  ` gives ` Hello  `).
- **Choice (done):** a `union` failing v12's checks (`VENN_UNION_ONE_SET`, `VENN_UNKNOWN_SET`, v12's message first) is left out of the model, as v12 added nothing, but keeps its AST node and gives the indented `text` lines after it its sets.
- **Choice (done):** one syntax diagnostic per line: after a syntax or lexer error the parser skips to the line break without reporting what follows on that line (cynefin reports every lexer error); v12's two DB checks do not stop a statement, so a line can give two. Lexer-error codes `UNCLOSED_STRING`, `UNCLOSED_LABEL` (`[` with no `]`), `UNEXPECTED_CHARACTER` (a run of adjacent bad characters is one).
- **Choice (done):** AST ids percent-encode `+` (`%2B`) too, so `union:a%2Bb+c` stays unambiguous; XML-invalid characters as cynefin.
- **Choice (done):** `VENN_UNKNOWN_TARGET` treats a pair of a three-or-more overlap as drawn (v12's `ensurePairwiseSubsets` adds it) and a one-id style naming a text node as known; `VENN_EMPTY` only when the parse has no error. `VENN_ZERO_SET` is left to T3, as the ticket allows.
- Oracle finding: a `__proto__` style key is dropped by v12's plain-object `styles`; v13's `properties` is a plain object too, so the same. Not in the corpus.
- Not covered: v12 sorts member ids in its placeholder text (`ﬂ°amp¶ß`), v13 in the decoded text (`&amp;`), so a quoted id holding an entity can sort differently. Not in the corpus, not listed.
- For T6: the grammar's lexer modes `on` / `onBol` carry the indent mode (a zero-width `pop pop` ends it); the highlighters give both modes the same scopes, so the four-way agreement should hold, but it is T6's spec. Symbols are `set` and `text` (D418), statement spans `header`, `set`, `union` (holding their indented `text` lines), `text`, `style`, `title`.

## #495 T4 renderer
- Exploration: `w.outline` takes no sketch options; settings are fixed per role in `plugin-hand-drawn/src/roles.ts` and `fillStyle` is solid or hachure only (`sketch.ts:128`). v12's venn values (fill weight 2, gap 8, angle −41 + 60i, cross-hatch for a styled overlap) are not expressible. **Choice (planned):** use the closest existing role with no hand-drawn plugin change, and list v12's parameters as a MIGRATION.md row. **For the maintainer:** an additive per-call option on `w.outline` is the alternative.
- Exploration: "palette on when `borderColorArray` is non-empty" cannot be a theme rule (slots past the end read `currentColor`; `inline()` rejects palette slots). **Choice (planned):** the renderer reads `theme.palette('borderColorArray')` (flowchart's `paletteSlots` precedent; a palette, not a theme name) and, when non-empty, slot i is `borderColorArray[i mod len]`; else `venn<i mod 8 + 1>` when written; else `primaryColor`. The table's `venn1`–`venn8` rows hold the classic formulas only.
- Exploration: v12's set-label colour uses `isDark(background)` (luminance of the resolved background, `vennRenderer.ts:120`), not a theme trait. **Choice (planned):** follow the spec and v12: luminance of the resolved `background` value, so an author's dark background in a light theme behaves as in v12.
- Exploration: core has `rgbToHsl`/`shiftHsl`/`hslToRgb` but does not export them; lightening an author's `style.fill` by 30 needs either a core subpath export (only if the CDN core closure does not grow) or package code. T4 measures and picks.
- Exploration: v12's `VennDiagramConfig` defaults `venn.theme` to `'redux-color'` and `venn.look` to `'neo'` (`config.schema.yaml:3070–3100`, docs page L13–19). **Answered (coordinator, 2026-11-08):** 12.2.0 ships `venn:{useMaxWidth:!0,theme:"redux-color",look:"neo",…}` in its defaults (`mermaid@12.2.0/dist/chunks/mermaid.core/chunk-DSNLSHJZ.mjs`), and v12's `resolveAppearance` (`fa796a943:packages/mermaid/src/config.ts:76–104`) ranks the diagram's default above the global default, below `initialize()` and the diagram text. So a plain `venn-beta` with no theme set draws in **redux-color** (palette from `borderColorArray`) in v12; an explicit `theme` anywhere wins. v13's `resolveAppearance` (`packages/core/src/config/resolve.ts:302`) does the same once `venn.theme` is honoured (#501). T4's render specs should pass the theme explicitly; the default-render case belongs to T5.
