# #141 T3 sequence layout: handoff

## Exports (`@mermaid-js/diagram-sequence`, also `src/layout/index.ts`)
- `SequenceModel` and its parts (`src/model.ts`): the shared contract #139 adopts. Participants in first-mention order (`kind`, `label`, `alias?` as written, `wrap?`, `box?`, `createAst?`/`destroyAst?` = the `create`/`destroy` statement, `createdBy?`/`destroyedBy?` = the message); `boxes`; one ordered `statements` tree: `message` (`arrow` = v12 LINETYPE name lower-cased, `activation?: 'activate'|'deactivate'` for `+`/`-`, `central?: 'to'|'from'|'both'`), `note` (`placement`, one or two participants), `activation`, `fragment` (`sections[0].label` is the fragment label; later sections carry the `else`/`and`/`option` AST id; `wrap?` per section), `rect`, `autonumber`; `title`, `accTitle`, `accDescr`, `warnings`. `wrap: undefined` follows `sequence.wrap` / global `wrap`. Parser contract (model.ts header): every id a statement names is declared (v12 auto-adds); `autonumber N` is `{start: N, step: 1}`.
- `layoutSequence(model, ctx)`: `ctx` is `Pick<RenderContext, 'config'|'measurer'|'units'|'theme'|'warn'>`. Returns `SequenceLayout` (`src/layout/types.ts`): participants (box x/width/height, `top`, mirrored `bottom`, lifeline), messages (line `y`, `startX`/`stopX` with head room off, placed label, `self` loop, `number`), activations (with `depth`), notes, fragments (tab, title, section dividers, `depth`), rects, boxes, title, `bounds` (v12's viewBox, grown to hold everything).
- `sequenceLayoutViolations(model, layout)`: the invariants as readable strings, each independent of the layout's own formulas, with a 1e-6 tolerance: no NaN; every model message/note laid out; messages inside both participants' span and columns (bars included); frames contain member lines, labels, notes, nested frames, tab, title, section labels; notes clear of participant boxes; a first bar covers its lifeline, a stacked bar starts on the bar below it; columns apart. Bounds containment is not checked: the layout grows `bounds` to hold everything by construction. Use it on parser-produced models once #139 lands.
- `metricsTable(units)`, `sequenceMetrics(units, config.sequence)`, `REVERSE_ARROWS`.

## How it works
- `layout/metrics.ts` is the only file with length literals (px = v12 schema defaults and renderer constants; cell = hand-scaled). Config px values go through `fromPx` per axis with the profile's minimum. `packages/conformance/src/sequence-layout-literals.spec.ts` enforces it.
- Passes: `columns.ts` (measure, actor margins, box margins, place) → `geometry.ts` (x pass, v12 `calculateLoopBounds`) → `rows.ts` (y pass, v12 draw loop) → `layout.ts` (bottom row, boxes, title, bounds).
- Cells: every coordinate is a whole cell (`half()` floors); spec checks it.

## Test helpers
- `src/layout/fixtures.ts`: hand-built models (`FIXTURES`, `hello`) and builders (`p`, `msg`, `note`, `act`, `frag`, `rect`, `model`), not exported from the package.
- `src/layout/regressions.spec.ts`: the #141 review inputs, and a 200-config seeded fuzz over all fixtures in px and cells.
- `src/layout/layout.spec.ts`: invariants on every fixture × {px, cell} × {default, every option changed}; v12 px numbers for two participants; cell numbers.

## Size
- Layout alone 21.2 KB min / 7.1 KB gz; with the invariants 24.8 KB / 8.3 KB gz (esbuild, core external).

## Deviations from v12 (all listed in `layout.ts` header)
- Small bug fixes: box grows with a multi-line label or a word longer than `width`; a creating/destroying message moves down so the box centred on it clears the row above; frames hold message labels, self loops, their title and section labels (v12 let them overrun); a box with no visible member takes no room; `autonumber N` restarts the step at 1; empty frame spans the columns; a frame reaches past its last section title and holds its tab; tab width fits its keyword (v12 fixed 50); row after a created stick figure starts below it; `deactivate` with nothing open is ignored; lifelines and bottom boxes start below the tail of any short activation; non-mirrored lifelines end where bottom boxes would start (v12: y=2000, clipped). A statement naming an undeclared participant is left out with a `SEQUENCE_UNKNOWN_PARTICIPANT` warning; a left-out message still takes its sequence number. The px minimum of `activationWidth` is 1. Unclosed activations are not drawn (as v12).
- Not ported: v12's `look: neo` geometry (no look in v13), the activation-top quirk from `updateBounds`, popup menu sizing.
- Fonts: family keys inherit the theme `fontFamily`; size/weight keys apply when set, else the theme `fontSize`. v12 overwrote every per-key size with the global `fontSize` (16), so the effective v12 default is kept, but a set `messageFontSize` etc. now takes effect. Needs a maintainer nod (T5, `configDefaults` would make 14/16 the defaults).

## Unmet
- Invariants on parser-produced fixtures: waits for #139 (GAPS).
- A message to a participant after its destroying message is drawn below the participant's end, as in v12; the span invariant reports it. Whether the parser rejects it is #139's call.
