# #141 T3 sequence layout: handoff

## Exports (`@mermaid-js/diagram-sequence`, also `src/layout/index.ts`)
- `SequenceModel` and its parts (`src/model.ts`): the shared contract #139 adopts. Participants in first-mention order (`kind`, `label`, `wrap?`, `box?`, `createdBy?`/`destroyedBy?` = AST id of the message); `boxes`; one ordered `statements` tree: `message` (`arrow` = v12 LINETYPE name lower-cased, `activation?: 'activate'|'deactivate'` for `+`/`-`, `central?: 'to'|'from'|'both'`), `note` (`placement`, one or two participants), `activation`, `fragment` (`sections[0].label` is the fragment label; later sections carry the `else`/`and`/`option` AST id), `rect`, `autonumber`; `title`, `accTitle`, `accDescr`, `warnings`. `wrap: undefined` follows `sequence.wrap` / global `wrap`.
- `layoutSequence(model, ctx)`: `ctx` is `Pick<RenderContext, 'config'|'measurer'|'units'|'theme'|'warn'>`. Returns `SequenceLayout` (`src/layout/types.ts`): participants (box x/width/height, `top`, mirrored `bottom`, lifeline), messages (line `y`, `startX`/`stopX` with head room off, placed label, `self` loop, `number`), activations (with `depth`), notes, fragments (tab, title, section dividers, `depth`), rects, boxes, title, `bounds` (v12's viewBox, grown to hold everything).
- `sequenceLayoutViolations(model, layout)`: the invariants as readable strings (no NaN, messages inside both participants' span and columns, frames contain members/nested frames/tab/dividers, notes clear of participant boxes, activations on their lifeline, everything in bounds, columns apart). Use it on parser-produced models once #139 lands.
- `metricsTable(units)`, `sequenceMetrics(units, config.sequence)`, `REVERSE_ARROWS`.

## How it works
- `layout/metrics.ts` is the only file with length literals (px = v12 schema defaults and renderer constants; cell = hand-scaled). Config px values go through `fromPx` per axis with the profile's minimum. `packages/conformance/src/sequence-layout-literals.spec.ts` enforces it.
- Passes: `columns.ts` (measure, actor margins, box margins, place) → `geometry.ts` (x pass, v12 `calculateLoopBounds`) → `rows.ts` (y pass, v12 draw loop) → `layout.ts` (bottom row, boxes, title, bounds).
- Cells: every coordinate is a whole cell (`half()` floors); spec checks it.

## Test helpers
- `src/layout/fixtures.ts`: hand-built models (`FIXTURES`, `hello`), not exported from the package.
- `src/layout/layout.spec.ts`: invariants on every fixture × {px, cell} × {default, every option changed}; v12 px numbers for two participants; cell numbers.

## Size
- Layout alone 21.2 KB min / 7.1 KB gz; with the invariants 24.8 KB / 8.3 KB gz (esbuild, core external).

## Deviations from v12 (all listed in `layout.ts` header)
- Small bug fixes: box grows with a multi-line label; empty frame spans the columns; a frame reaches past its last section title and holds its tab; tab width fits its keyword (v12 fixed 50); row after a created stick figure starts below it; `deactivate` with nothing open is ignored; non-mirrored lifelines end where bottom boxes would start (v12: y=2000, clipped). Unclosed activations are not drawn (as v12).
- Not ported: v12's `look: neo` geometry (no look in v13), the activation-top quirk from `updateBounds`, popup menu sizing.
- Fonts: family keys inherit the theme `fontFamily`; size/weight keys apply when set, else the theme `fontSize`. v12 overwrote every per-key size with the global `fontSize` (16), so the effective v12 default is kept, but a set `messageFontSize` etc. now takes effect. Needs a maintainer nod (T5, `configDefaults` would make 14/16 the defaults).
