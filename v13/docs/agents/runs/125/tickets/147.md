# #147 actor menus in plugin-interactions (T0 into `mermaid-v13`)

Branch `feature/147_interactions-actor-menus`, base `mermaid-js/mermaid-v13` (merged at 0fcb0a4bf). Review fixes (10 items) are in.

**Contract (core):**
- `AstMenu` (`@mermaid-js/core/parser-kit`) is `{ target, links?, properties?, details? }`, on a node field `menu`. Like `callback`, that field name is reserved on every AST node, and values of another shape are skipped.
- `ExtensionClaim` gains `'menus'`.

**Plugin structure:** a feature table (`FEATURES` in `index.ts`, contract in `feature.ts`). Each entry owns one AST field, with `start(ctx)`, `collect(value)`, then `plan(doc)`, which gives `{ key, bind(scope) }`. Class #158 adds one entry and one file. `scope.ts` gives each feature the diagram root svgs in `el`, picked by the render's `data-id` sequence when `el` holds several, plus `anchors(ids, accept?)` (innermost `g[data-id]`) and listeners that tear down.

**Binding is per svg and keyed on content:** the same interactions bind once, and different ones replace that svg's menus and listeners. `mount()` now calls `bindFunctions` on every render, including when the svg string is unchanged (`packages/mermaid/src/dom.ts`). Flowchart callbacks use the same path, on `g.node` groups.

**Menus (`menus.ts`):**
- **DOM:** `div.actorPopupMenu[data-menu-for][data-mermaid-menu]` goes right after the svg and never inside it. Earlier menus after that svg are removed on re-bind.
- **Links:** `a.actor[target=_blank][rel=noopener noreferrer]`. URLs go through `checkUrl` (`securityLevel`, `linkSchemes`), and a refused one becomes `about:blank` with `URL_REFUSED` (v12 `sanitizeUrl`).
- **Merging:** labels enumerate with integer-like keys first (v12 objects). Bags are null-prototype, and `__proto__`, `constructor` and `prototype` are skipped. `properties.class` adds plain class names to the panel. `details` reads the page element's JSON at mount.
- **Placement:** absolute with no `left`/`top`, so the menu sits at its static position after the svg and follows reflow. Margins offset it to below the first anchor. It is re-placed on every show, and a forced menu also on svg resize (`ResizeObserver`), which covers mounting while hidden.
- **`forceMenus`:** `<diagram>.forceMenus` shows every menu and binds no click.

**What sequence must emit (integration branch, after merging `mermaid-v13`):**
- Add `menu?: AstMenu` to `SequenceMenuStmt`.
- `Links`/`Link` → `menu: { target: participant, links }`. Leave `links` out when the JSON was rejected.
- `Properties` → `menu: { target: participant, properties }`.
- `Details` → `menu: { target: participant, details: text }`.

#143's `data-id` on `g.actor-top` and `g.actor-bottom` is what the menu binds to.

**Open, for the maintainer:**
- Review item 9 asked for a missing-plugin warning. Spec #125 user story 20 says menus are "ignored silently in static output", so no warning is added. The `menus` claim exists, so sequence could warn (`MENU_IGNORED`) if the maintainer decides otherwise.
- The svg root has no id and `RenderResult` has no `id`, so scoping uses the `data-id` sequence. Two identical drawings in one element both match the later render.

**Tests:**
- Unit: `menus.spec.ts` and `index.spec.ts` use a shared fake DOM (`src/testing/fake-dom.ts`) and a `sequence` test diagram (`src/testing/menu-diagram.ts`, which draws #143's groups). Both are excluded from the build. Placement checks use real per-element rects.
- E2E: `e2e/dom/interactions.spec.ts` covers nested groups, two diagrams in one element, `mount().update` with changed menus, `forceMenus` (reflow and resize) and `details`.

**Checks:**
- `pnpm check`: green (6421 tests).
- `e2e:dom`: chromium + firefox, 42/42.
- WebKit: not run here; the orchestrator runs it in the Playwright image.

**Size:** plugin's own code 0.70 → about 3 KB gz. The `mermaid` bundle is unchanged apart from three lines in `dom.ts`.

**Deviations:**

- Inline neutral styles (`Canvas`/`CanvasText`).
- The lifeline isn't clickable.
