# #147 actor menus in plugin-interactions (T0 into `mermaid-v13`)

Branch `feature/147_interactions-actor-menus`, base `mermaid-js/mermaid-v13` (merged at 4d413bcd4).

**Contract (core, type only):** `AstMenu` from `@mermaid-js/core/parser-kit`: `{ target, links?, properties?, details? }`. Any AST node with a `menu: AstMenu` field is a menu statement. `target` is the rendered `data-id`. Statements for one target fold in source order, and later labels/keys replace earlier ones in place (v12 `insertLinks`/`insertProperties`).

**Plugin (`packages/plugin-interactions/src/menus.ts`):**
- `postParse`: a table of per-field collectors (`COLLECTORS` in `index.ts`: `callback`, `menu`). Class #158 adds an entry for its field and needs no node kinds. Links go through `checkUrl` with the render's `securityLevel`/`linkSchemes`. A refused or non-string URL drops that entry with `URL_REFUSED`.
- `afterMount`: one `div.actorPopupMenu[data-menu-for=<target>]` per target, appended to the mount element (HTML, never svg). Inside it: `div.actorPopupMenuPanel` + `properties.class` (only plain class names), then `a.actor[href][target=_blank][rel=noopener noreferrer]` with the label as `textContent`. It binds to the target's innermost `g[data-id]` groups (falling back to the outermost `[data-id]` elements), and a click toggles it. It opens below the first group. `<diagram>.forceMenus` (read as `config[ctx.diagram].forceMenus`) shows it with no listener. A target with no safe link gets no menu. `details` is read at mount: `document.getElementById(id).textContent` as JSON `{links, properties}`. Its links are checked too, with no warning sink. Bound elements live in a module `WeakSet`, so repeated `bindFunctions` calls, even from another render, add nothing.
- Flowchart `click` callbacks are unchanged (existing specs pass unmodified).

**What sequence must emit (integration branch, after merging `mermaid-v13`):** in `parser/ast.ts`, add `menu?: AstMenu` to `SequenceMenuStmt`. The parser then sets:
- `Links`/`Link` → `menu: { target: participant, links }`, leaving `links` out when the JSON was rejected
- `Properties` → `menu: { target: participant, properties }`
- `Details` → `menu: { target: participant, details: text }`

The renderer already writes `data-id=<participant name>` on `g.participant` and on the `g.actor-top`/`g.actor-bottom` groups, so top and bottom both toggle and the menu opens under the top symbol. Sequence must draw nothing for menus and warn nothing when the plugin is absent. `properties.class`/`icon` on the actor symbol stay sequence render concerns.

**Tests:** `menus.spec.ts` (fake DOM parsed from the svg, `withMenus` AST-injecting extension, and a `sequenceLike` fixture diagram registered as `sequence` that draws #143's nested groups). It covers bind-once, unsafe URLs, strict/linkSchemes, svg unchanged + `assertInert` over `PAYLOADS`, forceMenus, merge/details, and no plugin. Also `e2e/dom/interactions.spec.ts` "element menu" (real browser: toggle, placement under the node, no duplicates).

**Checks:** `pnpm check` green (5304 tests) before and after the merge. `e2e:dom` chromium + firefox 34/34. WebKit not run: it won't launch on the macOS host and the docker run was denied, so it needs a run in the Playwright image.

**Size:** plugin's own code 0.70 → 2.24 KB gz (2.89 KB with core's `checkUrl`, which `mermaid` already ships). The `mermaid` bundle is unchanged (the core change is a type).

**Deviations/notes:** the menu sits outside the svg, so v12's svg growth for popups (`drawActorsPopup` bounds) does not apply. It uses inline neutral styles (`Canvas`/`CanvasText`), not `actorBkg`. The lifeline (outer `g.participant`) is not clickable, only the symbols are.
