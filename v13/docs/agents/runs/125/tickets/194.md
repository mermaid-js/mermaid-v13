# #194 Neo geometry as theme variables: handoff

Branch `feature/194_sequence-neo-geometry`. The redux themes draw v12's `look: neo` sequence geometry, the classic themes v12 classic, from theme variables only (D152). No theme name or `look` is read.

## Exports
- Core theme variables (vocabulary, `specs/geometry.ts` `NEO_SEQUENCE`/`CLASSIC_SEQUENCE`, schema, `gen:config`/`gen:theme`), redux / classic: `actorGlyphBand` 44 / 0, `messageEndGap` 3 / 0, `labelBoxExtraHeight` 15 / 0, `actorFooterPadding` 30 / 0.
- `layout/metrics.ts`: `ThemeLengths` (`glyphBand`, `messageEndGap`, `labelBoxExtra`, `footerPadding`, from the theme), `themeLengths(units, theme)`; `SequenceMetrics` extends it; `sequenceMetrics(units, config, theme?)` (no theme = classic). Fixed lengths appended to both tables: `stackOffset`, `figureRadius`, `glyphLabelGap`, `labelLifelineGap` (px 6/22/6/6, cell 0); `symbolLabelTop.collections` is gone (`stackOffset` replaces it).
- `ParticipantLayout`, additive: `band?: GlyphBand` (`height`, `top`/`bottom` = box top to the band's bottom edge), set only for actor, boundary, control, entity and database (`GLYPHS` in `layout.ts`, the one list); `stackInset?` for `collections` under the band model; `bottomLabelY?`.
- `sequenceLayoutViolations` checks rows: a lifeline starts at or below its row's bottom; a band lies inside its row; a label lies under its band and inside the row, top and bottom.

## How it works
- `actorGlyphBand` > 0 turns on v12's band model (`actorBands.ts`): every row is `max(height, band + 6 + label + 6)` for every kind; every lifeline starts at the row's bottom; actor, boundary, control, entity and database stand on the band (the header stack grows up from the lifeline, the footer stack down); every symbol is scaled to the band: round circles r = band / 2 (other parts by band / 44), the stick figure by band / 65, the cylinder band tall with its ends flattened to at most half the band, the control head never larger than v12's; `collections` rects are `stackOffset` shorter. The renderer reads `stackOffset`, `figureRadius`, `figureLabelHeight` from the metrics; its other v12 drawing constants are named (literals scan covers `render/`).
- `messageEndGap`: every arrow but `->` stops that far short, a bidirectional one starts that far in (v12 `sequenceRenderer.ts:1912`), before the arrowhead room. `labelBoxExtraHeight` adds to the tab height (the layout holds it). `actorFooterPadding` adds to the viewBox when the model has participants.
- Cells: the themed set is all 0 in every theme (text draws symbols as boxes), so ASCII (#150) output is the same in every theme. The cell value set is unchanged.

## Test helpers
- `layout.spec.ts`: invariants over fixtures × {redux, default} × {px, cell} × {default, every option}; cell layouts equal across themes; a neo block (row height, band and labels, message ends, tab, footer, variables vs theme name). `regressions.spec.ts`: the fuzz alternates themes and sometimes sets a random `actorGlyphBand`.
- `layout.spec.ts` also: invariants at bands 1, 10, 20, 44, 100 with multi-line labels and created/destroyed participants; a broken-band spec; cell output equal with every geometry variable set.
- `conformance/src/sequence/render.spec.ts`: the corpus in `redux-color` and `default` (`sequenceApi(theme)`, additive); viewBox check through `path-bounds.ts` (`pathPoints`: arc and cubic extremes), tolerance 0.01 plus `CONTROL_HEAD_POKE` 0.12 on control heads (v12 neo's head rises 10.11 px over its circle, 0.11 past the 10 px margin). `render-features.spec.ts`: neo vs classic, symbols at bands 10-100, the cylinder pinned to 0..44.
