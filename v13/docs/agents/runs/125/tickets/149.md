## Behaviour
- Completion (`src/facet/completions.ts`) from the probe (statement = after the last line break or `;`): statement keywords where a statement may start (`end`, `else`/`and`/`option` only in their blocks, no `destroy` after `create`, `link` only at a statement start), note positions after `note`, `as` after a declared id, `off` after `autonumber`, participant ids with their kind and label wherever an id is tested, all 26 arrows after an id, the rest of a half-typed arrow on a message (`A-|`, `A--|`, the whole arrow around the cursor replaced; nothing on a note line), participant ids after a menu keyword (`links |`), participant data keys not yet written and the eight participant types as the value of `type:` (not inside another key's quoted value). Message, note, block and title text (`title |` too), comments: nothing.
- Hover (`src/facet/hover.ts`): participant (label, type, box, messages in/out, notes, created/destroyed); arrow (what it draws, from → to); keywords, `left of`/`over`, `+`/`-`/`()` from `generated/docs.ts`.
- Folding, symbols, rename, references come from #139's statement spans and symbols: `box`, `rect`, every fragment and each `else`/`and`/`option` section fold; rename of a participant checks the new name in nine statement shapes (`isValidId`).

## Grammar change (`grammar/sequence.ebnf`, regenerated)
- Mode transitions use one pop at most (`pop push(X)` instead of `push` then `pop pop`): the same mode stack for the reference lexer (grammar differential and corpus specs green), and Monarch/Lezer no longer stay in `ID` after `participant A as …`.
- Entities (`#lt;`) are text and part of ids for the highlighters, not a `#` comment (the lexer already reads them as placeholders).
- Generated highlighters `grammar/generated/sequence.*` are now committed (`git add -f`, as flowchart's): `check:grammar` failed on a clean checkout without them.

## Language-service change
- `lines.ts`: a range keeps a last `end`/`}` line that closes a block nested in it (an `else` ending with `opt … end` folds to that `end`); separate commit, `lines.spec.ts`.
