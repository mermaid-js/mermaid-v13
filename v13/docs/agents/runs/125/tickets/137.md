# #137 T1: sequence lexer parity gate (handoff)

Branch `feature/137_sequence-lexer`. The lexer matches v12's jison lexer on 100% of the gate
corpus: 193 e2e files, 177 harvested spec/doc strings, 16 line-separator and 35 edge cases,
each also with comment lines injected (834 of 842 sources reach v12's sequence lexer; the 8
others are not detected as sequence by v12).

## Exports (`@mermaid-js/diagram-sequence`)
- `sequenceTokens(src)`: significant tokens `{kind, text, range}` (trivia and EOF left out);
  `text` is what v12's parser read (entities decoded to `&name;`, CRLF as LF, removed spans cut).
- `SequenceTokenKind` (`T` in `src/parser/tokens.ts`): one kind per jison terminal, plus
  `Semi` (`;`), `AliasEnd` (empty alias NEWLINE), `Eof` (`<<EOF>>` NEWLINE), and
  `AccDescrMultiline`/`AccDescrMultilineEnd` (jison returns no token for these).
- `JISON_NAMES`: kind → jison terminal name (dev/test only). `Kind.Error` → `LEXICAL_ERROR`.

## For #139 (parser)
- Internal: `lex(src, from, view)` in `parser/lexer.ts` returns a core `TokenStream` with
  comments/directives as trivia; `sourceView(src, bodyStart, directiveRanges)` and
  `cook(src, start, end, view)` in `parser/source.ts` (copied from flowchart's, plus CRLF holes
  and a `lexText` with entity placeholders). Use `cook` for token values.
- Separators: `Kind.Newline`, `T.Semi`, `T.AliasEnd`, `T.Eof` are all jison `NEWLINE`.
  Two zero-width tokens can end the stream (the clipped sentinel line break, then `T.Eof`).
- jison's `INVALID` is `T.Invalid` (the grammar accepts it as a line); a lexical error is a
  zero-width `Kind.Error` (ID state at a line break), after which lexing resumes in INITIAL.
- Ids and INVALID are trimmed (ranges end at the last non-blank). `#`, `%…` and `x%%…`
  comments that jison skipped are `Kind.Comment` trivia (note `x%%` swallows the `x`).
