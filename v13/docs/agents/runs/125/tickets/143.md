# #143 T4 sequence SVG renderer: handoff

Branch `feature/143_sequence-renderer`. Draws `SequenceLayout` through the `SvgWriter` only.

## Exports (`@mermaid-js/diagram-sequence`)
- `sequence`: the plugin object (`DiagramPlugin<SequenceModel, SequenceLayout>`, `layoutKind: 'custom'`, `formats: ['svg']`, no `configDefaults`). No manifest, not in the registry (#145).
- `renderSequence(model, layout, ctx, w)`, `SequenceRenderContext` (`config`, `theme`, `warn`, `idPrefix`, `version`).
- Layout, additive: `ParticipantLayout.labelY` (box top to label centre; metrics `symbolLabelTop`, `figureLabelHeight`), symbol labels held in `bounds`; `fontsOf` exported from `layout/env.ts` (internal).

## How it works
- `render/render.ts` sections as named functions, in v12 stacking order: boxes, rects, participants (lifeline + `actor-top` + `actor-bottom` in one `g.participant[data-ast=p:…]`), activations, fragments, notes, messages, title. `render/symbols.ts` one factory per kind (v12 classic geometry); `render/arrows.ts` v12 marker paths placed in JS as `polygon`/`polyline.arrowhead`; `render/paint.ts` every theme lookup before the root.
- Theme (core, through `gen:theme`/`gen:config`): 13 v12 colour names (`actorBkg` … `sequenceNumberColor`) in the vocabulary with v12 `theme-base.js` rules and per-theme v12 values; `actorRadius` token (redux 6 / classic 3) in the schema; palette `data-color-id` per participant and its bars; `dropShadow` filter. No theme name or look read.
- Fonts: a section whose per-key font (`sequence.*FontSize` etc.) differs from the Mermaid font writes it on its group.
- Every structural SVG change is in MIGRATION.md "Sequence SVG structure"; theme rows in "Themes" and "Theme geometry".
