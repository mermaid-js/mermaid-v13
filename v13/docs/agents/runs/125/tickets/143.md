# #143 T4 sequence SVG renderer: handoff

Branch `feature/143_sequence-renderer`. Draws `SequenceLayout` through the `SvgWriter` only.

## Exports (`@mermaid-js/diagram-sequence`)
- `sequence`: the plugin object (`DiagramPlugin<SequenceModel, SequenceLayout>`, `layoutKind: 'custom'`, `formats: ['svg']`, no `configDefaults`). No manifest, not in the registry (#145).
- `renderSequence(model, layout, ctx, w)`, `SequenceRenderContext` (`config`, `theme`, `warn`, `idPrefix`, `version`).
- Layout, additive: `ParticipantLayout.labelY` (box top to label centre; metrics `symbolLabelTop`, `figureLabelHeight`), symbol labels held in `bounds`; `fontsOf` exported from `layout/env.ts` (internal).

## How it works
- `render/render.ts` sections as named functions, in v12 stacking order: boxes, rects, participants (lifeline + `actor-top` + `actor-bottom` in one `g.participant[data-ast=p:…]`), activations, fragments, notes, messages, title. `render/symbols.ts` one factory per kind (v12 classic geometry); `render/arrows.ts` v12 marker paths placed in JS as `polygon`/`polyline.arrowhead`; `render/paint.ts` every theme lookup before the root.
- Theme (core, through `gen:theme`/`gen:config`): 13 v12 colour names (`actorBkg` … `sequenceNumberColor`) in the vocabulary with v12 `theme-base.js` rules and per-theme v12 values; `actorRadius` token (redux 6 / classic 3) in the schema; palette `data-color-id` per participant and its bars; `dropShadow` filter. No theme name or look read.
- Fonts: a section whose per-key font (`sequence.*FontSize` etc.) differs from the Mermaid font writes it on its group.
- Every structural SVG change is in MIGRATION.md "Sequence SVG structure"; theme rows in "Themes" and "Theme geometry".

## Test helpers
- `conformance/src/sequence/render-api.ts`: `sequenceApi()` (fresh `createMermaid()`, plugin registered as an external diagram) and `asTest(src)`. The first-party `sequence` row has no loader and wins detection, so the helper registers `sequence-test` under the same-length header `zequenceDiagram` and swaps it back in `parse` (ranges unchanged). **#145: delete the swap and use the generated registry.**
- `sequence/render.spec.ts`: every corpus source the parser accepts (e2e + v12 specs; 7 syntax rejects) well-formed, `assertInert`, deterministic, no NaN/`foreignObject`/`<marker>`, only `-title`/`-desc` ids, coordinates inside the viewBox, AST round-trip; hostile inputs inert.
- `sequence/render-features.spec.ts`: symbols, heads per arrow, classes, palette, shadow, `actorRadius`, colour overrides, per-key font size.

## Size (esbuild, minified, core external)
- Renderer: 16.7 KB / 5.6 KB gz. Whole plugin (parser, layout, renderer): 78.9 KB / 26.4 KB gz.

## Deviations and open points (for the maintainer)
- v12 `look: neo` symbol geometry (`actorBands.ts`, taller tabs, +30 px actor rows) is not drawn: the layout (#141) has no neo geometry, so every theme draws v12 classic symbols. Porting it needs layout geometry variables (D152): decision needed.
- Sequence number badge r = 12: v12's marker circle is r 6 in stroke-width units on a line whose CSS width is 2px (`#id line`). Lifelines 2px for the same reason.
- v12's black async/half/stick heads are drawn in `signalColor`; classic `rect`/box grey shadows are dropped (shadow only where `dropShadow` is set).
- Simplified: central-connection fine offsets with autonumber (v12 -5/-7.5/+15) and bottom-symbol footer offsets; multi-line labels are centred per line in their placed box.
- Not drawn: actor popup menus (#147), icons (`properties.icon`).
