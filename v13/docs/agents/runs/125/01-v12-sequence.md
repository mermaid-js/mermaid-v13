## 1. Jison grammar (J)
- Options J:13 `case-insensitive` (so `Participant`, `END`, `SequenceDiagram` all match). Start conditions J:17 (`%x`, exclusive): `ID ALIAS LINE CONFIG CONFIG_DATA` (CONFIG_DATA is declared, never used), plus `acc_title acc_descr acc_descr_multiline` J:19-21. No lexer action calls `yy`; all `yy` use is in grammar actions.
- State switches:
  - `participant`/`actor`/`destroy`/`activate`/`deactivate` -> `begin('ID')` J:41,42,44,68,69. `create` does NOT switch (J:43); the next token is `participant`/`actor` which does.
  - ID: `@{` -> CONFIG J:31; CONFIG body `[^\}]+` J:32; `}` followed by `\s+as\s` pops CONFIG and begins ALIAS J:33, else pops twice (CONFIG and ID) J:34.
  - ID: ACTOR with lookahead `\s*@{` J:35 (stays in ID); with lookahead `\s+as\s` J:36 begins ALIAS; ACTOR to end-of-line/`;`/`#` J:37 pops. `<` in an id -> INVALID J:38; catch-all INVALID J:39.
  - ALIAS: `as` pops twice, begins LINE, returns `AS` J:45. Empty-match rule J:46 (pops twice, returns NEWLINE) is the escape when no `as` follows.
  - `box loop rect opt alt else par par_over and critical option break` -> `begin('LINE')` J:40,47-57. LINE: `(?:[:]?(?:no)?wrap:)?[^#\n;]*` -> `restOfLine` J:58, pops. `restOfLine` may carry the `wrap:`/`nowrap:`/`:wrap:` prefix; db strips it (DB:355 `extractWrap`).
  - `accTitle\s*":"` -> `acc_title` state J:72-73; `accDescr:` J:74-75; `accDescr {` multiline J:76-78 (closes on first `}`, no nesting).
- Rule-order traps:
  - Quoted keyword literals (`"par"`, `"end"`, `"loop"`, `"note"`, `"over"`, `"off"` ...) are compiled by jison-lex with a trailing `\b` when they end in a word character (so `par` does not match `par_over`, `end` not `endpoint`); `\b` treats `_` and digits as word chars. Regex rules (`accTitle`, `links`..`details` with lookahead) are verbatim. v13 tokens must reproduce this boundary; confirm with the oracle (from knowledge of jison-lex, not re-tested here).
  - Order still matters: keywords are tried before the generic ACTOR J:84 but after the ID/LINE states, so inside a message (`A->>B: end`) the text is TXT, not `end`. `keywordActors.spec.ts` (137 lines) shows what v12 promises for `link`/`links`/`properties`/`details` as actor ids.
  - `links`/`link`/`properties`/`details` J:62-65 are keywords only with lookahead `[ \t]+[^/\\+()<>:\n,;\s-]`; `actor: 'link'` J:382 lets `link` be an actor id.
  - `"title"\s[^#\n;]+` J:70 and `"title:"` J:71 are single tokens; the db strips with `substring(6)`/`substring(7)` (J:186-187).
  - NEWLINE J:24 is `[\n]+`; `;` is also NEWLINE J:83; `<<EOF>>` returns NEWLINE J:125; `\s+` skipped J:25.
  - Comments: `#` to EOL J:27 (only in INITIAL/ID/ALIAS/LINE), `%%(?!\{)` J:28, `[^}]%%` J:29. `#` also terminates TXT/restOfLine, so `#35;` entity codes survive only because `Diagram.fromText` runs `encodeEntities` first (`fa796a943:packages/mermaid/src/Diagram.ts:77`, `utils.ts:895`; `decodeEntities` `utils.ts:920` runs on the SVG, `mermaidAPI.ts:366`). Hex colours in `rect`/`box` are not supported for the same reason (DB:392 comment).
  - `NUM` J:30 `([0-9]+(\.[0-9]{1,2})?|\.[0-9]{1,2})(?=[ \n]+)`: only after autonumber (needs trailing space or newline).
  - Generic ACTOR (INITIAL state) J:84: `[^/\\+()+<\->\->:\n,;]+` then repeated `(?!arrow-prefix list)[-]*[^+<\->\->:\n,;]+`; trimmed. This is why `A-B->>C` lexes `A-B` as one actor. Edit with the arrow list J:84 in sync with J:85-118.
  - Arrow order J:85-118 (longest first, hand-ordered): `->>`, `<<->>`, `-->>`, `<<-->>`, `->`, `-->`, `-x`, `--x`, `-)`, `--)`, then four families (dotted, reverse-dotted, normal, reverse) of `|\ |/ \\ //` heads. `TXT` J:120 `":"(?:(?:no)?wrap:)?[^#\n;]*` then fallback `":"` J:121. `+` `-` `()` J:122-124; catch-all `.` -> INVALID J:126.
- Terminals (J:24-126): NEWLINE NUM CONFIG_START CONFIG_CONTENT CONFIG_END ACTOR INVALID box participant participant_actor create destroy AS restOfLine loop rect opt alt else par par_over and critical option break end left_of right_of links link properties details over note activate deactivate title legacy_title acc_title acc_title_value acc_descr acc_descr_value acc_descr_multiline_value SD autonumber off `,` SOLID_ARROW BIDIRECTIONAL_SOLID_ARROW DOTTED_ARROW BIDIRECTIONAL_DOTTED_ARROW SOLID_OPEN_ARROW DOTTED_OPEN_ARROW SOLID_CROSS DOTTED_CROSS SOLID_POINT DOTTED_POINT SOLID_ARROW_TOP(_DOTTED)(_REVERSE)(_REVERSE_DOTTED) SOLID_ARROW_BOTTOM_* STICK_ARROW_TOP_* STICK_ARROW_BOTTOM_* TXT `+` `-` `()`. (`SPACE` is used in J:137,148,160,318 but never emitted.)
- Grammar J:136-: `start` (SD document, `yy.apply($2)` J:139) -> `document` (list of `line`) -> `statement`: participant_statement (incl. `actor_with_config` J:269-272, `destroy` J:268), `create` + participant J:168, `box restOfLine box_section end` J:169, `signal NEWLINE`, `autonumber` x4 forms J:175-178, `activate`/`deactivate` J:179-180, note/links/link/properties/details, `title`/`legacy_title`, acc*, `loop rect opt alt par par_over critical break` blocks J:191-242 with `else_sections`/`par_sections`/`option_sections` J:245-261 (recursive, `document` between separators). `signal` J:331-356 has 6 shapes: `+`/`-` activation suffix, `()` central connection (3 variants, J:340-353), plain. Arrow list -> LINETYPE in `signaltype` J:386-415. `note`: `left of|right of` actor, or `over` actor[,actor] J:276-287. Quirk: `else` after `break`/`loop` is not allowed; `critical` uses `option`; `par_over` emits `parStart` with `PAR_OVER_START` J:225.

## 2. Database (DB)
- LINETYPE DB:34-91 (numeric; keep values: SOLID 0 DOTTED 1 NOTE 2 SOLID_CROSS 3 DOTTED_CROSS 4 SOLID_OPEN 5 DOTTED_OPEN 6 LOOP 10/11 ALT 12/13/14 OPT 15/16 ACTIVE 17/18 PAR 19/20/21 RECT 22/23 SOLID_POINT 24 DOTTED_POINT 25 AUTONUMBER 26 CRITICAL 27/28/29 BREAK 30/31 PAR_OVER_START 32 BIDIR_SOLID 33 BIDIR_DOTTED 34; head families 41-48, 51-58; CENTRAL_CONNECTION 59/REVERSE 60/DUAL 61). ARROWTYPE DB:93 (FILLED 0, OPEN 1). PLACEMENT DB:98 (LEFTOF 0, RIGHTOF 1, OVER 2). PARTICIPANT_TYPE DB:104 (actor boundary collections control database entity participant queue).
- Participant types: the `participant`/`actor` keywords only give `draw` `participant`|`actor`; all other types come from `@{ type: ... }` YAML metadata (DB:164-174, `yaml.load` with JSON_SCHEMA; metadata without a newline is wrapped in `{ }`). `metadata.alias` is used when no `as` description exists or description equals the name DB:177.
- `addActor` DB:155-231: map keyed by id (insertion order == render order, "first mention"). Redeclare updates box (must be same box, else throw DB:185) and never nulls a description DB:195. Actors mentioned only in messages are created by the grammar: every `signal`/`note`/`link` action puts the `actor` nodes (`type: addParticipant`, no draw) in the returned array ahead of the message J:333-355, so first mention = textual order of appearance. `prevActor`/`nextActor` linked list DB:213-225. `description.wrap ?? autoWrap()`.
- `apply` DB:557-718 is the dispatcher over `param.type`; `createParticipant` DB:581 throws on duplicate id, sets `lastCreated`, records `createdActors[id] = messages.length`; `destroyParticipant` DB:591 records `destroyedActors`; the next `addMessage` must involve that actor or throw DB:622-646.
- Boxes: `boxStart`/`boxEnd` DB:656-661, `addBox` DB:145, `currentBox.actorKeys`; `parseBoxData` DB:394 (colour first: `rgb[a]()`/`hsl[a]()`/word, validated with `CSS.supports` or `new Option()` DB:400-412; unsupported colour => transparent and the whole string becomes the title). Needs DOM; v13 must replace.
- Activation: `activeStart`/`activeEnd` become zero-text signals (from=actor) DB:595-606; `+`/`-` suffix emits an extra activeStart/End after the message J:334,338. `addSignal` DB:272 throws "Trying to inactivate an inactive participant" with a jison-like `hash` DB:280-295; `activationCount` DB:233 counts the whole message list, so unbalanced deactivate inside a loop still counts.
- Autonumber: grammar emits a message of type AUTONUMBER with `{start, step, visible}` DB:564-577; the renderer owns the counter (SR:1269).
- Links/properties/details: `addLinks` JSON.parse DB:452, `addALink` `label @ url` DB:468 (`&equals;`/`&amp;` reversed, `sanitizeText`), `addProperties` DB:498, `addDetails` DB:526 reads `document.getElementById(...).innerHTML` (DOM dependent). Errors are swallowed with `log.error`.
- Wrap: `extractWrap` DB:355 (`^:?wrap:` true, `^:?nowrap:` false, else undefined => `autoWrap()` DB:366: `setWrap` value, else `config.sequence.wrap`); `parseMessage` DB:380 trims and returns `{text, wrap}`. Text goes to messages unsanitised except box title / links; the renderer sanitises. `getConfig()` DB:726 returns `config.sequence`.
- Message rows (TY): `{id, from, to, message, wrap, type, activate, centralConnection, placement, answer}`. `addNote` DB:425 pushes to `notes` AND to `messages` as type NOTE (to = 2nd actor, same as from for single-actor notes).
