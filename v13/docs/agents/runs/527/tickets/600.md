# Ticket 600: eventmodeling T1, lexer parity gate on the Langium oracle

**`@mermaid-js/diagram-eventmodeling`** (private, `0.0.0`, no manifest until T5). Exports `.` (`src/index.ts`, empty) and `./testing` (`src/testing.ts`):
- `eventModelingTokens(src): EventModelingToken[]` (`{ kind, text, range }`): what v12's lexer saw, in order: significant tokens, the hidden comments (`%%`, `/* */`, `//`), directives and YAML in v12's text, `Kind.Error` over the characters Chevrotain skipped (then lexing goes on). Whitespace writes no token (EM_WS is skipped; T2 reads line breaks from offsets). Cut directives and `EOF` left out. `text` is `cook()`ed.
- `eventModelingView(src)`: `{ bodyStart, view }`, the one preprocess → view shape; **T2 must use it** (see below).
- `EventModelingTokenKind` (`T`, `src/parser/tokens.ts`): one kind per keyword (`Header`, `Tf`, `Timeframe`, … `Rf`, `Arrow` `->>`, `OpenRef` `[[`, `CloseRef` `]]`, `Backtick`, `Dot`), `Id`, `FrameId`, `DataInline`, `DataBlock`, `AccDescr`, `AccTitle`, `Title`, `Yaml`, `BlockComment`, `LineComment`; `%%` comments are `Kind.Comment`, directives `Kind.Directive`. `KEYWORDS` (word → kind), `EVENTMODELING_TRIVIA` (Comment, Directive, Space, Yaml, BlockComment, LineComment), `LANGIUM_NAMES` (kind → Chevrotain name, test use).
- Internal for T2: `lex(src, from, view)` in `src/parser/lexer.ts` returns the full `TokenStream`.

**Rules T2 must know** (all gated, probed on 2.0.1): token order is keywords (longest first), EM_ID, EM_FID, EM_DATA_INLINE, EM_DATA_BLOCK, EM_ACC_DESCR, EM_ACC_TITLE, EM_TITLE, EM_WS, then the hidden rules. Every word keyword has EM_ID as longer alternative: a keyword only as a whole `\w` run (`tf01`, `evtA` are names; `text`, `data` are never names). `eventmodeling` needs `%%`, `\s` or the end after it (`eventmodeling-beta` = EM_ID + error). EM_ID precedes the title/acc rules, so they match only after a blank on the line of a previous token; their images keep the blanks and keyword (`" title My Model"`); `title` after a line break is EM_ID; `a titleBar` = `a`, `" title"`, `Bar`. EM_FID splits after 3 digits. Inline data is greedy to the last `}`/`"`/`'` on its line (regex `.`, so U+2028/U+2029 end it). EM_DATA_BLOCK's optional body is tried first: `{\n}\n…\n}\n` runs to the later `}`. A `}` closes only at a line start and before a line break, `\s` or the end.

**Comment lines are kept (no core change):** v12's event modeling db set `preserveCommentsWhenParsing`, so v12 parsed `withComments` (directives cut, `%%` lines kept, untrimmed) and lexed them as EM_SINGLE_LINE_COMMENT. Core's `sourceView` has no option for that; `eventModelingView` takes a second view of a copy with the first `%` of each comment line replaced (same length, so tag quotes and dropped `;` match v12) and reads the text back from `src` via the runs. A comment span that starts inside a directive is handled. The lexer does not trim leading blanks.
