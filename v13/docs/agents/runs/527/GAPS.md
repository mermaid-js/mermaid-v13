- **For T4 (#606), decided by the orchestrator:** D528's `relation:<source>-><target>` is the AST id of each `->> id` (a `Source` child of its frame, `@2` for a repeat). - **For T6:** no probe hooks yet (`tested()`, `PROBE_FOLLOWS`), as treemap's T2; the facet adds them. Folding: data blocks and `/* */` comments are single tokens (`T.DataBlock`, `T.BlockComment`).
- **Diagnostics (choices):** v12's thrown duplicate id is the error `EVENTMODELING_DUPLICATE_FRAME` at the second id, checked as soon as the id is read (so a frame that also fails later gives two errors). Syntax: `UNEXPECTED` (with hints for keyword names, `title`/`accTitle`/`accDescr` at a line start, upper-case keywords, part order, four-digit ids, block vs inline data, a second header), `UNEXPECTED_CHARACTER`, `UNCLOSED_DATA`, `UNCLOSED_STRING`. D525: one warning per kind at the first case, the others in `related` (wardley's pattern); `EVENTMODELING_INVALID_SOURCE` checks only sources that become relations (a later frame gets `UNKNOWN_SOURCE` alone; v12's validator checked both), with its message verbatim (`a event` included).
- **Parity normalisation (`conformance/src/eventmodeling/v12.ts`):** v12's `getState()` runs against a stub document (text 0 × 1 px, so nothing wraps); positions and sizes are not compared (T3).
