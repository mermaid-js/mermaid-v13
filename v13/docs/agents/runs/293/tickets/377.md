# #377 T1 lexer parity gate: handoff

Branch `feature/377_gantt-lexer`. Lexer only: no grammar, model or AST (T2, #378).

## Exports (`@mermaid-js/diagram-gantt`)
- `ganttTokens(src): GanttToken[]`: significant tokens (`{ kind, text, range }`), trivia (comments, directives, dropped `;`) left out; `text` is what v12's parser read (entities decoded, CRLF as LF, removed spans cut).
- `GanttTokenKind` (`T` in `src/parser/tokens.ts`): one kind per jison terminal, plus kinds for the rules that return no jison token (`ClickKeyword`, `ClickEnd`, `HrefKeyword`, `HrefEnd`, `CallKeyword`, `CallbackEmptyArgs`, `CallbackArgsOpen`, `CallbackArgsClose`, `AccDescrMultiline`, `AccDescrMultilineEnd`) and `OpenDirective`.
- `JISON_NAMES`: kind → jison terminal (`NL` for `Kind.Newline`, `LEXICAL_ERROR` for `Kind.Error`). Dev/test only.
- Internal for T2: `lex(src, from, view, probe?)` in `src/parser/lexer.ts` returns the full `TokenStream` (trivia included), as timeline's does.

## For T2 (#378)
- jison's `NL` is not a statement terminator: `\s+` takes line breaks after blanks, `click`'s ids end at one blank or line break (`ClickEnd`, which may be the line's `\n`), and `%x…`/`x%…` comments take their line break. The grammar has `line: statement | NL`, so statements need no separator.
- `title`/`section`/`dateFormat`… are one token each, keyword included; values are `substr(n)` of the token text (see `01-v12-gantt.md` §1).
- `TaskText` keeps trailing blanks; `Date` and `AccDescription` have no grammar rule (syntax errors in v12).
- `OpenDirective` is followed by an `Error` token to the line end (jison threw there); lexing goes on.
