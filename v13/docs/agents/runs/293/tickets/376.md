## Exports (`src/dates/index.ts`)

- From `dates.ts` (dayjs 1.11 subset, local time): `add(date, n, unit)`, `addDays`, `format(date, tpl)` (`undefined` for tokens v12's dayjs cannot format), `parseStrict(input, tpl, now)` (`dayjs(input, tpl, true)`), `isValid`, `isoDate` (`YYYY-MM-DD`), `isoWeekday`, `WEEKDAYS`, `type Unit`.
- v12 readers, also in `dates.ts`: `readStartDate(input, fmt, now)` is the written-date branch of `getStartDate` (x/X digits as ms, strict parse on the trimmed format, `Date` fallback, |year| > 10000 rejected); `undefined` is v12's `Invalid date:` error. `readEndDate(input, fmt, now)` is `getEndDate`'s strict parse; `undefined` means "try a duration". `parseDuration(str)` is v12's `[value, unit]`, `[NaN, 'ms']` when invalid.
- From `axis.ts` (d3-time / d3-time-format subset): `timeFormat(spec, date)`, `autoTicks(start, stop, count)` (d3 `scale.ticks`), `intervalTicks(interval, weekday, start, stop, limit)` (`undefined` for a bad interval or more than `limit` ticks), `type TickUnit`.

## Use (T3)

- `after`/`until`, `inclusiveEndDates` (+1 `d` via `add`), the duration fallback and the diagnostics stay in T3's `schedule`. Pass `ctx.now`; nothing here reads the clock.
- v12's over-10,000 check uses `getEstimatedTickCount` (dayjs duration, a month of 365/12 days). `intervalTicks`' `limit` estimate is Pele's (`min(step, cycle)·ms`). T3 runs v12's estimate first and passes a `limit` above it (GAPS #379).
