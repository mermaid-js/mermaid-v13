# #60 handoff: Diagram tab (Messages + console capture)

Branch `feature/60_dev`. No new dependencies (Shoelace `split-panel` and `badge` were already in the package). viewer.ts, context.ts and styles.css are untouched.

## Components (packages/dev/src/browser/explorer/tabs/)

- `diagram.ts`, `dev-tab-diagram` (`DiagramTab`): an `sl-split-panel` with `.canvas > svg` (the shell's render, `bindFunctions` applied) on the left and the Messages side on the right. The position is kept in localStorage under `devExplorer.viewer.splitPosition` (v12's key; default 75).
  - Messages: `messagesOf(outcome, text)` (exported) → `Message { severity, code, message, line?, column?, detail? }`. An ok render lists `warnings` (severity `warning`; `detail` = config `path (source)`). A failed render lists the `MermaidError`'s `diagnostics`, with line:column from `range.start` in `ctx.text`. With no diagnostics it lists the error itself, at `err.line/column` when it has an offset. A non-Mermaid error is listed as code `ERROR`.
  - Each entry is a `[data-message][data-severity][data-code]`. Entries with a position are `<button>`s that call `ctx.goto('code', { line, column })`. With no entries, `[data-messages-empty]` is shown.
- `console-panel.ts`, `dev-console-panel` (`DevConsolePanel`), a port of v12's `console-panel.ts`. `installConsoleCapture()` wraps `console.log|info|debug|warn|error` once per page, on first mount. The originals still run, `%c` and its css args are stripped, entries are batched per animation frame and capped at `MAX_LOGS` (5000). The store is module-level, so it survives the panel re-rendering.
  - Controls: `sl-input[data-filter]`, native checkboxes `input[data-toggle="debug|info|warn|error"]` (debug = v12's `: DEBUG :` marker), `sl-button[data-action="copy|clear"]`. Lines: `.logline[data-level]` with a `.message` span.

## Extending

- The tab must contain exactly one `svg`: `dev-tab-diagram svg` in the #58/#59 specs pierces shadow roots. So the panel uses no icon-drawing Shoelace parts (no `sl-icon`, `clearable`, `sl-checkbox` or spinner). Keep it that way, or change those specs to `.canvas > svg`.
- Diagnostics with `related` locations, or warnings that carry a position, need only a change in `messagesOf`. (`Warning` has no position today; `toWarning` in packages/mermaid/src/api.ts drops `range` from parse-warning diagnostics.)

## Tests

- `e2e/dev/diagram-tab.spec.ts` (one `startExplorerServer` root for the file): ICON_UNAVAILABLE warning listed; UNCLOSED at 3:10, and clicking it gives `tab=code` with the Code cursor at {3,10}; a clean render shows the empty state and exactly one svg; console.warn/error captured, `%c` stripped, filter/toggle/clear narrow it; the split position survives a reload.

## Unmet criteria / deviations

None unmet. `pnpm check` and `e2e/dev` (chromium, 21 tests, after merging #62) pass. Deviations from v12: native checkboxes and icon-less buttons (the svg constraint above); "Select + Copy" became Copy (clipboard only); console capture is page-wide and starts when the Diagram tab first mounts, not per viewer instance; no logLevel-driven filter defaults (logLevel is dropped in v13).
