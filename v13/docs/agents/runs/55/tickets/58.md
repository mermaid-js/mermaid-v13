# #58 handoff: Dev Explorer shell at /dev/

Branch `feature/58_dev`. New dev deps: `lit@^3.3.3`, `@shoelace-style/shoelace@^2.20.1`. Both CLIs serve the explorer; `pnpm dev` prints `<url>dev/` per address. `MERMAID_PORT=0` (serve) picks a free port.

## Server (packages/dev/src/explorer.ts)

- `explorerServerOptions(root, { folders? })` → `{ routes, entries: { explorer }, watch: { paths: [root] } }`, spread into `startServer`. `resolveExplorerRoot(env)`: `MERMAID_DEV_EXPLORER_ROOT` (relative to the checkout), default `e2e/diagrams`. At the default root the top level lists `supportedFixtureFolders()` (relative import, with an eslint-disable for `import-boundaries`).
- Routes: `GET /dev` → 302 `/dev/`; `/dev/` is `www/dev/index.html` (static), script `/build/explorer.js`, `www/dev/styles.css`; `GET /dev/vendor/shoelace/*` (theme css, icons); `GET /dev/api/files?path` → `{ root, path, entries }`, where `root` is named the way `/events` names paths; `GET|POST|PUT /dev/api/file?path`. Non-`.mmd`, escapes, NUL and missing files get 400; POST on an existing file gets 409; an empty POST writes a starter flowchart.
- `browser/mermaid.ts` (the dev bundle) also exports `devThemes` (`THEME_NAMES` + `auto`), `devLayouts` (`layered` + loaders) and `devLayoutLoaders` (empty; add an engine here and the selector lists it).

## Page (packages/dev/src/browser/explorer/)

`app.ts` (URL `?path&file` via pushState, popstate, `/events` with 1 s reconnect, `<html data-dev-events="connected">`), `file-explorer.ts`, `viewer.ts` (the shell), `settings.ts` (URL/storage helpers, `loadSettings`, `renderConfig`, `arrowAction`, `effectiveTheme`), `render.ts` (`loadMermaid(build)` imports `/mermaid.esm.mjs?build=<n>` and makes a `createMermaid()` instance with interactions; `renderText` never throws and returns a `RenderOutcome` with `result`/`warnings`, or `error` plus `mermaidError`), and `api.ts` (file API client).
The shell owns URL params `path file tab theme layout` and the storage keys `devExplorer.viewer.theme|layout`. On `/events`: a change to the open `.mmd` reloads it (or, when there are unsaved edits, sets `diskChanged` and shows a notice with Revert); a source change re-imports the build and re-renders with no page reload; a change to explorer code or `www/dev/` reloads the page.

## Tab contract (tabs/context.ts): #59 code.ts, #60 diagram.ts, #61 compare.ts, #62 profile.ts

Each tab replaces only its own placeholder file, `dev-tab-<name>`, which extends `ViewerTabElement` (props `ctx`, `active`). It renders in its own shadow root with `static styles` and leaves `styles.css` and `viewer.ts` alone. `ctx` is a new snapshot on every shell update; use `changed.get('ctx')` to diff it.
- Data: `file, source, text, dirty, diskChanged, settings {theme?, layout?}, outcome, rendering, build, event {seq,time,paths}, reveal {seq,line,column}`.
- Functions: `render(text, settings?)` (any text, current build), `mermaid()` (the `DevMermaid { module, instance }` for timing and similar), `setText(text)` (live re-render plus `dirty`), `save()` (PUT; the banner shows a failure), `revert()`, `goto(tab, {line, column}?)` (sets `reveal`; for #60's diagnostic → Code at line).
- Do heavy work only while `active`. Re-run your own renders on a new `event.seq`. Tab-specific keys (Compare's D) go on a `document` keydown listener that checks `active`. ←/→ ignore inputs, Shoelace controls, contenteditable and `.cm-editor`. Own URL/storage state: use `setUrlParams`/`writeStorage` from `settings.ts` with new keys.
- The Diagram placeholder draws `ctx.outcome.result.svg` and calls `bindFunctions`; the e2e specs locate `dev-tab-diagram svg`, so #60 should keep an `svg` in that element.

## Tests and helpers

- `packages/dev/src/explorer.spec.ts` (port 9614, temp root): listing and the folder filter, read, create, 409, overwrite, traversal (`..`, backslash, NUL, leading `/`), non-`.mmd`, missing files, the page, vendor, `resolveExplorerRoot`.
- `e2e/dev/explorer.spec.ts`: folders = `supportedFixtureFolders()`, open by click + back, ←/→ + counter + Next, selector options, theme changes the svg and survives a reload (URL and localStorage), and an on-disk edit re-renders without a reload.
- `e2e/dev/explorer-server.ts`: `startExplorerServer(files)` → `{ origin, root, path(f), url(f?), close() }` spawns a second server over a temp root. Use it for any spec that writes files (#59 save).
