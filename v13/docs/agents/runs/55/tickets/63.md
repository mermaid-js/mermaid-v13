# #63 handoff: every .mmd tier, unsupported types skipped

Branch `feature/63_dev`. `pnpm e2e` now collects every tier folder (as v12 develop does). Folders whose diagram types have no v13 package are skipped, and they join automatically when `pnpm gen:registry` gives their type a `load`.

## Exports (e2e/helpers/mmd-snapshots.ts)

- `discoverMmdFixtures({ diagramsDir?, tiers?, supportedTypes?, folderTypes? }) → Promise<string[]>`: sorted paths relative to `diagramsDir` (default `e2e/diagrams`). If `tiers` (a comma-separated string, i.e. `MERMAID_E2E_FIXTURE_TIER`) is unset or empty, every tier is collected. Otherwise it collects `<folder>/<tier>/**/*.mmd`.
- `supportedFixtureFolders({ diagramsDir?, supportedTypes?, folderTypes? }) → string[]`: the sorted top-level folders that the run collects from. It throws on a folder that `folderTypes` doesn't list. **#58's explorer should use this** to list exactly the folders e2e runs. It is synchronous; import it by relative path from packages/dev.
- `FIXTURE_FOLDER_TYPES`: folder → the v12 `detectType` types it holds (e.g. `flowchart: ['flowchart-v2']`, `railroad` lists its four variants, `state-diagram-v2` also lists `info` because one fixture is an info diagram). A folder runs only when *all* of its types are supported.
- `SUPPORTED_TYPES`: the registry rows (`packages/mermaid/src/generated/registry.gen.ts`) that have `load`. The helper imports that file directly; it has a type-only import and lazy loaders, so Playwright loads it without a build.

## Run

`e2e/rendering/mmd-snapshots.spec.ts` calls `discoverMmdFixtures({ tiers: process.env.MERMAID_E2E_FIXTURE_TIER })`. Today that is 502 fixtures: flowchart 494, plus `conf-and-directives` (4) and `katex` (4), which `detectType` finds to be all flowchart. All 502 pass in chromium, and full `pnpm e2e` gives 523 passed. `MERMAID_E2E_FIXTURE_TIER=baseline` gives 94. The ci.yml and playwright.config.ts comments were updated. The gallery is still built from `flowchart/baseline`.

## How to extend

- **New diagram package:** run `pnpm gen:registry`. Its folders join without any other change.
- **New fixture folder:** add it to `FIXTURE_FOLDER_TYPES`. Until you do, discovery and the spec fail loudly.

## Tests

`e2e/helpers/mmd-snapshots.spec.ts` (vitest) covers discovery over a temp dir: all tiers by default; env-style narrowing with whitespace and the empty string; a folder included only when all its types are supported; an undeclared folder throws; the folder listing. On the real tree, it checks that flowchart is in and sequence and zenuml are out, and that every fixture's `detectType` result is declared for its folder (undetectable fixtures are ignored).
