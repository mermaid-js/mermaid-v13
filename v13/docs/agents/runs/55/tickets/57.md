# #57 handoff: mermaid from source, watch, SSE live reload

Branch `feature/57_dev`. New dev deps on `@mermaid-js/dev`: `chokidar@^5` and `@mermaid-js/plugin-interactions`.

## Exports (packages/dev/src)

- `server.ts`: `ServerOptions` gains `watch?: boolean | WatchOptions` (`{ paths?, debounceMs? = 100 }`; default off, both CLIs turn it on) and the rebuild hook `onRebuild?(paths)`. It runs on every rebuild, alongside the built-in contexts and before the broadcast. A throw is reported on stderr and the broadcast still goes out. `DevServer.rebuild(paths?)` does exactly what the watcher does (rebuild, hook, broadcast). Rebuilds are serialized. `bundleEntry?` overrides the `/mermaid.esm.mjs` entry (a test seam). Also re-exports `ReloadEvent`.
- `live.ts`: `createEventHub()` (`{ route, broadcast(event) }`), `watchSources(root, extra, debounceMs, onChange)` and `ReloadEvent { time, paths }`. `paths` are repo-relative and posix, or absolute for watched paths outside the repo.
- `browser/mermaid.ts`: the bundle entry. It re-exports all of `mermaid` (named and default) plus `interactions`.
- `browser/reload.ts`: the reload client.

## Routes (added after `builtInRoutes`, before `options.routes`)

- `GET /mermaid.esm.mjs`: its own esbuild context (no splitting, so one file), built at startup and on every rebuild, served from memory with `no-store`. If the last build failed, it returns 500 with the esbuild message.
- `GET /events`: SSE. On connect it sends a comment (`: connected`). After each rebuild it sends `data: {"time":…,"paths":[…]}`.
- `GET /dev/reload.js`: proxies to the page context's `/build/reload.js`. Opt in with `<script type="module" src="/dev/reload.js">`. It reloads on any event (no client/server clock comparison, unlike v12, because the user may be on another machine), reconnects after 1 s, and sets `<html data-dev-reload="connected">` while connected.

## What is watched

chokidar watches `packages/` with an `ignored` filter: only `packages/<name>/src/**`, plus `packages/dev/www/**` (the explorer's static assets go in `www/dev/`). Packages added later are picked up without a restart. `node_modules`, dotfiles and `~`/`.swp` files are ignored. Events: add, change, unlink. Explorer sources under `packages/dev/src` are covered already.

## How to extend (#58 explorer)

- `.mmd` root: `startServer(port, { watch: { paths: [explorerRoot] } })`. Changes rebuild and broadcast, and the explorer reads `paths` from the event to refresh only the open file. Filter there; the watcher does not filter by extension.
- After a file API `PUT`/`POST`, either rely on the watcher or call `server.rebuild([rel])`.
- Profile (#61) can switch on `@mermaid-js/core/timing` in `browser/mermaid.ts`.

## Tests and helpers

- `packages/dev/src/watch.spec.ts`, ports 9612 and 9613. Its `events(port)` helper is an SSE reader whose `next()` resolves with the next data line. On 9612, the real bundle is checked to be one ESM file exporting `createMermaid` and `interactions`, and `/dev/reload.js` is checked to be served. 9613 uses `watch: { paths: [tmp] }` and `bundleEntry: tmp/entry.js`, a temp dir from `mkdtemp`. On it, a `utimes` gives an event whose `paths` contains the file, and an edit shows up in `/mermaid.esm.mjs` after the event. No real source file is modified.
- `e2e/dev/reload.spec.ts`: on `/`, it injects `/dev/reload.js`, waits for `data-dev-reload`, touches the core source and expects a reload. The Playwright webServer (`serve`) now watches.
