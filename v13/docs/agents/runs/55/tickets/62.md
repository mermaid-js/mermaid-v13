# #62 handoff: Profile tab (stage timings)

Branch `feature/62_dev`. No new dependencies. The tab is `dev-tab-profile` in `tabs/profile.ts`; viewer.ts, context.ts and styles.css are unchanged.

## Stage timing in the dev bundle

- `server.ts`: the `/mermaid.esm.mjs` esbuild context (and only that one) gets `define: { __MERMAID_BENCH__: 'true' }`. Production bundles never define the flag, so their timing stays compiled out or off. The page context and the e2e viewer are untouched.
- `browser/mermaid.ts` also exports `installStageClock`, `STAGE_TIMING` and the types `Stage`/`StageClock` from `@mermaid-js/core/timing`. Because the bundle is a single file, it holds one copy of core, so the clock the tab installs is the one the pipeline reads.
- v13 records `parse` (mermaid `api.ts`), `layout` and `serialise` (core `pipeline/draw.ts`). `measure` exists in the type but isn't bracketed yet. The tab shows the stages that recorded something, in core's order, so `measure` will appear once it's bracketed.

## Tab behaviour

- Controls: Scope (`This diagram` / `Whole folder`), Runs (1–50, default 10) and one checkbox per `devLayouts` entry. Storage keys are `devExplorer.profile.scope|iterations|layouts`.
- A run gets `ctx.mermaid()`'s module, makes its **own** `createMermaid()` instance (layout loaders + interactions), and installs a `performance.now` clock, which it removes when the run ends. For each layout it does one untimed warmup render. Each timed run first calls `initialize(config)`, because `render` caches the parse per (text, site snapshot) and would otherwise skip parse after the first run. Total = wall time of `render()`.
- Aggregation follows v12: drop the fastest and slowest run by total (when there are 3 or more), average the rest. The stage table holds the sum over diagrams of those means; the score is the sum of the totals. Folder mode adds `table.files` with one row per file.
- A new `ctx.event.seq`, or switching tabs, cancels a running profile. The partial result is kept and marked `cancelled`.
- Copy as JSON gives `{ capturedAt, build, scope, iterations, theme, aggregation, unit, cancelled, stages, layouts: [{ layout, score, stageTotals, failures, perDiagram: [{ diagram, total, stages, samples, failures, error? }] }] }`. Numbers are rounded to 3 decimals, the same values as the tables' `data-ms`.

## Tests

- `packages/dev/src/watch.spec.ts` (port 9612): imports the served bundle in Node and checks `STAGE_TIMING === true`. A render with an installed clock records exactly parse, layout and serialise.
- `e2e/dev/profile.spec.ts`: one diagram (a 103-line pr-check fixture, 10 runs) fills one row per stage with every value > 0, plus the score row. Folder mode (`flowchart/baseline/subgraphs`, 3 runs) adds one row per file. Copy-as-JSON parses and its numbers equal the tables' (it uses the clipboard permissions, chromium). It passed 8× repeated.

## Deviations / unmet

- **Contract deviation:** folder mode reads its sibling files with `listFiles`/`readFile` from `../api.ts` (read-only GETs). context.ts says tabs never fetch the file API, but the context carries only the open file. The clean fix is to add a `siblings`/`read(path)` entry to `ViewerContext` in the shell.
- Timers aren't cross-origin isolated on `/dev/` (resolution about 0.1 ms), so stages on tiny diagrams can show 0.00. Serving `/dev/` with COOP/COEP would fix this, but it might affect Compare's CDN iframes, so it was left out.
- None unmet. `pnpm check` and `e2e/dev` (chromium, 16) pass after merging `feature/55_dev-server` (with #59).
