# #64 handoff: e2e/dev specs in CI

> Changed in the review pass (tickets/review.md, maintainer decision): there is no `e2e:dev` script and no `dev-server` job. `pnpm e2e` runs the `chromium` and `dev` projects in one command, and the Visual baseline job's `pnpm e2e` step covers the dev specs. The offline-skip annotation is kept.

Branch `feature/64_dev`. No new dependencies. Only ci.yml change: a new `dev-server` job (name "Dev server") after `dom-adapter`.

## What changed

- `playwright.config.ts`: new project `dev` (`testMatch: 'dev/**/*.spec.ts'`, top-level `use`, i.e. Desktop Chrome). The `chromium` project now ignores `dev/**`, so each spec runs in exactly one project.
- `package.json` (now): `pnpm e2e` = `playwright test --project chromium --project dev`. Same webServer as everything else (`pnpm --filter @mermaid-js/dev serve`, the `pnpm dev` server).
- `.github/workflows/ci.yml`: the dev specs run in the Visual baseline job's `pnpm e2e` step (the separate `dev-server` job was removed in review).
- `e2e/dev/compare-tab.spec.ts`: when the CDN/registry probe fails and `GITHUB_ACTIONS` is set, `beforeAll` writes `::warning title=Compare tab CDN specs skipped::<reason>` and appends the reason to `$GITHUB_STEP_SUMMARY`. The CI reporters (`github`, `line`) don't print skip reasons, so without this the skip would show only as "5 skipped". It fires once per worker (up to 4 identical lines).

## How to extend

- New dev spec: put it under `e2e/dev/`; the `dev` project picks it up.
- Another network-dependent spec: copy the probe + `announceOffline` pattern from compare-tab.spec.ts.
