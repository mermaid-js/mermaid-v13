# #64 handoff: e2e/dev specs in CI

Branch `feature/64_dev`. No new dependencies. Only ci.yml change: a new `dev-server` job (name "Dev server") after `dom-adapter`.

## What changed

- `playwright.config.ts`: new project `dev` (`testMatch: 'dev/**/*.spec.ts'`, top-level `use`, i.e. Desktop Chrome). The `chromium` project now ignores `dev/**`, so `pnpm e2e` (and the Visual baseline job) no longer runs the dev specs; they run once, in their own job.
- `package.json`: `pnpm e2e:dev` = `playwright test --project dev`. Same webServer as everything else (`pnpm --filter @mermaid-js/dev serve`, the `pnpm dev` server).
- `.github/workflows/ci.yml` `dev-server`: ubuntu-latest, 20 min, `MERMAID_PORT=9000`; checkout, pnpm, node, `pnpm install --frozen-lockfile`, `pnpm exec playwright install --with-deps chromium`, `pnpm e2e:dev`; uploads `test-results/` as `dev-playwright-results` on failure. It runs on every push (except `renovate/**`) and PR, like the other jobs.
- `e2e/dev/compare-tab.spec.ts`: when the CDN/registry probe fails and `GITHUB_ACTIONS` is set, `beforeAll` writes `::warning title=Compare tab CDN specs skipped::<reason>` and appends the reason to `$GITHUB_STEP_SUMMARY`. The CI reporters (`github`, `line`) don't print skip reasons, so without this the skip would show only as "5 skipped". It fires once per worker (up to 4 identical lines).

## How to extend

- New dev spec: put it under `e2e/dev/`; the `dev` project picks it up.
- Another network-dependent spec: copy the probe + `announceOffline` pattern from compare-tab.spec.ts.
