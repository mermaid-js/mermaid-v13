## Exports (`packages/bench/src/size-budget.ts`, re-exported from `@mermaid-js/bench`)

- `readSizeBudget(file = SIZE_BUDGET_FILE): SizeBudget` (validates `gzipBytes > 0`, `core.entry`).
- `measureStaticClosure(entry, outdir?) → { bundle, size }`: bundles any entry (repo-relative or absolute) with `bundle()`'s production esbuild options (`bench: false`, browser, es2022, minify, splitting, `mermaid-source`) into a temp dir and sizes its static import closure. T6: call it on the CDN/ESM entry.
- `closureSize(bundle, roots = [entryFile]) → SizeSummary` (`source: 'static'`): static closure from any output files.
- `chunkOf(bundle, entryPoint)`: output file of a lazily imported chunk by repo-relative source module; `FLOWCHART_ENTRY`.
- `flowchartClosureSize(bundle)`: entry closure + flowchart chunk closure (the bench's static fallback).
- `checkBudget(size, budget) → { ok, actual, limit, detail }`.

Example (#247): `const { size } = await measureStaticClosure(readSizeBudget().core.entry); expect(checkBudget(size, readSizeBudget().core).ok).toBe(true)`; compare `size.gzip` (or `size.files`) across the with/without-packages builds.

## What changed

- `core-size.spec.ts` (in `pnpm check`, ~1 s, no browser): core within budget; fails against `__fixtures__/size-budget-70kb.json`; fallback = entry + flowchart closures.
