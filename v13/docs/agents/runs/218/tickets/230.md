# T6 #230 — CDN build (ESM + classic loader, cdnBase, plugin queue)

Branch `feature/230_cdn-build`. R-PLUG-7, D162, D163, D167.

## Files

- `packages/mermaid/scripts/cdn-build.ts` (`buildCdn(outdir?) → { files, esmClosureGzip, loaderGzip }`, `closureGzip`, `ESM_FILE`, `LOADER_FILE`): run by `mermaid`'s `build` after `tsc` (`tsx scripts/cdn-build.ts [outdir]`; prints both gz sizes). Two esbuild passes from the `mermaid-source` sources: pass 1 finds every lazy `import()` target; pass 2 makes each one an entry with a stable name (`chunks/diagram-<id>.mjs`, `-ascii`, `-language`, `core-theme-specs-<theme>.mjs`, `mermaid-ascii.mjs`; shared code in `chunks/chunk-<hash>.mjs`) and rewrites each lazy `import('…')` in the sources to `import(cdnUrl("chunks/<name>.mjs"))` (`src/cdn-base.ts`, one module per build: the base is never page-wide; URLs via `new URL(path, base)`). A lazy import it cannot name, or a relative one left in the output, fails the build. Linked source maps with sources embedded; map sources read `node_modules/<package>/<path>`, so T3's `assertLoadedOnly` attributes CDN chunks too.
- `src/cdn.ts` (ESM entry → `dist/mermaid.esm.min.mjs`): `index.ts` + `initialize` that sets `cdnBase` only when the key is present (`undefined` = default `new URL('./', import.meta.url)`; a non-string is ignored with `console.warn`; a missing/non-object config initializes with defaults), sets `globalThis.mermaid`, connects the queue. Not in `tsc` output. `src/cdn-base.ts`: `setDefaultBase`, `setCdnBase` (relative values resolve against `document.baseURI`; query and hash dropped; trailing `/` added), `cdnUrl`.
- `src/cdn-loader.ts` (→ `dist/mermaid.min.js`, IIFE, no imports): sets a stand-in `globalThis.mermaid` (every API method) at once, `import()`s the ESM file beside `document.currentScript.src`, or from `<src>/dist/` when the src is a bare package URL. Calls before load replay strictly in call order (async ones return a promise of the real result), each in try/catch; properties set on the stand-in (`parseError`) are copied to the module; `renderSync`/`detectType`/`supportsFormat`/`mount` throw until loaded. Calls `contentLoaded()` itself when the page `load` already fired, even after a failed replayed call. A property set on an old stand-in reference after load is not copied.
- `src/plugin-queue.ts` `connectPluginQueue(api, scope = globalThis, { timeLimitMs }?)`: replaces `push` first, then drains `scope.mermaidPlugins`; each entry goes to `addDiscovered` on its own (a stuck one holds up nothing else); an unreadable entry becomes an unnamed one the registry skips. Entries: anything `registerExternalDiagrams` takes, with an optional `package` (fallback: manifest id, then plugin id), or a seam entry `{ kind: 'plugin' | 'layout', package, … }` (layouts register lazily). Bad entries → `PLUGIN_SKIPPED`.
- `api.ts` (T1 seam): draws (`prepare`/`render`/`parse`/`preload`) also wait for `addDiscovered` calls still in flight, each at most `timeLimitMs` (default 5 s, new optional `addDiscovered(api, list, { timeLimitMs })`); past it the draw goes on with `PLUGIN_DISCOVERY_FAILED` and the registration still lands later. `addDiscovered` never rejects (a failure is a `PLUGIN_DISCOVERY_FAILED` warning) and clears the analysis cache again when it settles. `registry.ts`: the discovered `(package, kind, id)` claims persist across batches, so a duplicate pushed while the first registers is "already discovered".
- Config: `cdnBase` in `INTEGRATOR_ONLY_KEYS` (core) and `IntegratorOptions`/`INTEGRATOR_KEYS` (snapshot; left out of `optionsKey`, so ids do not change), reference text via `gen:config`.
- `package.json`: `unpkg`/`jsdelivr` → `./dist/mermaid.min.js` (the classic loader, as v12); both CDN files in `sideEffects`; devDeps `esbuild`, `tsx`. `files` unchanged (`dist`). No `exports` change. `knip.json`: a `packages/mermaid` block (CDN entries, `scripts/`).

## Unmet / notes

- An overriding `cdnBase` on another origin loads the shared chunks a diagram imports from there too: a second copy of core modules (works in the e2e; same build assumed).
- The base is one per build copy: every API object of that copy shares it (chunks are module singletons).
- Bare URLs: `https://unpkg.com/mermaid@13` and `https://cdn.jsdelivr.net/npm/mermaid@13` serve `unpkg`/`jsdelivr` = the classic loader. `currentScript.src` is then the bare URL, not the redirect target, so the loader resolves the ESM file as `<src>/dist/mermaid.esm.min.mjs` when the src path does not end in `.js`/`.mjs`; the ESM module's own `import.meta.url` (after redirects) sets the default `cdnBase`. Not e2e-tested (the test server does not redirect); unit-tested in `cdn-loader.spec.ts`.
- Not run in the Playwright Docker image (as T2/T3).
