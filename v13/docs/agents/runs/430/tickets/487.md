# Ticket 487: wardley T1, lexer parity gate on the Langium oracle

**`@mermaid-js/diagram-wardley`** (private, `0.0.0`, no manifest until T5). Exports `.` (`src/index.ts`, empty for now) and `./testing` (`src/testing.ts`).
- `wardleyTokens(src): WardleyToken[]` (`{ kind, text, range }`): what v12's lexer saw, in order, as `radarTokens` does: significant tokens, the hidden comments, directives and YAML still in v12's text, `Kind.Error` where no rule matched (one token over the skipped characters, then lexing goes on). - `WardleyTokenKind` (`T`, `src/parser/tokens.ts`): `LBracket, Comma, RBracket, At, Slash, LParen, RParen, Dash, LBrace, RBrace, Decimal` (WARDLEY_NUMBER), `Arrow, LinkPort, LinkArrow, LinkLabel, Strategy, WardleyBeta, Size, Evolution, Anchor, Component, Label, Inertia, Evolve, Pipeline, Note, Annotations, Annotation, Accelerator, Deaccelerator, Name` (NAME_WITH_SPACES), `AccDescr, AccTitle, Title, Int, String, Id, Yaml`; line breaks `Kind.Newline`, `%%` comments `Kind.Comment`, directives `Kind.Directive`. `WARDLEY_TRIVIA` (Comment, Directive, Space, Yaml) for `TokenCursor` in T2. `LANGIUM_NAMES`: kind → Chevrotain name (test use). `KEYWORDS`, `STRATEGIES` (tokens.ts) list the words in Chevrotain's order, for T2's "name starts with a keyword" diagnostic (D423).
- Internal for T2: `lex(src, from, view)` in `src/parser/lexer.ts` returns the full `TokenStream` (use `sourceView` with default options, as `wardleyTokens` does). Title/accessibility images are raw (no trimming; value conversion is T2's).

**Rules T2 must know** (all gated, probed on 2.0.1): token order is the runtime dump (GAPS "Token order", closed). Every keyword and STRATEGY has no boundary (`notebook` = `note` `book`, `buyer` = `buy` `er`, `componentA` = `component` `A`, `annotation1` = `annotation` INT). `-` has longer alternatives ARROW, LINK_ARROW, YAML: `a-->b` is NAME `a-`, ARROW, NAME `b`. NAME_WITH_SPACES takes every letter start except `title` before any `\s` char (then TITLE, image `title` alone if no blank follows), `accTitle…` and `accDescr…` (ACC_* or, failing that, ID: `accTitleX` is an ID). WS precedes the common rules, so title/acc/directive/comment images never start with blanks. INT: `0` alone, `12.` = INT `1` ID `2` error, `1.` = ID `1` error. `.5` is an error. `+'…'` scans to the first `'`, across lines. `;` alone at a line end is an error. NEWLINE is `\r?\n`; v12 turned CR into LF, so a lone CR is a break here; a CR that ends the source is one break, not a CRLF with the appended `\n` (radar's lexer has this bug; no radar case hits it).
