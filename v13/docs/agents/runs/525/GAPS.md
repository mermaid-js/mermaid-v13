# Gaps and choices, spec #525

Unmet acceptance criteria and choices the spec and D-ids don't decide, under the ticket that owns each. Items that visibly change rendering for existing documents are marked **needs a D-id**.

## T0 #590

Unmet criteria: none. Choices the spec and D-ids leave open:

- **Rows line up on `anchorY`, not on node tops.** Pele top-aligns a row (every service has the same icon). `compass` lines each row up on its nodes' `anchorY` (the middle when absent), so `left`/`right` ends always meet in line. Identical to Pele when every node has the same `anchorY` (T3: `iconSize / 2`).
- **Ports sit on the box, not on the icon.** Pele puts `L`/`R` ends at `centre ± iconSize/2` and a `B` end 2 px below a labelled box. `compass` knows only the box, so `L`/`R` ends are on the box's side at `anchorY` and `B` on its bottom. Where a label is wider than the icon, T4 extends the line along the anchor line to the icon (v12's cytoscape endpoint is the icon edge too).
- **Junctions are plain nodes.** Pele's junction dot, centre ports and the wire through a group border are drawing; T3 gives junctions an `iconSize` box (spec), and T4 runs the line on to the centre as v12 does (`svgDraw.ts:73-86`). Facing metrics unchanged.
- **Engine lengths are fixed at v12's defaults.** The cell gap is `max(padding, 0.75 × iconSize)` = 60 and an empty group's cell 80 × 40, from `METRICS`. Node sizes and group padding come from the graph, so `architecture.iconSize`/`padding` still size services and groups, but a document that changes them keeps the 60 px gap (Pele scales it). If T3 wants it scaled, it needs a way in (a `LayoutGraph` field or `ctx.options`): **needs a D-id** if taken.
- **Edge ends on groups** (a flowchart edge to a subgraph; architecture rejects them, D504) place the group's block. The end meets the group's side in line with the other end where the side reaches it, else the side's middle, and a labelled edge widens the gap outside the group's border (review finding 5). **`border` on a node with no group** is ignored (D504).
- **Group order and parents.** Groups are reordered parents-first (Pele assumes it); a missing or non-group parent counts as none, and so does the parent of every group on a cycle of parents.
- **Labels.** The middle label is placed as Pele does, also when it is 0 × 0; when that spot lands on a third node (only seen on flowchart/class/state/ER), it takes the first clear spot along the route. End labels (D102, class multiplicities) go beside the first or last run, past the side and the edge's marker, on the first spot clear of nodes, labels, markers and other edges' runs; when none is, the first clear of all but the runs. D507's v12 label placement is T4's: it may re-place from the route. Nodes, labels, markers and runs are bucketed by a uniform grid (cell = gap + mean column width) so placement stays near linear (`compass-linear.spec.ts`).
- **Input checks** match `layered`'s (sizes, title, `minLen`, markers, `spacing`, `headRoom`) plus `anchorY` and `sides`; an unknown side is a `RangeError`. `grid` is not checked, since `compass` ignores it. **Follow-up:** one shared `checkGraph` for all engines (`layered`, `tree`, `compass`), not done here so this PR leaves `layered` and `tree` untouched.
- **Self-loop ends** part by 8 px but stay on their side (Pele could push them off a short side).
- **`validateLayout` reads `border`**: a `border` end on a node must lie on the border of the node's group (within the validator's slack); an end on a group is checked against that group, `border` or not.
- **Known quality limits on other graph types** (no validator checks them): all edges on one side of a node meet at one point (Pele), and a route between non-neighbours can pass over an intermediate node in the same row or column.
- **Registry:** the D502 exemption is `ANY_GRAPH_LAYOUTS` in `packages/mermaid/src/registry.ts`, one row per engine; swimlane's T0a adds `'swimlane', // D535`.

## T0b #591

- **Merged as-is at +1,270 B gz** (#647, 7d8589e43); no decision comment was left on the A/B/C options. #591 stays open for the maintainer.

Unmet criteria: none of the ticket's. **Size is open, for Knut (A/B/C in tickets/591.md):** gated core +1,270 B gz as is; +1,195 without node-wide lane avoidance.

Choices:
- **Redrawn from the ends.** An edge is redrawn only where a named side moves an end; graphs without sides are byte-identical.
- **Named `left`/`right` ends go to `anchorY` even when layered already used that side** (second review 4). Architecture wants its icon line, so those edges are always redrawn. Other ends whose sides match stay as layered drew them.
- **Stubs and links.** The source stub is `corner` plus the start marker; the target stub is `corner` plus `headRoom` plus the end marker. Links run stub → label → stub, chosen by cost: nodes crossed and doubling back 9 each, a turn 1, length a little. Lanes are tried past the end boxes, then past any node the best path still crosses. Points the route runs straight through are dropped.
- **Growth.** The drawing grows, shifting everything, where a stub or lane enters the margin (first review 3).
- **`anchorY`** must be finite and within 0…height; a bad value is a `RangeError` (second review 5).

Known limits:
- **Edges between a node and its own group** keep layered's route and ports. Layered ends them inside the group box (second review 1, 2).
- **A self-loop with both ends on one side** keeps layered's loop, which lies on the right or below, and reports those ports (`it.todo`, second review 6). A loop with two sides routes through layered's loop label.
- Ends on one side are not spread apart (`it.todo`).
- An unknown side is not refused (`it.todo`).
- Lanes are tried past the end boxes and past nodes the best path crosses, not past every node, so a route can still cross a node when both lane passes fail. Groups are not avoided.
- Not applied on the grid.

## T0c #592

Unmet criteria: none of the ticket's. Core is unchanged: gated size 96,072 B gz, the same as base. The ELK adapter chunk grows by 893 B gz after the review fixes (389 B before them).

Choices:
- **One port per named end.** Each port has the id `<edge id>\u0000source|target`, is 0×0, and has `elk.port.side` set to NORTH, SOUTH, WEST or EAST. Its node (or group) gets `elk.portConstraints: FIXED_SIDE`. An end with no side attaches to the node, and ELK picks its side.
- **`anchorY` gives `FIXED_POS`.** This applies to a node that sets `anchorY` and takes a named `left` or `right` end. FIXED_POS needs a position for every port, so on such a node every end gets one (review 1):
  - A free end takes the flow's side: out downstream, in upstream, by the direction of the node's container.
  - `left`/`right` ports spread `spacing.edge` apart about `anchorY`, with one alone exactly on it.
  - `top`/`bottom` ports spread evenly across the side.
  - All ports stay 12 off the corners where the box allows (review 4).
  - The order along a side is edge order, so ELK can't reorder these ports to cut crossings, as it can under FIXED_SIDE.
  - A node with `anchorY` and only `top`/`bottom` ends keeps FIXED_SIDE.
- **Groups narrower than their title** (review 2). When a group has ports and ELK lays it out narrower than its title needs, the engine lays the graph out a second time, with half the shortfall added to the group's left and right padding. This way its ports move with its sides instead of being left behind by `widenForTitles`. Graphs without such a group are laid out once.
- **`anchorY` checks** (review 3). The engine refuses `anchorY` exactly as `layered`'s `check()` does, with the same messages, on every node and under every algorithm: non-finite or negative values, and values below the box. **Core disagreement, not changed:** `compass` refuses non-finite and negative values but clamps a value below the box (`Math.min(n.height, anchorY)`), where `layered` refuses it. A follow-up should pick one.
- **ELK layered only.** stress, force, mrtree, box, rectpacking, sporeOverlap and radial ignore ports, so they get none, and their `ports` are still read off the route. I probed stress, force, mrtree and box: they route between the boxes or not at all. Under layered, `ports` reports the named side wherever ELK routed the edge and reads the other ends off the route.
- Reversed edges (`orientFeedbackEdges`) keep each port on its real end.

Known limits:
- **An edge between a group and its own member gets no ports** (review 6), as `layered` keeps its own route there. ELK's route and the sides read off it stand, even if the edge names sides.
- **`border` (`{group}`) is not read**, as in `layered`. The end sits on the node's named side, not on the group's border, and `validateLayout` reports it (`does not start at its source`). Mapping it would mean attaching the end to a port on the parent group, which touches the hierarchy-handling and common-ancestor code, so I left it out.
- **Site-level `layout` not tested:** `initialize({ layout: 'elk' })` didn't reach architecture in the scratch run, though front matter `config: layout: elk` did. I didn't investigate; T5/T6 may want to check that the site-level `layout` applies to architecture.

Identity: re-run after the review fixes, with the same result. Every `.mmd` under `e2e/diagrams` (3,199 files) was rendered three ways: as written, with `layout: elk` and with `layout: elk.stress` (9,597 renders, 3,027 ELK calls). Base and branch give identical graphs, models and SVG. The only difference is gantt's `today` line in `should-render-when-compact-is-true.mmd`, which follows the clock.
