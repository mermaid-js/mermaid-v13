## How to use (T3, T5)
- Mindmap plugin: `layoutKind: 'graph'`, `layoutEngine: { default: 'tree', aliases: { 'cose-bilkent': 'tree', 'tidy-tree': 'tree' } }`. In `plugin.layout` call `ctx.layout(graph)` only, never `(ctx.layout ?? tree)` (that would pull `tree` into the mindmap chunk).
- Graph in: measured `width`/`height`, edges parent → child in source order (the first incoming edge of a node is its tree edge), `spacing.rank` = gap from a parent out to its children (every level, root included), `spacing.node` = gap between sibling subtrees. `diagramPadding` honoured. `direction` is returned unchanged; `availableWidth`, `routing`, `metrics`, `grid` unused. No extra branch gaps (Pele's `BRANCH_GAP_*`): pick the numbers in T3 through `fromPx`.
- Model out: node centres; a tree edge is 2 points `axis: 'h'`, parent's facing side → child's near side at the centres, `ports` right/left (left side mirrored). Curve it in the renderer. Which side a branch is on: compare the child's `x` with the root's.
- `mermaid` puts `default` in the plugin-defaults config layer (`config-snapshot.ts`), maps aliases (`layoutName` in `registry.ts`), loads `tree` lazily (`LAZY_LAYOUTS` in `registry.ts`), and draws unknown / uninstalled ELK names with the default plus `LAYOUT_UNKNOWN` / `ELK_NOT_INSTALLED` ("using the built-in tree engine"). `renderSync` before `prepare()` → `NotLoadedError [{kind:'layout', name:'tree'}]`.
- Only plugins whose `layoutEngine.default` is `tree` reach it; for others `layout: tree` is `LAYOUT_UNKNOWN`.
