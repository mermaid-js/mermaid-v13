# #386 T2 grammar, parser, model and AST: handoff

Branch `feature/386_mindmap-parser`. Core and the registry are untouched. `@mermaid-js/diagram-mindmap` had no plugin export or manifest at this ticket (#390, T5, added them).

## Exports (`@mermaid-js/diagram-mindmap`)

- `parseMindmap(src, { preprocessed?, colorBy?, keepTokens? })` → `ParseResult<MindmapModel, MindmapDocument>`; never throws. `detectMindmap(src)` (v12's case-sensitive `/^\s*mindmap/` after front matter and directives, for T5). T5's plugin passes `colorBy: config.mindmap.colorBy`.
- `MindmapModel` (`src/model.ts`): `nodes` in source order (= depth-first), `nodes[0]` the root; each `{ ast, id, label, shape, level, depth, parent?, children, classes, icon?: { text, range }, section? }`. `level` is v12's raw indent less the root's (`edge-depth-<level+1>` for T4), `depth` the tree depth. `shape`: `default|rect|rounded|circle|cloud|bang|hexagon`. Labels raw (entities decoded, line breaks kept); every label is markdown. `mindmapSections(nodes, colorBy)` and `MINDMAP_SECTIONS` (11) recompute sections.
- AST (`src/parser/ast.ts`), flat in source order: `Node` (`n:<id>`, `n:<id>@k`; id trimmed, an id-less node's label), fields `nodeId?`, `label`, `shape`, `indent`, `decorations: { type: 'Class'|'Icon', text, range }[]`. No edge or decoration ids. Statement spans: `header`, `node` (blocks nested by subtree), `class`, `icon`. No symbols (T6 #389) and no probe yet.
- `mindmapIcons(model)` for `DiagramPlugin.icons` (D293): each icon as `mindmapIconName(ref)` names it (D297: `mdi:fire` as is; `<pack> <x>-<name>` on one line → `<pack>:<name>` when `<x>` is the pack or `fa` after a Font Awesome pack, `fa[bdklrs]?`; anything else trimmed as written). Order is source order, not deduplicated.
- Errors: `UNEXPECTED`, `UNCLOSED_SHAPE`, `UNCLOSED_STRING`, `UNCLOSED_ICON`, and v12's DB errors as semantic diagnostics: `MINDMAP_SECOND_ROOT` (v12's message, then a hint; the node and its decorations are in the AST only, with no spans) and `MINDMAP_DECORATION_BEFORE_NODE`. A node that fails inside its shape is still added (partial label), so one mistake gives one diagnostic; a source with no header gets that one diagnostic only.
