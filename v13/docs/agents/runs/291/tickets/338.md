# #338 T4a: `cScale`, `cScaleInv`, `cScaleLabel` palettes (branch `feature/338_timeline-palettes`)

## Variables (mindmap reuses these; D258)

| Name | Kind | Slots | Overrides |
| --- | --- | --- | --- |
| `cScale` | palette (literal colours, no CSS variable) | 12 | whole list `cScale: [...]` or `'a, b'`; `cScale0`–`cScale11` one slot |
| `cScaleInv` | palette | 12 | `cScaleInv: [...]`; `cScaleInv0`–`cScaleInv11` |
| `cScaleLabel` | palette | 12 | `cScaleLabel: [...]`; `cScaleLabel0`–`cScaleLabel11` |
| `THEME_COLOR_LIMIT` | schema key, `ignored` | | always 12, cycle by slot modulo 12 |

- Read: `theme.palette('cScale' | 'cScaleInv' | 'cScaleLabel')` → `readonly SafeColor[]` (12 in every built-in theme). `NUMBERED_PALETTES` and `PALETTE_LIMIT` (12) from `@mermaid-js/core/theme`.
- Precedence per slot: numbered override > author's whole list > theme entry. An unsafe colour is dropped with `THEME_VARIABLE_DROPPED`; a slot past the list is ignored (R-CONF-5).
- Theme entries are rules (builders in `specs/scales.ts`, lists in `specs/palettes.ts`), so they follow overrides exactly as v12: `cScale` follows `primaryColor`/`secondaryColor`/`tertiaryColor` in base, forest, dark (slot 0), neo-dark, redux-dark, and `mainBkg` in redux; default, neutral, neo and the colour themes are fixed as in v12. `cScaleInv` follows a `cScale<n>` override where v12 does (darkened, then inverted); `cScaleLabel` follows `labelTextColor` (default, base, neo*, redux*), `actorTextColor` (forest), `cScale1` (neutral slots 0/2), `cScale<n>` (redux-dark-color).
- `themeVariables.darkMode: true` (the author's flag, not a theme's `dark`) switches to `ThemeSpec.darkModePalettes`: darken by 75 (base, neo, neo-dark, redux, redux-dark), black labels (dark, neutral).

## Core additions

- DSL (`dsl.ts`): `adjustHue(c, deg)` (khroma `adjust(c, { h })`, CSS `hsl(from c calc(h + deg) s l / alpha)`) and `ifSet(v, b)` (v12's `v || b`: the author's value, else `b`; CSS `var(--mermaid-v, b)`; `v` may be a palette slot). Plain-number token copied byte for byte from #309.
- HSL steps keep khroma's HSL channels (`Resolved.hsl`), so a hue survives lightness 100 and `invert` reads them as khroma does (`khromaRgb`). Existing rules never chain HSL steps, so their values are unchanged.
- `ThemeSpec.palettes` entries may be rules naming slots (`invert(cScale3)`); palettes are evaluated on first `palette()` read.
