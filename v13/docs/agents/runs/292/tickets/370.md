# Ticket 370: gitGraph T2, grammar, parser, model, AST and ported specs

**Exports** (`@mermaid-js/diagram-gitgraph`, runtime entry, next to T1's): `parseGitGraph(src, options?) → GitGraphParseResult` (`ParseResult<GitModel, GitGraphDocument>`, never throws), `detectGitGraph(src, pre?)` (v12's `/^\s*gitGraph/` after front matter, directives, comments), types `GitGraphParseOptions` (`ParseOptions` + `preprocessed?`, `mainBranchName?` default `main`, `mainBranchOrder?` default 0), `GitModel`, `GitCommit`, `GitBranch`, `GitDirection`, `GitCommitType`, `GitWrittenType`, and the AST node types (`GitGraphDocument`, `GitStatementNode`, `GitHeaderNode`, `GitCommitNode`, `GitBranchNode`, `GitMergeNode`, `GitCheckoutNode`, `GitCherryPickNode`, `GitTextNode`, `GitValue`).
- **Plugin hook for T5:** `parse: (text, ctx) => parseGitGraph(text, { preprocessed: ctx.preprocessed, mainBranchName: ctx.config.gitGraph?.mainBranchName, mainBranchOrder: ctx.config.gitGraph?.mainBranchOrder })` (keys are `pending` until T5 makes them honoured).
- **Model** (`src/model.ts`, frozen): `direction`; `commits` by `seq` (a commit whose id a later one reuses is gone, D264), each `{ id, customId, message, seq, type, customType?, tags, parents, branch, astId }`; `branches` in drawing order (by `order`, stable) `{ name, order, head, astId? }` (main has no `astId`); `mainBranch`, `currentBranch`, `head`; `title?` (in-text if non-empty, else front matter, D265), `accTitle`, `accDescr`; `warnings`. Types are names (`'MERGE'`, …), not v12's numbers. **Parents may form cycles** (`A`,`B`,`A`): T3/T4 must terminate on them, and draw no arrow for a self-parent.
- **Ids (D260):** Pele's `nextId`; a derived id also keeps clear of every `id:` written anywhere in the text (deviation 1). `0-9e3779b`, `1-3c6ef36`, `2-daa66d1`, …
- **AST** (`ast.children`, source order; a statement with a syntax error has no node, one with a DB error keeps its node): `st:<k>` header/title/accTitle/accDescr, `c:<id>` (`@2` on a repeat) or `c#<k>`, `m:<branch>#<k>`, `cp:<source>#<k>`, `b:<name>` (`@2`), `co:<name>#<k>`; names percent-encode `%>@#` and XML-illegal characters. Values are `GitValue { value, range }` (quotes in the range). Ranges start at the keyword.
- **Symbols:** kind `branch` (def at `branch`, refs at `checkout`/`switch`/`merge`) and kind `commit` (def at commit and merge `id:`, refs at cherry-pick `id:`/`parent:`). **Statements:** `header`, `commit`, `branch`, `merge`, `checkout`, `cherryPick`, `title`, `accTitle`, `accDescr`. **Probe:** `tested` hooks at every decision, modes `title`/`accTitle`/`accDescr`/`string`/`INITIAL` (T6).
- **Diagnostics:** `UNEXPECTED` (with hints: quote names starting with `title`/digits/keywords (D269), case, glued keywords, `accTitle:`), `UNEXPECTED_CHARACTER`, `UNCLOSED_STRING`; DB checks (`src/parser/build.ts`) `GIT_BRANCH_EXISTS`, `GIT_UNKNOWN_BRANCH`, `GIT_MERGE_{INTO_ITSELF,CURRENT_BRANCH,NO_COMMITS,UNKNOWN_BRANCH,EMPTY_BRANCH,SAME_HEAD,DUPLICATE_ID}`, `GIT_CHERRY_PICK_{UNKNOWN_COMMIT,NOT_A_PARENT,MERGE_PARENT,SAME_BRANCH,NO_COMMITS}`, ranged on the argument, statement changes nothing; warning `GIT_DUPLICATE_ID` with `related`.
- **Value conversion** `src/parser/convert.ts`: pie's converter copied (`stringValue` = Langium `convertString`); text as written (D263).

**Grammar** `packages/diagram-gitgraph/grammar/gitgraph.ebnf` (Langium token rules in order; longer-alt as `(?![-.\/\w]*[-\w])` lookaheads), `tools/gen-grammar` row `gitgraph` (`documented: String, Reference`); generated `grammar/generated/*`, `src/generated/{categories,docs}.ts` (`gitgraphCategories`, `gitgraphDocs`, checked by `src/generated.spec.ts`), `v13/docs/syntax/gitgraph.md`.

**Ported specs** (`src/v12-specs/`, `pnpm --filter @mermaid-js/diagram-gitgraph port:v12-specs`): `gitGraph.spec.ts` (65 pass; 4 skipped in v12; 5 `getConfig` skipped: no DB config, #374) and parser `gitGraph.test.ts` as `langium-gitGraph.spec.ts` (24 pass, 3 skipped: mermaid@12 rejects them, only Langium's recovery built the asserted statements). `adapter.ts` maps codes to v12's messages.

**Size:** esbuild, core external, minified: runtime entry 27.0 KB, **9.4 KB gz** (T1: 0.7 KB gz entry, lexer 3.1 KB gz). Core untouched, nothing registered (R-PERF-8 not measured).

**Deviations:** (1) Derived ids skip ids written later in the text too (D260 says "already in use"): `commit` then `commit id:"0-9e3779b"` would otherwise merge two commits where v12 (random digits) keeps both. (2) Syntax-failed statements change nothing and get no node; DB-failed ones keep their node. (3) Merge/cherry-pick ids repeated across kinds use `#k` per base (`m:dev#2`), commits `@n` (pitfall 9). (4) v13 messages are its own (R-ERR-2); the ported specs' adapter rewords them as v12 did. (5) `customId` on every commit (v12: merges only).

**Unmet criteria:** none.
