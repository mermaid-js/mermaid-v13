# #94 (+ #208 item 5): flowchart back-to-back shape data; edge-text entities in the lexer harness

## #94: grammar vs parser on `A@{…}@{…}`

- The real trigger is not the unterminated `@{`. It is two shape-data blocks written back to back: `F@{ … }@{ … }`. Minimal repro: `flowchart TB\nF@{ shape: rect }@{ shape: rect }`.
- Oracle (mermaid@12.2.0): `flowchart TB\nF@{ shape: rect, }@{ label: x }` is **accepted** (also with `--> b` and `& G` after it). The jison `shapeData: shapeData SHAPE_DATA` rule joins the block texts (it drops `}` and the `@{` image). The #94 repro and the minimal repro fail in v12 on YAML only (`v12Syntax` undefined), not on syntax. `F@{…}  @{…}` (blanks between) is rejected by v12, the grammar and the parser alike.
- Verdict: the **grammar is right** (`shapeData = SHAPE_DATA+`, flowchart.ebnf:252) and the parser was wrong. The ebnf is unchanged and nothing is regenerated.
- Fix: in `packages/diagram-flowchart/src/parser/parser.ts:820-850`, `shapeData()` now loops. When another `@{` comes right after `}`, its pieces are appended to the same text, and the data range covers every block. As before, the YAML is read from `{\n<joined>\n}`. An unclosed later block is reported against its own `@{`.
- Tests:
  - `packages/conformance/src/flowchart/grammar/sentences.spec.ts:19` (`REGRESSIONS`, `it.each` at :49) holds the exact #94 repro plus 6 variants. Each one checks grammar vs parser accept/reject and AST, the v12 syntax verdict, and, where v12 accepts, v12 vs v13 model snapshots. The list is fixed and does not depend on corpus weights. It was red before the fix (6 of 7) and is green after.
  - `packages/diagram-flowchart/src/parser/parse.spec.ts:245` checks the joined model (`cyl`/`Disk`), a join that YAML rejects (`SHAPE_DATA`) and an unclosed second block (`UNCLOSED`).

## #208 item 5: `#y;` in edge text (flowchart lexer-parity harness)

- Cause: jison splits EDGE_TEXT into one token per character. The harness decoded the entity placeholders (`ﬂ°`, `¶ß`) per token, before merging, so a split placeholder was never decoded.
- Fix: `packages/conformance/src/flowchart/lexer-parity.spec.ts:175` now runs `normalise()` first and decodes after it. The header comment is updated to match.
- Test: `EDGE_TEXT_ENTITIES` (:124) adds `A -- x:#y; --> B`, `#quot;`/`#9829;`, `==` and `-.` forms, each also run in its commented variant. All 8 failed before the fix and pass after. Parity covers 1757 of 1764 sources with 0 diffs.
- The class and sequence lexer-parity harnesses also decode per token. They were not touched (out of scope) and no current case hits this there.
