# #206 (+ #208 items 1–2): left single-run labels, underline runs, tab/LF/CR in attributes

## What changed

- #206: the writer's fast path for a label of one plain run (`packages/core/src/svg/writer.ts:111-122`) now honours `left: true`. It writes `x` = box left edge + `indents[0]` and `text-anchor="start"`. Without `left`, output is unchanged.
- #208.1: `layoutLabel` runs carry `underline: true` when the style has `Style.Underline` (`packages/core/src/text/label.ts:441`). Before, only bold, italic and mono were carried.
- #208.2: new `escAttr()` (`packages/core/src/svg/escape.ts:27-38`) writes tab, LF and CR in attribute values as `&#9;`, `&#10;`, `&#13;`. Both backings use it (`writer.ts:168`, `tree.ts:291`). Text content is unchanged. Tab is included because GAPS #126 lists it and XML normalises it the same way.
- Class drops both workarounds (`packages/diagram-class/src/render/render.ts:382-394`, ~470). `drawRow` no longer writes its own start-anchored `<text>`, and static members no longer get `text-decoration` on `<text>`.
- `packages/conformance/src/class-render.spec.ts` drops `attrForm`, so `data-ast` now round-trips exactly. `class-behaviour.spec.ts:111` now expects underline on the member's inner `<tspan>`. MIGRATION.md:749 is updated to say the same.

## Tests (red before, green after)
