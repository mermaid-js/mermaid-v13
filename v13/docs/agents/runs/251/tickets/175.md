## #208 item 3: directive after a comment (oracle verdict: v12 rejects; matched, no conflict with D67)

- v12 `directiveRegex` reads a directive only where a word follows `%%{` (blanks allowed). With `%%{` followed by a comment line, the text stays in the diagram: flowchart, class, sequence, ER and state reject it, while v13 accepted it. The same rule covers `%%{}%%`, `%%{ }%%`, `%%{"a":1}%%` and `%%{: …}%%`. In those cases v12 class and sequence accept while flowchart, ER and state reject; v13 accepted them all.
- `directives.ts:64`: a `%%{` with no word after it is not a directive. This is a recognition rule only, with no rewrite and the same offsets, so it is consistent with D67.
- `diagram-start.ts:12-16`: detection skips such a line, as v12's `anyCommentRegex` did, and each grammar then decides.
- Oracle check: `conformance/src/preprocess.spec.ts` (`directives around comments…`) covers 50 sources (5 types × 9 heads + 5 in-body). Acceptance and the resolved `theme` now match v12 on all of them; 8 tests failed before the fix.
- Class `lexer-parity.spec.ts`: the exclusion for comments after `%%{` is removed and the suite still passes.
- Changed existing test: `directives.spec.ts` no longer expects `%%{}%%` to read as a directive named `''`. The oracle shows that expectation never matched v12.

## #208 item 4: invalid YAML front matter (oracle verdict: v12 rejects; matched)

- A fuzzer over corpus front matter (5 seeds × 150k mutations) found one family: a lone `-` or `?` used as a value.
- `yaml.ts:324-328`: a lone `-` after `key:`, or a lone `?` there, is now "bad indentation of a mapping entry". `yaml.ts:461-472`: in flow, `-` before a blank, line break, flow indicator or end, and `?` before a flow indicator or end, are now "missed comma between flow collection entries". These are the js-yaml messages. After the fix the fuzzer finds nothing.
- Tests: `yaml.spec.ts` gets 10 reject and 4 accept cases. `preprocess.spec.ts` checks 7 front matters, each rejected by js-yaml, by v12 `parse` and by v13 `parse`.
