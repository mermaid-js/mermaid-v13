# #275 T4: SVG writer fast paths (handoff)

Branch `feature/275_svg-writer`, cut from `feature/265_render-speed` at `d22cfee90` (T3 merged). PR #413 into the integration branch.

## What changed (`packages/core/src/svg/`)

- **Escaping** (`escape.ts`): `esc` and `escAttr` return a value unchanged after one test of a plain ASCII class (`RE_CHANGED`: printable ASCII but `& < > "`), and run the Unicode-aware tests only otherwise. This is how path data and transforms skip escaping. It doesn't trust their brand, which is checked only at compile time, so untyped callers stay safe.
- **Labels** (`writer.ts`, `Stream.plainLabel`): the stream writer writes a label without inline boxes straight into its buffer, with no attribute object per element. `writeLabel` still draws, as before:
  - styled runs (through `open`);
  - labels with inline boxes;
  - labels whose attrs set the label's own attributes or have inherited keys.

  The tree writer is unchanged.
- **Not done:** the root-style memo. It's one string per render, and the escape check already covers it.

Specs, green on the base by design because the output must not change:
- **`backings.spec.ts`:** stream and tree agree on labels of one line, several lines and styled runs, on empty and escaped text, and on attrs that set the label's own attributes. Random programs now include these label shapes.
- **`gradient.spec.ts`:** a label painted with the gradient.
- **`escape.spec.ts`:** every character up to U+00FF.

Four deliberate breakages of the direct write each turned the specs red.

Checks:
- identity against `d22cfee90`: 163 of 163; none dropped;
- `pnpm check` green.

The step is from a second run, started with load under 3 and no process above 25% CPU. The first run, taken while Docker's VM used about 82% CPU, gave 0.997 · 0.998 · 0.991. Either way the effect is within noise in Chromium. A Node render of the 14 largest is 3–4% faster.

## For the maintainer

- **Core size:** core is 95,002 B of D314's 95,232 B. The escape check costs 32 B; the direct label write costs 347 B, for no measured gain in the browser. I recommend dropping the label write and keeping the escape check, which leaves 577 B for T5 and T6.
- **`VIEW_BOX` regex:** in `drawDiagram`, it is 4.4% of a Node render of the 14 largest, the largest single cost left in the write stage. It belongs to T5 ("size from the writer").
