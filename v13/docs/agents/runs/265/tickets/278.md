## What changed

- `compound.ts`: `compoundLayout` hands a graph with no groups to `ungrouped`. That graph has one level and no ports, so its nodes and edges go to `layered` and come back in one pass. It skips the levels, depths, two path arrays per edge, the route Map, and the convert-then-append copy. `endLabelRoom` is shared by both paths. `check()` is unchanged.
- `layered.ts`, `assignTracks`: the `taken` Set is an `Int32Array` stamped `at + 1`.
- `ungrouped.spec.ts`, recorded on the base before the change:
  - 19 graphs that reach each branch of the root level, in full, with exact numbers and the sign of zero kept;
  - the 67 layout fixtures without groups, as digests.

## Deviations and unmet

- **Spec-first:** the specs pass on the base by design, because the output must not change. Instead I broke the fast path on purpose. Nodes in the wrong order, and end labels without head room, both turned them red. Three other breakages stayed green, because no graph the engine accepts can show the difference:
  - no dedup of points within 0.01;
  - no −0 → 0 in the offsets;
  - no self-loop label in `CEdge`, which `run` never reads.
  The code is kept anyway, matching the general path.
- **"One conversion":** `LayoutGraph` → `CNode` stays, because it carries the self-loop room and the spans. The per-level conversion and the route assembly collapse into one pass.
- **Gain:** the ticket estimated 10–20% for the layout engine; the result is 3.4% of render time on the 14 largest. A Node profile puts the wrapper at about 7% of render time, mostly building the output model. Track assignment is also about 7%, nearly all of it the O(n²) pick loop and the clash lists in `lay`, which T7 leaves out of scope. That loop is a candidate follow-up for the maintainer.
- Nothing dropped under the identity gate.
- During the A/B, an esbuild from another checkout (`mermaid`, worktree `bug-8283`) used about 8% CPU, with load under 3.
