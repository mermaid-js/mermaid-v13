# #277 T6: parser trivia and shape-data fast path (handoff)

Branch `feature/277_parser-trivia`, cut from `feature/265_render-speed` at `0d2904e9d` (T5 merged). PR #425 into the integration branch.

## What changed

- **Shape data** (`core/preprocess/yaml-flat.ts`, used by `FlowParser.shapeData`): `flatYamlMap` reads a one-line flat `key: value` list exactly as `parseYaml` reads `{\n<data>\n}`:
  - keys are plain identifiers, not `null`, `true`, `false` or an unsafe key;
  - separators are `: ` and commas;
  - values are double-quoted strings (through `unescapeDouble`), single-quoted strings, and plain words and numbers (typed as `scalar()` types them, through `plainNumber`).

  Anything else falls back to `parseYaml`. AST ids are untouched.

Specs (`yaml-flat.spec.ts`, written first; red, no module):
- a table of quoted values, colons in values, escapes, numbers and words;
- 35 inputs that must fall back, nested values among them;
- 3000 generated texts, each falling back or equal to `parseYaml`'s value in key order with no diagnostics; more than 300 take the fast path.

Four deliberate breakages each turned the spec red.

Checks: identity against `0d2904e9d` 163 of 163; `pnpm check` green, parity and fuzz specs included; core 94,646 B of D314's 95,232 B. The module adds about 500 B: under D313 it sits in core although only the flowchart parser imports it.
