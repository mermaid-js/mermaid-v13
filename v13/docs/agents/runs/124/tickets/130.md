Branch `feature/130_er-lexer-gate`. `pnpm check` green after merging `feature/124_er-diagram`.

## Exports (`@mermaid-js/diagram-er`, `private: true` until T5 adds the manifest and release wiring)
- `erTokens(src): ErToken[]`: significant tokens `{kind, text, range}`; `text` is v12's image (CR as LF, removed spans left out, entity placeholders decoded to `&name;`), `range` is a source range. Comments, directives and the final `Kind.EOF` are left out.
- `ErTokenKind` (`T`): one kind per jison terminal (e.g. `OneOrMore` covers `1+`, `|{`, `one or more`). `T.Char` is jison's `.` rule (name = its text); `T.Eof` is jison's `EOF` terminal (zero-width, at `src.length`). Newlines are `Kind.Newline` (one token per `[\n]+` run); style-state errors are `Kind.Error`.
- `JISON_NAMES`, `jisonName(kind, text)`: kind → jison terminal (dev/test only, R-ERR-5).
- Internal for T2: `parser/lexer.ts` `lex(src)` → `{tokens: TokenStream (trivia included, source ranges), textStart, textEnd, view}`; `parser/source.ts` `sourceView()` (text v12 lexed, as 4 edit layers with `start(i)`/`end(i)` maps back to source, trivia ranges), `decodeEntities`.

## Behaviour T2 must know
- v12's appended `\n` is lexed: the last token (usually `NEWLINE`) holds it, range clipped to the source end. Empty-image tokens jison emits at end of input (`EOF`; `acc_title_value`/`acc_descr_value`/`acc_descr_multiline_value` when the text ends in that state) are zero-width tokens at `src.length`.
- `END` includes trailing whitespace and newlines (`end\b\s*`), so no `NEWLINE` follows it. `.*direction\s+TB[^\n]*` swallows everything before it on the line in INITIAL (even `A ||--o{ B : "direction TB"`). In the style state, `\s+` eats a newline that follows a blank, so the state goes on.
- `<block>` ATTRIBUTE_WORD also accepts U+00B5 (µ), a side effect of case-insensitive matching.

## Tests and helpers
- `packages/conformance/src/er/jison-lexer.ts`: `loadErLexerOracle()` (`tokens`, `input`), the v12 lexer driven with a fresh `ErDB`.
- `packages/conformance/src/er/lexer-parity.spec.ts`: 2595 of 2599 sources compared, 0 diffs. The sources: 206 e2e fixtures, 581 harvested spec strings, line-separator and preprocessing cases, each also with comment lines and as CRLF, plus every UTF-16 code unit per character-class position. The 4 sources not compared are commented variants whose mid-line cut splits `erDiagram`, so v12 does not detect them.
- Exclusions, listed in the spec: comment and directive trivia; the stream-final `Kind.EOF` (`$end`). Images are compared with entity placeholders decoded on both sides; both streams are cut at the first `INVALID`.
- `packages/conformance/corpus/er-v12-specs.json` comes from `pnpm --filter @mermaid-js/conformance harvest:er`, which runs the v12 specs with stubbed imports and records each `parse` argument. A regex would miss most of them, since they are template literals.
- `packages/conformance/src/er/stress.spec.ts`: 13 pathological inputs, time ratio 4n/n < 10 (best of 7 after a warm-up).
- `packages/diagram-er/src/parser/removed-spans.spec.ts`: one token per v12 token across comments, CRLF and entities, plus trivia order (pitfall 4).
