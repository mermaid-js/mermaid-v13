## ErModel (for T3 layout and T6 language), plain data, insertion order
- `direction` (`TB|BT|LR|RL`, default `TB`), `accTitle`, `accDescr`, `warnings`. No `title`: front matter is core's (the oracle never sees it; v12's jison `title` rule is dead).
- `entities[]` `{id: n:<name>, name, alias ('' = none, first alias wins), attributes[], classes[] (no 'default'), styles[]}`, first-mention order. Names that are subgraph ids are left out (v12's getData draws none).
- `attributes[]` `{id: a:<entity>.<name>[#k], type ('string?', '~T~' kept), name, keys[] as written (PK/FK/UK, any case), comment ('' = none)}`.
- `relationships[]` `{id: e:<from>><to>[#k], from/to: {name, subgraph, cardinality}, identifying, label}`. `cardinality` ∈ `zeroOrOne zeroOrMore oneOrMore onlyOne mdParent`, the one written next to that end. `subgraph` = the name was an already-closed subgraph id when read (v12's timing).
- `subgraphs[]` `{id: s:<name>[@k], name, title (trimmed), members[], direction?, classes[], styles[]}` in close order (inner first). Reopening an id adds a second subgraph (as v12). `members` = v12's list minus items naming neither an entity nor a subgraph; each member in one subgraph only.
- `classes[]` (classDef) `{name, styles, textStyles}`. Styles/classes reach only entities/subgraphs existing at that statement (v12 order). Style parts are joined without blanks (v12).
- AST: statements `Header Entity Relationship (children: 2 Entity mentions) Subgraph AccTitle AccDescr Direction Style ClassDef Class`; mentions `n:A@2…`; unnamed `<kind>:<n>` (`style:1`). Attribute ids percent-encode `.` too (`a:a%2Eb.c`), else `a:A.b.c` was ambiguous. Symbols: `entity` (def at first mention), `class`, `subgraph`.
