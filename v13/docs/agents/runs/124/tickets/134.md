# #134 ER T5: integration (handoff)

Branch `feature/134_er-integration`, merged with `feature/124_er-diagram` @ 9a14932c0 (#136 ASCII in). `pnpm check` and `pnpm e2e` green.

## What changed
- `@mermaid-js/diagram-er` is public (13.0.0-alpha.0, README). Manifest `{id: er, types: [er], formats: [svg, ascii], export: er, ascii, language}`; `gen:registry` keeps v12 order, so `erDiagram` renders through `createMermaid()`, `mermaid/slim` + `er`, `format: 'ascii'`, and the language service loads the facet. `mermaid`, `language-service` (optional peer) and `language-server` depend on it; release/layout specs list it. Format matrix: er svg yes, ascii yes.
- `er` section defaults generated (`SECTION_OWNERS`, `erConfigDefaults`, `er.configDefaults`). Honoured: `nodeSpacing` 140, `rankSpacing` 80, `minEntityWidth` 100, `useMaxWidth` (ER override of the base key), `entityPadding` 15, `diagramPadding` 20. Ignored with reason (12.2.0 reads none of them): `layoutDirection`, `minEntityHeight`, `fontSize`, `stroke`, `fill`. Still `pending`, as flowchart: `theme`, `titleTopMargin` (titles are not drawn yet).
- D116 (`layout/prepare.ts` `cellPad`, `ErPrepared.pad`): in px `entityPadding` is the padding on each side of every table cell, across and down (name band and attribute-less boxes too), in place of `builder.nodePad`. `diagramPadding` is the px margin. In cells both are ignored (1-cell padding, margin 0).
- D117: core theme DSL gains `lightenHsl(a, N%)` / `darkenHsl(a, N%)` (khroma's HSL lightness with its 10-decimal rounding; CSS `hsl(from a h s clamp(0, l ± N, 100) / alpha)`). Classic rows: base and forest derive from `mainBkg`, default from `primaryColor`; dark and neutral are constants, because v12 sets them in the theme constructor and they never follow an override. Shared `strokeWidth` and the whole-table author fill are kept; D117 cited in code, tests and MIGRATION.
- D118 (`prepare.ts` `sizeKey`): in cells, `er.nodeSpacing`, `rankSpacing`, `minEntityWidth` convert from px only when the author set them. Flowchart has no way to tell them apart: it converts its own defaults in cells. The resolved config already holds the generated defaults, so ER treats a value equal to `erConfigDefaults[key]` as not set (setting exactly 140 draws as not setting it). One addition: in cells the rank gap is at least 6 (`ENDS_GAP`). With the profile's 4, both 2-cell cardinality ends touched the label or each other and the structural check failed on 158 corpus files. **Maintainer:** confirm the 6-cell floor.
- ER goldens changed by D118: 140 files (`er/` 109, `er-ascii/` 9, `er-v13/` 22). Boxes fit their text (no 13-column minimum), LR gaps are 9 columns instead of 18, and TB gaps 6 rows instead of 5. The upstream structural check is green, and `ascii-divergences.json` is unchanged and has no stale entries (its one ER entry is still accurate). The `ascii.spec.ts` expectations were rewritten to match.
- Removed: `conformance/src/er/mermaid.ts` and `ER_SECTION_DEFAULTS`. `er-render.spec`, `ascii/er-render.ts` and `er-api.spec` use `createMermaid()`.
- T6 finished: goldens moved to `language-service/goldens/er` (outputs unchanged). Flowchart `completions/empty.out` gains only `erDiagram`. Property spec is green over ER. Rename round-trip has one new known entry, not a model change: `2.5` is percent-encoded in attribute ids. New `conformance/src/er/service-symbols.spec.ts` (oracle through the service): 751 docs. 314 names are written only quoted, and the service gives those no definition (shared `symbols.ts` gap, as flowchart's quoted subgraph ids). Counted as `QUOTED_ONLY`.
- Baselines: 9 fixtures in `e2e/diagrams/er-diagram/baseline/` (all accepted by v12), shown in the gallery under `er/` (`dev/src/fixtures.ts` `galleryFixtures`). The ER e2e corpus (215) now runs in `mmd-snapshots`.
- New specs: `mermaid/src/er.spec.ts` (renders, SYNTAX not UNSUPPORTED, svg+ascii, defaults, slim), `conformance/src/er-row-colours.spec.ts` (D117 vs v12 themes through the oracle), D116/D118 cases in `layout.spec.ts`, D117 in `er-render.spec.ts`, `lightenHsl` in `rules.spec.ts` and the browser CSS=JS test.
