## API (`@mermaid-js/core/svg`)
- `SvgWriter.linearGradient({ x1, x2, y?, from, to }: LinearGradient): GradientRef` returns `url(#<scope>-g-<hash>)` for `fill`/`stroke`. `from`/`to` are `StopColor` (`SafeColor` or a `ThemeRef`), rechecked with `checkColor` (throws otherwise); numbers go through `num()` (2 decimals; NaN or Infinity throws).
- `finish()` writes `<defs>` as the root's first child: D182's gradient first (unchanged bytes, only when referred to), then each user-space gradient once, in first-ask order: `<linearGradient id gradientUnits="userSpaceOnUse" x1 y1 x2 y2>` (y1 = y2 = `y ?? 0`), `<stop offset="0" stop-color>`, `<stop offset="1" stop-color>`.
- Id: `styleScope(ctx.idPrefix)` + `-g-` + `hash36` (FNV-1a, the hash `styleScope` already used, now exported from style.ts) of the *written* ends and stops, so values equal after rounding share one element. On a hash collision it rehashes, so ids stay unique within a render. The pipeline passes `WriterOptions.idPrefix` lazily: it is read only on the first call, and other types never read it.
- `mix-blend-mode`: a PROPERTIES entry with a `style` target. `checkStyle` keeps `normal`/`multiply` (case-folded, `!important` stripped) as `shape.style = 'mix-blend-mode:<v>'`, because it is not an SVG presentation attribute. No current `...style.shape` spread site (flowchart, class, state, ER, gantt) has a renderer `style`; a renderer that adds one must pass `shape.style` as `styleText(own, shape.style)`, as `CheckedStyle` documents. Any other value is dropped with `STYLE_VALUE_DROPPED`. `styleText({ 'mix-blend-mode': … })` throws on other values. It is not added to `STYLE_PROPERTIES`, so icon bodies (D295) still drop it.
- `assertInert`/`inertProblem` take a new optional `scope`, which the pipeline's post-hook re-check always passes (`styleScope(idPrefix)`). When it is left out, the scope comes from the D182 gradient id (given or found), else from the first user-space id. A `<defs>` holding no gradient is rejected. They accept D182's shape or D391's exact shape (exactly 6 attrs, numeric coords, y1 === y2, exactly two stops, no stop-opacity), unique ids, and `fill`/`stroke` `url(#id)` only for declared ids. `gradient: false` now rejects only D182's gradient, not `<defs>` holding user-space gradients.

## How sankey (T4) uses it
```ts
const stroke = w.linearGradient({ x1: src.x1, x2: tgt.x0, from: colour(src), to: colour(tgt) });
w.leaf('path', { d, stroke, 'stroke-opacity': 0.5, style: styleText({ 'mix-blend-mode': 'multiply' as SafeValue }) });
```
Put opacity on the element: user-space stops take no `stop-opacity`. In tests, use `assertInert(svg, { gradient: false, scope: '<styleScope(id)>' })`.

## Decisions
- No `stop-opacity` on user-space gradients (not needed; it keeps the inert shape exact).
- User-space gradients are written whether or not anything still refers to them (writer-owned, deterministic). D182 keeps "only when referred".
- DESIGN §7.1 got the note and the interface line. DECISIONS is untouched. `SvgWriter` gains a required method, so the two writer doubles in tests (`mermaid/src/outline.spec.ts`, `conformance/src/outline-identity.spec.ts`) and `core/svg/testing` forward it.
