# #496 T2 grammar, parser, model and AST: handoff

Branch `feature/496_sankey-parser`. Core and the registry are untouched. `@mermaid-js/diagram-sankey` still has no plugin export or manifest (T5).

## Exports (`@mermaid-js/diagram-sankey`)

- `parseSankey(src, { preprocessed?, keepTokens? })` → `ParseResult<SankeyModel, SankeyDocument>`; never throws. `detectSankey(src)` (v12's case-sensitive `/^\s*sankey/` after front matter, directives and comments, no `\b`; for T5).
- `SankeyModel` (`src/model.ts`): `nodes` in first-appearance order `{ id, ast, range }` (range: the trimmed field, or the quoted field with its quotes); `links` in row order `{ source, target, value, flow, ast, range }` (`value` = v12's `parseFloat`, NaN kept; `flow` = what T3 draws: `value`, or 0 for NaN, negative or infinite); `title?` (front matter, D396); `warnings: SankeyWarning[]` (`Diagnostic` plus optional `astIds`).
- AST (`src/parser/ast.ts`): `Document` > `Link` per row (`link:<s>-><t>`, `@k` for repeats; `source`/`target`/`value` fields `{ text, quoted, range }`) > `Node` children for the names the row introduces (`node:<name>`). Names escaped with core's `AstIds` rules, copied into `parser/ids.ts`. T4: `data-ast` on `g.node` (`model.nodes[i].ast`) and `g.link` (`model.links[i].ast`).
- Codes (`src/codes.ts`): `SANKEY_CYCLE` (error, D393, Pele's message, range = the cycle's first row), `SANKEY_INVALID_VALUE` (one warning per parse at the first bad value, worded per cause: not a number, negative, not finite; `related` lists every row, `astIds` their link ids), `SANKEY_VALUE_TRAILING_TEXT` (one warning per value, at the text after the number). Syntax: `UNEXPECTED`, `UNCLOSED_STRING`. Statement spans: `header`, `link`.

**How `astIds` reaches the render warning (T4/T5):** nothing to carry by hand. The parse returns the `SankeyWarning` object itself in `diagnostics`; `mermaid`'s `analyse` turns every parse warning into a render `Warning` with `toWarning` (`packages/mermaid/src/errors.ts`), which copies `astIds` (and drops `related`). T4/T5 must not `ctx.warn` it again, and T5 adds a `render()` spec asserting `warnings` holds one `SANKEY_INVALID_VALUE` whose `astIds` are the rows' `link:` ids.

## Decisions (also in GAPS.md #496)

- An infinite value counts as 0 with `SANKEY_INVALID_VALUE` too (d3-sankey would draw that node and its links with NaN; D394's "never draw NaN").
- One `SANKEY_CYCLE` per group of nodes that reach each other (strongly connected component), at its first row; the node named is that row's source.
- A row with a syntax error adds nothing; a missing header is reported once and the rows are still read (a later `sankey` line is the header).
