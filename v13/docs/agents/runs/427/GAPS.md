## #496 T2 parser

Core's `Diagnostic` has no `astIds`: the package types the warning as `SankeyWarning` (`model.ts`), and `toWarning` copies the field. No core change.
- **Choice:** D397 ids: node names can contain `->` and `@`, and core's `AstIds` escape is not exported. The package escapes names with the same rules as core's escape (copied, not imported) so `node:`/`link:` ids are unambiguous; `parse.spec.ts` checks names with `->`, `>`, `@`, `#` and `%` give distinct ids (the T4 round-trip proves it over the corpus).
- **Choice:** an infinite value (`Infinity`, `1e999`) counts as 0 with `SANKEY_INVALID_VALUE`, like NaN and negative values: D394 names only those, but d3-sankey would draw that node and its links with NaN, against D394's "never draw NaN"; the message says "is not a finite number". v12's value (Infinity) stays in the model for parity.
- **Choice:** D393 gives one error per group of nodes that reach each other (strongly connected component), at the group's first row, naming that row's source; two separate cycles are two errors (N errors, N diagnostics).
- **Choice:** `SANKEY_VALUE_TRAILING_TEXT` is one warning per value with text after its number, at that text (D394 says "one … warning" for "a value field").
- Closed: 35 parity divergences, all D393 cycles (`reject`: v12 parses a cycle, v13 rejects it); v12's two `__proto__` spec tests parse a cycle and are skipped in `v12-specs/` with that reason.
- Note for #499: links carry `flow` (the value to draw, 0 for invalid ones); `value` is v12's for parity and T6's hover.

## #499 T3 layout
- Closed: `packages/diagram-sankey/THIRD_PARTY_NOTICES` in treemap's form (from `feature/428_treemap`): d3-sankey 0.12.3, d3-array 2.12.1 (`sum`/`min`/`max`) and d3-shape 1.3.7 (`linkHorizontal`), each **BSD 3-Clause** (read from the installed `LICENSE`s), and in the package's `files`.
- **Choice:** where d3-sankey writes NaN, v13 does not (D394): when every flow is 0 (`values-nan`, `values-infinity`, `values-overflow`, `values-negative-zero-sign`) `ky` is 0, so nodes are 0 high and spread as d3 spreads them; flows are scaled by a power of two first, so sums never overflow (bit-identical to d3 elsewhere); a 0-high extent with one node per column pads by `nodePadding` (d3: `0 / 0`).
- **Choice (amended by #502):** `nodeColors`: a node's own entry takes it out of the Tableau10 slots (v12's `??`) only when it is a string that passes `checkColor`; any other entry counts as absent (see #502). Inherited members (`constructor`, `__proto__`) do not count: v12's `nodeColors[id]` found `Object.prototype` members there.
- **Choice (divergence):** `sankeyLayoutConfig` reads a length as a finite number of 0 or more, or a numeric string as its number; anything else (negative, `NaN`, `"wide"`) falls back to the default. v12 passed `+value` to d3: a negative `nodePadding` overlapped nodes and a negative `nodeWidth` drew boxes inside out, and a string `nodePadding` was concatenated with `+ 15` (`"12"` → 1215). Kept so boxes are never broken or NaN.
- **Choice:** the bounds hold what is drawn (D224): nodes, label boxes (advance width, ascent to descent about the baseline) grown by half the 4 px outline under `outlined`, and each link's stroke (at least 1 px, so zero links and 0-high nodes count).
- **Choice:** node depths and heights come from one topological pass instead of d3's repeated whole-set sweeps (quadratic on a long chain): the same values, linear (`conformance/src/sankey/layout-stress.spec.ts`). A node with n links stays quadratic, as in d3 (`reorderNodeLinks`).
- Note for #503: the layout's length defaults are in `layout/metrics.ts` until `sankey` joins `SECTION_OWNERS`. `sankeyLayoutConfig` drops wrong types, negative lengths, unknown enums and `nodeColors` entries that fail `checkColor` silently: warn on each there (`SANKEY_COLOR_INVALID` and a config code).
- Note for #502: every renderer constant is in `layout/metrics.ts` (`outlineWidth` 4 and `outlineJoin` round, `minLinkWidth` 1, `linkOpacity` 0.5, `labelShiftEm` 0.35 × `fontSize`); node `fill`, link `sourceFill`/`targetFill`.

## #504 T6 language facet
- Closed (**Choice**, shared): D398's rename needs a facet hook. `LanguageFacet.nameSyntax?: NameSyntax` (`read(text, symbol)` → the range a rename replaces and its quote, or drop; `write(newName, occurrence, text)` → the edit), typed in core's `parser-kit/language.ts` next to the facet (type only, no bytes) and run by the service's `symbols.ts`. Without it nothing changes; with it `isValidId` judges every new name and the facet escapes quotes. The service's read-back check now shifts each renamed symbol by its own edit's length change (identical for every other type: their edits are the name). Goldens of the other types unchanged but `completions/empty.out` (lists `sankey`).
- **For the maintainer:** `LanguageFacet.nameSyntax` changes the facet contract (DESIGN §4.5, updated there as `standalone` was for D289) and needs a D-id; none was added here.
- **Choice:** a quoted occurrence is the whole text between its quotes (`" a "` renames to `"x"`); a bare one quoted by a rename takes the blanks around it in its field (`  a  ,b` to `"a, b",b`), since v12 reads no blank outside the quotes. A name whose source does not read as v12's name (a CRLF or a blank line inside quotes, a directive through it) is dropped, so its rename is refused.
- **Choice (review of #504):** a name on a line v12 may rewrite (it holds `;` and `style` or `classDef`: `encodeEntities` drops such a line's last `;` only while the line matches `style…:…#…;`) is dropped too, so its rename is refused: renaming `style` in `style,b,1 :#f;` made `#f;` an entity, which v12 rejects. The oracle spec has no known case left (was 12).
- Checked (review of #504): `SANKEY_INVALID_VALUE` is at the first bad value field with `related` at each bad row's value field; `SANKEY_VALUE_TRAILING_TEXT` at the text after the number, inside its value field; `SANKEY_CYCLE` at the cycle's first row (D393). No parser change.
- **Choice:** `isValidId` refuses, besides D398's characters outside printable ASCII (a line break is allowed: it is written in quotes): an empty name, blanks at either end (fields are trimmed), a blank line (v12 collapses it) and an entity (`#35;`).
- **Choice:** "Folding: none beyond the body": the body is one `sankey` statement span from the header to the end of its last row (front matter and directives fold as for every type). T2's `header` span is now that block and rows have no span (a row with a line break in a quoted name would have folded).
- **Choice:** completion also offers `sankey` where the header goes, leaves out the row's own source as its target (a self-link, D393) and a name whose only occurrence is the field being typed; a name is written as the field needs it (quoted, `""`). Hover on a node: in and out totals of the drawn values (D394) with link counts; on a value: the number read, and why it counts as 0 or what `parseFloat` dropped.
- **Choice (grammar, gate unchanged):** `grammar/sankey.ebnf`'s closing `DQUOTE` and `ESCAPED_TEXT` rules are written for `escaped_text` only (jison lists them for every mode, where the rules before them always win); TextMate took the closing quote as the end of the `csv` block. `tools/gen-grammar` `progressPattern` also turns a starred `(?:…)` group into `+` (only sankey's highlighters change), so Monarch and TextMate colour quoted text. Four-way agreement green with no exemption.
- R-LANG-4 (review of #504), one run, back to back under the lock, load 10–13, *not measured on a steady machine*; cycle = update + every query, median of 50 after 10 warm-up: flowchart (the bench's `measureLanguage`, 50,510 chars) 20.5 ms, bare parse 4.3; **sankey** (50,012 chars, 2,156 rows) **16.1 ms**, bare parse 2.8; kanban (50,035 chars, about 650 cards with ticket, assignee and priority) 10.3 ms, bare parse 2.5.   - Closed (this ticket): the parse went from 5.6 to 2.8 ms: v12's text built from slices of the source (not a string per character), the per-field and per-row closures hoisted, link ids counted by node index (no id string hashed), `""` undone only where a field has one, and the probe lexer stops reporting steps once past the offset.
  - Open, owner a service-wide follow-up (not sankey): every cycle parses three times (update, the rename read-back, the completion probe: 10 ms here) and the semantic-token loop allocates an object per token (3.8 ms): 14 of sankey's 16 ms, and the same stages are 18.8 of flowchart's 20.5.
