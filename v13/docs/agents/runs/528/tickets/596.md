# #596 T0c: shared line hops in core, lazy chunk (closes #78)

Branch `feature/596_line-hops` (own PR into `mermaid-v13`).

## Exports
- `@mermaid-js/core/layout/hops` (lazy, never re-exported from `./layout`): `lineHops(paths, style)` (pure, path data of one frame in drawing order → new `d` per line or `undefined`), `parsePath`, `hopWriter(w, style)` (the shared edge-path step: keeps the writes, hops every `outline('edge', 'path')` line per frame = space under the nearest `transform`, then replays into `w`, stream or tree), `hopPlugin(plugin, style)` (the plugin drawing through a `hopWriter`), `HopStyle = 'arc' | 'gap'`.
- `mermaid` (`registry.ts`): `LINE_HOPS = 'lineHops'`, a `LAZY_LAYOUTS` row loading the chunk; `hopStyle(config, sources, engine)`; `Registry.hops()`. `api.ts` keeps the author's config layers on the analysis (`sources`) and, for a render whose style is not `false`, adds `{ kind: 'layout', name: 'lineHops' }` to what it needs and draws with `hopPlugin`. Diagrams need nothing: every edge-drawing renderer already draws its line with `w.outline('edge', 'path', …)`.

## Use
- Config: top-level `lineHops` (`false` | `true` | `'arc'` | `'gap'`, default `false`); `swimlane.lineHops` (`'arc'`, now honoured) and `elk.lineHops` (`true`) override under their engine. The engine section is the layout name up to the first dot (`elk.stress` → `elk`), so core never names ELK.
- `renderSync` without the chunk: `NotLoadedError` naming layout `lineHops`, or with `placeholders` drawn without hops plus `PLACEHOLDER`, as a missing lazy layout. `prepare()` / `render()` load it; `preload({ layouts: ['lineHops'] })` too. `layout: lineHops` is `LAYOUT_UNKNOWN` (D285 gate).
- Fixtures: `e2e/diagrams/flowchart/baseline/edges/line-hops-{on,off}.mmd` (K3,3 with `curve: step`).
- Specs: `core/src/layout/hops/hops.spec.ts` (rules, writer, frames, drawer); `mermaid/src/line-hops.spec.ts` (render/renderSync, chunk loading, tree backing draws the same, `hopStyle` table); `core/src/layout/hops/stream.spec.ts` (`drawDiagram` with hops keeps the stream writer); ELK `hooks.spec.ts` migrated (same hops through the shared path, precedence); `core-chunks.spec.ts` gains `hops`.

## Sizes
- Chunk `hops`: 3,369 B raw, 1,668 B gz, its own lazy chunk; none of it in core.
- Core (`measureCoreSize`, limit 98,304): 94,412 → 94,666 B gz (+254). Key +6 B; the `LAZY_LAYOUTS` row and `hops()` +52 B; the resolution glue in `api.ts`/`registry.ts` (`hopStyle`, the author's layers, the need and the plugin wrap) about +196 B. More than "the key and a dynamic import" alone: deciding that a render hops needs the precedence in core.

## Decisions / gaps
- **Choice:** the shared key accepts `'gap'` too (same values as both engine keys and the one hop function; v12 swimlane accepted it).
- **Choice (precedence):** a top-level `lineHops: false` set by the author turns hops off everywhere; else the engine key set by the author; the top-level key set by the author; the engine default (`swimlane` `'arc'`, from code since no package holds swimlane's section defaults yet; `elk` `true` from its fragment); `false`. "Set by the author" = present in `initialize()`, front matter or a directive.
- **Choice:** the shared step is `SvgWriter.outline('edge', 'path')` (D302) wrapped by a replaying writer, so hops work on both backings and under the hand-drawn drawer (it sketches the hopped line); renders without hops are untouched.
- **Choice:** the hop resource is named as a layout (`layout "lineHops"`), so `preload({ layouts })` and `NotLoadedError` behave as for a lazy engine. Behaviour change for ELK users: `preload({ layouts: ['elk'] })` + `renderSync` now also needs `'lineHops'` (or `prepare()`); MIGRATION row updated.
- ELK: `hops.ts`, `drawLineHops` and `postRender` removed; ELK renders now keep the stream writer. ELK's hop output is byte-identical to before.
- Not verified by a render: swimlane crossings (placeholder routes overlap, never cross, until T0b); covered by `hopStyle` and chunk-loading specs.
