# #596 T0c: shared line hops in core, lazy chunk (closes #78)

Branch `feature/596_line-hops` (own PR into `mermaid-v13`).

## Exports
- `@mermaid-js/core/layout/hops` (lazy, never re-exported from `./layout`): `lineHops(paths, style)` (pure: path data of one frame in drawing order → new `d` per line, `undefined` when no hop is drawn on it), `parsePath`, `hopStyle(config, layers, section)` (the precedence), `hopWriter(w, style)` (the shared edge-path step: passes every call through, notes each `outline('edge', 'path')` line and its frame, and its `finish` writes the hopped data into the finished markup; nothing with fewer than two lines), `hopStep(config, layers, section)` (`drawDiagram`'s `edges`, or undefined), `HopStyle`.
- Core: `drawDiagram(plugin, model, ctx, hooks?, edges?)` and `EdgeStep` (wraps the writer, either backing, never the plugin); `Resource` kind `chunk`. `CORE_SECTIONS` in `tools/gen-config` (`swimlane`): core's own engine sections resolve their defaults in `CORE_DEFAULTS` (`swimlane.lineHops: 'arc'`), as ELK's fragment does (`elk.lineHops: true`).
- `mermaid` (`api.ts`, `line-hops.ts`): keeps the author's config layers (`sources`); asks only "could hops be on?" (`config.lineHops` or the `lineHops` of the section of the engine that really lays the render out: stand-in, or none when `layered` draws for an unknown name); loads the chunk with the render's resources; draws with `hopStep(...)`. `preload({ lineHops: true })`; preloading a layout (or type default) whose section defaults hops on, or with `lineHops` from `initialize()`, loads it too. The chunk module is shared by API objects, as loaded themes are.

## Use and specs
- Config: top-level `lineHops` (`false` | `true` | `'arc'` | `'gap'`, default `false`); `swimlane.lineHops` (`'arc'`) and `elk.lineHops` (`true`) override under their engine. `renderSync` without the chunk: `NotLoadedError` for chunk `lineHops`, or with `placeholders` drawn without hops plus `PLACEHOLDER`.
- Fixtures: `e2e/diagrams/flowchart/baseline/edges/line-hops-{on,off}.mmd` (a 6-cycle over two ranks, `curve: linear`).
- Specs: core `layout/hops/hops.spec.ts` (rules, writer, frames, drawer, `hopStyle` table incl. invalid values), `stream.spec.ts` (`drawDiagram` with hops keeps the stream writer); `mermaid/src/line-hops.spec.ts` (renders, tree backing), `line-hops-lazy.spec.ts` (loading, placeholders, every edge diagram, `preload({ lineHops })`), `line-hops-preload.spec.ts` (`preload` swimlane); ELK `hooks.spec.ts` (migrated, precedence, `elk.nope` → no hops) and `preload.spec.ts`; `core-chunks.spec.ts` gains `hops`; `outline-identity.spec.ts` compares hop fixtures with hops off on both sides and asserts they hop.

## Decisions / gaps
- **Choice:** the shared key accepts `'gap'` too (same values as both engine keys and the one hop function; v12 swimlane accepted it).
- **Choice:** an author's top-level `lineHops: false` turns hops off everywhere; else the engine section key the author set, the top-level key the author set, the engine default, `false`. "Set" = a valid value (`false`, `true`, `arc`, `gap`) in `initialize()`, front matter or a directive.
- **Choice:** core loads the chunk when hops could be on; with an author's top-level `false` under a layout whose key defaults on, it loads and draws nothing.
- **Choice:** hops are written into the finished markup, so `postRender` hooks see lines before their hops, and a line an outline drawer redraws (hand-drawn) keeps its drawing without hops.
- ELK: `hops.ts`, `drawLineHops` and `postRender` removed; ELK renders keep the stream writer; hop output byte-identical.
- Not verified by a render: swimlane crossings (placeholder routes never cross until T0b).
