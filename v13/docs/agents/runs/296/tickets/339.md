# T0 (#339): the `w.outline` hook (D302)

Branch `feature/339_outline-hook`. Core only: `svg/writer.ts`, `pipeline/extensions.ts`, `pipeline/draw.ts`, `svg/testing`. `mermaid`'s API needed no change. The mindmap port's T4 (D309) and T1 draw through this hook.

## For diagrams: `w.outline(role, tag, attrs?)`

```ts
import type { OutlineRole, OutlineTag, SvgWriter } from '@mermaid-js/core/svg';
type OutlineRole = 'node' | 'part' | 'divider' | 'mark' | 'group' | 'edge';
type OutlineTag = 'rect' | 'circle' | 'ellipse' | 'polygon' | 'line' | 'path';
w.outline('node', 'rect', { x, y, width, height, rx, class: 'basic', fill, stroke, filter });
```

- No drawer, or an inactive one: exactly `w.leaf(tag, attrs)`, byte for byte, in both backings.
- Roles: `node` is a node's shape, `part` is a piece of one (a compartment, an underlay), `divider` is a line inside a node, `mark` is a small dot or cross, `group` is a cluster or subgraph frame, `edge` is an edge line. Arrowheads (`class: 'marker'`), label backgrounds and text stay `w.leaf`/`w.label`.
- Put every attribute on the call, paint included (`class`, `style`, `fill`, `stroke`, `filter`, `transform`). The drawer sees only `attrs`, not the parent `<g>`.

## For extensions: `ExtensionPlugin.outline`

```ts
import type { OutlineDrawer, HookContext } from '@mermaid-js/core';
import type { Attrs, OutlineSink } from '@mermaid-js/core/svg';
interface OutlineDrawer {
  active(ctx: HookContext): boolean; // once per SVG render
  draw(role: OutlineRole, tag: OutlineTag, attrs: Attrs, sink: OutlineSink): boolean;
}
interface OutlineSink { open(tag: 'g', attrs?): void; leaf(tag: 'path', attrs?): void; close(): void; path(): PathBuilder }

const sketch: ExtensionPlugin = {
  id: 'hand-drawn',
  outline: {
    active: (ctx) => ctx.config.handDrawn === true,
    draw(role, tag, attrs, sink) {
      if (tag !== 'rect') return false; // the plain leaf
      const { x = 0, y = 0, width = 0, height = 0, ...paint } = attrs;
      sink.open('g', { class: `sketch-${role}`, filter: paint.filter });
      sink.leaf('path', { d: sink.path().moveTo(x, y).lineTo(x + Number(width), y).done(), stroke: paint.stroke });
      sink.close();
      return true;
    },
  },
};
```

- **Who draws:** only the first registered extension with an `outline` is asked. Its `active(ctx)` runs once per SVG render with that extension's hook context (`ctx.diagram`, `ctx.config`, `ctx.state`). If it returns `false`, nothing draws; a later drawer is not asked. Text output never calls `active` or `draw`.
- **`draw`:** called for every `w.outline` call while the drawer is active. It returns `true` when it has written the replacement and `false` to get the plain `<tag …attrs/>`. Anything it wrote before returning `false` stays, in front of the plain leaf, so it can add an underlay. `attrs` belongs to the diagram: don't mutate it. It is `{}` when the diagram passes none.
- **Sink rules:** `open` takes only `'g'` and `leaf` only `'path'`. Every attribute name must be on the allow-list (checked at run time, as `checkFragment` does for inline boxes), and values go through the writer's encoding (`num()` for numbers). Each `open` needs its `close` within the same `draw`: no closing what you didn't open, and nothing left open. The sink stops working once `draw` returns. Build `d` values with `sink.path()`.
- **Errors:** any of these is `MermaidError('INTERNAL')` with the message `Extension "<id>" failed in outline: …`: a throw from `active` or `draw` (a `MermaidError` it throws passes through unchanged, as for every hook), a forbidden tag or attribute name, an unbalanced open/close, reuse of a sink after its `draw`, or a result that isn't a boolean. A drawer that is not `{ active(), draw() }` is refused when it registers (`Extension "<id>": outline needs active() and draw()`). With an active drawer, the finished SVG is checked against the allow-list again, values as well as names, as after `postRender`; a failure there is `INTERNAL` with `The extension "<id>"'s outline output fails the allow-list: …`.
- **Seams:** `HookRun.outline()` returns `ActiveOutline | undefined` (`{ id, draw }`). `drawDiagram` passes `draw` to `streamWriter`/`treeWriter` as `WriterOptions.outline` (`OutlineDraw`). Core never names a plugin (D153).

## Test helpers (`@mermaid-js/core/svg/testing`)

- `outlineFixture`: an always-active drawer. Register it as `{ id: 'fixture-outline', outline: outlineFixture }`. Each outline becomes `<g class="outline-<role>"><path …other attrs d="…"/></g>`. The `d` traces the shape: rect with square corners, circle and ellipse as two arcs, polygon closed, line, path's own `d`.
- `outliningEveryLeaf(w, role = 'node')`: a writer proxy that routes every outline-tag `leaf` through `w.outline`. It stands in for an adopted diagram (`packages/mermaid/src/outline.spec.ts`, `packages/conformance/src/outline-identity.spec.ts`).
- T1 can check each role with `/<g class="outline-edge">/` and similar, and identity with `{ active: () => true, draw: () => false }`.
