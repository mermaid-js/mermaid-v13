# H1 (#341) — sketch adapter and seeds

Branch `feature/341_sketch-adapter`. New package `packages/plugin-hand-drawn` (`@mermaid-js/plugin-hand-drawn`): `roughjs` pinned `4.6.6` in `dependencies`, `THIRD_PARTY_NOTICES`, a first-release changeset. No manifest, drawer or config fragment (H2). Independent of T0's types.

## Exports (`src/index.ts` → `src/sketch.ts`)

- `sketch(tag, attrs, options, seed): SketchPath[] | undefined`. `tag`: `rect | circle | ellipse | polygon | line | path`; `attrs`: core `Attrs` of the plain leaf; `seed`: the raw `handDrawnSeed`. Returns roughjs's op sets in its order, each `{ set, attrs }`:
  - `fillPath` (solid): `{ d, fill: <leaf fill>, stroke: 'none' }`
  - `fillSketch` (hachure): `{ d, fill: 'none', stroke: <leaf fill>, 'stroke-width': options.fillWeight }`
  - `path` (outline): `{ d, fill: 'none', stroke, 'stroke-width', 'stroke-dasharray' }` from the leaf (undefined values are left in; the writer skips them).
  - `undefined` = geometry missing or not numeric (`width: '100%'`, no `r`, < 2 polygon points, empty `d`): H2's drawer returns `false`, so the plain leaf is written.
- `SketchOptions` (the role table, H2): `{ roughness, fillStyle: 'solid' | 'hachure', fillWeight, hachureGap, hachureAngle? }`. `roughness >= 1` or another fill style throws `RangeError` (D304: roughjs's other `Math.random` paths). `strokeWidth` (leaf number, else v12's 1.3) and `strokeLineDash` are derived from the leaf; neither changes roughjs's ops.
- `roughSeed(seed)`: `seed | 0 || 2147483647` (D304). `strokeLineDash(value)`: v12's `getStrokeDashArray`.
- Mapping: `rect` → `rectangle`; rect with `rx`/`ry` > 0 → `path` of v12's `createRoundedRectPathD` (radius `rx ?? ry`, clamped to half a side as SVG does); `circle` → `circle(cx, cy, 2r)`; `ellipse` → `ellipse(cx, cy, 2rx, 2ry)`; `polygon` (flat `points`) → `polygon`; `line` → `line`; `path` → `path(d)`. Paints into roughjs are placeholders (`'F'`, `'S'`, `'none'`); `fill` absent or `none` → no fill set; `stroke` absent or `none` → no outline set. Ops go through `pathBuilder()` (`M`, `L`, `C`), never `opsToPath`.
- For H2: the `<g>` wrapper (class, filter, opacity) and an edge's single `<path>` (leaf attrs + sketched `d`) are the drawer's. Other leaf paints (`fill-opacity`, `stroke-opacity`, `stroke-linecap`…) are not copied onto the paths; the drawer decides.

## roughjs import (deviation, see GAPS.md)

`import rough from 'roughjs/bundled/rough.esm.js'`, then `rough.generator()` (a `RoughGenerator`; `rough.svg` is never called). Types: `src/roughjs.d.ts` declares that module with `bin/` types. `roughjs/bin/generator.js` cannot load in Node's ESM loader (`bin/fillers/filler.js` imports `./hachure-filler` without an extension), and the main entry is CJS in Node but ESM in bundlers. The ESM bundle is the same code in Node and in every bundler.

## Tests

- `src/sketch.spec.ts` (vitest, Node): op parity against `RoughGenerator` per tag (7, rounded rect included) × 5 role option sets × 3 seeds; paint mapping; seeds; `Math.random` stubbed to throw over every tag × option set × seed (0 included) × filled/unfilled, plus a check that the trap fires for roughjs itself at seed 0; v12 dash-array cases; bounds; unsketchable geometry.
- Bounds bound (spec has the derivation): `(roughness [+0.8 for a solid path fill]) × 2.3 × (1 + diagonal / 200)`, `+ 2 × hachureGap` for hachure, `+ 6 % of the radius` for ellipses. E.g. a 120×40 node at roughness 0.7: ≈ 2.6 units for the outline, ≈ 5.6 with hachure. H3 checks the viewBox padding against it.
- `e2e/browser/hand-drawn.spec.ts` (Playwright, chromium): 320 cases, Node (tsx, unbundled) vs Chromium (esbuild bundle) byte-equal.
