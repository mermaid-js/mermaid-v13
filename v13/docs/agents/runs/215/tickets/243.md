## Unmet / later

- Activates on install in #218's SSR app: waits for #218 T4 (#226), not on this base. The package has no `layout` manifest yet; a discovered package would also need the manifest to name its `extension` (GAPS "From E4").
- Language service: `elk` no longer completes in front matter. Not restored: the LS checks front matter against a plugin-less render (`front-matter.spec.ts` "warnings equal a render's"), and the generated LS schema has core keys only. Cheapest route found: gen-config writes each fragment's JSON schema into the LS's generated module as `pluginSchemas` (`{ package, properties }`), and `createLanguageService({ plugins: ['@mermaid-js/layout-elk'] })` merges the chosen ones (hover then names the package). That is new public API on the LS, so it is left for a decision.
- Dev Explorer (`packages/dev/src/browser/mermaid.ts` `devLayoutLoaders`) does not offer ELK: the explorer bundle is one unsplit file, and the Profile tab would profile all nine names by default.
