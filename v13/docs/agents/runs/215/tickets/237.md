## Provider contract (what M1/M2 build on)

```ts
const math: ExtensionPlugin = { id: 'math', inline: [{ open: '$$', close: '$$', box(tex, req) { … } }] };
// req = { font: FontKey, measurer, metrics: measurer.metrics(font), ex: font.size / 2 }
// return { width, height, baseline /* top → baseline, px */, node: SvgFragment } or undefined
```
- Registered sync by the extension entry; `box` runs during layout, so it is sync. Until a lazily loaded engine is ready, return `undefined` (span drawn as written). Loading it is M2's resource (`loadResources` gap still open).
- **ex→px**: the measurer has no x-height, so core passes `ex = 0.5 × font.size` (MathJax's default `exFactor`), plus `font` and `metrics` (ascent/descent/lineHeight) if a provider wants its own ratio. Escalate if a real x-height is wanted (would need `gen-metrics` + `VerticalMetrics.xHeight`).
- `node` is an `SvgFragment` `{ tag, attrs?, children? }` (children: fragments, or strings inside text holders), drawn with the box's top-left at (0,0), y down. The writer replays it through `open/leaf/text/close`, so tags, attrs and branded values (`d: PathData`, `transform: Transform`) are the allow-list's. MathJax paths need wrapping into `PathData` (M1/M2: a validating constructor, or PathBuilder).
- Spans are extracted from the raw label before line breaks, markdown and HTML (`\nabla` stays TeX). At most 32 boxes per label; a label already containing U+FDD0–U+FDEF is left as written. First registered provider of a delimiter wins.

## Drawing

A label with a box is drawn `text-anchor="start"`, lines placed from measured widths; each box is a `<g transform="translate(x,y)">` after the `<text>`, carrying the label's `class`/`fill`/`style` (and its `transform`). Paths without `fill` inherit the label colour.
