# E4 #242 — v12 ELK options, presets and passes; `elk` config fragment

Branch `feature/242_elk-options`, on `feature/215_feature-plugins` (E3 #241, T0b #238).

## Exports and changes

- `packages/layout-elk/schema/config.fragment.yaml` (fragment id `layout-elk`): the 13 v12 `elk.*` keys with v12 develop's defaults, all `honoured`. Removed from core's schema in the same change; `gen:config` writes `src/generated/config-fragment.ts` (committed: `.gitignore` re-includes `packages/layout-elk/src/generated/`) and the `elk` (plugin) section of config-reference.md. Every loader carries it as `config`.
- `@mermaid-js/layout-elk`: new export `elkExtension` (id `layout-elk`), also on every loader as `extension`. `postRender` draws `lineHops`; `postLayout` turns engine notes into warnings. Both are no-ops until a loader has imported the engine, and act only when `config.layout` is one of the nine names. `ElkLayoutLoader` gains `config` and `extension`.
- Engine (internal): `options.ts` (`resolveElkPreset`, `rootOptions`, `groupOptions`, `elkConfigOf`, `ElkConfig`), `passes.ts` (`findSubgraphFeedbackEdges`, `findCyclicEntryNodes`), `straighten.ts` (`straightenTerminalJogs`, `straightenEdgeTerminals`, `projectLabelOntoStraightenedRun`), `hops.ts` (`drawLineHops`), `adapter.ts` `takeNotes`. `toElkGraph(graph, algorithm, elk?)`; `elkEngine` reads `ctx.config.elk`.
- `lineHops` = LayoutModel untouched + the package's `postRender` (no T0 proposal needed). It parses each `g.edgePaths > g > path` line, finds crossings between straight `L` runs only, and splits the run with `A r,r` (`arc`/`true`) or `M` (`gap`); v12's orientation rule, 6 px radius, 0.6 minimum and 2 px clearance. Corners keep their rounding (v12 dropped it).
- `mermaid`: `LayoutLoader.extension?: ExtensionPlugin`, run only on renders laid out by that loader's name (a per-render `HookRunner` of the registered extensions plus it), so other renders keep the stream writer; `isElkName` exported from `registry.ts`. `ELK_ALGORITHM_IGNORED`: raised in `ctx.layout` when the layout name is an ELK name and a `LayoutGroup` has `algorithm`, once per render, listing the algorithms (final review: only when an ELK engine lays the graph out, never alongside `ELK_NOT_INSTALLED` or `LAYOUT_UNKNOWN`).
- `elk.radial` on a graph ELK calls "not a tree" (in practice: a cycle) draws with core's `layered` plus one `ELK_RADIAL_NOT_A_TREE`. v12 never had the name and failed such a container's render.
- Deviation: `cycleBreakingStrategy: MODEL_ORDER` is left off groups ELK lays out with their parent. elkjs 0.12 throws there ("Cannot read properties of undefined (reading 'a')"), so v12 develop fails that render; the root's value covers those groups.
