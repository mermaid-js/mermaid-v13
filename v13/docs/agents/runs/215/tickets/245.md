# #245 M2 — `@mermaid-js/plugin-math` (lazy MathJax)

Branch `feature/245_plugin-math`. Consumers: M3 #246 (every type), S1 #247 (size check), M4 icons (the resource hook).

## Exports

- `@mermaid-js/plugin-math` (published, 13.0.0-alpha.0, manifest `{"plugin":"extension","id":"math","entry":"./dist/index.js","export":"math"}`): `math` (also default), an `ExtensionPlugin` with one `$$…$$` inline provider and one resource, `{ kind: 'math', name: 'tex' }`. The engine (`src/engine.ts`, #244) is internal now: no `./engine` export.
- Core, additive: `ExtensionPlugin.resources?: { provides, missing(parse, { config, format }), load(resource) }` (`ExtensionResources`, `ResourceRequest`, `ExtensionNeed` from `@mermaid-js/core`); `HookRunner.resources(parse, req)` and `.provided(kind)` (resources checked and stored once at `register`), guarded (a throw, a failed load or an unprovided resource is `MermaidError('INTERNAL')` "Extension "<id>" failed in resources: …"). `InlineRequest.warn`, deduplicated per render by code + message. Core names no package; `Resource` already had kind `math`.
- `mermaid`: `prepare()` loads every extension need with the diagram's own; `renderSync` lists them in `NotLoadedError` (or warns `PLACEHOLDER` with `placeholders`); `preload({ math: true })` loads what extensions provide of kind `math`.

## Use

`import math from '@mermaid-js/plugin-math'; await mermaid.registerExternalDiagrams([math]);` then `render()`. For `renderSync`: `await mermaid.preload({ math: true })` or `prepare(text)` first.

- `missing` reports `math "tex"` only for SVG and only when a string anywhere in the parse (AST or model, walked generically, cached per parse) has a `$$…$$` pair; text output never needs it (D179).
  - Why every string, not just labels: the parse has no diagram-agnostic label notion (each type's AST and model differ), so `$$` in a click tooltip, URL or class name also loads MathJax; comments are not in the parse (pinned in `index.spec.ts`). Narrowing needs a core "label strings" walk per type (M3 #246 could add it).
  - Label text the parse does not hold reaches the provider unloaded: it warns `MATH_NOT_RENDERED` ("the math engine has not loaded …"), unless the last `missing()` reported the engine (then the API threw or warned `PLACEHOLDER`).
- Bad TeX: drawn as written, one `MATH_ERROR` ("$$…$$ is not valid TeX (<MathJax message>): it is shown as written.").
- Characters the TeX font lacks are measured with the request's measurer (label font, italic/bold passed); MathJax's width cache is cleared per call (R-ARCH-6).

## Build and size

`pnpm build` = tsc, then `scripts/build.ts` replaces `dist/engine.js` with an esbuild bundle (`scripts/bundle.ts`): MathJax + TeX font inlined, `#default-font/*` → `@mathjax/mathjax-tex-font`, core external. So MathJax is a devDependency, not a runtime one: no `THIRD_PARTY_ALLOWED` entry; `THIRD_PARTY_NOTICES` credits both packages with the Apache-2.0 text, and `tools/release/licenses.ts` accepts notices that credit a bundled dev dependency (as it did a runtime one).

- Engine chunk `dist/engine.js`: 1,832,274 B, **676,980 B gz** (gzip -9). Entry: 740 B gz (esbuild --minify), 1,322 B gz as tsc emits it.

## Tests and helpers

- `src/index.spec.ts` (`createMermaid().render()`/`renderSync()`): paths, no `MATH_NOT_RENDERED`; `NotLoadedError` naming `math "tex"`; placeholders; no load without a pair (`$5 or $10`, a lone `$$`); renderSync after prepare equals render; `preload({ math: true })`; `MATH_ERROR` once; ascii. Allow-list + determinism + tree-writer identity over `katex/**` and `flowchart/**`. `freshMath()` (resetModules) gives an unloaded plugin.
- `src/bundle.spec.ts`: bundles a page (mermaid + plugin), checks MathJax is in one lazily imported chunk, deletes it, then renders a diagram without `$$` (works) and one with (rejects naming the chunk). Also checks the engine build has no New Computer Modern and no core.
- `mermaid/src/extensions.spec.ts` "extension resources": the mechanism with a non-math fixture (`iconPack "logos"`).
