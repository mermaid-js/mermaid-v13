# #241 E3 — ELK adapter (LayoutGraph ↔ ELK graph)

Branch `feature/241_elk-adapter`, on `feature/215_feature-plugins` with T0b #238.

## Exports and changes

- `packages/layout-elk/src/adapter.ts` (internal): `toElkGraph(graph, algorithm) → { root, nodes, edges, layered }`, `elkEngine(algorithm)`, `ElkAlgorithm`. The builder now ports v12 develop's mapping:
  - a group with `direction` gets `SEPARATE_CHILDREN` and its own `elk.direction`; an edge whose ends sit in different groups sets `INCLUDE_CHILDREN` on every group from each end up to and including their common ancestor (v12 `configureCrossHierarchyEdges`), so a crossed group follows its parent. Every group gets the direction its contents actually run in.
  - each edge lives in its ends' common ancestor (v12 semantics: self edge → parent, group ↔ its member → the group); edges reach ELK in v12's nested order.
  - v12's fixed options (no `elk.*` key sets them): root `INCLUDE_CHILDREN`, `unnecessaryBendpoints`, `wrapping.multiEdge.*`, `selfLoopDistribution EQUALLY`, `mergeHierarchyEdges`, `portsSurrounding 12`; groups `nodeFlexibility PORT_POSITION`, `portsSurrounding`. Now for every algorithm, as v12 (only `elk.sporeOverlap` output moves).
  - a titled group reserves `nodeSize.minimum` (title + side padding) before layout; an end label is grown by its end marker's width (v12's marker clearance).
  - read-back is E2's (root coordinates, no `$H`, frame widening, straight fallback).
- `packages/layout-elk/src/tree.ts` (internal): `ROOT`, `Tree`, `findCommonAncestor`, `isInside`, `orderNestedEdgeEnds` (v12 `find-common-ancestor.ts`, `nestedEdgeOrder.ts`).
- Core (additive): `LayoutGroup.algorithm?: string`. Flowchart sets it from `id@{ algorithm: … }`. The ELK engine carries it but does not apply it (D174); layered ignores it.

## Tests and helpers

- `src/corpus.spec.ts`: the 56 flowchart/class/state/ER sources of `fixtures/v12-elk-corpus.json`, rendered with `createMermaid().render()` and the package's own loaders (recorded). `validateLayout` clean on every graph; a fresh API gives the same SVG; `renderSync` after `prepare` equals `render()`; `@{ algorithm }` and `ctx.config` reach the engine. Shape check against v12's own ELK input per source (hierarchy, handling, direction, edges per container in order, label kinds, fixed options; ids normalised, `layoutReversed` undone). Exceptions: `@{ algorithm }` groups (D174) and `elk-notes-keep-their-layout` (v12 wraps a state and its note in a group; v13's state graph doesn't).
- `src/adapter.spec.ts`: own-direction groups, crossed groups, common-ancestor rule, group↔member containment, title minimum, `algorithm` not applied, nested order, marker clearance, fixed options. `src/tree.spec.ts`: v12's `nestedEdgeOrder.spec` cases plus `findCommonAncestor`.
- The `api(laid)` recorder in `corpus.spec.ts` wraps each loader to capture `(graph, model)`; copy it for E4.
