# #240 E2 — `@mermaid-js/layout-elk` package, layout names, `ELK_NOT_INSTALLED`

## Exports

- `@mermaid-js/layout-elk` (`src/index.ts`, published, 13.0.0-alpha.0): default export `elkLayouts: readonly ElkLayoutLoader[]` (v12's `LayoutLoader[]` shape), with nine names, D171 order: `elk`, `elk.layered`, `elk.stress`, `elk.force`, `elk.mrtree`, `elk.sporeOverlap`, `elk.box`, `elk.rectpacking`, `elk.radial` (`elk` and `elk.layered` both mean ELK `layered`). Each `loader()` dynamically imports `./adapter.ts` and resolves to a sync `LayoutEngine`. Type: `ElkLayoutLoader`.
- `src/adapter.ts` (internal; E3 grows it into the v12 port): `elkEngine(algorithm)`, `toElkGraph(graph, algorithm)`, `ElkAlgorithm`. It maps sizes, groups (padding, title band), edge labels (centre/`TAIL`/`HEAD`), direction, spacing and `diagramPadding`. Read-back uses ROOT coordinates and never touches `$H`. Two post-passes: frames are widened for their titles, because ELK layered drops a compound's minimum size once the compound has internal edges under INCLUDE_CHILDREN; and the drawing is sized from its contents, because mrtree sizes the root before its groups. When an algorithm leaves an edge unrouted, or its section does not end at its boxes, the edge runs straight between the two borders. Only layered places labels; elsewhere a label goes at 10/50/90 % of the route. `hierarchyHandling: INCLUDE_CHILDREN` is set for layered only.
- `@mermaid-js/layout-elk/sync` is unchanged (E1).
- `mermaid` (`registry.ts`, `api.ts`): `dagre` → `layered`, no warning. With no ELK name registered, `elk`/`elk.*` and the `flowchart-elk` header get state `elk`: drawn with `layered` plus one `ELK_NOT_INSTALLED` that names `@mermaid-js/layout-elk`. Once any ELK name is registered, an unknown `elk.x` gets `LAYOUT_UNKNOWN`. Core is untouched.

Use: `import elkLayouts from '@mermaid-js/layout-elk'; mermaid.registerLayoutLoaders(elkLayouts);`. After that, `layout: elk` and `flowchart-elk` are laid out by ELK.

## Tests and helpers

- `src/adapter.spec.ts` (engine seam): an A→B literal from ELK layered; ports per direction; `validateLayout` on a grouped graph per algorithm (stress and force may overlap, as ELK does); determinism and no `$H`; radial needs a tree.
- `src/index.spec.ts` (`createMermaid().render()`): v12 snippet; `layout: elk` with and without the plugin; `flowchart-elk`; every name renders, deterministically; `renderSync` after `prepare`; flowchart/class/state/ER with no layout are byte-identical with and without the plugin.
- `mermaid/src/api.spec.ts`: `dagre` silent, ELK names and `flowchart-elk` warn once, `elkish` is `LAYOUT_UNKNOWN`. `tools/workspace/layout.spec.ts`: core's sources and manifest never name `layout-elk`/`elkjs`.
