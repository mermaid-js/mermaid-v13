Branch `feature/247_optional-size-check`. Builds on #218 T0 (`../218/tickets/220.md`). No budget value changed.

## Which packages are optional (generic, D170)

`findOptionalPackages(packages)` (`tools/check-deps/check-deps.ts`): a workspace package that is published, is not `@mermaid-js/core` or `mermaid`, is not one of `mermaid`'s dependencies (`dependencies`, `optionalDependencies`, `peerDependencies`), and plugs into core: it has a `mermaid` plugin manifest (any kind) **or** `@mermaid-js/core` as its only peer. Today: `layout-elk` (no manifest yet, core-only peer), `plugin-interactions`, `plugin-math`. Diagram packages are out (mermaid ships them); the language service is out (it peers on the diagrams too). M4's icons and hand-drawn packages join by manifest with no code change; a package stops being optional once `mermaid` depends on it.

## Size: with vs. without (`tools/check-deps/optional-size.spec.ts`, in `pnpm test`, ~3 s)

Bundles the core budget's entry (`size-budget.json` `core.entry`, `src/cdn.ts`) twice with the size job's production options via `measureStaticClosure(entry, outdir?, options)`:
- **present**: `{ installed }` symlinks every optional package into a temp `node_modules` passed as esbuild `nodePaths`, so any module could resolve it by name (as an app's install).
- **absent**: `{ hidden }` is an esbuild `onResolve` plugin that fails the build on any import of an optional name or subpath (as if not installed anywhere).
- Asserts identical static-closure file list, raw and gz bytes, and sha256 of every output file (lazy chunks too), plus the core budget. A temp fixture entry `import('@mermaid-js/layout-elk')` bundles with them present and fails with them hidden.
- Why this method: two in-process esbuild builds, no file system mutation of the workspace, no temp copy or reinstall (pnpm's store/symlink layout makes copying slow and fragile). `mermaid` cannot resolve the optional packages today (not in its node_modules), so "present" has to be simulated anyway; `nodePaths` makes them resolvable from every module, the strongest form of "installed".
- Placement: in `tools/check-deps`, beside `findOptionalPackages`, importing bench's `size-budget.ts` relatively. The bench's own spec cannot import from `tools/` (`mermaid/import-boundaries` forbids relative imports leaving a package).

## Import-boundary lint

- `check:deps` (in `pnpm check`) now also runs `findOptionalNameViolations(packages, readCoreSources(root, packages))`: no file under `packages/core/src` (code, strings or comments) and no dependency field of core's package.json names an optional package (whole-name match). Fixture specs: a static and a dynamic core import fail, a string and a comment fail, a manifest devDependency fails, a new `plugin-icons`/`look-hand-drawn` is picked up.
- eslint `mermaid/import-boundaries` already allow-lists core → nothing, diagram → core, mermaid → core + diagram-*; new fixture `tools/eslint-plugin/fixtures/import-optional-package.ts` (static, dynamic, and a not-yet-existing `plugin-icons`) pins that it fires in core, a diagram package and `mermaid`.
- `mermaid` may still name `@mermaid-js/layout-elk` in its `ELK_NOT_INSTALLED` message (settled); the naming rule covers core only.
