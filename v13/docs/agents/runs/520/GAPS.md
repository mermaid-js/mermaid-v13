## #579 T6 language facet
- **For the maintainer** (needs a D437 clarification; D439 is the free escalation id): D437 says a rename "adds quotes when the new name is not a valid unquoted string (D431–D432's rules, keyword prefixes included)". Read literally (any string v12's `unqString` takes, `[\w][^:,\r\n{<>\-=]*`), it breaks or refuses renames: the targets of `style` and `class` (and `classDef` names) lex in v12's style state, which takes `\w+` only, so `style r1 fill:#f00` renamed to `my req` or `a.b` bare becomes `style my req fill:#f00` (a different statement) and the service's read-back check refuses the rename. Implemented: a name is bare only when it is `\w+` and no keyword or keyword-like word (`title x`, `accDescr {`, a line-start `direction`); every other name a quoted string holds is quoted at each bare occurrence (`quoteId`: `my req`, `a.b`, `café`, `test`, `r#1`), and a name a quoted string cannot hold is refused: a `"`, a line break, a `#name;` entity v12 decodes, a `%%{word` directive opener (`quotedReadsBack` holds the rule to a parse in every place), or an existing name. Bare names with blanks that v12 reads in a header or relation (`requirement my req {`) stay as written; only a rename quotes them. Alternative: quote only where a style-state occurrence exists (a per-occurrence `nameSyntax`).
