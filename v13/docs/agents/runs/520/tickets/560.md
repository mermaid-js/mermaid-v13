## Exports (`@mermaid-js/diagram-requirement`)

- `RequirementTokenKind` (`src/parser/tokens.ts` `T`): one kind per `requirementDiagram.jison` terminal, plus kinds with no jison name: `Quote` (each `"`), `AccDescrOpen`/`AccDescrClose`, `StyleEnd` (the line break ending a style statement), and `NewlineAfterBlank` (D431, below). Shared: `Kind.Newline` (`NEWLINE`), `Kind.Error` (`LEXICAL_ERROR`), `Kind.Comment` (`#…`, `%…` and removed `%%` lines).
- `JISON_NAMES`: kind → jison terminal (dev/test only). `requirementView(src)` → `{ from, view }`; `requirementTokens(src)` → `RequirementToken[] { kind, text, range }` (trivia left out; `text` as v12's parser read it: entities decoded, CRLF as LF, removed spans cut).
- Internal for #564: `lex(src, from, view)` in `src/parser/lexer.ts` returns `Lexed { tokens, text(j), textOf(start, end) }` (trivia included, ends in `Kind.EOF`). `UnqString` ranges are trimmed (jison's `trim()`); `QString` ranges hold no quotes (the quotes are `Quote` tokens); `""` gives two `Quote`s and no `QString`.

## Token facts the parser needs (oracle-checked)

- Keywords win at a token start, with `\b`: `element test {` is `ELEMENT VERIFY_TEST`, `text: high quality` is `HIGH_RISK unqString`. `title …` is a `title` token no rule takes. `<*>[0-9]+` never matches.
- A text that ends inside quotes, an `accTitle:`/`accDescr:` value or an `accDescr {` block ends with an empty value token and no `EOF`; in a style state with no `EOF` either.
- Style lines return no `NEWLINE` (`StyleEnd` instead); `classDef` and `class` lex as `style`.
- **D431:** a blank run after other text on its line ends at its first line break, which is a `NewlineAfterBlank` run; at a line start the run is skipped whole (v12). Take `NewlineAfterBlank` as `NEWLINE` only where the grammar needs one and skip it elsewhere, so v12's six accepted split forms stay accepted (GAPS #560 Choice).
- **D432:** `DirectionXX` only at a line start whose first word is `direction` + `\s+` + a direction; kind and end as v12 (rule order over the line, rest of line in the token, leading blanks included).
