## Exports (`@mermaid-js/diagram-class`)
- `layoutClass(model, ctx: ClassLayoutContext)` → `ClassLayout` (a `LayoutModel` plus `class: ClassPrepared`), as flowchart's `layoutFlowchart`. `ctx` = `{ config, measurer, theme, units?, layout? }`; `ctx.layout` defaults to `layered` (D106). `prepareClass` builds the graph alone. `classTitle(node)` = `Label<T>`. `classCurve(name)` maps a v12 curve name.
- Layout ids (keys of `nodes`/`groups`/`edges`): class `c:<id>`, note `t:<noteN>`, interface `i:<interfaceN>`, namespace `s:<qualified id>`; edges use the relation's AST id (`#2`… if repeated), note edges `note>:<noteN>`. Prefixes stop a class, note and namespace with one name colliding. `views` maps layout id → view; `data-id` is the view's `id`.
- `boxes: ClassBoxView[]` (declaration order = v12 `colorIndex`): `width`, `height`, `annotation?` (first only, `«name»`, as v12), `name` (bold), `compartments` (`attributes`, `methods`: `top`, `height`, `rows`), `dividers` (y of each line, one per compartment). A `ClassRow` has `text`, `label: MeasuredLabel` (ready for `SvgWriter.label`), `x`/`y` from the box's top-left (`y` = label top; `x` = centre for `anchor: 'middle'`, left edge for `'start'`), `style` bits (Bold name, Italic `*`, Underline `$`), `member` and `ast` on member rows.
- Geometry (px, all through `fromPx`; P = `class.padding`, v12 effective 12): header P + annotation + name + P (a blank name keeps a line); a compartment with rows P + rows (3 px apart) + P; an empty one 2 P, or 1.5 P each when the class has no members; methods under empty attributes start 1.5 P down. So `class A` is label + 5 P, as v12's `classBox`. `hideEmptyMembersBox` drops both compartments only when the class has no members.
- `notes: NoteView[]` (markdown, unwrapped, text + `class.padding ?? 6`), `interfaces: InterfaceView[]` (name + `labelPatch`, borderless; placed in its class's namespace), `groups: NamespaceView[]` (outermost first, `depth`, title label; padded `class.padding ?? 16` on every side, as v12).
- `edges: ClassEdgeView[]`: note edges first, then relations (v12 order). `kind` `relation | lollipop | note`, `line` `solid | dashed` (`..` and notes), `startMarker`/`endMarker` (`RelationType`, `none` on notes; the lollipop marker is at the interface end; a lollipop end resolves to its interface before a class of the same name), `label` (markdown, `edgeWrap`), `startLabel`/`endLabel` (multiplicities, `"none"` dropped). Positions come from the model: `edges.get(id).{points,label,startLabel,endLabel}`.
- `ClassPrepared.curve`: `flowchart.curve` through flowchart's mapping (`rounded` when unset); `graph.routing` follows it (`linear` straight, S-curves curved, the rest stepped). Spacing/padding: `class.nodeSpacing`, `class.rankSpacing`, `class.diagramPadding`, else builder defaults (50, 50, 8).
- Every label (names, annotations, members, notes, relation labels, multiplicities, namespaces, interfaces) goes through core's `layoutLabel` with markdown on, as v12's `createText`: `__bold__()`, `_italic_()`, `<br>` and the HTML subset are read; `List<T>` stays text.

## For #156 (T4)
- End markers must stay within 12 px across (2 × `endLabelAcross`): the engine's across offset is what keeps multiplicities clear of them; no extra room is reserved. v12's are 12 px across (lengths 18/18/18/9/13); the conformance spec asserts the clearance with those sizes.
