## What changed (`packages/core/src/parser-kit/source-view.ts`)

`sourceView` now gives the result of v12's steps run in order, each on the previous one's output:

- Line comments are found as if directives were already cut out. A line break inside a directive is no line start, so a `%%` line inside a multi-line directive is not a comment. A comment's `[^\n]+` runs on past a directive (`outsideDirectives` wraps the `lineEnds` lookups). The `%%` opener and its third character skip directives between them (`past`).
- The `style`/`classDef` semicolon drop scans the cut text (directives and comments removed) and marks the mask at source offsets through `SourceOffsets`. A directive's text neither starts a match nor stops one, and a `style` that only exists once a directive is cut does match. `directivesOnLine` is gone.
- The extra cut happens only when the source has a `;` and either has holes or contains `style`/`classDef`. Every step stays a linear scan (the R-PARSE-7 timing tests pass).

No exports changed. `SourceView`, `Hole`, `cook`, `localOffset`, `firstHole` and `SourceOffsets` work as before.

## Tests

- `source-view.spec.ts`, describe "directives that start mid-line": both ticket strings in class and flowchart forms, a comment running on past a directive that holds a line break, `%%` then a directive then a line break (no comment), and a `style` completed by a cut directive (drops the `;`).
- `lexer-parity.spec.ts`: `MID_LINE_DIRECTIVES`, six flowchart sources (the two ticket cases, the INVALID form of the `;` case, and the three edge cases above), each also lexed in commented form. All match v12. They are inline next to `LINE_SEPARATORS` because `corpus/flowchart-v12-specs.json` is generated by `harvest:flowchart` from v12's spec files.
- Flowchart parity and output did not change: no snapshot or golden changed, and `pnpm check` is green.
