# #158 class interactions: handoff

Branch `feature/158_class-interactions` at 760d13df2 (base `feature/126_class-diagram` 28580501e, with #202 menus). `pnpm check` green under the lock (7,442 tests). No core or diagram-class changes (D105).

## What changed (`@mermaid-js/plugin-interactions`)
- No new feature entry: class's `callback` / `click … call` already emit the `callback` field (`AstCallback`, tickets/154.md), which the existing `callbacks` feature reads, so a second entry would bind twice. Class boxes are `g.node[data-id=<class id>]`, so they bind as flowchart nodes do.
- Fix (`index.ts`, `drawsNode`): a callback binds only a `g.node` whose `data-ast` names its id (`n:A`, `n:A@k`, `s:S`; no `data-ast` = accepted). Before, a class named `note0` / `interface0` also bound the note / lollipop interface with that `data-id` (`note:1`, `i:A`), and a callback on a missing class `note0` bound the note. Flowchart unchanged (its nodes are `n:`).
- `testing/fake-dom.ts`: `innerHTML` setter, so specs can drive `mount()`.
- README mentions class callbacks/links; changeset `.changeset/plugin-interactions-class.md` (patch).
