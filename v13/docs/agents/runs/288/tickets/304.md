# Ticket 304: pie T1, lexer parity gate and the shared Langium oracle

**`@mermaid-js/diagram-pie`** (new, `private`, version 0.0.0, no `mermaid` manifest until T5; peer `@mermaid-js/core`, zero dependencies). `src/index.ts` exports:
- `pieTokens(src): PieToken[]` (`{ kind, text, range }`): what v12's lexer saw, in order: significant tokens, the hidden comments, directives and YAML still in v12's text, and `Kind.Error` where no rule matched. Spans v12 removed (comment lines, directives) and the final `EOF` are left out; the last `Newline` is zero-width at the end (v12's appended `\n`). `text` is `cook()`ed: CRLF/CR as LF, tag quotes `'`, entities `&name;`.
- `PieTokenKind` (`T`): `ShowData, Pie, Colon, Number, AccDescr, AccTitle, Title, String, Yaml`; line breaks are `Kind.Newline`, in-text `%%` comments `Kind.Comment`, in-text directives `Kind.Directive`. `PIE_TRIVIA` (a `KindSet`): Comment, Directive, Space, `Yaml`. Pass it to `TokenCursor`/`significantTokens` in T2.
- `LANGIUM_NAMES`: kind → Chevrotain token type name (`NUMBER_PIE`, `ACC_DESCR`, …, `LEXICAL_ERROR`). Test use only.
- Internal for T2: `lex(src, from, view)` in `src/parser/lexer.ts` returns the full `TokenStream` (removed spans as trivia, in source order). Use `sourceView` with default options. Title/accessibility tokens keep v12's images: leading blanks included, stopped before `%%`, untrimmed; value conversion is T2's.

**Shared Langium oracle** (`packages/conformance/src/langium-lexer.ts`, D220). Keep this API stable:
- `LANGIUM_LEXERS: Record<type, { probe, factory, key }>`: `probe` is a source v12 parses as the type (used once to reach v12's registered parser object), `factory` the `@mermaid-js/parser` export (`'createPieServices'`), `key` the services key (`'Pie'`). **gitGraph's T1 adds one row** (e.g. `gitGraph: { probe: 'gitGraph\n  commit', factory: 'createGitGraphServices', key: 'GitGraph' }`) and nothing else.
- `loadLangiumLexerOracle(type) → Promise<LangiumLexerOracle>` (memoised per type). Methods: `input(source)` (the exact text v12's parser got, or undefined when v12 never reached it), `lex(source)` (`lexText(input)` with the appended `\n` clipped off the token that matched it), `lexText(text)` (raw).
- `LangiumLex = { input, tokens, hidden, errorAt? }`: `tokens`/`hidden` are `[name, image]` pairs **before the first lexer error**; `errorAt` is its offset in `input`. WHITESPACE (skipped) is in neither list. Calls must be sequential.
- `langiumParserVersions()` for the version check. Dependency: `"mermaid-parser-v12": "npm:@mermaid-js/parser@2.0.1"` (lock: one importer entry, no other change).

**Gate** (`packages/conformance/src/pie/`): `lexer-parity.spec.ts` compares names + images (entities decoded) and the hidden list; on an error both are cut there and the error must sit at the same place, written `LEXICAL_ERROR @<length of the text v12 read before it>` (D220). Corpus (`corpus.ts`): 24 e2e files, `corpus/pie-v12-specs.json` (45 after dedupe: pie.spec 14, pieRenderer.spec 2, parser pie.test 27, docs 2; `pnpm --filter @mermaid-js/conformance harvest:pie`), 77 quirks, 10 line-separator cases, 2 unclosed directives, each also CRLF and `commented()`: 467 of 474 lexed by v12 (the rest are not detected as pie), 100 with a lexer error, 0 diffs. `stress.spec.ts`: 27 shapes, n vs 8n, bar 24x (ratio, best of five; not measured on a steady machine). Removing the digit-run or string memo fails it (zero runs and escaped quotes are quadratic in v12).

**Exclusion** (listed in the spec): `unclosed directive …`. Core's preprocess ends an unclosed `%%{` at its line end and reports `UNCLOSED_DIRECTIVE` (v13 rejects); v12's regex also took the line break, or the rest of the text. Core behaviour shared by every type, not a pie rule.

**Size:** `diagram-pie` dist, core external, minified 6.4 KB, **2.5 KB gz**.

**For T2:** NUMBER backtracks like the regex (`12.` → `1` + error, `1.23.` → `1.2`, `01` → `0`,`1`); `;` is an Error. Error tokens span what Chevrotain skipped (to the next offset any rule matches).

**Unmet criteria:** none.
