# Ticket 306: pie T4, SVG renderer

**Exports** (`@mermaid-js/diagram-pie`, runtime entry, next to T1–T3's): `pie` (the `DiagramPlugin<PieModel, PieLayout>`: `id: 'pie'`, `formats: ['svg']`, `layoutKind: 'custom'`, `detector` = `detectPie`, `parse` = `parsePie(text, { preprocessed })`, `labels` = title and legend texts, `layout` = `layoutPie`, `render` = `renderPie`), `renderPie(model, layout, ctx, w)`, `PIE_HOVER_IGNORED`, type `PieRenderContext` (`config`, `theme`, `warn`, `idPrefix`, `version`). Internal: `src/render/paint.ts` (`PIE_COLOUR_STAND_INS`, `PIE_OPACITY_STAND_IN`), `src/labels.ts`, `src/plugin.ts`.

**Using it before #325:** `createMermaid().registerExternalDiagrams([pie], { lazyLoad: false, replace: true })` takes over the first-party `pie` row (detection, config section, ranges as they will be). `packages/conformance/src/pie/render-api.ts` `pieApi(config?)` does that with `deterministic: true`. #325 adds the manifest, `gen:registry`, and deletes `render-api.ts`'s `replace` (use plain `createMermaid()`).

**SVG** (MIGRATION.md "Pie SVG structure"): root `class="mermaid mermaid-pie" role="img" aria-roledescription="pie"`, `font-family` on the root, `useMaxWidth` as v12; `<g transform="translate(center)">` holding `circle.pieOuterCircle`, one `path.pieCircle` per shown slice (`data-id` = section `astId`, fill `pieN`, stroke, width, opacity) and `text.slice` percentages (`data-id`); `text.pieTitleText`; one `g.legend` per section (`data-id` = `data-ast` = `astId`) with swatch `rect` and left-aligned text. Highlight: `pieCircle highlighted`, `transform="scale(1.05,1.05)" opacity="1"`; hover: `pieCircle highlightedOnHover` on every slice, one `PIE_HOVER_IGNORED` warning (`path: 'pie.highlightSlice'`). `<style>` only for `theme: 'auto'` (core's theme sheet, as every type).

**Theme stand-ins for #325** (`src/render/paint.ts`; each name a literal, read with `theme.color(name)` / `theme.number('pieOpacity')` as soon as `THEME_VARIABLES` has it, so #325 only deletes the table): `pie1`…`pie12` = v12 `default`'s computed values (`#ECECFF`, `#ffffde`, `hsl(80, 100%, 56.27…%)`, … `hsl(0, 100%, 66.27…%)`) in every theme; `pieStrokeColor`, `pieOuterStrokeColor` = `black`; `pieTitleTextColor`, `pieSectionTextColor`, `pieLegendTextColor` = the shared `textColor` (v12: title/legend `taskTextDarkColor`/`mainContrastColor`, section `textColor`); `pieOpacity` = 0.7 (must be kind `opacity` in [0, 1], D221). Lengths still come from #335's `PIE_THEME_DEFAULTS` through the layout. Shared edit: `textColor`'s `usedBy` lists `pie` (`vocabulary.ts`, `gen:theme`).

**Tests:** `packages/conformance/src/pie/render.spec.ts` through `render()`/`renderSync()`: the gate corpus in `default`, `redux-color` and `auto` (≈ 412 rendered each, rejected ones are `SYNTAX`): well-formed, `assertInert`, deterministic across fresh API objects, no NaN/Infinity/undefined/`foreignObject`, ids only `-title`/`-desc`, every coordinate (arc bulges, the scaled slice, circle strokes) in the viewBox, AST round-trip (rule in GAPS.md: sections 1 `data-ast` each, repeats/negatives 0 with their diagnostic); plus input order and hidden-slice colour slot, slot mod 12, highlight, hover, empty and zero-sum pies, donut, showData + front-matter title, `useMaxWidth`, stand-in paints, D133 naming, id collisions, hostile labels, `ascii` → `UnsupportedFormatError`. Ported `pieRenderer.spec.ts` (2 pass) via `src/v12-specs/adapter.ts` `draw` and an imported `document` object (no global shim) that answers `querySelectorAll('.<class>')` and `__data__.data` from the rendered tree.

**AST ids (parser change):** slice ids now also percent-encode the characters XML 1.0 cannot hold (`\0` → `%00`, DEL `%7F`, lone surrogate `%D800`), since the writer drops them and `data-ast` stopped matching the id (parser case 10). One-to-one; `parse.spec.ts` pins it.

**Size** (esbuild `--minify`, core external, `gzip -9`): `src/index.ts` 26.4 KB / **10.5 KB gz** after merging #307 (was 20.5 / 8.1 after #305); `pie` plugin alone 23.0 / 9.2 KB gz; the renderer (with `slicePath`) 4.6 / **2.1 KB gz**.

**Deviations:** (1) `data-id` on slice, percentage and legend row is the section's AST id (`slice:<label>`), pie having no user ids. (2) `highlightedOnHover` is kept on every slice under `hover` (v12's class, so host CSS can add the hover). (3) Slice ids encode XML-invalid characters (above). (4) The highlighted slice's transform is core's `scale(1.05,1.05)`, equal to D222's `scale(1.05)`. (5) Colour stand-ins use v12 `default`'s literals in every theme until #325.

**Unmet criteria:** none. (`pie` is not yet in the generated registry, so `cli.spec.ts`/`codemirror.spec.ts` still assume it is unported: #325.)
