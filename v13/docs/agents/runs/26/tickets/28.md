## How it works
Kind keys are read from `export const T = {…}` and matched to grammar terminals by name with
case and `_` ignored (`acc_title` ~ `AccTitle`, `ELLIPSE_END` ~ `EllipseEnd`). Kinds lexed by an
unnamed `-` rule are listed in `kinds.unnamed` (flowchart: `ShapeDataEnd` → `<shapeData> /\}/`).
A kind with no rule fails generation. Names whose rules have mixed scopes take the first rule's
(flowchart: SHAPE_DATA Meta/String), listed in the generated file's doc comment.
Idempotent; `pnpm check:grammar` and highlight.spec's up-to-date test cover the new file.
