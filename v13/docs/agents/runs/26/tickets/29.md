# #29 flowchart `./language` facet skeleton (branch feature/29_language-facet)

## Exports
- `@mermaid-js/core/parser-kit`: `type LanguageFacet<A>` (`id`, `parse`, `categories`,
  `namespaces`, `isValidId`) and `type FacetParseOptions` (`{ keepTokens: true; probe?: number }`).
  **In core, not language-service**: diagram packages import only core (DESIGN §2, the
  import-boundaries rule). #31 re-exports it from `@mermaid-js/language-service`.
  `completions`/`hover` are not on the interface yet: #32 adds them with `Probe` (#27) and the
  service's `DocumentView`/`CompletionItem`/`Hover` types.
- `@mermaid-js/diagram-flowchart/language` (`src/language.ts`): `flowchartLanguage`,
  `flowchartCategories`, `parseFlowchart`, `detectFlowchart`, `flowchartTokens`,
  `FlowTokenKind`, all parser types. Manifest: `"language": "./dist/language.js"`
  (`DiagramManifest.language` in tools/gen-config/src/registry.ts; the registry generator
  ignores it, `firstPartyFacets` is #31's).

## Use
- `flowchartLanguage.parse(text, { keepTokens: true })` = `parseFlowchart` (probe ignored until #27).
- `namespaces`: `[['node','subgraph'], ['class'], ['edge']]` (symbol kinds the parser emits).
- `isValidId(name)`: parses `flowchart TD\n<name>\n`; ok iff no error and exactly one `node`
  symbol spanning all of `name`. Reasons: empty, line break, spaces, arrow (Link/StartLink
  token), keyword (single End/Subgraph/Graph/Style/… token), else `'x' is not a node id.`
  `a%%x` is accepted (mid-line `%%` is node text, as in v12). Class-name validity is not
  checked separately.
