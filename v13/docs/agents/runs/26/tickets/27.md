# #27 parser-kit probe mode + flowchart wiring (branch feature/27_probe)

## Exports (`@mermaid-js/core/parser-kit`)
- `ParseOptions.probe?: number`, `ParseResult.probe?: ProbeResult` = `{ offset, expected: TokenKind[], mode, prefix: Range }`.
- `Probe(source, offset)`: `isAt(view, i, from?)`, `tested(kinds, tokenStart)`, `lexed(start, end, mode)`, `freeze()`, `reset()`, `result()`. `ParseState.result(..., options, probe?)` attaches it.
- `ProbeCursor(tokens, probe, trivia?)` extends `TokenCursor`: `at`/`eat`/`peekAt`/`tested` record at the probed token. New on `TokenCursor`: `peekAt(kind)`, `tested(kinds)` and `recovering()` (no-ops there; `syncTo` calls `recovering()`). `peek()` returns a kind, so it cannot record: use `peekAt`.
- Flowchart: `parseFlowchart(src, { probe })` and `flowchartLanguage.parse(text, { keepTokens: true, probe })` (closes the GAPS item). `lex(..., probe?)` reports the jison start condition (`INITIAL`, `text`, `edgeText`, `shapeData`, `dir`, …).

## Rules (read before #32)
- Probed token: first significant token ending at or after the offset, **except** one ending exactly there with a non-word last char (`:::`, `-->`, `[`, a blank): the next token is probed. A word the cursor is in or after is probed itself; `prefix` = its text up to the offset, leading blanks dropped (` TD` → `TD`). Free-text tokens (labels, shape data) give the whole token so far as prefix.
- `expected` = kinds tested at that token, plus the first sets a loop would accept where it stops without testing them (document loop at the end of the text, optional blanks before the header). `End` only inside a subgraph. Includes structural kinds (Space, Newline, Eof): the facet maps what it knows.
- Recovery: once the probed token was tested, recovery freezes the record. A flowchart restart that re-lexes from before the offset resets it (the new tokens win).
- Mode: the step whose text holds the offset, else the first step at or after it, else the final state.

## Deviations / for the maintainer
- D95 says "first token that ends at or after the offset". Taken literally, `A:::|` probes `:::` and gives no class names, which the ticket's own spec needs. The non-word exception above is my reading; confirm or amend D95.
- `flowchart |` (keyword + blank) gives statement kinds, not directions: v12 lexes the blank as `NoDir`. `flowchart T|` gives directions. #32 may add directions after a bare keyword.
- `A --|` gives `EdgeText`/`Str` with mode `edgeText`: `-->` is a different lex, so #32 should use the mode to offer arrow ends.
- Size: +1 KB gz on the render path (no budget gate for it here; M1 size budget handled at M1 close).
