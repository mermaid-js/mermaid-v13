# #33 front-matter config: completion, hover, unknown-key warnings (R-LANG-5, D96)

Branch `feature/33_frontmatter-config`. Code: packages/language-service/src/config/ (schema.ts, front-matter.ts,
completion.ts, hover.ts), dispatch in src/completion.ts + src/hover.ts, snapshot methods in snapshot.ts.

## Exports
- `DocumentSnapshot.completions(offset): readonly CompletionItem[]`, `DocumentSnapshot.hover(offset): Hover | undefined`.
- `CompletionItem { label, kind, insertText, range, detail?, documentation? }`, `CompletionKind = 'property'|'value'|'keyword'`,
  `Hover { range, contents (markdown) }`: in core parser-kit/language.ts next to `LanguageFacet`, re-exported by the service.
- `ConfigSchema`, `SchemaNode`, `Annotation` (types). `createLanguageService({ schema })` takes a `ConfigSchema`.
- Schema: `pnpm gen:config` writes packages/language-service/src/generated/config-schema.gen.ts (`configSchema`: the
  YAML schema as JSON Schema, minus `required`/`tsType`/`$schema`; `check:config` keeps it fresh). Not a copy.
  When no `schema` is passed, `preload()` dynamic-imports it (its own chunk); before that, config features are off.

## Shape for #32 (completion/hover on the diagram text)
src/completion.ts and src/hover.ts: if the offset is inside the front matter block (fences included, `inFrontMatter`)
the front matter answers (possibly empty) and the facet is never asked; otherwise the `// #32` line runs the facet
(re-parse with `probe: offset`, `facet.completions(probe, view)` / `facet.hover(target, view)`). #32 extends
`CompletionKind` and adds `Probe`, `DocumentView`, `HoverTarget` to parser-kit/language.ts.

## Behaviour
- Completion (block style, text-based: one backward line scan finds the parent keys): top level `title`, `displayMode`,
  `config`; under `config` the schema keys minus removed/moved and keys already in the mapping; diagram sections
  (root `$ref` to a whole def) only the detected type's (`entry.id`, as the renderer's `sectionOf`), all of them when
  no type is detected; nothing inside another type's section. Values: enum (quoted when YAML would not read it back,
  `'null'`, `''`) or `true`/`false`; `detail: 'default'` on the default. `displayMode` values = `gantt.displayMode`.
- Hover on any key (tree mode, so flow mappings too): description, type, default, status/since/reason/replacement.
- Warnings `CONFIG_UNKNOWN_KEY` (+ `Did you mean "x"?`, edit distance ≤ max(1, len/3) capped at 3, case-insensitive),
  `CONFIG_REMOVED_KEY`, `CONFIG_MOVED_KEY`, same messages and rules as core `resolveConfig` (spec checks it); a
  third-party type's own section is open. Merged in source order into `diagnostics()`. Directives: nothing new.
