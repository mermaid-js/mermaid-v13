## Behaviour (after review)
- Section: `configSection(ctx)` = a first-party row's generated `section` (the package id, as mermaid's
  `sectionOf`; `pnpm gen:registry` writes it), a third-party row's id. Types with no v13 package have none, so
  `config.class` is not offered in a classDiagram and `classDiagram:` warns, as core does.
- Completion (block style; one backward line scan finds the parent keys): top level `title`, `displayMode`,
  `config`; under `config` the schema keys minus removed/moved, core's secure keys, `look` (D153) and keys present;
  only the type's own diagram section (all while no type is detected); nothing inside another section or `look`.
  Values: enum (quoted when YAML would not read it back) or `true`/`false`; top-level `displayMode` only where gantt
  config is offered. Inserts follow CRLF and tab indents. Unclosed front matter runs to EOF for completion/hover.
- Hover on any key (tree mode): description, type, default, status/since/reason/replacement; prototype names none.
- Warnings are core's own: `resolveText` over the config the render reads (none for YAML with errors or an unclosed
  block), each placed on its key or list item (`flowchart.0.bogus`); unknown keys get `Did you mean "x"?` among
  settable keys. Codes as core: CONFIG_UNKNOWN/REMOVED/MOVED/SECURE_KEY, LOOK_REMOVED, CONFIG_UNSAFE_VALUE.
