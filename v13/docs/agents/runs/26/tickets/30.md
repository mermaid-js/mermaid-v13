# #30 YAML reader tree mode (R-LANG-5, D96)

Branch `feature/30_yaml-ranges`. Code: `packages/core/src/preprocess/yaml.ts` (+ `yaml-nodes.ts` types, `yaml-text.ts` = pure helpers moved out of yaml.ts for max-lines).

## Exports (`@mermaid-js/core/preprocess`)
- `parseYaml(src, { start?, end?, indent?, tree: true }): YamlTreeResult` (overload; without `tree` it is the old call, same result type).
- `YamlTreeResult = { value, root: YamlNode | null, diagnostics }`. `value` = what was read around the errors.
- `YamlNode = YamlScalarNode | YamlSeqNode | YamlMapNode`, each with `range` (offsets into `src`).
  - map: `{ kind: 'map', flow, pairs: YamlPair[] }`, `YamlPair = { key, keyRange, value?: YamlNode }` (source order; `value` missing when it could not be read).
  - seq: `{ kind: 'seq', flow, items }`; scalar: `{ kind: 'scalar', value, style: 'plain'|'single'|'double'|'literal'|'folded' }`.
- Also `YamlTreeOptions`, `YamlScalarStyle`. Does not touch `isYamlMap` (PR #119 adds it at the end of yaml.ts; a merge is append-only).

## Ranges
- keyRange covers the key as written (quotes included). Quoted scalars include their quotes; block scalars run from `|`/`>` to the end of the last text line; plain from first to last non-blank char.
- Empty value (`key:`, `-`, `{e}`) = plain `null` scalar with an empty range where the value would start (after `key: ` / `- `): use it as the completion position.
- Block map/seq range = first key/`-` to the end of the last value.

## Recovery
- Each block-map entry and block-seq item (tab indents included) catches its own error, reports it, then skips the rest of that entry (deeper lines, blanks, comments, lines starting `}`/`]`). At most one error per line. NUL bytes are reported per line.
- A failed entry keeps its key in `pairs` (no value) and is left out of `value`. Prototype keys are dropped from both; the depth cap holds.
- Root that ends early (less indented line, map after a root seq): one error on that line, then the next lines are read as another root block, and so on. Root = first block that is a mapping (else the first block); later mappings append their pairs (a key seen before is a duplicate error); other later blocks only report errors.
- A map whose keys are all dropped spans its lines.
- Known, by design: a duplicate key is in `pairs` twice (the second without a value); an error on a plain value's continuation line drops the whole value; an unclosed `{`/`"` that runs onto the next line gives one diagnostic, where js-yaml fails (often that next line).
- Not recovered: an error inside a flow collection ends that whole entry; a root flow document with an error (`{a: 1, a: 2}`) gives `root: null` (GAPS.md, owner #33).

## Tests
- `packages/core/src/preprocess/yaml-tree.spec.ts`: `spans(src, root)` helper flattens a tree to `path → source text` (`$.config.theme#key` for keys); `where(src, r)` gives `line:col CODE` per diagnostic.
- `stress.spec.ts`: tree-mode linearity over 8 recovery shapes.
- `packages/conformance/src/yaml-tree.spec.ts`: corpus front matter, tree value+diagnostics == default, ranges nest, key text matches, and value text fits its kind/style (one-line scalars read back to the same value).
- Default mode: a before/after dump of parseYaml/preprocess over the corpus (48k inputs) was byte-identical; 20k-line bench unchanged (flat 7.5 ms, nested 28 ms, quoted 9 ms).
