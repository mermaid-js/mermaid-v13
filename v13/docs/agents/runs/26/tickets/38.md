# #38 LSP server `mermaid-language-server` (branch feature/38_lsp-server)

## Exports (`@mermaid-js/language-server`, packages/language-server, published)
- Bin `mermaid-language-server` (src/cli.ts): stdio only (`--stdio` accepted). Depends on
  `vscode-languageserver` ^11 (D88; `THIRD_PARTY_ALLOWED` in tools/check-deps), core, flowchart, service.
- `startServer(connection, { facets? })`: wires a connection. `initialize` scans `node_modules`
  (rootUri → first workspace folder → cwd, then parent dirs), builds the service and awaits
  `service.preload()` before answering (D155). Full-text sync; `.mmd`/`.mermaid` URIs only (`isMermaidUri`).
- Methods: push diagnostics (open/change; empty on close; `expected` appended to the message,
  `related` → relatedInformation), definition, references, prepareRename/rename (a refusal is a
  `RequestFailed` -32803 error carrying the reason), hover (markdown), foldingRange (by line, one per
  start line), semanticTokens/full (legend = `SEMANTIC_TOKEN_LEGEND`), completion (textEdit per item).
- `encodeSemanticTokens(index, text, tokens, multiline)`: cuts a token per line (breaks left out)
  unless the client sent `multilineTokenSupport`, then delta-encodes. UTF-16 positions via `LineIndex`.
- `discoverFacets(root, { log })`: rows for packages whose `mermaid` manifest is a diagram with
  `id`, `detector` (module; `detector` export else default) and `language`. Never throws: bad JSON,
  missing id/detector, a detector that fails to import or is not a function → skipped with a log line
  (sent as `window/logMessage` warnings); a broken `language` module → `LANGUAGE_LOAD_FAILED`.
  First-party ids and repeated ids are skipped.

## Tests
