# Gaps (cross-ticket)

- **Highlighters ignore front matter** (found by #28). The generated TextMate/Monarch/Lezer
  grammars read a leading `---` … `---` block as flowchart text (a `'` or `(` in the YAML can
  leave a mode open into the diagram). Fix in gen-grammar (a front-matter state at the start
  of the document; TextMate `\A---`, Lezer at offset 0, Monarch via a start state). The #28
  agreement test blanks front matter until then (exception 1 in
  tools/gen-grammar/src/categories.spec.ts). Owner: whoever picks up the CodeMirror/Monaco
  adapters (#35/#36), since first paint shows it. **Monarch: closed by #36** (start state
  `frontMatterStart`, `monarch-front-matter.spec.ts`; an unclosed block runs to the end, Monarch
  cannot look ahead). TextMate and Lezer remain.
- **#30 → owner: open (#33 did not need it): a front matter that is one flow mapping does not recover.** In YAML tree mode an error anywhere in a root flow document (`{a: 1, a: 2}`) gives `root: null`, so no key in it gets a range (no hover or config warnings there). Block front matter recovers per entry. No #33 golden needed it; fix in `Reader.flow` (recover per flow entry) if an editor case does.
- ~~**#29 → owner #31: `LanguageFacet` lives in `@mermaid-js/core/parser-kit`**~~ Closed by #31: `@mermaid-js/language-service` re-exports it.
- ~~**#29 → owner #32: `completions` and `hover` are not on `LanguageFacet` yet.**~~ Closed by #32: required members, with `DocumentView` and `HoverTarget`. The facet takes `ProbeResult`, not `Probe` (DESIGN §4.5's name; the kit's `Probe` is the recorder class). A third-party facet without them now fails `preload` with `LANGUAGE_LOAD_FAILED`.
- ~~**#29 → owner #31: `isValidId` checks lexing only.**~~ Closed by #31: `isValidId(name, kind)` checks class and edge names by their own rules, and `rename` refuses a clash and any rename that does not read back the same after a re-parse.
- ~~**#31: `click A …` recorded the node symbol with the range of `click A`.**~~ Fixed in the parser on feature/31_service-core (the Click token's own range); the service no longer narrows symbol ranges and leaves out one that does not hold its name.
- **#31 → owner: flowchart parser: the `accDescr { … }` statement span starts after `{`,** so its fold starts on the first body line, not on `accDescr {`. Golden: goldens/flowchart/folding/blocks.out.
- **#31 → owner #28 follow-up: the `click` keyword has no token** (the Click token covers only the id), so it gets no keyword semantic token or highlight.
- **#31 → owners #35/#36/#38: facets load before use (D155).** #36: `registerMermaid` awaits `service.preload(options.preload)` before registering anything. The adapter/server setup function awaits `service.preload()` (or `preload({ types })`) before the first `update`; a type not preloaded gets `LANGUAGE_NOT_LOADED` and generic features only. `doc.pending` is gone.
- **#31 → owners #35/#36: the first-party facet is a dynamic import of an optional peer** (`@mermaid-js/diagram-flowchart/language`). Bundlers resolve it at build time: a host without the package may get a build error rather than the `LANGUAGE_LOAD_FAILED` diagnostic. The example editors should install it or mark it external. #36: the Monaco example installs it; its Playwright spec runs `vite build` (Vite 8), which resolves the import.
- **#31 → owner #38: semantic tokens can span lines** (multi-line labels, `accDescr { }` bodies, `@{ }` blocks). The LSP server splits them per line (unless the client has `multilineTokenSupport`) and delta-encodes them.
- **#31, parser-side quirks seen while reviewing rename (no change made):** `class A , AA foo` reads class `,` as in v12's grammar; `style A,B …` is one node `A,B`; a node named `😀` records no symbol. A rename touching these is refused by the read-back check rather than done wrong.
- ~~**#27 → owner #32: probe edges.**~~ Closed by #32. Kit fixes (rule 3 in tickets/27.md): an empty line inside a run of line breaks, and the blanks any token takes after its text (links, `end`), are after the token; a word never joins across a line break or such blanks (`end\n  A`). Facet-side: `flowchart |` at the end of the text gets directions by position; right after `--`/`==`/`-.` the rest of the arrow comes from the link-start token; shape data works out its own range; label/string/callback modes, comments, directives and front matter get nothing. A probed token skipped by recovery still gives nothing.
- **#32 → owner open: completion gaps (not in the ticket's list).** Not offered: closing arrows after edge text (`A -- text |`), curve names after `interpolate`, edge `@{ }` keys (`animate`, `curve`; node keys only), header keywords `flowchart-elk`/`swimlane-beta`, a `@{ shape: … }` snippet after an id.
- **#32 review → record only: a half-typed arrow glued to an id gets nothing** (`A-|`, `A <-|`, `A -- text --|`). v12 lexes `A-` as one id, `<-` and `--` after edge text as id/edge text, so the probe sees an id or label, not a link start. Follows v12 lexing; not fixed.
- **#32 → maintainer: R-LANG-4 with completion and hover (D156: 15 ms).** `pnpm --filter @mermaid-js/bench language`, 50k fixture, same laptop: cycle median 14.9–15.2 ms, best 13.9–14.3 (base 10.4–10.7); `completions` 3.95–4.0 ms (the probe re-parse), `hover` 0.23 ms; other stages unchanged (A/B both orders + A/A). At the 15 ms line on this laptop (one of three runs 0.2 ms over). Not optimised.
- **#27 → maintainer: D95 wording.** Reviewer confirmed the deviation; the exact (token-kind) rule is in tickets/27.md for the D95 amendment.
- **#33 → open question (D91 vs D96): the service shows only the first YAML error of the front matter.** `diagnostics()` takes preprocess's default-mode YAML diagnostics as they are (D91), and that read stops at the first error, while the tree mode the service also runs reports one error per bad line (`config:\n  theme: dark: bad\n  layout: "x` → 1 shown, 2 in tree mode). Replacing the front matter's `YAML_*` diagnostics with the tree mode's would give N in, N out; not done without a decision.
- ~~**#33: section key = diagram id.**~~ Closed after review: the service takes the renderer's section (the package id, generated as `section` in `firstPartyFacets`). A type with no v13 package has no section in either, so `config.class`/`config.state`/`config.xyChart` are offered once those types are ported with a package id equal to their schema section (a port with another id needs a decision).
- **#33: front-matter completion is block-style only.** Flow mappings (`config: { the| }`) and quoted keys get no completion (hover and warnings work there, from the tree).
- **#34 → maintainer: R-LANG-4 is over budget locally (escalated, not optimised).** `pnpm --filter bench language` on the 50k-character fixture (Apple Silicon laptop, not the reference runner): cycle median 10.6–11.1 ms, best 9.3–9.7 ms. Median per stage: update (parse) 3.4, rename 3.7 (the read-back re-parse), semanticTokens 2.7, astAt 0.55, everything else < 0.2; a bare facet parse with tokens is 3.0. Options: drop the rename read-back to prepare-time or on-commit only, or make semantic tokens cheaper; either is a decision. PR CI asserts ratios only (cycle ≤ 4 bare parses, ×2 text ≤ ×2.6 time).
- **#34 → owner: flowchart parser/service rename: two renames change the model** (pinned in `rename-round-trip.spec.ts` `KNOWN_MODEL_CHANGES`): renaming node `D` renames the generated edge id `L_B_D_0`, so a written `L_B_D_0@{ … }` then names nothing; `class link …` for edge id `link` is recorded as a node mention, so renaming either leaves the other behind. Renaming the written `L_B_D_0` itself is refused (`KNOWN_REFUSALS`).
- **#34 → owner: flowchart parser: a quoted subgraph id (`subgraph "One"`) has no definition or references** in the service: the symbol range is the quoted token, which the service leaves out (13 corpus cases, pinned as `QUOTED_SUBGRAPH_IDS` in conformance `service-symbols.spec.ts`). Fix: record the range inside the quotes.
