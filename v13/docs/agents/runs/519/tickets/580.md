## Exports (`@mermaid-js/diagram-ishikawa`)

- `IshikawaTokenKind` (`src/parser/tokens.ts` `T`): `Ishikawa` (both keywords), `CommentLine` (`\s*%%.*`) and `SpaceLine` (`[\s]+[\n]`, both `SPACELINE`), `SpaceList`, `Text`, `Eof`. Shared kinds: `Kind.Newline` (`NL`, always one LF), plus `Kind.Comment`/`Kind.Directive`/`Kind.Space` trivia (removed comment lines, directives, a dropped `;`). There is no `Kind.Error`: no input makes jison throw.
- `JISON_NAMES`: kind → jison terminal (dev/test only).
- `ishikawaTokens(src)` → `IshikawaToken[] { kind, text, range }`: significant tokens. `text` is what v12's parser read: entities decoded, CRLF as LF, removed spans cut.
- Internal for #581: `ishikawaView(src)` (`src/parser/index.ts`) → `{ from, view }`, then `lex(src, from, view)` (`src/parser/lexer.ts`) → `Lexed { tokens, text(j) }`. Trivia is included and the stream ends in `Kind.EOF`. Read text only through `text(j)`.

## Token facts the parser needs (oracle-checked)

- Leading blanks before the header are no token (v12 trimmed them). Text on the header line is `SPACELIST TEXT`. `ishikawa-betax` is `ISHIKAWA:ishikawa TEXT:-betax`.
- A keyword is a token wherever a token starts, so `  Ishikawa review` is `SPACELIST ISHIKAWA SPACELIST TEXT` and v12 rejects the document. `ishikawas` and `The ishikawa way` are `TEXT`.
- `TEXT` runs to the LF: it keeps trailing blanks, inline `%%`, `<br>` and U+2028/U+2029. The `$2.trim()` is the parser's job. `SPACELIST` holds every `\s` blank except LF, and U+2028 counts as one column.
- A `%%` that v12 left (on the header line, or a bare `%%` line) is `T.CommentLine` together with the blanks and line breaks before it, and it ends at U+2028.
- `ishikawa-beta` alone gives `ISHIKAWA NL:'' EOF` (rejected). `ishikawa-beta\n` gives `ISHIKAWA SPACELINE EOF` (accepted, empty).

## Tests

- `conformance/src/ishikawa/lexer-parity.spec.ts` runs 864 sources: 33 e2e, 4 harvested, 82 cases, each also in seven variants (commented, CR cut by a comment, CR cut by a directive, CRLF, tabs, dedented, mid-line directive). 853 are lexed by v12 and all are equal. The 11 skipped are `ishikawas` (not detected), its variants, and commented one-line bodies; the spec asserts which. Nothing else is excluded. Mutation check: dropping `\b`, ending a comment at LF only, skipping the trim, or treating U+2028 as LF each fail the gate.
- `conformance/src/ishikawa/stress.spec.ts`: 27 shapes (blank runs, long indents, long lines, comments, separators, CR/CRLF, directives), 10k against 80k units, pie's ratio below 24. Plus 80k cause lines with an exact token count.
- `diagram-ishikawa/src/parser/lexer.spec.ts`: 22 tests, one per quirk, plus removed spans (pitfall 4), CRLF ranges and EOF.
