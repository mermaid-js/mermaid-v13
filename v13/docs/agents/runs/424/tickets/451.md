## Token facts the parser needs (oracle-checked)

- Everything mindmap's #383 handoff lists holds outside `@{` (same rules line for line), with `@` an id stop: `a@b` is `NODE_ID`, error, `NODE_ID`.
- `kanban` is a keyword wherever a token starts: `  Kanban board` is `SPACELIST KANBAN …` (v12 rejects it); `kanbanCard`, `mykanban` are ids.
- Shape data pieces: `b@{x: 1}@{y: 2}` is four `SHAPE_DATA` (`''`, `x: 1`, `''`, `y: 2`); v12 joins them. A quoted run left open at the end took v12's appended `\n`, so its text ends in `<br/>`.
- `Kind.Error` (one character, lexing goes on in the same state): also an `@` that starts no `@{` and a `^` in shape data. No `Eof` when the text ends inside shape data.
- A mid-line `%%` SPACELINE followed by a blank-line SPACELINE is rejected by v12's grammar (`kanban-cases/comment-then-blank-line`).
