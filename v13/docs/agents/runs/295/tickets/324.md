# #324 I3: label icons in every type

Branch `feature/324_label-icons`. Consumers: I6 #330 (docs), M4 types as they port.

## What changed

- No type needed code: flowchart (nodes, edge labels, subgraph titles, markdown), class (titles, annotations, members, notes, multiplicities), state (descriptions, transitions, notes, aliases, composite titles), ER (aliases, relationship labels, attribute cells) and sequence (messages, notes, participants, fragment and box labels, title) all lay labels out through `ctx.inline` and list them in `labels()`; each slot draws its icon from a loader-only pack (so `missing()` saw it). Class relation labels and state single-line notes cannot hold `:` (v12 grammar), so icons there are not possible.
- `currentColor` strokes (open item from #322), plugin only, core unchanged: a label icon that still paints `currentColor` after #322's fill stripping gets the class `mermaid-label-icon`; the extension's new `postRender` sets `color` on it to the fill its label inherits (nearest `style` fill or `fill` attribute above it; none for `none`/`url()`) and drops the class. Labels take their colour from attributes in every type (theme sheets set only variables), so this is the label text colour, in every theme.
- `packages/dev/src/adapter.ts` (the e2e page, gallery and explorer render path; `e2e/platform/viewer.js` is v12's and is not served) registers `@mermaid-js/plugin-icons` and `packages/dev/src/icon-packs.ts`: v12 viewer.js's static packs (`fa` bell, `fluent-emoji`, `aws`, `material-icon-theme`) plus `fal` (`circle-check`, a stroked stand-in drawn here).
- Fixtures: `e2e/diagrams/{flowchart,class-diagram,state-diagram-v2,er-diagram,sequence}/baseline/icons/label-icons-{default,redux,neo,neo-dark}.mmd` (20), each with filled and stroked icons in several slots.

## Tests

`plugin-icons/src/types.spec.ts` (63): every slot of every type draws its icon with no warning and nothing left as written; without the extension each slot gives exactly one `ICON_NOT_RENDERED`; placement in 7 label kinds (box width − text start = 1em × aspect for 1:1 and 2:1, bottom 0.125em below the baseline); stroked icons get the label colour (explicit `color:#f00`, inherited `var(--_nt)`, every label kind in default and neo-dark, allow-listed); text output shows icons as written with one `ASCII_DROPPED` (flowchart, ER, sequence: the types with ASCII); a user class of the marker's name is left alone; fill-only icons are unchanged. `corpus.spec.ts` now compares the tree-backed render with a streamed one (the extension without `postRender`).

Corpus-wide specs that list every fixture gain the 20 (conformance layout crossings, YAML digest, sequence lexer parity count 222 → 226): additions only.

## Sizes

Plugin entry (esbuild --minify, core external, gzip -9): 5,118 → 5,474 B gz. Core unchanged (R-PERF-8 untouched).

## Decisions

- Stroke colour in the plugin via `postRender`, not core's writer: the label's fill is mostly inherited from a group (`<g class="nodes" fill=…>`), which the writer does not track, and core has ~200 B left. Cost: with the extension registered every SVG render writes into the tree backing (byte-identical to the stream by construction).
- The marker is matched only as the element's whole `class`, so a user class of that name (always beside `node …`) is not touched.
- The e2e page draws real glyphs for icon shapes now too (`aws:…`, `fa:bell`), which changes I4's icon-shape baselines.
