# Review fixes on T0 #314 + T0b #316, and R-PERF-8

Branch `fix/314_316_review` (from `feature/295_icons` at 7849828d3). Consumer: I2 #322.

## Size (R-PERF-8, `cdn-build.spec.ts`, budget 90,112 B gz)

90,789 B (90,793 in CI's run) → 89,895 B: 217 B headroom. Before T0 + T0b: 89,225 B. Templating the `FEATURES` messages cost 40 B and was dropped; turning pairs into regexes, one deduper, the closure registry and moving fitting out of core paid for the fixes.

## What changed (each with a spec in `icon-contract.spec.ts` / `icon-packs.spec.ts`)

1. Spans are found by regex, pairs too (`open`, fewest characters, `close`); an empty match steps on by a code point, so `/x*/u` and `/x*/v` over astral text end.
2. Glyph fitting is the provider's: `GlyphProvider.glyph(name, req)` returns an `SvgFragment` already fitted into the `req.size` square (xMidYMid meet, exact: no 0.01 rounding). Core checks the fragment and returns it as given. `Glyph` type removed; the size check is the provider's too.
3. One deduper per render, `InlineSpans.warn`: inline providers, `ctx.icon`'s glyph providers and core's feature warnings share it. A feature's not-rendered code (`ICON_NOT_RENDERED`, `MATH_NOT_RENDERED`) is given once per render by code alone (D291), first message wins; other codes once per code + message. `mermaid` no longer warns about a failed pack: `IconPacks.error(name)` gives the loader's message (untruncated) for I2's warning.
4. `iconPack` resources are the API object's: `HookRunner.resources` never checks them against `provides` and loads them through `request.iconPacks.load` (nothing for an unregistered pack). `renderSync` lists one as missing only while `pending`: unregistered and `failed` packs are unresolved, not missing.
5. A feature span is claimed when a provider span found in the label covers it whole: `sofa:fa-car` with a `\bfa:…` provider and `fa:fa-car2` with `fa:fa-[a-z]+` warn; an icon inside `[[…]]` of another provider does not.
6. Moot: the failed-pack warning left `mermaid`.
7. Registering a name while its loader runs: `load()` then loads the new entry, so `prepare()` never leaves it `pending`.
8. `ResourceRequest.iconPacks` (now required) is `{ names, state, get, error, load }`, no `register`/`failure`. `RenderContext.iconPacks` is the same object typed `IconPacks`.
9. `InlineRequest.iconPacks` and `GlyphRequest.iconPacks` carry the render's packs.

Trims: registry is a closure (`iconPackRegistry(): [source, register]`), unfrozen; one `TypeError` "registerIconPacks() takes [{ name, icons } or { name, loader }]", no Iconify shape check (`get()` returns what the loader gave, `prefix` set: I2 checks `icons`); `guarded()` one message; fragment errors no longer say "in an inline box" (the `failed()` prefix names the hook); `ICON_PACKS_UNSUPPORTED` "registerIconPacks() needs @mermaid-js/plugin-icons registered."

## Decisions

- Fitting moved to the provider (D293 leaves who fits open): smaller core, and the plugin fits in exact numbers.
- An extension can no longer load its own `iconPack` resource (`extensions.spec.ts`'s fixture now uses `math`).
- A provider with a `RegExp` `pattern` is a pattern provider even if it also has `open`/`close` (no longer refused).
- `error(name)` is not cleared by a later successful load; read it while `failed`.
