# #322 I2: `@mermaid-js/plugin-icons` (the extension)

Branch `feature/322_package`; review fixes `fix/322_review`. Consumers: I3 #324 (label fixtures), I4 #326 (flowchart icon shapes), I5 #328 (mindmap), I6 #330.

## Exports

- `icons` (also default), an `ExtensionPlugin`: `claims: ['icons']`, one pattern provider (D296 regex), `glyphs`, `resources` (`provides: []`, `missing` reports `{ kind: 'iconPack', name }` per pack a diagram names that is `pending` or `failed`; SVG only). Types `IconifyJSON`, `IconifyIcon`, `IconifyAlias` (core's). Published (no `private`), manifest `{"plugin":"extension","id":"icons","entry":"./dist/index.js","export":"icons"}`. I1's `getIcon`/`buildIcon`/`convertBody` are internal now.
- Use: `await mermaid.registerExternalDiagrams([icons]); mermaid.registerIconPacks([{ name: 'fa', icons }])`, then `render()`, or `prepare()` before `renderSync`.
- Label icon: box `size·w/h × size`, baseline `0.875·size` (size = label font size), node `<g transform="[translate(…)] scale(s)">`. `currentColor` fills are left off where nothing above them in the icon sets a fill, so they inherit the label's fill (its text colour, as v12's `.label-icon path`).
- Glyph: `iconName(name, fallbackPrefix)` (port of `stringToIcon`: `prefix:name`, `@provider:prefix:name`, `prefix-name`, a simple name only with a fallback), fitted xMidYMid meet into the square, numbers to 1e-6. Keeps `currentColor`: the diagram sets `color` (I4).
- Pending pack at draw: empty 1em box in labels, `undefined` for glyphs (frame only). `missing()` reports every pending pack the diagram names, so the API threw `NotLoadedError` or warned `PLACEHOLDER`.
- `ICON_NOT_RENDERED`: one per render, given in `postRender`, naming each icon the providers could not draw, in the order drawn (up to 8), with why: no pack registered, pack failed (`error()` cut to 60), not Iconify JSON (`get()` checked: object with an `icons` object), no such icon, not a `pack:name`. It ends "Labels show them as written", "Their shapes are drawn without them" or both, by what failed. In flowchart, unresolved shape icons also get the deprecated alias `ICON_UNAVAILABLE` right after it (D299, from #326's wording): flowchart's own alias runs during its render, before this warning exists, so with this extension the plugin gives it; never for placeholders. `ICON_SIMPLIFIED`: one per render, also from `postRender`, naming the simplified icons.
- Core (types only): `DiagramPlugin.icons()` / `ResourceRequest.icons()` return `DiagramIcon[]` = `string | { name, fallbackPrefix? }`, so `missing()` reports packs named only through a fallback.

## Decisions

- Names in `ICON_NOT_RENDERED`/`ICON_SIMPLIFIED` (review fix): the providers note what they meet per render, keyed by the render's warnings sink (`InlineRequest.warn` = `GlyphRequest.warn` = `ctx.inline.warn`); `postRender` warns once through that sink and drops the notes. Linear (a Map and a Set).
- No module state carries `missing()` results to the draw (review fix, D294). Left: caches of pure functions (packs per parse, built icons per pack object, label nodes per built icon) and the per-render notes above. Cost: a pending pack reached through label text a diagram's `labels()` leaves out draws a silent placeholder (every D292 type lists its labels, #324).
- Label colour: `currentColor` fills inherit the label fill; strokes get `color` in `postRender` (#324).
- Glyph names split as v12's `stringToIcon` (dash form, `@provider`, `@:name` with a fallback), not only `prefix:name`.
- `tools/release/licenses.ts`: `@iconify/utils` in `UPSTREAMS` and `REQUIRED_CREDITS` (`plugin-icons/src/{resolve,name}.ts`); the reference implementation's text is not required when every ported file comes from another upstream; a missing notices file names the upstreams found.

## Unmet

None of #322's criteria or review findings. Flowchart still warns `ICON_UNAVAILABLE` beside `ICON_NOT_RENDERED` for an unresolved shape icon (I4, D299 alias).
