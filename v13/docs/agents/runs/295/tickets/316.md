# #316 T0b: pack registry, `iconPack` resources, `preload({ iconPacks })` (D294)

Branch `feature/316_pack-registry`. Consumer: I2 #322 (the icons extension).

## Exports

- `mermaid` (and `mermaid/slim`): `registerIconPacks(packs: IconLoader[])`, real; types `IconLoader`, `AsyncIconLoader` (`loader` may return the pack itself), `SyncIconLoader`, and from core `IconifyJSON`, `IconifyIcon`, `IconifyAlias`, `IconPacks`, `IconPackState`. Registry: `packages/mermaid/src/icon-packs.ts` (`IconPackRegistry`), one per `createMermaid()`.
- Core, additive (`packages/core/src/pipeline/icon-packs.ts`, types only): `IconPacks { names(), state(name): 'ready' | 'pending' | 'failed' | undefined, get(name) }`, `IconPackSource` (+ `load(name)`, never rejects). `ResourceRequest.iconPacks?: IconPackSource`, `RenderContext.iconPacks?: IconPacks` (always set by `mermaid`; hooks see it on `HookContext`). `ExtensionClaim` gains `'icons'`. `HookRunner.resources`: an `iconPack` resource whose pack is registered need not be in `provides`; its need loads through `request.iconPacks.load` (an extension that does provide it still loads it itself, as before).
- `preload({ iconPacks: [names] })` runs those loaders; unknown names are ignored.

## Use (I2)

- `claims: ['icons']` (silences `ICON_PACKS_UNSUPPORTED`). `resources: { provides: [], missing(parse, req) → names from req.labels()/req.icons() whose req.iconPacks.state(n) !== 'ready' and !== undefined, as { kind: 'iconPack', name }, load: unused }`.
- At draw: `get(name)` is the pack with `prefix` = registered name; `state` tells `pending` (placeholders asked for: `PLACEHOLDER` box) from `failed` (as written / frame).
- `mermaid` itself warns once per failed pack per render: `ICON_NOT_RENDERED` "Icon pack "x" failed to load (<reason>): its icons are not drawn." I2 should not warn again for icons of a `failed` pack.
- Core's `IconifyJSON` is assignable to I1's own (`plugin-icons/src/resolve.ts`); I2 can import core's and drop the copy.

## Decisions

- An extension claims `icons` to count as "an icons extension" (D299's condition); no plugin is named in core.
- Host-loaded `iconPack` resources skip `provides` only when the pack is registered; an unregistered one is still the extension's `INTERNAL` error.
- `failed` packs are not missing in `renderSync` (warning, no throw); `prepare()` retries them. `preload` never rejects for a pack (D299 applied to preload) and ignores unknown names.
- `name` overrides `prefix` for `{ name, icons }` too (v12 only re-keyed it). Registering a name again replaces the pack. A loader that resolves to a non-pack fails like a rejection. Validation is `TypeError`, whole call checked first: no name, not exactly one of `icons`/`loader`, `icons` without an `icons` object, a non-array.
