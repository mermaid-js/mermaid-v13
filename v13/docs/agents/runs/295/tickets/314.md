# T0 #314 — icons' core contract (D293)

Branch `feature/314_core-contract`. Consumers: I2 #322 (plugin-icons), I3–I5, mindmap (D286), M5 (architecture, treeView, usecase). DESIGN §5.3, §12.1, §12.2 describe it.

## Exports (all additive)

- `@mermaid-js/core/text`: `InlineProvider` is now `InlinePairProvider | InlinePatternProvider` (both exported). A pattern provider is `{ pattern: RegExp, box(source, req) }`; `source` is the whole match (`fa:fa-car`). Flags are kept except `g`/`y`/`m`; an empty match is no span. Of every provider's next span the earliest start wins, pairs and patterns alike; ties go to the first registered. The box is one unbreakable piece, as for pairs.
- `FEATURES` gains `icon`: D296's `/(fa[bdklrs]?):fa-([\w-]+)/` (no left boundary). A match that no pattern provider matches *whole* gives one `ICON_NOT_RENDERED` per render ("Icons (fa:fa-…) are not rendered without an icons extension…", names no package). Text output: one `ASCII_DROPPED` with `feature: 'icon'` (D299). `InlineSpans.notRendered('icon')` works as for `'math'`.
- `@mermaid-js/core`: `ExtensionPlugin.glyphs?: GlyphProvider` = `{ glyph(name, { size, fallbackPrefix?, warn }) → Glyph | undefined }`, `Glyph = { width, height, node: SvgFragment }` in its own units, top-left at the origin (fold Iconify `left`/`top` in). Types `Glyph`, `GlyphProvider`, `GlyphRequest`, `IconOptions` exported.
- `RenderContext.icon?: (name, size, options?: { fallbackPrefix? }) => SvgFragment | undefined` (a function property, not a method: `unbound-method`). Core asks each extension's `glyph` in registration order, takes the first glyph, checks it (positive finite width/height, allow-listed fragment, else `MermaidError('INTERNAL')` "Extension "<id>" failed in glyphs") and returns `{ tag: 'g', attrs: { transform: 'translate(dx,dy) scale(s,s)' }, children: [node] }` fitted into the `size` square at the origin (xMidYMid meet). The diagram translates it and sets its colour. `warn` dedups code+message per render. A non-positive or non-finite size returns `undefined`. `ctx.icon` is absent when no extension has `glyphs`, and in text output. `HookRunner.icon(warn)` builds it.
- `DiagramPlugin.icons?(model): readonly string[]`: icon names drawn outside labels, as written. `mermaid` passes them as `ResourceRequest.icons?()` next to `labels()`. Flowchart implements it (`flowchartIcons`: every vertex `icon`).
- `@mermaid-js/core/svg`: `writeFragment(w, fragment)` (was private).
- Layout-loader extensions refuse `glyphs`, as they refuse `inline` and `resources`.

## Flowchart

`drawIcon` takes `ctx.icon`. It draws the frame as before, then the glyph in a `<g transform="translate(-size/2, top)">`, and skips `ICON_UNAVAILABLE` when a glyph is drawn. Colour, gradient and the borderless frame are I4's (D298).

## Decisions (not covered by D293)

1. A pattern feature is claimed per match: by a pattern provider whose pattern matches the whole match text, so the icons extension silences core and warns itself about unresolved icons (D291), while a narrower provider leaves core's warning.
2. Core, not the provider, fits glyphs into the square: providers return their own view box, so every consumer gets the same xMidYMid-meet geometry.
3. Glyphs: the first registered extension that has the glyph wins (as "first match wins" for providers).
4. Flowchart draws the fitted glyph now, uncoloured, so "a glyph reaches flowchart" is visible in output. Flowchart's `icons()` lands here, not in I4.
5. Text output's `ASCII_DROPPED` for icons (D299) lands here: it comes from the same `FEATURES` entry.
