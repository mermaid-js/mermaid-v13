# Ticket #861 (X6): small core functions

Branch `feature/861_core-small-functions`. One commit per file, each with its scoped checks green.

## What moved where

- `core/parser-kit/source-view.ts`: `markDroppedSemicolons` keeps the line and word loop; the per-match work is `dropLastSemicolon` + `findHashAfterColon` + `isGone` (the per-match `gone` closure became a top-level function). `cook` keeps the loop; its cases are `isPlainRange`/`isSplit` (fast path), `isQuoted`, `crEnd` (CR/CRLF), `entityEnd` + `entityRef` (`#name;`), `braceBlanks` + `blanksEnd` + `lastNewline` (`}\s*\n`). `braceBlanks` returns one int: the index to continue at, `NO_BRACE_CASE` (-1) to copy the character, or `-2 - k` to emit a newline and continue at `k`. No tuples or objects per character.
- `core/text/label.ts`: `inline` keeps its closures and locals. Its three markup decisions moved out as pure helpers: `tagAt` (HTML tag match), `emphasisAt` (length of an opening or closing `*`/`_` mark, 0 for plain text) and `escapedAt`/`codeEnd` were tried and dropped; only `tagAt` and `emphasisAt` stay. A first version with a per-line `Scan` record and one function per markup kind cost +200 B of core gz, so it was replaced.
- `core/layout/validate.ts`: `validateLayout` is a driver over a `Check` record: `checkDrawingSize`, `checkBoxes` (`place`), `checkNesting` (`checkMembers`, `checkOverlaps`), then per edge `checkEdgeShape`, `checkEdgeEnds` (`meets`), `checkEdgeLabels` (`checkLabel`), then `checkLabelClashes`. Same order of findings.
