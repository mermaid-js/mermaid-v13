# Ticket 859 (X4): createMermaid split

Branch `feature/859_create-mermaid-split`. Only `packages/mermaid/src` and `eslint-suppressions.json` changed.

## What moved where

`createMermaid` (api.ts, was 778 lines) is now the wiring, plus `blocksOf` and `createSession`.

| File | Holds |
| --- | --- |
| `analyser.ts` | `Analyser`: detect, site config layers, parse, the analysis cache. `invalidate()` is the only place the cache is cleared from |
| `draw-context.ts` | `contextFor` split into `applyMissingPolicy`, `chooseLayout` (+ `warnLayout`), `layoutCall` and the literal; `missingFor`, `loadFor`, `themeFor` |
| `draw.ts` | `draw`, `drawWith`, `drawSvg`, `drawAscii`, `analysisFor` |
| `prepare.ts` | `prepareWith`, `parseText`, `preload`, `loadText`, `checkFormat` |
| `session.ts` | `Session` (the pieces of state), `rebuildHooks`, `hooksFor` |

The four `cache.clear()` sites and the `seam.ts` callback now call `analyser.invalidate()`. `block-pass` and `ascii` are still dynamic imports (`embeds.ts`, `prepare.ts`); `core-chunks.spec.ts` and `cdn-build.spec.ts` pass.

## Suppressions

`max-lines-per-function` for api.ts: 1 to 0. Total entries: -1. The `explicit-module-boundary-types` entry for api.ts stays. No entry or disable comment added.

Every cross-function call now passes the session, and that costs bytes in the entry file. This spec is the tight one.
