# Ticket 565: usecase T3, layout

**Exports** (`@mermaid-js/diagram-usecase`, `.`): `layoutUsecase(model, ctx)` → `UsecaseLayout` (core's `LayoutModel` plus `usecase: UsecasePrepared`); `prepareUsecase(model, ctx)`; `relationText(r)` (`«include»`, `«extend»`, an association's label); `usecaseLayoutConfig(section, warn)` and `USECASE_CONFIG_DEFAULTS` (`src/config.ts`, v12's schema defaults, no manifest yet); the code `USECASE_CONFIG_IGNORED`; view types `ActorView`, `UseCaseView`, `NoteView`, `JsonTableView` (+`JsonRowView`), `BoundaryView`, `UsecaseEdgeView`, `UsecaseNodeView`, `UsecasePrepared`. `./testing` adds `usecaseLayoutProblems(layout)`.
- **Context** (`UsecaseLayoutContext`): `config`, `measurer`, `theme`, `warn`, optional `layout` and `inline`; the pipeline's `RenderContext` fits. T5's plugin: `layout: (m, ctx) => layoutUsecase(m, ctx)`, no `layoutEngine` (core gives `layered`, `dagre` → `layered`, `ELK_NOT_INSTALLED`, `compass` by name).
- **Ids:** layout ids are AST ids (`actor:A`, `usecase:B`, `note:1`, `json:P`, groups `boundary:S`, edges `rel:…`); a note's edge is `<note id>-edge`. Graph order: actors, use cases, notes, JSON tables; relations, then note edges.

**How it lays out** (`src/layout/`): `prepare.ts` measures each label in its own font (actors in `actorFont*`, use cases in `usecaseFont*`, families from the theme unless set; notes, tables, titles in the theme font; edge labels 10px) with the element's checked style (`classDef default`, its classes, its `style`), then sizes as v12's shapes: actor = glyph 56×72 + 8 + stereotype (+2) + name, padded 10, no least width; oval = label block (≥ `minNodeWidth`) + 20 each side, a stereotype folded over the label (business: 2px gap); `[rect]` = block + node padding 16×12; note = label (≥ `minNodeWidth`) + 10; JSON = title row (≥ `minNodeWidth`) and key/value rows, cells 8×4, border 1. Boundaries are groups padded 20 with the title (a package's tab: title + 10 high, + 20 and ≥ 80 wide). `minLen` = `minlen`; spacing `nodeSpacing`/`rankSpacing`; margin `diagramPadding`. Ovals set `span` to half their side so ends stay near the oval. `layout.ts`: `(ctx.layout ?? layered)(graph)`, then `clip.ts` moves each end on an oval along its last segment onto the oval. `metrics.ts` is the one px table; core's px profile gives label patch, head room, edge wrap and edge spacing.

**Tests:** `src/layout/layout.spec.ts` (17: sizes, fonts, boundaries, tabs, note edges, minLen, labels, config and its warnings, ends on ovals). Conformance: `usecase/layout.spec.ts` (every accepted source of the e2e corpus, harvested v12 strings and cases: 195 sources, with its own config and theme, through `layered`, ELK and `compass`), `usecase/layout-engine.spec.ts` (a test plugin over the `usecase` id through `createMermaid().render()`: default = `layered`, `dagre` = `layered`, `elk` without the plugin = `layered` + one `ELK_NOT_INSTALLED`, ELK installed, `compass`), `usecase-layout-literals.spec.ts` (pitfall 13). Invariants (`usecaseLayoutProblems`): core's `validateLayout` (no NaN, inside the drawing, no overlaps, containment, ends at own boxes, labels clear), graph nodes equal their views, model members inside their boundary and every other node outside, every edge routed, each end on the drawn outline (oval or box, 0.5px), notes beside their target (no node between). Mutants checked: no clipping, no note edges, no `parent`: each fails a spec.

**Size:** `.` 67.1 KB min, **22.0 KB gz** (core external; T2 was 18.3). `./testing` 6.1 KB gz. Core and the mermaid registry untouched: core size not affected (not measured).

**Decisions (no D-id):** `USECASE_CONFIG_IGNORED` for config values the layout cannot use (pitfall 22); families inherit `fontFamily` unless set (D132), so T5 leaves both family defaults out; JSON cells and boundary titles wrap at 200 (v12's defaults); an actor stereotype in the actor font; notes outside boundaries (v12); "beside" = no node between (GAPS). `compass` misses one corpus note (rigid groups, D326; listed exactly). No visible rendering change beyond v12's sizes, so no D-id needed; the ELK → `layered` default is R-LAYOUT-7's (T5 MIGRATION row).
