# Ticket 565: usecase T3, layout

**Exports** (`@mermaid-js/diagram-usecase`, `.`): `layoutUsecase(model, ctx)` → `UsecaseLayout` (core's `LayoutModel` plus `usecase: UsecasePrepared`); `prepareUsecase(model, ctx)`; `relationText(r)` (`«include»`, `«extend»`, an association's label); `isOval(view)`; `usecaseLayoutConfig(section, warn)`, `USECASE_CONFIG_DEFAULTS` and `fontWeight(v)` (`src/config.ts`, v12's schema defaults, no manifest yet); the codes `USECASE_CONFIG_IGNORED` and `USECASE_STYLE_IGNORED`; view types `ActorView`, `UseCaseView`, `NoteView`, `JsonTableView` (+`JsonRowView`), `BoundaryView`, `UsecaseEdgeView` = `RelationEdgeView | NoteEdgeView` (by `kind`), `UsecaseNodeView`, `UsecasePrepared` (with `layoutIds`: model id → layout id). Every node, boundary and relation view carries `font`, the font its labels were measured in (style applied): T4 draws in it. `./testing` adds `usecaseLayoutProblems(layout)`.
- **Context** (`UsecaseLayoutContext`): `config`, `measurer`, `theme`, `warn`, optional `layout` and `inline`; the pipeline's `RenderContext` fits. T5's plugin: `layout: (m, ctx) => layoutUsecase(m, ctx)`, no `layoutEngine` (core gives `layered`, `dagre` → `layered`, `ELK_NOT_INSTALLED`, `compass` by name).
- **Ids:** layout ids are AST ids (`actor:A`, `usecase:B`, `note:1`, `json:P`, groups `boundary:S`, edges `rel:…`); a note's edge is `<note id>-edge`. Graph order: actors, use cases, notes, JSON tables; relations, then note edges.

**How it lays out** (`src/layout/`): `prepare.ts` measures each label in its own font (actors in `actorFont*`, use cases in `usecaseFont*`, families from the theme unless set; notes, tables, titles in the theme font; edge labels 10px) with the element's checked style (`classDef default`, its classes, its `style`; a `font-size` it cannot measure warns `USECASE_STYLE_IGNORED` once per value), then sizes as v12's shapes: actor = glyph 56×72 + 8 + stereotype (+2) + name, padded 10, no least width; oval = label block (≥ `minNodeWidth`) + 20 each side, a stereotype folded over the label (business: 2px gap); `[rect]` = block + node padding 16×12; note = label (≥ `minNodeWidth`) + 10; JSON = title row (≥ `minNodeWidth`) and key/value rows, cells 8×4, border 1. Boundaries are groups padded 20 with the title (a package's tab: title + 10 high, + 20 and ≥ 80 wide). `minLen` = `minlen`; spacing `nodeSpacing`/`rankSpacing`; margin `diagramPadding`. Ovals set `span` to half their side so ends stay near the oval. `layout.ts`: `(ctx.layout ?? layered)(graph)`, then `clip.ts` moves each end on an oval along its last segment onto the oval (trailing copies of the end count once; an end already on the oval is kept; a flat oval or a route wholly inside is left as drawn; a line that misses steps toward the centre). Axes follow `RoutePoint.axis` (runs into): a target hit takes the axis of the point it replaces, a source hit the leg it leaves by. `metrics.ts` is the one px table; core's px profile gives label patch, head room, edge wrap and edge spacing.

**Tests:** `src/layout/layout.spec.ts` (19: sizes, fonts, styled fonts and their warning, boundaries, tabs, note edges, minLen, labels, config and its warnings, ends on ovals); `src/layout/clip.spec.ts` (7: target and source ends, source points inside the oval, a missed line, a zero-length last segment, an end on the oval, flat ovals, a route inside). Conformance: `usecase/layout.spec.ts` (every accepted source of the e2e corpus, harvested v12 strings and cases: 195 sources, with its own config and theme, through `layered`, ELK and `compass`), `usecase/layout-engine.spec.ts` (a test plugin over the `usecase` id through `createMermaid().render()`: default = `layered`, `dagre` = `layered`, `elk` without the plugin = `layered` + one `ELK_NOT_INSTALLED`, ELK installed, `compass`), `usecase-layout-literals.spec.ts` (pitfall 13). Invariants (`usecaseLayoutProblems`): core's `validateLayout` (no NaN, inside the drawing, no overlaps, containment, ends at own boxes, labels clear), graph nodes equal their views, model members inside their boundary and every other node outside, every edge routed, each end on the drawn outline (oval or box, 0.5px), notes beside their target (the next rank over: no node wholly in the gap along the flow, none on the centre line). Mutants checked: no clipping, no note edges, no `parent`, note edges three ranks long: each fails a spec. `compass` misses five notes on boundary members (rigid groups, D326), listed exactly.

**Size:** `.` 68.4 KB min, **22.5 KB gz** (core external; T2 was 18.3). `./testing` 6.3 KB gz. Core and the mermaid registry untouched: core size not affected (not measured).

**Decisions (no D-id):** `USECASE_CONFIG_IGNORED` and `USECASE_STYLE_IGNORED` (pitfall 22); config lengths as numbers or numeric strings below 10000 (v12's schema has neither); include/extend labels measured as text (v12 forced it); families inherit `fontFamily` unless set (D132), so T5 leaves both family defaults out; JSON cells and boundary titles wrap at 200 (v12's defaults); an actor stereotype in the actor font; notes outside boundaries (v12); "beside" = no node between (GAPS). `compass`'s sides from `direction` are the architecture spec's proof (D327), not this ticket's; no layout stress spec (class and ER have none). No visible rendering change beyond v12's sizes, so no D-id needed; the ELK → `layered` default is R-LAYOUT-7's (T5 MIGRATION row).

**Unmet:** "`pnpm check` green": scoped checks only, per the brief (no core, shared conformance code, tool or other package changed).
