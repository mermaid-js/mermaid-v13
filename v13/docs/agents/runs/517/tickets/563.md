# Ticket 563: usecase T2, grammar, parser, model, AST

**Exports** (`@mermaid-js/diagram-usecase`, `.`): `parseUsecase(text, { preprocessed?, keepTokens? })` → `ParseResult<UsecaseModel, UsecaseDocument>` (never throws); `detectUsecase(text)`; the `USECASE_*` codes and `MODEL_CODES` (`src/codes.ts`); the model types (`src/model.ts`) and AST types (`src/parser/ast.ts`). `./testing` as T1 left it.
- **Model** (`UsecaseModel`, frozen): `actors`, `useCases`, `boundaries` (with `members`), `relationships` (`arrowType` as names: `point`, `reversedPoint`, `line`, `circle`, `cross`, `reversedCircle`, `reversedCross`; `minlen`), `notes` (`note-<n>`), `jsonTables` (`value`, `propertyOrder`, and `rows`, v12's `flattenJsonRows`), `classDefs`, `direction` (`TD` as `TB`), `accTitle`, `accDescr`, `title` (front matter, D472), `warnings`. Order is v12's: elements and boundaries by first mention, relations and notes by statement. Every element has `astId`. Text is shown as v12 drew it (`#amp;` as `&`, core's entity table); ids and JSON values are as v12's lexer read them.
- **AST ids** (D475): `actor:A`, `usecase:A`, `boundary:S`, `json:P`, then `@2`… per mention, by the kind the id resolves to; `rel:e1` or `rel:A->B` (`@2`); `note:<n>`; `metadata:1`, `classDef:1`, `class:1`, `style:1`, `direction:1`, `accTitle:1`, `accDescr:1`. Relations and boundaries have `Element` children. **Statements**: one span per statement, a boundary's members as children. **Symbols** (D477): first mention defines; a quoted element's symbol is its label (GAPS).
- **Errors** (D473): model checks are diagnostics with v12's message minus the location (a conflict's earlier declaration is `related`); syntax, lexer and JSON errors are v13's own (`Expected …, got …`), starting where v12 reported (its LL(3) statement choice reports at the statement's start). N errors give N diagnostics; recovery skips to the line end, inside `@{ … }` to its `}`, after an unclosed `accDescr {` to a keyword line; a failed boundary header still opens its block.

**How it parses:** `reader.ts` (token arrays, errors, recovery), `items.ts` (names, suffixes, metadata, arrows), `parser.ts` (statements), `build.ts` (v12's model builder over `drafts.ts`), `assemble.ts` (ids, model, symbols), `json.ts`, `tables.ts` (v12's LL(3) decisions: the second and third token of a named statement, `@{ … }` separators). `--` labels are found with one scan per label run.
