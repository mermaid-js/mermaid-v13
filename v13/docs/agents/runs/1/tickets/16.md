# Ticket 16: DOM adapter (branch feature/16_m1, worktree .claude/worktrees/t16)
**`mermaid`** (`packages/mermaid/src/dom.ts`, wired in `api.ts` `createMermaid()`, exported from index): `run`, `mount`, `contentLoaded`; types `RunOptions` (= v12's, type-tested), `MountOptions {id?, config?, placeholders?, availableWidth?: boolean | number}`, `Mounted {element, result, error, ready, update(text), destroy()}`. Helpers `entityDecode`, `dedent`, `elementText` (v12 text cleaning) live in dom.ts (not exported from index).
- `run(opts)`: v12 semantics: `querySelector` default `.mermaid`, `nodes`, `data-processed`, ids `mermaid-<n>` (per API object counter; `deterministicIds` restarts at `deterministicIDSeed.length` each run), entity-decode + dedent + `<br>` normalise. Failure → `renderErrorSvg` in the element unless `suppressErrorRendering` (site config), `setParseErrorHandler` called per failure, carries on, rejects with the first `MermaidError` at the end unless `suppressErrors`. Skips elements inside a drawn `<svg>` (v13 svg root has class `mermaid`, so a 2nd run would otherwise re-render the svg itself).
- After inserting the svg: `postRenderCallback(id)`, then `result.bindFunctions?.(el)` exactly once (= extension afterMount, #22). mount calls it once per DOM replacement.
- `mount(el, text, o)`: renders via prepare+renderSync with one options object (one parse). `availableWidth: true` → element content width + ResizeObserver re-render when the rounded width changes; number → fixed; absent → no observer at all. `document.fonts` `loadingdone` → re-render; the DOM is replaced only when the svg string changed. No theme listener (CSS vars re-theme). Renders are serialised; requests during a render collapse. Error → error image (unless suppressErrorRendering in `o.config` or site), `ready` rejects (handled internally, so no unhandled rejection), `.error` set.
- Host `--mermaid-fontFamily` on the element (getComputedStyle) is passed as per-call `themeVariables.fontFamily`, so canvas measures what the svg draws (#9 gap). Known gap: front-matter `themeVariables.fontFamily` still wins for measuring while the host var wins for drawing.
- `startOnLoad`: index.ts adds `window.load → mermaid.contentLoaded` (runs `run({suppressErrors:true})` unless `startOnLoad: false`).
**api.ts:** `RenderOptions.availableWidth` → given to the layout engine when the graph has none (R-LAYOUT-5). Per-call `config` object identity → same snapshot (WeakMap), so prepare+renderSync with the same options hit the parse cache.
**measurer.ts fix:** while `document.fonts.check` is false the canvas `ctx.font` is re-set on next use (WebKit kept the fallback face otherwise; late-font spec failed without it).
**Schema:** `theme` top-level enum gains `auto` (only top-level; per-diagram `theme` enums unchanged so v12's types still accept v13's `parse()`); `ParseResult.config.theme` keeps v12's union (an `auto` from text still comes back as `'auto'`). Honoured: startOnLoad, suppressErrorRendering, deterministicIds, deterministicIDSeed. MIGRATION.md API table and error-image section updated.
