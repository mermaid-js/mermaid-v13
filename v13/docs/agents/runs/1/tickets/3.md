# Ticket 3: bench package (branch feature/3_m1)
**Run.** `pnpm --filter @mermaid-js/bench bench [--renderers v13,v13-stages,v12-frozen,v12-current] [--set corpus,pele] [--filter id] [--tiers ..] [--reps 10] [--budget 1000] [--timeout 30] [--mode auto|report|enforce] [--update-baseline] [--headed]`. Needs `playwright install chromium`. Full run is about 5–8 min locally (v12 dominates); `--renderers v13,v13-stages --set pele` takes seconds. Writes `packages/bench/dist/reports/<stamp>.{json,md}` and `latest.*`, and appends to `$GITHUB_STEP_SUMMARY`. `pnpm --filter @mermaid-js/bench gates [report.json]` re-applies gates to a saved report.
**Pipeline stage timing (for the pipeline ticket, #14/#15).** `@mermaid-js/core/timing` (new core subpath) exports `stageStart(): number`, `stageEnd(stage, t0)`, `installStageClock(clock)`, `STAGE_TIMING`, types `Stage = 'parse'|'measure'|'layout'|'serialise'`, `StageClock`. Bracket each stage in the core pipeline:
`const t = stageStart(); const ast = plugin.parse(body, ctx); stageEnd('parse', t);` (same for measure, layout, serialise). Do not wrap in closures. Production bundles define `__MERMAID_BENCH__=false` (use `benchDefine(false)` from bench `build.ts` or the same esbuild define), and the minifier removes everything. In unbundled code the flag is undefined, so timing is off and no clock can be installed. Core reads no timers: the bench runner injects `performance.now`.
**What `mermaid` must export for the harness.** `render(id, text)` resolving to `{ svg }` (or `default.render`). `initialize(cfg)` is called with `{ maxTextSize: 1e7, maxEdges: 1e6 }` when present. "Pipeline present" means `render('bench-probe', 'flowchart LR\n  A --> B\n')` in Node (tsx, `mermaid-source` condition) gives a string containing `<svg`. Until then, every gate reports and the job exits 0.
**Renderers.** `v13` is the production bundle of `packages/mermaid/src/index.ts` (esbuild, ESM, splitting, minified). Its warm time drives R-PERF-3 and its fetched files drive R-PERF-1; when it can't start, the size falls back to the static import closure. `v13-stages` is the bench build of `src/runner/v13-stages-entry.ts` (mermaid plus the clock) and provides the stage columns. `v12-frozen` is `mermaid-v12-frozen` (`npm:mermaid@12.2.0`) with `layout: 'dagre'`. `v12-current` is `mermaid-v12` (`^12.2.0`) with its default layout, information only. Every renderer gets its own Playwright context. Pages are served COOP/COEP (5 µs timers). "Ready at" is taken on a warm-cache reload. Look/ELK settings are stripped from inputs (`--strip false` turns that off).
**Gates (`src/gates.ts`, `LIMITS`).** size ≤ 80×1024 gz bytes. Speed: geomean of v12-frozen/v13 warm medians over the common set ≥ 50. ok-count: v13 OK on the 158 corpus diagrams (the Pele sequence/class fixtures are excluded). Stage regression: per stage, the geomean of current/baseline over diagrams ≤ 1.10. It is enforced only when `baselines/<runner>.json` exists, where runner = `BENCH_RUNNER` or `local-<platform>-<arch>`. ready-at ≤ 15 ms is never enforced. `BENCH_GATES` / `--mode` override auto.
**Exports (`@mermaid-js/bench`).** `loadFixtures()`, `evaluateGates`, `resolveMode`, `speedup`, `stageRatios`, `LIMITS`, `formatMarkdown`, `bundle`, `benchDefine`, `detectPipeline`, `baselineFrom`, `STAGES`, plus the report types.
**CI.** `.github/workflows/ci.yml` job `bench` with `BENCH_RUNNER=github-ubuntu-latest` and the report as an artifact.
**Known gaps.**
- No baseline is committed, because there is no pipeline yet and O-4 is open. Once render works, run `--update-baseline` on the reference runner and commit `packages/bench/baselines/<runner>.json`.
- Consider flipping the default mode from auto to enforce once the pipeline lands, so a broken probe can't silently drop back to report mode.
- The approaches comparison UI and the Pele/ondine/merman adapters were not ported. Only the timing loop, adapters, normalise, sizes and report were.
- R-PERF-7 enforcement is meaningless on GitHub-hosted runners (±20%) until O-4 picks a reference runner.
