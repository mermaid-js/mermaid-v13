# Ticket 4: conformance oracle (branch feature/4_m1 @ 2cee60977)
**Module** `@mermaid-js/conformance` (private, no `exports` map; import `packages/conformance/src/index.ts` relatively from inside the package).
- `DiagramAdapter<M>` = `{ id, v12Types: string[], detect(text), parse(text): M /* throw = reject */, normaliseV13(m), normaliseV12(db) }`. Both normalisers return the same plain-data shape; the runner deep-compares.
- `runParity({ adapters, corpus, divergences?, oracle?, onResult? })` → `ParityReport { results, unlisted, disappeared, expected, ok }`. Adapter is chosen by the oracle's `diagram.type` (or by `detect` when v12 rejects). Items no adapter claims are `skipped`. Model diffs report up to 5 paths (`vertices[2].text`).
- Kinds: `accept` = v13 accepts what v12 rejects; `reject` = v13 rejects what v12 accepts; `model` = both accept, models differ.
- `loadOracle()` → `{ version, parse(text) }` (mermaid-v12 12.2.0). No DOM: it patches **v12's own** DOMPurify instance (sibling dir in .pnpm) to identity, so no vitest alias or loader hook is needed. It also works under tsx. It calls `mermaidAPI.reset()` before every input. `db` is only valid until the next parse (some v12 DBs are singletons); runParity normalises v12 before calling v13.
- `divergences.json` at `packages/conformance/divergences.json` (currently `[]`). Matching key = `(id, kind, inputHash)`, with `inputHash(source)` = `sha256:<16 hex>`. A changed source makes its entry stale, so it fails as both unlisted and disappeared. Entries for ids outside the current run are ignored. `parseDivergences` rejects empty fields, unknown kinds and duplicate (id, kind).
- Corpus: `resolveCorpus(env, suites)`. The default is each suite's `corpusDirs` (relative to repo root, ids = repo-relative path). With `PARSE_FIXTURE_PATH` it reads every `.mmd` under that dir, with ids `external/<rel>`. `corpusFromDir(dir, prefix)`, `REPO_ROOT`.
- **Registry: `src/registry.ts` `PARITY_SUITES: ParitySuite[]` (empty).** #8 adds `{ adapter: flowchartAdapter, corpusDirs: ['e2e/diagrams/flowchart'] }`. `src/parity.spec.ts` is the suite and runs in `pnpm test`.
- Flowchart v12 side (`src/flowchart/v12.ts`): `flowchartV12Snapshot(db): FlowSnapshot`, `FLOWCHART_V12_TYPES` (`flowchart-v2`, `flowchart`, `flowchart-elk`), `decodeEntities`. Shape: `{ direction, accTitle, accDescr, vertices[] (insertion order, NOT sorted), edges[], classes[], subGraphs[] (nodes sorted), tooltips: [id, tip][] }`, with vertex/edge fields exactly as the Chevrotain `snapshotVertex`/`snapshotEdge`. #8 writes `normaliseV13: FlowModel → FlowSnapshot`.
  - v12 facts the snapshot exposes: `click` adds class `clickable` and the URL is normalised (`https://example.com` → `https://example.com/`); edge `style` is `undefined` without linkStyle; quoted label → `labelType: 'string'`; auto edge id `L_A_B_0`; `classDef … color:` also lands in `textStyles`.
  - Leaves out: callbacks/`funs`, `haveCallback`, domId, subgraph labelType, `defaultInterpolate`/`defaultStyle`, diagram title. #8 can extend the shape (edit v12.ts + its spec).
- Oracle check over e2e/diagrams/flowchart: all 400 accepted as flowchart, ~0.7 s total.
