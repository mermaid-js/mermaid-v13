# Ticket 13: core/theme (branch feature/13_m1, worktree .claude/worktrees/t13)
**Import** from `@mermaid-js/core/theme` (source `packages/core/src/theme/`).
**Theme names** (`registry.ts`): `resolveThemeName(config.theme, warn)` returns `{ name, dark? }`. `THEME_NAMES` = redux, default, dark, forest, neutral, base. `DEFAULT_THEME` = 'redux'.
- `loadTheme(name)` is async (lazy `import()` per spec). `loadedTheme(name)` is sync and works after a load; redux is always loaded. #15: add the theme to the `prepare` resource set.
- **Default decision (D55):** #7 keeps `flowchart.theme: redux-color`, and that wins over the top-level `redux` in the defaults layer, so `config.theme === 'redux-color'` for a flowchart with no user theme. `resolveThemeName` maps `redux-color` to `redux` **without a warning**. Other unshipped v12 names stand in with `THEME_UNAVAILABLE`: redux-dark, redux-dark-color and neo-dark go to dark, neo goes to redux, 'null' goes to base, and unknown names go to redux. `'auto'` gives `{ name: 'redux', dark: 'dark' }`. This is tested in `themes.spec.ts` against `resolveConfig`. The schema has `theme`/`themeVariables` flipped to honoured.
**Per-render theme:** `createTheme(spec, { themeVariables, cssVariables, rules, dark, warn })` returns a `Theme`. It records which variables are used, so make one per render and put it on `ctx.theme`.
- `color(name)` returns a `Paint`: `var(--_x)`, or a literal when `cssVariables: false`. `length(name)` returns a `Length`. `number(name)` returns a number for geometry and measuring (radius, fontSize, strokeWidth). `font()` gives the family. `value(name)`/`rgba(name)` give literals.
- `ink(fill)` (R-THEME-12) returns undefined when the theme's nodeTextColor reads on the author's fill, otherwise `#000000`/`#ffffff`. #14 calls it for classDef/style fills and uses the result as the label `fill`.
- `rootStyle()` returns the `{ '--_x': 'var(--mermaid-name,fallback)' }` aliases used so far, plus their deps. **Call it after the body is rendered.** The root `<svg>` is opened first, so #14 has to render the body into its own writer (or otherwise defer the root `style`), then pass `styleText({ 'max-width': …, ...theme.rootStyle() })`.
- Auto: pass `dark: await loadTheme('dark')`. Colour aliases then leave `rootStyle()`, and `autoDeclarations()` returns `{light, dark}`. Write them with `w.styleSheet(themeStyleSheet(prefix, light, dark))` as the first child of the root, put `'data-p': prefix` on the root, and run `assertInert(svg, { themeStyle: true })` in that mode only.
- Unknown variable names throw TypeError. A plugin's extra colour vars come in through `rules: { pie1: 'lighten(primaryColor, 20%)' }`; the alias is `--_pie1`.
- themeVariables are checked by kind: colours by `checkColor`, lengths `^\d+(px)?$`, fonts by the font-family check, weights. A bad value is dropped with `THEME_VARIABLE_DROPPED`. Names outside the inventory are ignored silently (R-CONF-5). `darkMode: true` switches to the dark rules (v12).
**Inventory:** `THEME_VARIABLES` (name → alias, kind, usedBy), `BASE_VARIABLES` (8), `TOKEN_VARIABLES` (strokeWidth, clusterStrokeWidth, radius, fontWeight, spacing1-3). `pnpm gen:theme` writes `v13/docs/theme-variables.md`, and `tools/gen-config/src/theme-inventory.spec.ts` fails when it is stale. **When #14 reads a new variable, add it in `vocabulary.ts` and run `pnpm gen:theme`.**
**DSL** (`dsl.ts`): `mix(a,b,15%)`, `lighten`, `darken`, `alpha(a,80%)`, `contrast(bg,a,b)`, `invert(a)`. contrast and invert are evaluated in JS when the theme is built. Shared rules are `LIGHT_RULES`/`DARK_RULES` in `spec.ts`.
**Colour utilities:** `parseColor`, `mixColors`, `contrastRatio`, `luminance`, `composite`, `formatColor`, `invertColor`.
**svg changes (#12 files):** `data-p` attr; `ThemeStyleSheet` brand plus `themeStyleSheet()`; `SvgWriter.styleSheet()` (root child only, both backings byte-identical); `InertOptions.themeStyle`; `styleSheetProblem`. Without `themeStyle`, `<style>` is still rejected.
**Gaps:**
- Browser tests (re-theming via `--mermaid-primaryColor`, emulated colour scheme) wait for #18's Playwright.
- That the JS fallback equals browser `color-mix` numerically is not checked in a browser.
- contrast/invert results are fixed at render time, so host re-theming of a base var does not flip ink. Tokens used in geometry (radius) are literals and can't be re-themed live.
- **Size:** svg+theme is about 14.0 KB gz against the 8 KB budget line (svg alone is 8.3 KB). The theme adds about 5.8 KB, of which the named-colour table is 1.2 KB; specs are 0.3–0.4 KB each.
- Colour resemblance to v12 is not reviewed by hand yet (D71). Reference values were dumped from the v12 theme files with khroma. Specs use v12 values where they meet AA; dark `edgeLabelBackground` is #555 (v12 #585858 fails AA) and dark `noteTextColor` is derived.
- No handDrawn/neo look tokens, gradients or drop shadows. The v12 numbered palettes (cScale, pie, git) are not in the inventory.
