# Ticket 7: config (branch feature/7_m1)
**Schema.** `packages/core/schema/config.schema.yaml` (v12 copy). Every key under any `properties:` has `x-mermaid: { status, since?, movedTo?, replacement?, reason? }`. Removed keys stay in the file (status `removed`) so they can warn; they are left out of types and defaults. Removed: `htmlLabels`, `flowchart.htmlLabels`, `class.htmlLabels`, `dompurifyConfig`. Ignored: `themeCSS`, `logLevel`, `altFontFamily`, every `arrowMarkerAbsolute`. `secure` is honoured. Everything else is `pending`: **flip it to `honoured` (with `since: 13.0.0`) when your ticket implements the key**, then run `pnpm gen:config`. v12 had no click-callback keys in the schema, so nothing is `moved` yet.
**Changed defaults.** `theme: redux` (D55); `layout: layered` (DESIGN §6.1 built-in engine). `layout` is a free string, so v12's `dagre`/`elk` stay accepted without warning and pass through resolveConfig unchanged; **#15's registry must map `dagre` and `elk` to `layered` until an ELK plugin exists** (annotated in the schema's `x-mermaid.reason`). For #13: `flowchart.theme` still defaults to `redux-color` and `flowchart.look` to `neo` (v12 values), so with the diagram-scoped appearance rule a flowchart with no user theme resolves `theme: 'redux-color'`; #13 should decide.
**Generator.** `pnpm gen:config` writes, `pnpm check:config` fails on stale output or a bad annotation (part of `pnpm check` and CI). Code: `tools/gen-config/src/{schema,generate,cli}.ts`. Outputs (committed; `.gitignore` un-ignores these two `generated/` dirs; prettier and eslint skip them):
- `packages/core/src/config/generated/config.type.ts` (`MermaidConfig`, `FlowchartDiagramConfig`, …, from json-schema-to-typescript)
- `…/generated/defaults.ts` (`CORE_DEFAULTS`, top level only), `…/generated/keys.ts` (`KEY_TREE`, `KEY_NOTES`)
- `packages/diagram-flowchart/src/generated/config-defaults.ts` (`flowchartConfigDefaults`). Add a section owner in `SECTION_OWNERS` (generate.ts) when a diagram package lands.
- `v13/docs/config-reference.md` and the config section of `v13/docs/MIGRATION.md`, between the `BEGIN/END GENERATED CONFIG SECTION` markers. #19 writes the rest of MIGRATION.md around the markers.
**API (`@mermaid-js/core/config`).**
- `resolveConfig(defaults, initialize?, frontMatter?, directives?: ConfigInput[], pluginDefaults?, { warn?, section? })` returns `ResolvedConfig` (DeepReadonly, deep-frozen).
  - Pass `CORE_DEFAULTS` and `{ flowchart: flowchartConfigDefaults }`.
  - `frontMatter` is the already-parsed `config` object. `directives` are the parsed init objects in source order. `section` defaults to the single key of `pluginDefaults`.
- Order: defaults, then pluginDefaults, initialize, frontMatter, directives. Arrays merge as a union (v12), and null/undefined never override.
- Warnings go to `warn(w: ConfigWarning { code, message, path, source })`. Codes: `CONFIG_UNKNOWN_KEY`, `CONFIG_REMOVED_KEY`, `CONFIG_MOVED_KEY`, `CONFIG_SECURE_KEY`, `CONFIG_UNSAFE_VALUE`. They never throw. Map them into `RenderResult.warnings` in #15.
- Diagram text loses: secure keys (`INTEGRATOR_ONLY_KEYS` plus the merged `secure` list), unknown keys, removed keys, and v12-unsafe values (`<`, `>`, `url(data:`, theme variables outside v12's charset, which become `''`, and unbalanced CSS in font keys).
  - `initialize` keeps unknown keys and still gets a warning.
  - Prototype keys are skipped from every source.
  - `fontFamily` from text is copied to `themeVariables.fontFamily`.
- Exports: `CORE_DEFAULTS` (frozen), `INTEGRATOR_ONLY_KEYS`, and the types `ConfigInput`, `ConfigSource`, `ConfigWarning(Code)`, `DeepReadonly`, `ResolveConfigOptions`, `ResolvedConfig`, `KeyTree`, `KeyNote`, plus every generated config type.
**Tests.** `packages/core/src/config/resolveConfig.spec.ts` (precedence mirroring v12 config.spec, secure, unknown/removed, R-CONF-5, sanitising, freeze, CORE_DEFAULTS vs a v12.2.0 literal), `packages/diagram-flowchart/src/config-defaults.spec.ts`, `tools/gen-config/src/generate.spec.ts` (staleness, annotation errors, splitting, splice).
**Known gaps.**

- v12's sankey/treeView dictionary value patterns are not ported.
