# Ticket 11: layered layout (branch feature/11_m1)
**Exports from `@mermaid-js/core/layout`** (`packages/core/src/layout/index.ts`):
- Types (`types.ts`): `LayoutGraph`, `LayoutNode`, `LayoutEdge`, `LayoutGroup`, `LayoutSpacing`, `LayoutModel`, `LayoutModelNode/Edge/Group`, `LayoutEngine`, `LayoutContext`, `Dir`, `Side`, `Point`, `RoutePoint`, `Box`, `Size`, `EdgeRouting`.
- `layered(graph, ctx?) → LayoutModel`, the default engine (`layered/index.ts`).
- `layoutSettings({nodeSpacing?, rankSpacing?, diagramPadding?})` → `{ spacing, diagramPadding }` with v12 defaults (50/50/edge 20/8). `V12_SPACING`, `TURN_BREAKPOINT` (640), `SpacingConfig`.
- `validateLayout(graph, model) → string[]` (empty means valid) and `countCrossings(model)`. These are engine-agnostic DDLT helpers.
**Contract additions beyond DESIGN §6.1** (all optional): `LayoutNode.span` (how far edge ends spread along a side; default is side−24), `LayoutGraph.diagramPadding`, `routing: 'curved'|'stepped'|'straight'` (Pele `tracks`/`straight`, from `curve`), `headRoom` (arrowhead room). `LayoutModelEdge.points` is `RoutePoint[]` = `{x, y, axis: 'v'|'h'}` (Pele's route triples; the renderer needs the axis for S-curves). `LayoutContext` is just `{ options? }` for now. All x/y values are **centres**.
**Usage.** Diagram code measures every node, label and group title first (the engine never measures). It sets `edge.label` to the label box plus any room it wants around it (Pele used +12 w, +4 h). A group title sits in `padding.top`: half the padding above it, half below. `model.groups.get(id).title` is the centre of the title band. Self-loops: the engine reserves room beside the node and returns a 4-point loop on the right (TB/BT) or below (LR/RL); the reported node size is the one you passed in. Unknown edge ends, duplicate ids and NaN or negative sizes throw.
**availableWidth.** If the drawing is too wide, it is laid out tight (node spacing ×0.5, rank spacing ×0.75, group padding ×0.6) and the narrower result is kept. An LR/RL drawing whose budget is under 640 is then also laid out as TB, and `model.direction` reports the result. Label wrap widths are not narrowed: diagram code would have to re-measure for that.
**Tests.** `layered.fixtures.ts` holds the hand-built fixtures (`handBuiltFixtures()`, `LayoutFixture`). The build excludes `*.fixtures.ts` (`tsconfig.build.json`). `layered.spec.ts` runs validity and determinism checks over every fixture and snapshots crossing counts. Other specs: `available-width.spec.ts`, `spacing.spec.ts`, `groups.spec.ts`, `validate.spec.ts`.
**Hook for parser fixtures (TODO, #8/#14).** core can't import the parser, so add a spec in `packages/diagram-flowchart` that goes `.mmd` corpus → v13 parser + table measurer → `LayoutGraph` → `layered` → `validateLayout` + `countCrossings` (snapshot). `FIXTURES` in `layered.spec.ts` marks the same place for core-local additions.
**Known gaps.**
- Size: the engine measures **20.6 KB gz** minified (esbuild, layered+compound+adapter), against the 18 KB budget. Pele's own two files measure 18.5 KB. No size check is wired up: there is no esbuild devDep, so that is left for the perf/size ticket.
- v12's `ranksep + 25` inside subgraphs is not reproduced.
- Edge ids and declaration order: groups get `seq` after all nodes, so an empty group sorts last.
- Pele's internal layered/compound unit tests were not ported. The tests sit at the LayoutGraph seam only.
- `registerLayoutLoaders` and `layout:` config selection are not done here (public API ticket).
