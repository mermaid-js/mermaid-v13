# Ticket 15: public mermaid API (branch feature/15_m1)
**`mermaid`** (`packages/mermaid/src/{index,api,registry}.ts`): named + default exports `render, prepare, renderSync, preload, parse, initialize, detectType, supportsFormat, registerExternalDiagrams, registerLayoutLoaders, registerIconPacks, setParseErrorHandler`, plus `createMermaid()` (an API object with its own Registry + defaults; use it in tests for isolation). Types `RenderOptions {id?, config?, placeholders?, format?}`, `RenderResult {svg, diagramType, width, height, warnings, bindFunctions?}`, `Prepared {diagramType, config, parse, warnings}`, `ParseResult`, `InitializeConfig`, `IntegratorOptions {measurer, deterministic, linkSchemes, output.cssVariables}`, `ExternalDiagram`, `LayoutLoader {name, loader → LayoutEngine | {layout}}`. Re-exports `MermaidError, NotLoadedError, UnsupportedFormatError, renderErrorSvg`. No `run`/`mount` (#16).
- `render(id)` uses `id` as idPrefix. `initialize()` replaces a frozen snapshot (v12 semantics, incl. `fontFamily` → `themeVariables.fontFamily`); render reads it synchronously at call start. Integrator-only options are split off before resolveConfig.
- prepare caches the analysis per text + snapshot identity (LRU 32); a per-call `options.config` makes a new snapshot, so it never hits the cache (still correct).
- Resources: `diagram`, `layout` (registered but unloaded), `theme` (resolveThemeName → loadedTheme), `plugin.resources?()`. `placeholders`: missing layout/theme → built-in stand-in + `PLACEHOLDER` warning; missing diagram → error image + warning.
- Layout: `layered`, `dagre`, `elk`, `elk.*` → built-in unless registered under that name; unknown → layered + `LAYOUT_UNKNOWN`. flowchart-elk adds `layout: 'elk'` at plugin-defaults precedence.
- Config: front matter + init directives; v12's init `config` key moved into the diagram section. securityLevel resolved ONCE in api.ts (`resolveSecurityLevel` → `ctx.securityLevel`), flowchart renderer reads `ctx.securityLevel`.
- Warnings: preprocess/parse warning diagnostics, ConfigWarning, ThemeWarning, renderer warnings, `SECURITY_LEVEL`, `ICON_PACKS_UNSUPPORTED`. Nothing to console.
- Errors: preprocess/parse error diagnostics → `errorFromDiagnostics` (formatDiagnostic text; codes SYNTAX/SEMANTIC/LIMIT for EDGE_LIMIT); unknown text and types without package → UNSUPPORTED_DIAGRAM; stray `--- x` → v12 message; other throws → INTERNAL (RangeError → LIMIT).
**`@mermaid-js/core`** (`.` = `src/pipeline/`): `DiagramPlugin<M,L>`, `RenderContext`, `DiagramParseContext {config, preprocessed, claims?}`, `Warning`, `Resource`, `MermaidError(code, message, {source, offset, length, expected, diagnostics, cause})`, `NotLoadedError(missing)`, `UnsupportedFormatError`, `errorFromDiagnostics`, `renderErrorSvg(error, {theme?, version?})`, `drawDiagram(plugin, model, ctx)` (layout/serialise stage brackets; parse bracketed in api.ts; no separate `measure` stage).
**Flowchart**: `flowchart.parse(text, ctx: DiagramParseContext)` (maps maxEdges/inheritDir/claims); use `parseFlowchart(text, options)` for raw options. package.json `mermaid` manifest `{plugin, id, types, formats, export}`. `@mermaid-js/diagram-flowchart/testing` (renderForTest) is GONE.
**Registry generation**: `pnpm gen:registry` (tools/gen-config/src/registry.ts) writes `packages/mermaid/src/generated/registry.gen.ts` from manifests + v12 detector table (v12 regexes verbatim, incl. c4's unanchored `C4Container|…`); staleness spec in `registry.spec.ts`.
**Tests**: `packages/mermaid/src/api.spec.ts` (all ticket criteria except type test), `conformance/src/api-types.spec.ts` (v12 .d.ts, checked by typecheck; conformance tsconfig gained DOM lib), `conformance/src/flowchart-behaviour.spec.ts` (old render.spec via render()), `flowchart-render.spec.ts` (corpus via prepare/renderSync), `flowchart-layout.spec.ts` (graphs captured with a registered layout loader).
