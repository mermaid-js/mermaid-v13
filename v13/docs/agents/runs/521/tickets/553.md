## Exports (`@mermaid-js/diagram-block`)

- `BlockTokenKind` (`src/parser/tokens.ts` `T`): one kind per `block.jison` terminal, plus kinds with no jison name: `StringStart`/`StringEnd`, `MdStringStart`/`MdStringEnd`, `AccDescrMultiline`/`AccDescrMultilineEnd`, `ArrowDirStart` (`]>\s*(`). `Block` covers `block` and `block-beta` (both `BLOCK_DIAGRAM_KEY`). Shared: `Kind.Error`, `Kind.Comment`, `Kind.Directive`, `Kind.Space` (a dropped `;` no token took). No `Kind.Newline`: blanks and line breaks are no token.
- `JISON_NAMES`: kind → jison terminal (dev/test only).
- `blockTokens(src)` → `BlockToken[] { kind, text, range }`: significant tokens; `text` as v12's parser read it.
- Internal for #554: `blockView(src)` → `{ from, view }`, then `lex(src, from, view)` (`src/parser/lexer.ts`) → `Lexed { tokens, text(j) }` (trivia included, ends in `Kind.EOF`). Read text only through `text(j)`; T2 adds a kind-and-range variant if its token view needs one.

## Token facts the parser needs (oracle-checked)

- Text rewrites (jison actions): `COLUMNS` reads the digits as written (`03`) or `-1` for `auto`; `SPACE_BLOCK` `1` or the digits; `SIZE` the digits; `DIR` drops a leading `,\s*` only (`( right , left )` → ` right `, `left `); `BLOCK_ARROW_END` reads `]>`.
- Images keep trailing blanks: `classDef `, `CLASSDEF_ID` (`c `), `class `, `style `, `end\n  `, `LINK` (`--> `, after a label ` --> `), `START_LINK` (`-- `), `acc_title`. `STYLECLASS`/`STYLE_DEFINITION_DATA` keep leading blanks. The grammar trims them (v12 `.trim()`).
- Empty tokens: `STR ''` at the end of an unterminated string; `CLASSDEF_STYLEOPTS`, `STYLECLASS`, `STYLE_DEFINITION_DATA`, acc values `''` before a line break or at the end. A stream ending in a shape, arrow or class/classDef keyword state has no `EOF`.
- `LINK_LABEL`'s image is the quote; the label is the `STR` after it. `MD_STR` (markdown) appears where `STR` is expected: a parse error in v12.
- Ids take `; , . | & % # ~ " '` and Unicode; `x--x` is `NODE_ID:x LINK:--x`; `a-->>b` is `LINK NODE_DSTART:>`.
- After a lexical error the lexer lexes on (one code point per `Kind.Error`, same state).
