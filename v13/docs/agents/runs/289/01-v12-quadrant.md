# 01 — v12 quadrant chart: pointers for the port (#289)

Read the spec first; this file only adds what it lacks. `V12` = `git show fa796a943:packages/mermaid/src/diagrams/quadrant-chart/`.
Items marked (probed) were run on the 12.2.0 oracle in this session; others are from reading the source.

## 1. `parser/quadrant.jison` (189 lines)
Options/modes: `case-insensitive` l.2; exclusive `%x` l.4-14 (`string` is declared twice, l.4-5, harmless).
Lexer rules in order (first match wins, no longest-match):
- l.16 `%%(?!{)[^\n]*` skip; l.17 `[^\}]%%[^\n]*` skip (eats the char before; `[^}]` also matches `\n`); l.18 `[\n\r]+` NEWLINE; l.19 `%%…` skip.
- l.21-22 `title` -> mode `title`, `<title>(?!\n|;|#)*[^\n]*` = rest of line (the lookahead is a no-op). l.24-27 `accTitle\s*":"\s*`, `accDescr\s*":"\s*` with value modes, same rest-of-line rule. l.28-30 `accDescr\s*"{"\s*` -> `acc_descr_multiline`, `}` pops, `[^\}]*` is the value.
- l.32-38 padded keywords `" "*"x-axis"" "*`, `y-axis`, `\-\-+\>` (two or more dashes; `--->` works, probed), `quadrant-1..4`. l.39 `classDef` (unpadded).
- l.41-46 strings: `"`` -> `md_string` (`[^`"]+` MD_STR; `` `" `` pops), `"` -> `string` (`<string>["]` pops BEFORE `[^"]*` STR).
- l.48-49 `:::` -> `class_name` (`^\w+`). l.51-55 `\s*:\s*\[\s*` -> `point_start`; `point_start` number rule, then `point_x` (`\s*,\s*`), `point_y` (number, pops), then `point_start` `\s*\]" "*` pops. Number rule `(1)|(0(.\d+)?)` at l.52 and l.55.
- l.57 `quadrantChart` padded. l.59 ALPHA `[A-Za-z]+`; l.61 UNICODE_TEXT `[^\x00-\x7F]+`; l.62-76 COLON PLUS COMMA EQUALS(x2) MULT BRKT(`#`) UNDERSCORE DOT AMP MINUS NUM `\s`->SPACE SEMI PUNCTUATION; l.77 EOF.
- PUNCTUATION class l.76 `[!"#$%&'*+,-.`?\\_/]` contains the range `,-.`; `( ) < > [ ] { } @ ^ ~ |` match nothing.
Grammar (l.85-188): `start: eol start | SPACE start | QUADRANT document` (l.110-114); `line: statement eol` (l.121); `statement` has an empty alt, so blank lines and `;;` are fine (l.125-136). Points l.138-143 (4 alts: class x styles). Axis l.145-152, quadrants l.154-159, `eol` l.161-165, `text` l.167-175, `textNoTagsToken` l.187.
Dead grammar: `NODE_STRING DOWN DEFAULT UNIT STYLE PCT` (l.85-86) and `section` (l.135, `substr(8)`). `alphaNum` (l.177) is unused. `setWidth/setHeight` are never called by the grammar.

Spec quirks, confirmed: comment eats char before `%%` (probed: `A %% c` -> "A"), padded keywords mid-line, title takes rest of line, unlexable chars, coordinate regex (probed: `0x5` -> x=2455), `:::\w+`, one space after `classDef`.
Quirks the spec misses:
1. Trailing `%%` comments are NOT stripped inside title/accTitle/accDescr: `title T %% c` -> title `T %% c` (probed). Whole-line comments are removed earlier by `cleanupComments` (`V12/../../diagram-api/comments.ts`: `/^\s*%%(?!{)[^\n]+\n?/gm`) and `%%{init}` by directive removal, so l.16-19 only see trailing comments.
2. `""` (empty quoted label) is a parse error: l.45 pops without emitting STR (probed). Quoted labels may span newlines (`[^"]*`, probed). `"a" b` concatenates to `a b` (grammar l.169, `text textNoTagsToken` applies after STR/MD_STR too; type stays the first part's).
3. `:` can never appear in unquoted text (COLON is in neither `alphaNumToken` l.185 nor `textNoTagsToken`): `quadrant-1 Q: x` is rejected (probed). Text cannot start with `-` or SPACE.
4. `quadrantChart x-axis A` on one line is accepted (QUADRANT eats trailing spaces, l.57; probed). `\s*:\s*\[\s*` and `\s*,\s*` cross newlines: `P:\n[0.1, 0.2]` and `[0.1,\n0.2]` are accepted (probed).
5. `classDef` names use `idStringToken` (l.85: no UNDERSCORE), so `classDef a_b …` is rejected (probed), yet `:::a_b` lexes (`\w+`). Hyphens work in classDef but not after `:::`. Style text allows only `ALPHA NUM COLON SPACE BRKT MINUS` (l.86), so no `.`/`%`; separator is COMMA.
6. Jison auto-adds `\b` to bare word literals (`title`, `classDef`), so `titleCase: [0.1, 0.2]` is a point (probed). The padded and regex keywords have no `\b`.
7. `point_x`/`point_y` yytext is a STRING (`'0.1'`); coercion happens in d3 `scaleLinear` (builder l.480-494). `0x5` works because `Number('0x5')`=5 and `.` is unescaped.
8. Detector is case-sensitive but lexer is not (spec says so). Header may be preceded by blank lines/spaces (l.111-112). Input always gets `+ '\n'` and `encodeEntities` (`Diagram.ts` l.77) before lexing; `#…;` entity text becomes placeholders.

## 2. DB and utils
`V12/quadrantDb.ts` (module-level singleton `quadrantBuilder` l.30; `clear()` l.147-150 resets the builder AND common DB). Every text setter l.32-62 stores `sanitizeText(text.trim(), getConfig())` (l.21-23), dropping `type` (markdown flag is lost, spec Q1). `addPoint` l.95-106 calls `parseStyles` first (throws), sanitises text, `className` may be `""`, spreads styles. `addClass` l.108-110 -> Map `set` (last wins). `addPoints` prepends (builder l.213-215), so `getQuadrantData().points` is REVERSED (probed: dup `A` points kept).
`parseStyles` l.64-93: per style `trim().split(/\s*:\s*/)`, takes `[key, value]` only (extra parts ignored; a bare key gives `value` undefined -> regex fails). Keys: radius l.68 (`validateNumber`, `parseInt`), color l.73, stroke-color l.78 (kept verbatim: `ff0000` without `#` becomes `fill="ff0000"`, probed), stroke-width l.83 (string `10px`). Errors, exact: `value for ${style} ${value} is invalid, please use a valid ${type}` with type `number` | `hex code` | `number of pixels (eg. 10px)` (`InvalidStyleError`, `utils.ts` l.1-6); else `style named ${key} is not supported.` (l.89). Regexes `utils.ts` l.8-18.
`getQuadrantData` l.120-145: `getConfig()` at call time; `setConfig(quadrantChart)` (whole section, merged over defaults, persists across calls), `setThemeConfig` of the 15 vars, `titleText = getDiagramTitle()`.
Title flow: `Diagram.fromText(code, {title})` (`Diagram.ts` l.19-77): `db.clear()` l.49, then `metadata.title` -> `db.setDiagramTitle` l.52-54, then parse, so an in-text `title` overwrites it. `mermaidAPI.ts` l.578 passes `processed.title`; `getDiagramFromText` (l.744) passes `{}` so it skips front matter. `setDiagramTitle` (`diagrams/common/commonDb.ts`) sanitises without trimming (the in-text path trims in the grammar, l.132; not probed for front matter).
Empty `title` line gives an empty title and no title row (probed).

## 3. `quadrantBuilder.ts` (623 lines)
Defaults l.153-179 are `defaultConfig.quadrantChart?.x || literal`, so a configured 0 falls back to the literal (spec's "no literals" pitfall); l.158-159 swap `chartHeight`/`chartWidth` (harmless at 500x500, wrong if defaults ever differ). Schema `QuadrantChartConfig` `config.schema.yaml` l.1306-1425: defaults chartWidth/Height 500, titleFontSize 20, titlePadding 10, quadrantPadding 5, x/yAxisLabelPadding 5, x/yAxisLabelFontSize 16, quadrantLabelFontSize 16, quadrantTextTopPadding 5, pointTextPadding 5, pointLabelFontSize 12, pointRadius 5, xAxisPosition `top`, yAxisPosition `left`, internal border 1, external 2; all 19 keys `required` (l.1311-1330), `unevaluatedProperties: false`. Section name `quadrantChart`, no entry in `defaultConfig.ts` beyond the schema-generated one.
`build()` l.604-622: showX/Y = has any label (l.605-608); showTitle = non-empty (l.609); x axis forced `bottom` if any point (l.611). Quantities:
- `calculateSpace` l.231-284: axis space = 2*pad + fontSize (l.237, l.244), title space = fontSize + 2*titlePadding (l.251); `quadrantLeft = quadrantPadding + yLeft` (l.256); `quadrantTop = quadrantPadding + xTop + titleTop` (l.257); width l.258, height l.260; halves l.267-268.
- Axis labels l.286-382: centred iff the right/top label exists (l.302-303). x: `x = quadrantLeft (+ halfW/2 [+ halfW for right])`, y top = `xPad + titleSpace.top`, bottom = `xPad + quadrantTop + quadrantHeight + quadrantPadding`, `verticalPos` center|left, rotation 0. y: x = `yPad` (left) or `yPad + quadrantLeft + quadrantWidth + quadrantPadding` (right); bottom label y = `quadrantTop + H - (mid? halfH/2:0)` (l.355); top label y = `quadrantTop + halfH - (mid? halfH/2 : 0)` (l.373-374), so a lone top label sits at the half line; rotation -90. Both use `horizontalPos: 'top'`.
- Quadrants l.384-473: order is q1 (top-right), q2 (TL), q3 (BL), q4 (BR) (l.401, 418, 435, 452). Label x = rect centre (l.460); y = centre, `middle` if no points, else `y + quadrantTextTopPadding`, `top` (l.462-469).
- Points l.475-514: scaleLinear [0,1]; x range [left, left+W], y range [top+H, top] (inverted); class merge `{...classStyles, ...point}` (l.490-492, inline wins; unknown or `""` class ignored); fill = `color ?? quadrantPointFill`, radius = `radius ?? pointRadius`, text y = `yAxis + pointTextPadding`, anchor center/top, stroke colour default = `quadrantPointFill`, width default `'0px'` string.
- Borders l.516-586: 4 outer (top, right, bottom, left; top/bottom overhang by half the external width, left/right inset by it) then vertical inner, horizontal inner. Widths are numbers.
- Title l.588-602: x = chartWidth/2, y = titlePadding, `top`, `center` (middle-anchored).
Theme vars read via `quadrant*` keys of `themeConfig` (l.86-102, defaults from `theme-default` l.181-199). Keys read from config: all 19 except `useMaxWidth`/`useWidth`; `showXAxis/showYAxis/showTitle` are builder-only (l.81-83, never set).
Oracle note (probed): default point fill is `hsl(240, 100%, NaN%)`, default quadrant1 `#ECECFF`, outer border `hsl(240, 60%, 86.2745098039%)`.

## 8. Oracle access
`packages/conformance/src/oracle.ts`: `loadOracle().parse(text, config?)` (l.53-95) imports `mermaid-v12` (npm `mermaid@^12.2.0`), patches DOMPurify to identity, calls `getDiagramFromText` (so front-matter title is skipped), returns `{accepted, diagramType: 'quadrantChart', db}`. `db` is v12's quadrantDb default export, so `db.getQuadrantData()` returns the `QuadrantBuildType` and the DB also has `getAccTitle/getAccDescription/getDiagramTitle`. The quadrant chunk loads lazily on first detection. Nothing is exposed for classDef or markdown flags; the builder's data is only reachable through `getQuadrantData()`, whose `points` are reversed and whose axis labels do not say left/right (infer from order and x).
Probed gotchas: (a) `getQuadrantData()` reads the GLOBAL config when called; `oracle.parse(text, config)` resets config in `finally` before returning, so an option-passed `quadrantChart`/`themeVariables` config is NOT seen (probed: `quadrant1Fill` came back `#ECECFF`). Config carried by `%%{init}` in the text is the usable route, or extend the oracle. (b) The builder is a singleton, and `setConfig` persists until the next `clear()`; call `getQuadrantData()` before the next parse.
Pattern for other types: `src/sequence/jison-lexer.ts` (wraps `parser.lexer.setInput` to capture the exact lexer input, re-lexes with a fresh DB class, `LEXICAL_ERROR` sentinel, `$end` = 1), `src/sequence/v12.ts` (snapshot of the DB). `loadJisonLexerOracle('quadrant')` (#285) does not exist yet in this tree. Probe: `probe.parser.parser` from `getDiagramFromText('quadrantChart')`; the DB constructor trick does not apply (quadrantDb is a plain object, pass it as `yy`).
