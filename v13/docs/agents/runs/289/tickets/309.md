# T0 #309: theme DSL `adjust()` (D232)

Branch `feature/309_theme-adjust`. Core only; no quadrant variable added (that is T5 #317).

## What exists

- DSL rule `adjust(color, r, g, b)`: adds a signed offset to each sRGB channel (0–255), each
  clamped, as khroma's `adjust(c, { r, g, b })` in v12's `/* quadrant-graph */` rules.
  Offsets are plain numbers from -255 to 255 (up to 4 decimals); `%` is rejected.
- JS: `adjustChannels(c, r, g, b)` in `packages/core/src/theme/color.ts` (not re-exported from
  the theme index; the DSL is the interface).
- CSS: `rgb(from <c> clamp(0, r + R, 255) clamp(0, g + G, 255) clamp(0, b + B, 255) / alpha)`,
  so the value follows a host `--mermaid-*` override (R-THEME-4).
- Tokenizer: plain signed numbers, `Expr` kind `num`; outside `adjust` they throw a SyntaxError.

## How T5 uses it (a theme spec or plugin rule table, as v12 theme-default)

    quadrant2Fill: 'adjust(quadrant1Fill, 5, 5, 5)',
    quadrant2TextFill: 'adjust(quadrant1TextFill, -5, -5, -5)',

## Tests

- `packages/core/src/theme/rules.spec.ts`: JS literals vs khroma 2.1.0 (`#fff4dd` +5 →
  `#fff9e2`, negatives, mixed signs, clamping both ways, alpha kept), the compiled CSS, and
  malformed-argument errors.
- `packages/core/src/theme/color.spec.ts`: `adjustChannels`.
- `e2e/browser/theme.spec.ts`: two `adjust` rules join the JS-vs-browser agreement check over
  seven backgrounds (black and white cover clamping).

## Choices and unmet criteria

- CSS clamps explicitly (`clamp(0, r + R, 255)`), not bare `calc(r + R)` as the ticket wrote:
  relative colour syntax can keep out-of-range channels, and `lightenHsl` already clamps the
  same way (D117).
- Unmet: none. Existing theme output unchanged: no existing rule edited, `pnpm check` green.
