# #332 T3 layout: handoff

Package scaffold `packages/diagram-quadrant`, `"private": true` (no manifest, no plugin, not packed or released: T5 adds the manifest, drops `private` and adds the `feat: first release` changeset, which `release-config.spec.ts` and `publish.spec.ts` then require; registry untouched). `theme-used-by.spec.ts` lists `quadrant` with a `NOT_YET_DRAWN` exemption from "reads a theme variable"; T4 removes it. `quadrantChart` now has a section owner (`tools/gen-config` `SECTION_OWNERS`), so `pnpm gen:config` writes `src/generated/config-defaults.ts`.

**Exports** (`@mermaid-js/diagram-quadrant`): the model types (`src/model.ts`), `layoutQuadrant`, `quadrantLayoutViolations`, the layout types (`src/layout/types.ts`), `quadrantChartConfigDefaults`.

**`QuadrantModel` contract (T2 adopts it, extends additively):**
- `title?` (effective: last in-text `title`, else front matter; `''` shows none), `titleAst?` (`st:<n>`), `accTitle`, `accDescr`.
- `quadrants`: 4-tuple, index 0 = `quadrant-1`, each `{ ast: 'q:N', text, markdown } | undefined`.
- `xAxis?`/`yAxis?`: `{ ast: 'ax:x'|'ax:y', start?, end? }` with `start`/`end` = text before/after `-->` as `{ text, markdown }`. Label ids: start = `ax:x`/`ax:y`, end = `ax:x/end`/`ax:y/end` (one `data-ast` each, pitfall 12). An axis statement sets only the labels it names (v12 `setData` merge). `x-axis Low -->` → `start: 'Low ⟶'`.
- `points` in source order: `{ ast: 'pt:<name>'[@n], label: { text, markdown }, className?, x: string, y: string, styles }`. `x`/`y` are the lexed text (`'0.3'`, `'0x5'`); the layout converts.
- `styles` (point and class): `{ radius?: number, color?: string (as written, `#` optional), strokeColor?: string, strokeWidth?: number (px) }`, all already validated.
- `classes: ReadonlyMap<name, { ast: 'c:<name>', styles }>` (last `classDef` wins), `warnings: Diagnostic[]`.
- An overridden statement (repeated `quadrant-N`, `title`, axis) draws nothing and has no slot; T2 gives its node `st:<ordinal>`.

**Use:** `layoutQuadrant(model, config, warn?)`, where `config` is the resolved `ctx.config.quadrantChart` (`QuadrantLayoutConfig`, core merges `configDefaults`). T5's plugin should set `configDefaults: quadrantChartConfigDefaults` and forward `ctx.warn`. Output: `width`/`height` (= chart size; D224 growth is T4's), `quadrants` (q1..q4, rect + text anchor, label `''` when unset), `borders` (4 external then 2 internal), `axisLabels` (x start, x end, y start, y end; `ast` per label as above), `points` (source order; T4 draws them reversed), `title?`. Text anchors carry `anchor` (`start`|`middle`) and `baseline` (`hanging`|`middle`), `rotation` (0 or −90), `fontSize`. Point `fill`/`stroke` are undefined unless a style sets them (renderer then uses `quadrantPointFill`), with `#` added (D235); `strokeWidth` px, default 0.

**Test helpers:** `src/layout/fixtures.ts` (`model`, `config`, `quadrants`, `axis`, `point`). Conformance: `src/quadrant/v12.ts` (`v12Quadrant(source)` → v12's builder output and a model built from v12's DB calls; `v13QuadrantConfig(source)`).

**Tests:** `layout.spec.ts`, `invariants.spec.ts` (hand-built models); `conformance/src/quadrant/layout-parity.spec.ts`: 14 corpus files + 6 extra cases (one with 0-valued options) equal `getQuadrantData()` to 0.01 px, styled point fill/stroke included (`#` added to v12's, D235; only v12's NaN default fill is left out), plus the invariants on each; `0x5` case; `quadrant-layout-literals.spec.ts`.

**Size:** 2.0 KB gz (4.8 KB min, esbuild ESM, core external). Timing not measured on a steady machine.

**Choices:**
- Interim fixtures: models come from recording v12's DB calls (`yy`) during the oracle parse, not from the v13 parser.
- The oracle does not apply `%%{init}` (12.2.0 `getDiagramFromText` drops directive config), so `v12Quadrant` sets the directive's `quadrantChart` options with v12's `initialize` around the parse. `oracle.ts` is unchanged.
- The square's width and height are clamped to >= 0: a schema-valid small chart (`chartWidth: 20` with a y-axis label) gave v12 a negative, invalid `<rect>` size. Differs from v12 only there.
- Coordinates convert as v12's d3 did (`Number(text)`); in [0, 1] is drawn, so `0x0`/`0x1` plot as in v12. Points left out still count for "has points" (x axis at the bottom, quadrant labels at the top), as v12 laid them out.
