feat: what icons build on (D293, D294). Inline providers take a `pattern` (`{ pattern: RegExp, box }`) besides a delimiter pair, and a `fa:fa-…` label icon no provider draws gives one `ICON_NOT_RENDERED` per render (text output: one `ASCII_DROPPED` with `feature: 'icon'`). An extension's `glyphs` draw icons outside labels as `RenderContext.icon(name, size, { fallbackPrefix, paint })`, which returns the glyph fitted into the square and painted with `paint` (a colour, or the gradient on its `currentColor` paints), `null` for a name the extension reports unresolved, or `undefined`; `DiagramPlugin.icons(model)` lists those names as `DiagramIcon` (`string | { name, fallbackPrefix? }`) for `ResourceRequest.icons()`. Types `IconPacks`, `IconPackSource`, `IconPackState`, `IconifyJSON`, `IconifyIcon`, `IconifyAlias`, `GlyphProvider`, `GlyphRequest`, `GlyphOptions`, `IconOptions`, `DiagramIcon`; the `icons` extension claim; `iconPacks` on `ResourceRequest`, `RenderContext`, `InlineRequest` and `GlyphRequest` (read-only at draw, without `load`), and one per-render `scratch` on `InlineRequest`, `GlyphRequest` and `InlineSpans`. `writeFragment` is exported from `@mermaid-js/core/svg` and `entityAt` from `@mermaid-js/core/text`; `fill-rule` and `clip-rule` (`nonzero`, `evenodd`) are allow-listed.
