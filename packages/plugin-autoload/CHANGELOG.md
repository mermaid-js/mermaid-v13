# @mermaid-js/plugin-autoload

## 13.0.0-alpha.1

### Patch Changes

- [#1132](https://github.com/mermaid-js/mermaid-v13/pull/1132) [`ade9f95`](https://github.com/mermaid-js/mermaid-v13/commit/ade9f95d7ba97fadc1306c3da0b19812a80212d3) Thanks [@ashishjain0512](https://github.com/ashishjain0512)! - refactor: the language server loads a plugin's detector and language module with `@mermaid-js/plugin-autoload`'s loader, which now exports `detectorOf`, `importWithin` and `IMPORT_TIMEOUT_MS`, so its timed imports no longer keep the process alive while they wait. The bundler plugin drops a branch the scan never reaches. Discovery results are unchanged.

- [#882](https://github.com/mermaid-js/mermaid-v13/pull/882) [`f8d171a`](https://github.com/mermaid-js/mermaid-v13/commit/f8d171ac342f588b8f9e73d873819ff67d1be9cb) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: first release of `@mermaid-js/plugin-autoload`, opt-in plugin discovery for Node. `await autoload(mermaid)` registers the plugins your app's `package.json` lists (`dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies`), read from the app's own `node_modules` and registered in package-name order: diagrams, extensions and layouts. Every manifest path must stay inside its package and each import has a time limit. It returns the warnings and never throws for a package's sake: a package that fails to load, has a bad manifest or repeats an id is skipped with a warning and the others still register. A plugin installed only as a dependency of another package is not found: add it to your `package.json`. Call it before the first render.
