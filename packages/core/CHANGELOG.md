- [#347](https://github.com/mermaid-js/mermaid-v13/pull/347) [`a58fba2`](https://github.com/mermaid-js/mermaid-v13/commit/a58fba2b78b680a018706c2662b1c8fe6f8583d2) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: what icons build on (D293, D294). - [#349](https://github.com/mermaid-js/mermaid-v13/pull/349) [`f433e76`](https://github.com/mermaid-js/mermaid-v13/commit/f433e76f0c391850c4100aaaf10f44207655d5b1) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: first release of `@mermaid-js/plugin-hand-drawn`, the hand-drawn look. Register `handDrawn` with `registerExternalDiagrams([handDrawn])` and set `handDrawn: true`, or v12's `look: handDrawn` at the top level or in a diagram section. Flowchart, class, state and ER outlines are sketched with roughjs 4.6.6's DOM-free generator, with v12's roughjs options per role, in the theme's own colours. `handDrawnSeed` moves from core's config to the plugin; 0 is a fixed seed (2147483647), so the output is the same on every render, in Node and the browser. Without the plugin, `handDrawnSeed` is an unknown key and `LOOK_REMOVED` names the package. The layout never changes, and text output gets one `ASCII_DROPPED` warning (`feature: 'handDrawn'`). The sketch adapter (`sketch(tag, attrs, options, seed)`) is exported too.

- [#255](https://github.com/mermaid-js/mermaid-v13/pull/255) [`aac2097`](https://github.com/mermaid-js/mermaid-v13/commit/aac2097c19d3b1517e8aa701003cd8f8397e4f8c) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: first release of `@mermaid-js/plugin-math`. Register it with `mermaid.registerExternalDiagrams([math])` and TeX between `$$` delimiters in flowchart labels is typeset by MathJax into SVG paths. MathJax is loaded only by `prepare()`/`render()` for a diagram with math; `renderSync` before then throws `NotLoadedError` naming `math "tex"`, or draws the TeX as written with a `PLACEHOLDER` warning when placeholders are asked for, and `preload({ math: true })` loads it up front. TeX that does not parse is shown as written with a `MATH_ERROR` warning. Core: extension plugins can declare `resources` that `prepare()` loads, and inline providers get a `warn` sink.
