### Patch Changes

- [#1132](https://github.com/mermaid-js/mermaid-v13/pull/1132) [`ade9f95`](https://github.com/mermaid-js/mermaid-v13/commit/ade9f95d7ba97fadc1306c3da0b19812a80212d3) Thanks [@ashishjain0512](https://github.com/ashishjain0512)! - refactor: the language server loads a plugin's detector and language module with `@mermaid-js/plugin-autoload`'s loader, which now exports `detectorOf`, `importWithin` and `IMPORT_TIMEOUT_MS`, so its timed imports no longer keep the process alive while they wait. - [#882](https://github.com/mermaid-js/mermaid-v13/pull/882) [`f8d171a`](https://github.com/mermaid-js/mermaid-v13/commit/f8d171ac342f588b8f9e73d873819ff67d1be9cb) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: the bundler plugin's build-time scan reads only the packages the app's `package.json` declares (`dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies`), so a plugin npm or Yarn hoists as another package's dependency is no longer bundled: add it to your `package.json`. A root with no readable `package.json` discovers nothing and warns once.

- [#256](https://github.com/mermaid-js/mermaid-v13/pull/256) [`2158515`](https://github.com/mermaid-js/mermaid-v13/commit/2158515780459fb92b9cba9c684f902bb0125dd0) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: first release of `@mermaid-js/bundler-plugin`, one-line Mermaid plugin discovery for Vite, webpack, Rollup and esbuild: `plugins: [mermaid()]` (from `@mermaid-js/bundler-plugin/vite`, `/webpack`, `/rollup` or `/esbuild`). At build time it scans the app's own `node_modules` for packages with a `mermaid` manifest and bundles each detector, with each diagram entry in its own lazily loaded chunk. Installed extensions, `@mermaid-js/plugin-interactions` among them, are activated with no registration code.
