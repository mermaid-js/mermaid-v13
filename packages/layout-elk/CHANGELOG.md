# @mermaid-js/layout-elk

## 13.0.0-alpha.1

### Patch Changes

- [#255](https://github.com/mermaid-js/mermaid-v13/pull/255) [`09f9319`](https://github.com/mermaid-js/mermaid-v13/commit/09f9319b902359410db4512c7b1052a135a4d14c) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: first release of `@mermaid-js/layout-elk` on the 13.x line, the ELK layouts (`elk`, `elk.layered`, `elk.stress`, `elk.force`, `elk.mrtree`, `elk.sporeOverlap`, `elk.box`, `elk.rectpacking`, `elk.radial`), laid out synchronously with elkjs. Register it as in v12 with `mermaid.registerLayoutLoaders(elkLayouts)`; installing it changes no default. Without it, `mermaid` draws an ELK name or the `flowchart-elk` header with `layered` and adds one `ELK_NOT_INSTALLED` warning.

- [#255](https://github.com/mermaid-js/mermaid-v13/pull/255) [`411e967`](https://github.com/mermaid-js/mermaid-v13/commit/411e9676909d16e790707d1cac4e1a00c99d226f) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: `@mermaid-js/layout-elk` honours every v12 `elk.*` key (`mergeEdges`, `nodePlacementStrategy`, `nodePlacementAlignment`, `preset`, `straightenEdges`, `lineHops`, `layeringStrategy`, `layeringLayerBound`, `cycleBreakingStrategy`, `forceNodeModelOrder`, `considerModelOrder`, `keepEntryNodeOnTop`, `orientFeedbackEdges`) with v12's defaults and presets. The `elk` section moves out of core's config schema into the package's config fragment: core knows it only while the package is registered. A group's `@{ algorithm }` is parsed but not applied yet and gives one `ELK_ALGORITHM_IGNORED` warning; `elk.radial` on a graph ELK cannot lay out as a tree draws with `layered` and one `ELK_RADIAL_NOT_A_TREE` warning. `LayoutLoader` gains an optional `extension`, whose hooks run only on renders laid out by that loader.
