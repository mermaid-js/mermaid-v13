- [#630](https://github.com/mermaid-js/mermaid-v13/pull/630) [`6021e9a`](https://github.com/mermaid-js/mermaid-v13/commit/6021e9ab701bfd79fb7f318b918eaa758fd0a263) Thanks [@ashishjain0512](https://github.com/ashishjain0512)! - feat: the `compass` layout engine at `@mermaid-js/core/layout/compass`, Pele's grid placement from edge sides (D326), loaded lazily by `mermaid`. Any graph type can select it with `layout: compass` (D327, D502); edges without sides take them from `direction`. `LayoutGraph` gains four optional fields that only `compass` reads: `LayoutEdge.sides`, `LayoutEdge.border`, `LayoutGraph.align` and `LayoutNode.anchorY` (D501).

- [#646](https://github.com/mermaid-js/mermaid-v13/pull/646) [`2a9ba2b`](https://github.com/mermaid-js/mermaid-v13/commit/2a9ba2b54c1b7a9ffe35fbbe84ec308fd03cf22e) Thanks [@ashishjain0512](https://github.com/ashishjain0512)! - feat: line hops for every diagram that draws edges (#78). A new top-level `lineHops` key (`false`, `true`, `'arc'` or `'gap'`, default `false`) draws a small arc, or a break, where one edge crosses another: a horizontal run gives way to a vertical one, otherwise the later edge does. `swimlane.lineHops` (default `'arc'`) and `elk.lineHops` (default `true`) still turn hops on under those layouts; a top-level `lineHops: false` turns them off everywhere. The hops live in a lazily loaded part of core, `@mermaid-js/core/layout/hops`, loaded like a lazy layout named `lineHops` when the shared key is on (the `swimlane` and ELK engines carry it, so preloading them is enough): `renderSync` needs `prepare()` or `preload({ layouts: ['lineHops'] })` first. `@mermaid-js/layout-elk` no longer draws hops itself and drops its `postRender` hook, so ELK renders keep the stream writer.
