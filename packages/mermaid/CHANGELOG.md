- [#255](https://github.com/mermaid-js/mermaid-v13/pull/255) [`09f9319`](https://github.com/mermaid-js/mermaid-v13/commit/09f9319b902359410db4512c7b1052a135a4d14c) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: first release of `@mermaid-js/layout-elk` on the 13.x line, the ELK layouts (`elk`, `elk.layered`, `elk.stress`, `elk.force`, `elk.mrtree`, `elk.sporeOverlap`, `elk.box`, `elk.rectpacking`, `elk.radial`), laid out synchronously with elkjs. Register it as in v12 with `mermaid.registerLayoutLoaders(elkLayouts)`; installing it changes no default. Without it, `mermaid` draws an ELK name or the `flowchart-elk` header with `layered` and adds one `ELK_NOT_INSTALLED` warning.

- [#255](https://github.com/mermaid-js/mermaid-v13/pull/255) [`411e967`](https://github.com/mermaid-js/mermaid-v13/commit/411e9676909d16e790707d1cac4e1a00c99d226f) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: `@mermaid-js/layout-elk` honours every v12 `elk.*` key (`mergeEdges`, `nodePlacementStrategy`, `nodePlacementAlignment`, `preset`, `straightenEdges`, `lineHops`, `layeringStrategy`, `layeringLayerBound`, `cycleBreakingStrategy`, `forceNodeModelOrder`, `considerModelOrder`, `keepEntryNodeOnTop`, `orientFeedbackEdges`) with v12's defaults and presets. The `elk` section moves out of core's config schema into the package's config fragment: core knows it only while the package is registered. A group's `@{ algorithm }` is parsed but not applied yet and gives one `ELK_ALGORITHM_IGNORED` warning; `elk.radial` on a graph ELK cannot lay out as a tree draws with `layered` and one `ELK_RADIAL_NOT_A_TREE` warning. `LayoutLoader` gains an optional `extension`, whose hooks run only on renders laid out by that loader.

- [#256](https://github.com/mermaid-js/mermaid-v13/pull/256) [`2158515`](https://github.com/mermaid-js/mermaid-v13/commit/2158515780459fb92b9cba9c684f902bb0125dd0) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: `mermaid/discovered`, an empty module that `@mermaid-js/bundler-plugin` replaces with the plugins it found at build time; `mermaid` registers them before the first render (`initialize({ discovery: false })` turns them off). Without the plugin nothing changes. `mermaid/node-scan` also exports `FIRST_PARTY_IDS`.

- [#161](https://github.com/mermaid-js/mermaid-v13/pull/161) [`24468c6`](https://github.com/mermaid-js/mermaid-v13/commit/24468c63c38a04cad0346e856443b55f527dd8d3) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: `mermaid` renders `erDiagram`, as SVG and as text (`format: 'ascii'`), through `createMermaid()`, `render()` and `mermaid/slim` with the `er` diagram. The `er` config section is honoured where v12 12.2.0 reads it (`nodeSpacing`, `rankSpacing`, `minEntityWidth`, `entityPadding`, `diagramPadding`, `useMaxWidth`); MIGRATION.md lists what differs from v12.

- [#347](https://github.com/mermaid-js/mermaid-v13/pull/347) [`a58fba2`](https://github.com/mermaid-js/mermaid-v13/commit/a58fba2b78b680a018706c2662b1c8fe6f8583d2) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: `registerIconPacks([{ name, icons }])` and `registerIconPacks([{ name, loader }])` register Iconify JSON packs on the API object (one registry per `createMermaid()`; `name` overrides the pack's `prefix`), for `@mermaid-js/plugin-icons` to draw. A loader runs only when a diagram names its pack, in `prepare()`/`render()`, or up front with `preload({ iconPacks: ['fa'] })`; `renderSync` before then throws `NotLoadedError` naming the pack, or draws placeholders with `placeholders: true`. A loader that rejects does not fail the render: its icons are not drawn, and the next `prepare()` retries it. While packs are registered and no extension claims `icons`, every render warns `ICON_PACKS_UNSUPPORTED`. Types `IconLoader`, `AsyncIconLoader`, `SyncIconLoader`, `IconifyJSON`, `IconifyIcon`, `IconifyAlias`, `IconPacks` and `IconPackState`.

- [#349](https://github.com/mermaid-js/mermaid-v13/pull/349) [`101dab1`](https://github.com/mermaid-js/mermaid-v13/commit/101dab15d7e6a18dd948f1876f2bfb2cb4a3f293) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: `mermaid` renders `pie` charts as SVG through `createMermaid()`, `render()` and `mermaid/slim` with the `pie` diagram. The `pie` config section is honoured (`textPosition`, `donutHole`, `legendPosition`, `highlightSlice`, `useMaxWidth`), and the pie theme variables (`pie1`–`pie12`, the pie text, stroke and `pieOpacity` variables) carry each theme's v12 values; `pieOpacity` is a new `opacity` kind, a number from 0 to 1. MIGRATION.md lists what differs from v12.

- [#350](https://github.com/mermaid-js/mermaid-v13/pull/350) [`c0b1a0b`](https://github.com/mermaid-js/mermaid-v13/commit/c0b1a0b9a4bd92e9146f9d6eb61622ef39bb1f1d) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: `mermaid` renders `timeline` diagrams (LR and TD) as SVG through `createMermaid()`, `render()` and `mermaid/slim` with the `timeline` diagram. The `timeline` config section is honoured where v12 12.2.0 reads it (`leftMargin`, `padding`, `useMaxWidth`, `disableMulticolor`, and the top-level `fontSize` in box heights); the keys v12's timeline never read are ignored. `Theme.paletteRgba()` gives a palette's colour channels. MIGRATION.md lists what differs from v12.

- [#349](https://github.com/mermaid-js/mermaid-v13/pull/349) [`f433e76`](https://github.com/mermaid-js/mermaid-v13/commit/f433e76f0c391850c4100aaaf10f44207655d5b1) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: first release of `@mermaid-js/plugin-hand-drawn`, the hand-drawn look. Register `handDrawn` with `registerExternalDiagrams([handDrawn])` and set `handDrawn: true`, or v12's `look: handDrawn` at the top level or in a diagram section. Flowchart, class, state and ER outlines are sketched with roughjs 4.6.6's DOM-free generator, with v12's roughjs options per role, in the theme's own colours. `handDrawnSeed` moves from core's config to the plugin; 0 is a fixed seed (2147483647), so the output is the same on every render, in Node and the browser. Without the plugin, `handDrawnSeed` is an unknown key and `LOOK_REMOVED` names the package. The layout never changes, and text output gets one `ASCII_DROPPED` warning (`feature: 'handDrawn'`). The sketch adapter (`sketch(tag, attrs, options, seed)`) is exported too.

- [#255](https://github.com/mermaid-js/mermaid-v13/pull/255) [`aac2097`](https://github.com/mermaid-js/mermaid-v13/commit/aac2097c19d3b1517e8aa701003cd8f8397e4f8c) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: first release of `@mermaid-js/plugin-math`. Register it with `mermaid.registerExternalDiagrams([math])` and TeX between `$$` delimiters in flowchart labels is typeset by MathJax into SVG paths. MathJax is loaded only by `prepare()`/`render()` for a diagram with math; `renderSync` before then throws `NotLoadedError` naming `math "tex"`, or draws the TeX as written with a `PLACEHOLDER` warning when placeholders are asked for, and `preload({ math: true })` loads it up front. TeX that does not parse is shown as written with a `MATH_ERROR` warning. Core: extension plugins can declare `resources` that `prepare()` loads, and inline providers get a `warn` sink.
