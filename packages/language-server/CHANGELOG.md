# @mermaid-js/language-server

## 13.0.0-alpha.4

### Patch Changes

- [#1132](https://github.com/mermaid-js/mermaid-v13/pull/1132) [`ade9f95`](https://github.com/mermaid-js/mermaid-v13/commit/ade9f95d7ba97fadc1306c3da0b19812a80212d3) Thanks [@ashishjain0512](https://github.com/ashishjain0512)! - refactor: the language server loads a plugin's detector and language module with `@mermaid-js/plugin-autoload`'s loader, which now exports `detectorOf`, `importWithin` and `IMPORT_TIMEOUT_MS`, so its timed imports no longer keep the process alive while they wait. The bundler plugin drops a branch the scan never reaches. Discovery results are unchanged.

- [#850](https://github.com/mermaid-js/mermaid-v13/pull/850) [`901a991`](https://github.com/mermaid-js/mermaid-v13/commit/901a9919836c45db23243a291c85725380048614) Thanks [@knsv-bot](https://github.com/knsv-bot)! - The language server highlights the other uses of the name under the cursor, grows and shrinks the selection by syntax, and shows the diagram's outline (#810).

- [#828](https://github.com/mermaid-js/mermaid-v13/pull/828) [`cbe3030`](https://github.com/mermaid-js/mermaid-v13/commit/cbe3030cd4ffaf020c53b562c1d3054ad9aa680d) Thanks [@knsv-bot](https://github.com/knsv-bot)! - fix: the language server exits when its editor closes stdin, prints `--version`, refuses the IPC, pipe and socket transports, sends the document version with its diagnostics, syncs changes incrementally, keeps the service's completion order in every LSP editor, and its README now covers every diagram type and shows Neovim, Helix and `vscode-languageclient` setups (#805, #806, #807, #812).

- [#850](https://github.com/mermaid-js/mermaid-v13/pull/850) [`5a5809c`](https://github.com/mermaid-js/mermaid-v13/commit/5a5809c25cfa8961786be39292d9050f7693f4c4) Thanks [@knsv-bot](https://github.com/knsv-bot)! - With `mermaid.markdown` on, the language server serves the Mermaid fences in Markdown files (`.md`, `.markdown`, `.mdx`); `mermaid.markdownTokensAndFolding` adds their highlighting and folding, and the language service exports `mermaidFences` (#811).

- [#850](https://github.com/mermaid-js/mermaid-v13/pull/850) [`fb6b49c`](https://github.com/mermaid-js/mermaid-v13/commit/fb6b49cf67f566e6aa3c96ad0e94a97d09e06317) Thanks [@knsv-bot](https://github.com/knsv-bot)! - With plugins on, the language server also finds plugins installed in a nested workspace package (`packages/foo/node_modules` in a pnpm workspace) once you open a file there (#172).

- [#882](https://github.com/mermaid-js/mermaid-v13/pull/882) [`f8d171a`](https://github.com/mermaid-js/mermaid-v13/commit/f8d171ac342f588b8f9e73d873819ff67d1be9cb) Thanks [@knsv-bot](https://github.com/knsv-bot)! - feat: the language server finds plugins with `@mermaid-js/plugin-autoload`, not `mermaid/node-scan`. With `plugins: true` it reads only the packages each workspace folder's `package.json` declares (`dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies`); a plugin installed only as a dependency of another package is no longer found. A workspace folder without a readable `package.json` discovers nothing, and the server logs one line saying so. The server no longer depends on `mermaid`.

- [#850](https://github.com/mermaid-js/mermaid-v13/pull/850) [`fd59fc6`](https://github.com/mermaid-js/mermaid-v13/commit/fd59fc6483c877ee06332f62781c6a02739e401d) Thanks [@knsv-bot](https://github.com/knsv-bot)! - The language server now finds plugins exactly as `mermaid` does in Node, so a plugin package needs its `entry` file to get editor support, and a client with no workspace folder gets no plugins; `mermaid/node-scan` adds `packageModule` (#808).
